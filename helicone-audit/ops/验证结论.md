### 本轮范围与剩余边界

生产 Nginx、Sub2API 源码未修改，生产流量尚未切入，未采集真实用户提示词。真实验证只调用只读模型列表，不能据此宣称计费已完成端到端验证。

完整上线仍需可信用户映射、会话关联、入口注入独立审计认证头、故障隔离及保留期限。不能把审计管理员身份当作业务用户，也不能信任客户端自报用户编号。直通路径仍标记 is_stream=false；原始 SSE 已保存，但结构化指标、模型费用解析、工具调用和 WebSocket 未验证。

升级时在新上游独立分支执行 `git apply --check authorization-passthrough.patch`，再应用、编译并回归；不要盲目覆盖冲突。停止测试网关可运行 `docker stop cc2cx-helicone-passthrough`，不会改变生产入口。

## 结论

本轮没有将 Helicone 接入生产 Nginx，没有修改 Sub2API、用户密钥或数据库，没有采集真实用户正文。

两只测试容器均已停止。源码、镜像和合成测试文件保留供复查。结束时外网访问 `https://cc2.cx/health` 返回 HTTP 200；此检查仅确认健康端点可访问，不代表完成所有业务回归。

当前官方独立网关镜像不符合“保留 Sub2API 原用户认证与计费、直接接入 Codex”的前置条件。不得使用公用上游密钥绕过该问题，否则请求将计入公用密钥所属用户。

## 实测

使用本机合成上游，不使用真实管理员或用户密钥。测试网关监听 `127.0.0.1:18480`，临时合成上游监听 `127.0.0.1:18481`。

| 配置与请求 | 结果 |
|---|---|
| 配置固定上游密钥，调用 `/openai/v1/responses` | HTTP 200，转发至 `/v1/responses`，但客户端密钥被替换为固定上游密钥 |
| 不配置上游密钥，调用 `/openai/v1/responses` | HTTP 200，但上游收到的 Authorization 为空 |
| 调用 `/ai/responses` | HTTP 400，Unsupported endpoint: responses |
| 合成 SSE 两段输出，间隔一秒 | 首字节约 0.003 秒，总时长约 2 秒，传输层没有整段缓冲 |

源码注释提及透传不支持流式，但实际镜像测试显示 SSE 字节可以及时转发，因此不能仅凭该注释断言传输失败。流式日志入库、真实模型计费、会话聚合和 WebSocket 均未通过本轮验证，不得标记为已支持。

## 旧通用 Worker 路径

主仓库仍有 `GATEWAY_API` 与 `Helicone-Target-URL` 处理代码，但现有 Docker 构建文件使用 Node 18.11，而 worker/package.json 要求 Node >=20，Docker Compose 中的 Dockerfile 路径也与实际文件位置不一致。旧 Worker 尚未构建或部署，不能声称其不可用，也不能声称可直接用于生产。

## 后续边界

优先验证旧 Worker 的独立部署及认证透传。若必须维护补丁、专用身份适配或采集层，应明确这是额外维护成本，而不是零适配部署。任何正式切流前必须验证原用户认证、费用归属、流式正文持久化、会话关联及回退路径。
