2026-10-09 更新：已修复 gzip 非流式响应的数据流结束异常，生产审计代理改为端口 18488、镜像 20261009-eof-v3。New API 测试 502 的证据、协议限制和回归结果见《NewAPI测试502-排查与修复.md》。

最新实现已升级为持久队列与独立上传进程：业务不等待审计名额或上传；500 并发突发响应测试中业务与审计均完整通过。两个生产接口的真实请求也已核对提示词与完整响应。架构、参数和最新测试以《数百并发审计-HMM改造.md》为准，下文早期接入实测作为历史证据保留。

状态：2026-10-02 扩展为全部有效密钥用户；2026-10-07 非永久记录保留期调整为 2 天。

## 生效范围

- 域名：cc2.cx、api.cc2.cx。
- 用户：正常状态且持有有效 API 密钥的所有用户。
- 路径：精确匹配 /v1/responses、/v1/chat/completions；仅 POST 且不含 Upgrade 的请求走审计。
- 映射从服务器数据库读取，每约 30 秒刷新，用户新建或撤销密钥存在短暂同步窗口。
- 其他接口、WebSocket、其他域名、直接访问 8080 端口和内部直连请求不在此次采集范围。

请求链路：生产 Nginx → 127.0.0.1:18488/openai → 原 Sub2API 127.0.0.1:8080。为平滑更换审计代理而改用新端口。完整审计先进入持久队列，再由独立进程上传；Sub2API 源码、账户权限和计费逻辑未修改。

## 身份与请求保护

原始 Authorization 透传给 Sub2API；独立审计密钥只由 Nginx 注入，映射文件权限为 600。身份字段由数据库映射生成，覆盖客户端同名头。入口清除跳过正文采集、外部 webhook 和 PostHog 等控制头。

可靠的业务身份字段是 properties 中的 helicone-property-sub2api-user-id 和 helicone-property-sub2api-api-key-id。Helicone 顶层 user_id 仍是审计管理员身份，不能用它代表 Sub2API 用户。audit-request-id 可用于区分请求。多轮会话自动聚合尚未实现。

## 健康检查与回退

cc2-audit-route.timer 每轮完成后约 30 秒再次运行。检查网关、审计后端、MinIO、ClickHouse、认证可用性及本地磁盘空间。依赖不可用或可用磁盘低于 5 GiB 时，后续新请求改为直连；恢复健康后重新开启。

这不是零丢失审计：两次检查之间仍可能出现短暂失败；直连期间不采集正文。不会自动重放已经发送的推理 POST，避免重复扣费。代理进程在连接失败、断流或客户端中断时的完整日志保证仍有限，WebSocket 和多轮自动关联未覆盖。

手动关闭采集并立即恢复直连：

```sh
rm -f /opt/cc2cx-audit-validation/production-enabled
python3 /opt/cc2cx-audit-validation/sync_audit_route.py
```

重新开启：

```sh
touch /opt/cc2cx-audit-validation/production-enabled
python3 /opt/cc2cx-audit-validation/sync_audit_route.py
```

完整恢复原 Nginx 入口前先关闭采集，再执行：

```sh
cp -a /opt/cc2cx-audit-validation/production-backup/cc2-apps.conf /etc/nginx/conf.d/cc2-apps.conf
nginx -t && systemctl reload nginx
```
