# New API 渠道测试 502 排查与修复

日期：2026-10-09，香港时间。

## 结论

不是假报错。Sub2API 已成功生成响应，但旧审计代理在压缩非流式响应时发生任务异常并断开连接，Nginx 因此返回真实的 502。已修复请求体、响应体的数据流结束状态，并部署 `cc2cx/helicone-passthrough:20261009-eof-v3`。

涉及分组：36（gpt 特惠）、53（6.1 sol astra 专线）。未修改分组、账户、模型映射和计费规则。

## 证据与因果链

香港时间 01:32:38，分组 53 的 gpt-5.6-sol 非流式 Chat Completions 请求在 Sub2API 用量表中记录完成；相同时刻审计代理出现 `Unfold must not be polled after it returned Poll::Ready(None)`，Nginx 记录 `upstream prematurely closed connection while reading response header from upstream`，上游为 127.0.0.1:18486。01:31:34、01:29:49 等时间也对应同类事件。

因果链：客户端声明接受 gzip → 代理压缩非流式响应 → 压缩读取链再次轮询已结束的 unfold 数据流 → 请求任务异常 → 上游连接关闭 → Nginx 502。

异常发生于请求任务，并未使整个容器退出。因此容器重启数为 0、没有 OOM、健康端点正常，都不能排除该故障。Sub2API 成功记录也不等于客户端已收到完整响应。

可控复现：两个分组对旧代理发送同类非流式请求，不带 gzip 时成功；加入 `Accept-Encoding: gzip` 后均发生 RemoteDisconnected。绕过旧代理后同类公网请求成功；修复版保留 gzip 功能后成功。此前并发回归覆盖 SSE，但未覆盖 gzip 非流式响应，这是验证缺口。

未登录客户的 New API 管理界面，也未假定其具体版本；以上使用服务器日志和实际 HTTP 请求验证。客户实际测试按钮仍可用于最终端到端复核。

## 修复与切换

1. 临时使用已有关闭开关，使新请求直连 Sub2API；此期间存在审计缺口。
2. 在请求体 unfold 和响应体 unfold 的消费边界使用 fuse，结束后再次轮询仍返回结束，不再触发异常。
3. 在 18488 启动独立候选容器，通过实际 gzip 请求后更新路由同步脚本与恢复脚本。
4. 恢复生产审计，执行 Nginx 配置检查和公网回归。
5. 确认旧端口没有已建立连接后停止旧容器，保留停止状态的回退容器；停止测试容器。

当前生产链路：Nginx → 127.0.0.1:18488/openai → Sub2API 127.0.0.1:8080。

业务仍不等待审计采集名额、落盘或上传。普通用户审计保留 2 天，用户 11 保留策略不变。本次不增加业务并发限制。

## 独立的接口参数限制

分组 53 的 Responses 上游返回了两种明确的 400：

- 非流式请求：要求 `stream: true`。
- 输出额度为 64：要求至少 100。

将 Responses 测试设为 `stream: true`、`max_output_tokens: 128` 后验证通过。Chat Completions 非流式已通过，不需要为本次 502 禁用整个分组。上游限制是本次测试观察，不应推广到所有模型或所有供应商。

## HMM 简要复核

- 现状：真实生成成功，但部分测试请求在响应返回链路失败。
- 目标：测试与真实调用均按各自协议完整返回，审计不破坏业务。
- 硬约束：不重复转发已执行的付费请求，不中断现有连接，不伪造成功响应。
- 隐式条件：gzip 压缩层会再次轮询结束后的流；健康检查不覆盖该路径。
- 候选路径：关闭所有压缩；永久绕过审计；修复数据流结束语义。
- 选择：修复结束语义。无需牺牲压缩或永久放弃审计，也无需增加缓存、排队和并发门槛。
- 反向检查：同时验证业务完整性、压缩解码、SSE 结束、实际输出、审计正文和高并发；对 400 保留真实语义，不改成 200。
- 剩余边界：未直接操作客户 New API 测试按钮；验证只能证明本次路径和负载，不承诺任意故障下零影响。
