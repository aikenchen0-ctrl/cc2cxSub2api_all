# 审计记录保留策略

生效日期：2026-10-01；2026-10-07 将非永久记录期限缩短为 2 天。

## 规则

- super@sub.com 对应 Sub2API 用户编号 11：已采集的提示词、响应正文及关联请求索引不设置自动到期删除。
- 其他已采集审计请求：超过 2 个完整的 24 小时后，进入下一轮清理。
- 每小时执行一次，另有最多 120 秒的随机错峰；不是精确到第 48 小时立即删除。
- 规则适用于本次部署的 Helicone 审计组织。没有扩大生产采集范围，不改动 Sub2API 的用户、账号、计费流水或其他生产数据库。

## 实现与保护

持久上传队列也遵循同一规则：普通用户超过两天的积压不再重新导入，用户 11 的完整待上传记录保留重试。已上传的正文及索引仍由本节的三层清理程序管理。队列不是异机备份。

从 PostgreSQL 与 ClickHouse 的 properties.helicone-property-sub2api-user-id 交叉识别用户。任一存储副本标记为 11，即排除在过期清理之外；不是按 Helicone 顶层审计管理员 user_id 识别。

已移除 request_response_rmt 和 request_response_versioned 中 request_body、response_body 的默认三个月清空规则。定时任务会复查这些列规则，避免永久正文被默认规则清空。

过期记录按精确的组织 UUID 与请求 UUID 清理：先处理 PostgreSQL 关联数据，再清理 ClickHouse 请求关联索引，最后删除 MinIO 对应 requests/UUID/ 目录下的原始和处理后正文。任务编号写入本地待办库，中断后可重试。删除前再次交叉检查永久用户标记。遇到未知外键关系或额外桶过期规则时停止，避免升级后盲目删除。

不设置整个对象桶统一 2 天过期规则，否则可能误删永久用户数据。没有索引可供判定归属的孤立对象不做盲删，需先修复归属信息。非请求级的系统运行日志、对象之外的外部附件、账单和业务配置不在本策略内。

仅对部署过程中已知的临时备份 audit-db-before-volume-fix.dump、postgres-volume-copy 设置 2 天清理；不会扫描或删除其他生产备份。永久保留表示此策略不自动删除，不等同于异机备份、磁盘故障保护或防管理员误删。

## 实测

使用随机 UUID 创建四类人工记录，并在 PostgreSQL、ClickHouse、MinIO 三层检查结果：

| 情况 | 结果 |
|---|---|
| 其他用户，已保存 11 天 | 请求元数据、索引和正文均删除 |
| 用户 11，已保存 120 天，仅 ClickHouse 有用户标记 | 三层数据均保留 |
| 用户 11，已保存 120 天，仅 PostgreSQL 有用户标记 | 三层数据均保留 |
| 其他用户，已保存 1 天 | 三层数据均保留 |

人工测试记录已定向撤销，没有更改真实记录的创建时间。2026-10-07 按 2 天规则重新运行上述四类测试，全部通过；真实历史记录另行分批清理。

## 运维

- 程序：/opt/cc2cx-audit-validation/audit_retention.py。
- 服务：cc2-audit-retention.service。
- 定时器：cc2-audit-retention.timer，启用开机恢复和错过任务补跑。
- 最近结果：/opt/cc2cx-audit-validation/retention-status.json。
- 测试结果：/opt/cc2cx-audit-validation/retention-test-results.json。
- 中断续办清单：/opt/cc2cx-audit-validation/retention-state.sqlite3，仅记录请求编号，不存提示词。
- 修改前 ClickHouse 结构：/opt/cc2cx-audit-validation/retention-schema-before.jsonl。

只预览，不删除：

```sh
python3 /opt/cc2cx-audit-validation/audit_retention.py
```

执行清理：

```sh
systemctl start cc2-audit-retention.service
```

暂停后续清理：

```sh
systemctl disable --now cc2-audit-retention.timer
```

暂停不能恢复此前已按规则删除的数据。每轮最多清理 2000 条，对象删除每组最多 50 个精确请求目录；retention_sweep.py 用于补清历史积压。如日后扩大采集量，应复核清理吞吐及待办积压。社区升级后，在重新接入前运行本服务并复核测试，不能仅依赖旧配置仍然有效。
