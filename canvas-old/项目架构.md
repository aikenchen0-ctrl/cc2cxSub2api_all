# infinite-canvas 项目架构

## 1. 总体结构

项目是浏览器端单页应用，核心运行时位于 `web`：

```text
浏览器
  └─ Vite/React 应用
      ├─ React Router 页面路由
      ├─ Zustand 本地状态与持久化
      ├─ 画布节点、连线和本地素材存储
      ├─ AI API 服务层（浏览器直连）
      └─ 模型脚本运行时（可选适配层）
```

项目没有统一的业务后端。AI 请求、配置保存和大部分素材读取都发生在浏览器中。

## 2. 目录职责

| 目录 | 职责 |
| --- | --- |
| `web/src/pages` | 路由页面和业务工作台 |
| `web/src/layouts` | 页面布局和全局初始化 |
| `web/src/components` | UI、配置面板、画布组件和 Agent 面板 |
| `web/src/stores` | Zustand 全局状态；画布状态位于 `stores/canvas` |
| `web/src/services/api` | 图片、视频、音频、文本和插件请求 |
| `web/src/services` | 本地文件、图片、WebDAV、配置导入导出 |
| `web/src/lib/canvas` | 节点工厂、几何、导出、插件运行时等画布工具 |
| `web/src/types` | 画布、图片、媒体和插件类型 |
| `canvas-agent` | 本地 Canvas Agent、HTTP/MCP 服务 |
| `plugins` | Codex App 插件和画布节点插件 |
| `docs` | 独立的项目文档站点 |

## 3. 路由和页面

路由定义在 `web/src/router.tsx`：

```text
/             首页
/image        图片工作台
/video        视频工作台
/assets       素材库
/prompts      提示词库
/canvas       画布项目列表
/canvas/:id   具体画布项目
/config       配置页
```

`UserLayout` 包裹主要页面，并加载分析跟踪和客户端初始化逻辑。

## 4. 配置模型

核心类型位于 `web/src/stores/use-config-store.ts`。

### 4.1 渠道模型

```text
AiConfig
  ├─ channels: ModelChannel[]
  │   ├─ id / name
  │   ├─ baseUrl
  │   ├─ apiKey
  │   ├─ apiFormat: openai | gemini
  │   └─ models: ChannelModel[]
  │       ├─ name
  │       ├─ capability: text | image | video | audio
  │       └─ script?
  ├─ imageModel / videoModel / textModel / audioModel
  └─ 生成偏好：quality、size、count、videoSeconds、audioVoice 等
```

模型选择值使用 `channelId::modelName` 编码。调用前通过 `resolveModelRequestConfig` 解析渠道，得到真实 Base URL、API Key、调用格式和不带渠道前缀的模型名。

### 4.2 能力识别

源码类型名为 `ModelCapability`，取值为 `text`、`image`、`video`、`audio`。

`guessCapability` 会根据模型名关键词进行初始判断：

- 视频：`video`、`sora`、`veo`、`kling`、`wan`、`hailuo`；
- 音频：`audio`、`tts`、`speech`、`voice`、`music`、`sound`；
- 图片：`seedream`、`gpt-image`、`image`、`dall-e`、`imagen`、`flux`、`sdxl` 等；
- 其余默认为文本。

这是启发式逻辑，不是服务能力探测。sub2api 使用自定义模型名时必须手工修改能力。

## 5. 配置导入和 sub2api 对接链路

入口文件：`web/src/components/layout/client-root-init.tsx`。

```text
浏览器打开 /?baseUrl=...&apiKey=...
          │
          ▼
读取 URLSearchParams
          │
          ├─ 更新第一个 ModelChannel
          ├─ 同步旧版顶层 baseUrl/apiKey
          ├─ history.replaceState 清理密钥参数
          └─ 打开配置面板并提示导入成功
```

该链路是当前最直接的 sub2api 对接点。它只接收已经存在的 Base URL 和 API Key，不实现 sub2api 登录、密钥创建或反向跳转。

## 6. AI 请求层

### 6.1 公共 URL 和鉴权

`buildApiUrl` 会把 Base URL 去掉末尾斜杠；若没有 `/v1` 后缀，则标准 OpenAI 请求自动补上 `/v1`。原生 OpenAI 请求使用：

```http
Authorization: Bearer <apiKey>
```

Gemini 请求使用：

```http
x-goog-api-key: <apiKey>
```

所有请求均由浏览器发出，因此 sub2api 必须允许浏览器跨域（CORS），并且网关不能依赖仅服务端可见的私有网络。

### 6.2 文本和多模态

实现主要在 `web/src/services/api/image.ts` 的文本请求部分：

- OpenAI：`POST /v1/responses`，支持流式 SSE；
- Gemini：`POST /v1beta/models/{model}:generateContent` 或流式版本；
- 图片问答会把图片编码成 `image_url`/`input_image` 或 Gemini `inlineData`/`fileData`；
- 工具调用消息会在 OpenAI Responses 与 Gemini function calling 结构之间转换。

### 6.3 图片

实现文件：`web/src/services/api/image.ts`。

```text
无参考图 ──> /images/generations
有参考图 ──> /images/edits (multipart)
Gemini   ──> generateContent + responseModalities IMAGE
```

响应解析兼容 `data[].b64_json`、`data[].url`，以及部分网关的 `images`、`results` 字段。未知字段会被明确报告，不会静默当作成功。

### 6.4 视频

实现文件：`web/src/services/api/video.ts`。

```text
创建：POST /v1/videos
查询：GET  /v1/videos/{id}
下载：GET  /v1/videos/{id}/content 或结果 URL
```

视频是异步任务：创建后轮询 `queued`/`in_progress` 等状态，完成后读取结果 URL，或下载 `/v1/videos/{id}/content` 的 `video/mp4` 原始二进制。请求参数按 `GET /v1/models` 的能力动态选择，支持 `seconds`/`duration`、`size`、`resolution`、`ratio`/`aspect_ratio`、`input_reference` 和 `input_audio` 等字段；不应固定参考图数量或时长上限。Gemini 格式在原生函数中会明确拒绝，避免把不兼容接口伪装成可用。

### 6.5 音频

实现文件：`web/src/services/api/audio.ts`。

原生 OpenAI 路径调用 `/v1/audio/speech` 并读取 Blob。Gemini 原生路径明确不支持音频；非标准音频服务需要模型脚本。

## 7. 模型脚本运行时

实现文件：`web/src/services/api/model-plugin.ts`。

模型脚本是按模型保存的 JavaScript 函数体，通过 `new Function` 在浏览器中执行。它提供两套请求工具：

- `http`：默认带 `Authorization: Bearer apiKey`，相对路径按 `/v1` 规则拼接；
- `request`：不添加默认请求头，脚本完全控制 URL、鉴权、请求体和响应类型。

脚本还提供 `poll` 处理异步视频任务，以及 `onDelta` 推送文本流。该机制适合适配 sub2api 的自定义路径、异步任务字段和非标准返回格式，但脚本权限等同于当前页面中的 API Key，应只加载可信脚本。

## 8. 画布数据和生成流程

画布类型位于 `web/src/types/canvas.ts`，生成逻辑主要在 `web/src/pages/canvas/project.tsx` 和 `web/src/components/canvas`。

```text
提示词节点 / 参考素材节点
          │
          ▼
连接关系解析与生成上下文构建
          │
          ├─ text   -> requestImageQuestion
          ├─ image  -> requestGeneration / requestEdit
          ├─ video  -> requestVideoGeneration
          └─ audio  -> requestAudioGeneration
          │
          ▼
结果写回节点 metadata，并保存到本地素材库
```

画布生成模式与模型能力一一对应：`text`、`image`、`video`、`audio`。节点选择模型时会按能力过滤，模型标签错误会导致下拉框中不可选或请求前校验失败。

## 9. 本地存储和同步

- AI 配置通过 Zustand `persist` 保存到 `localStorage`；
- 画布和业务记录使用项目封装的本地存储服务，图片/媒体不会作为大 JSON 直接塞入配置；
- 配置 JSON 导入导出位于 `web/src/services/config-file.ts`；
- WebDAV 同步位于 `web/src/services/webdav-sync.ts` 和 `web/src/services/app-sync.ts`，属于可选同步层；
- sub2api 只作为外部 AI 接口渠道，不会自动接管本地画布数据。

## 10. 对接 sub2api 的兼容清单

### 最低要求

- 提供可从浏览器访问的 HTTPS Base URL；
- CORS 允许 `http://localhost:3522` 或实际部署域名；
- API Key 可以通过 `Authorization: Bearer` 使用，或提供模型脚本所需的自定义鉴权；
- 提供 `/v1/models`，或允许用户手工填写模型名；
- 为每种模型明确标记真实能力。

### 按功能要求

| 功能 | 必须兼容的接口 |
| --- | --- |
| 文本 | Responses，或通过脚本改写为 Chat Completions/自定义接口 |
| 文生图 | Images Generations，或脚本 |
| 图生图 | Images Edits multipart，或脚本 |
| 文生视频 | Videos 创建 + 查询 + 结果下载，或脚本 |
| 图生视频 | Videos 的参考图字段，或脚本转换 `images` data URL |
| TTS | Audio Speech，或脚本 |

若 sub2api 只提供统一聊天接口而没有图片、视频、音频端点，不能仅靠填写 Base URL 解决，必须为对应能力编写脚本，或者在 sub2api 侧提供兼容路由。

## 11. 适配建议

推荐按以下顺序对接：

1. 先用 sub2api 的 API Key 和 Base URL 打开 URL 自动填充链接；
2. 先验证 `/v1/models` 和文本模型；
3. 再验证文生图、图生图；
4. 最后验证视频异步任务的创建、轮询和下载；
5. 对不兼容的模型单独绑定脚本，不要修改全局请求层来迁就单个供应商。

需要新增“一键跳转 sub2api”时，建议把跳转和密钥生成放在 sub2api 或统一门户侧，最终只向 infinite-canvas 发送短期授权码；不要在长期链接中暴露永久 API Key。
