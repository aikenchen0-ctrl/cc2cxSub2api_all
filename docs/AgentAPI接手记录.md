# AgentAPI 接手记录

检查日期：2026-10-04。本文记录本次读码和本地检查结果，不替代公共接入协议或收费模块说明。

## 项目定位和技术栈

AgentAPI 是共享多租户代理站。一套服务、数据库和前端承载多个站长的站点；开分站是在主站创建租户关系，再通过既有 SSO 进入共享实例，不应为每位站长部署容器。

- 后端：Go 1.27、标准库 HTTP、`modernc.org/sqlite`。入口为 `agentapi/backend/main.go`。
- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router。路由为 `agentapi/frontend/src/router/index.ts`。
- Docker 构建前端后，由 Go 同源托管静态资源；本地入口为 `http://localhost:18081`，SQLite 数据保存在独立卷中。

## 身份和权限边界

1. 主站签名 SSO 携带 `agent_id`、角色和用户身份；AgentAPI 消费一次性票据并建立三天 HttpOnly Session。
2. 浏览器请求通过服务端 Session 确定租户；外部 `/v1/*` 请求通过 AgentAPI 自有 Key 确定租户和用户。不能相信调用者自行传入的租户或用户标识。
3. 业务数据按 `agent_id` 隔离。共享 Host 白名单与数据库内自定义域名共同约束请求入口，未知 Host 返回 421。
4. 模型调用使用公共目录中的模型 ID，由服务端发送应用凭据、`X-Sub2API-On-Behalf-Of` 和 `X-Sub2API-Satellite`。SuperKey 不能作为普通 API Key，也不能进入浏览器。
5. 站长权限局限于自己的租户。管理员 API Key 是服务端控制面凭据，不能用于模型调用。

## 收费现状

以 `agentapi/收费模块.md` 和实际代码为准。默认用户直结路径与开启本站支付后的路径必须区分：开启本站支付时，订单使用本站渠道，确认付款后计入该用户的本站钱包；模型请求仍保留当前用户身份，另由服务端携带站长 `X-Sub2API-Payer`，主站从站长账户扣实际费用。代码在发起模型请求前检查本站钱包是否为正。

支付渠道包括 EasyPay、支付宝、微信、Stripe 和 Airwallex。设置、渠道、套餐、订单及回调均需保持租户隔离和幂等。模型结算涉及请求幂等记录、操作租约、usage 同步和异步任务；不能用一次首页健康检查替代收费闭环验证。

当前 README 中“不创建可消费本地余额”“开通本站支付后再扣一笔”等描述与新的收费模块说明不一致，后续维护需先核对代码，不应据此恢复旧逻辑。本次未修改收费行为。

## 进一步读码补充（2026-10-04）

- 请求入口 `Server.ServeHTTP` 先检查 Host，再分发认证、本站业务和 `/v1/*`。未明确暴露的主站 API 不做通用透传。
- 前端 `agent/client.ts` 使用同源 Cookie；`agent/session.ts` 用 `identityVersion` 防止登出或切换身份后，旧异步响应重新写入用户状态。路由守卫区分已登录用户和本站站长，服务端仍独立校验权限。
- 模型入口 `handleModelRelay` 解析 Session 或本站 Key、校验公开模型、检查用户状态和余额，建立持久化结算记录后调用上游。用户直结模式的重试标识按租户、用户和客户端幂等键生成；结算租约按实际付款主站用户串行化。
- 支付回调按租户查找渠道并验签，再校验渠道实例、订单和金额。订单完成后的钱包入账可幂等重试，以恢复订单完成但钱包写入失败的情况。退款另有额度预扣及渠道失败后的恢复逻辑。
- **自有 Key 文档差异**：当前 `store.go` 的 `CreateAPIKey` 同时保存哈希和加密密文，`APIKeys` 会解密返回当前用户的 Key；历史仅哈希记录还会进行兼容升级。README 中“数据库只保存哈希，完整 Key 仅创建时返回一次”已不符合工作区实现。这里指 AgentAPI 自有 Key，不是 SuperKey 或主站服务端凭据。本次只记录，不改变现有行为。
- 当前工作区含大量已有修改和新增支付模块；后续开发以这些工作区文件为起点，不以 Git HEAD 或旧 README 还原功能。

## 首次接手时的运行配置问题（部署前）

现有 AgentAPI 容器并不等同于完整接通主站：

- SSO Secret 与主站一致，但应用凭据不一致。
- 未配置公开 `LINK`；当前 `AGENT_BILLING_MODE=owner_upstream`，与共享模式文档默认值不同。
- 未配置只读预检身份；原始 `--preflight` 未通过。
- 仅对预检子进程临时补入本地 `LINK`、`user_upstream` 和已有普通用户探测身份后，管理员用户只读接口返回 200，但卫星余额接口返回 401。临时参数没有改变容器持久配置。

下一次处理 AgentAPI 部署时，应先确认收费模式的实际要求，统一主站应用凭据与公开地址，再验证 SSO、两租户隔离、用户 Key 和余额查询。不能把当前健康状态描述成模型和计费链路全部可用。本次按用户任务只熟悉 AgentAPI，未重建其容器或更改上述配置。
