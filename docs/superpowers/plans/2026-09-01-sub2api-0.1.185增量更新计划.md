# Sub2API 0.1.185 增量更新计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 以当前定制版为唯一基线，仅选择性移植官方下载包 `sub2api-0.1.185` 的稳定性、性能、计费观测和后台优化，绝不改变或删除现有 Superkey、媒体协议适配、子应用入口、计费和禁用实际在线更新等定制行为。

**架构：** 以当前 `sub2api` 为唯一工作基线，把官方代码当作优化补丁来源，而不是新的代码基线。非定制文件的官方修复可直接移植；与定制入口重叠的网关、鉴权、计费、路由和前端版本组件只允许围绕现有行为做最小手工移植，并以现有定制测试作为不可回退的验收门槛。数据库只允许通过现有迁移器在副本中演练，生产 PostgreSQL/Redis 数据卷不覆盖。

**技术栈：** Go、Vue/TypeScript、PostgreSQL migrations、Docker Compose。

---

## 差异审计结果

- 同名文件差异：229 个。
- 官方包新增：13 个，包含 7 个 Go 回归测试、1 个 SQL 迁移、1 个前端测试、1 个旧系统测试、1 个合作方 Logo。
- 当前定制版独有：35 个，包含 Superkey/媒体/协议适配器、定制前端、文档、备份和生成物。
- 后端差异主要集中在 150 个 Go 文件；前端差异为 42 个 TypeScript、25 个 Vue 文件。
- 官方包内置 `backend/cmd/server/VERSION` 为 `0.1.184`；目录名为 `0.1.185`。按用户确认，视该目录为官方下载目标包，但构建版本号必须在合并前单独确认。

## 必须保留的定制行为

- 用户级 Superkey 跨分组调用，不允许在前端选择或绑定单一分组。
- Canvas、QRCode、PPT 的统一入口，以及文本、图片、视频协议适配。
- 计算万物 OpenAI-compatible 兼容配置。
- 原有文本调用方式、计费口径、余额和扣费流程。
- 控制面板保留版本提示，但不提供实际在线更新和回滚动作。
- 暗色主题和当前 Docker 数据卷隔离方式。

## 官方优化的引入边界

### 可以优先移植

- 数据库初始化瞬时失败重试，以及对应单元测试。
- OpenAI WebSocket 入口容量保护、连接生命周期和日志改进，但不得改变 Superkey 路由和现有媒体入口。
- usage log 的新增观测字段、请求类型记录和统计查询优化，但不得改变现有扣费金额。
- 后台统计查询缓存、频道监控展示和配额重置校验。
- Codex 模型目录缓存/过滤、Anthropic Responses 兼容修复，以及不改变现有公开 API 的错误分类改进。
- 官方新增回归测试和纯文档更新。

### 只能手工移植并逐项回归

- `openai_gateway_handler.go`、`billing_service.go`、`gateway_usage_billing.go`、`api_key_service.go`、`api_key_auth.go`。
- `grok_media.go`、图片/视频处理和 `openai_codex_models_service.go`。
- 前端 `VersionBadge.vue`、系统更新 API、账户 Key 表单和媒体相关页面。

这些文件必须保留当前定制逻辑，再将官方优化嵌入周边流程；不得用官方文件整文件替换。

### 不引入

- 官方恢复或扩展的在线更新、回滚动作。
- 会重新绑定 Superkey 分组、限制跨分组调用或改变子应用入口的代码。
- 会改变当前文本计费公式、余额扣减时机或计费模型选择的重构；除非证明只是观测字段且回归测试确认金额完全一致。
- 官方删除当前媒体/协议适配器的变更。

## 禁止覆盖的内容

- `deploy/data`、`deploy/postgres_data`、`deploy/redis_data`、`.env`。
- 当前定制版独有的适配器、Superkey 相关代码、定制测试和文档。
- 已应用过的历史 SQL 迁移文件；只能新增迁移，不能重写旧迁移。

## 执行顺序与停止条件

1. 先执行 Task 1，确认版本号和备份校验。
2. Task 2 完成并通过数据库副本迁移后，才进入优化移植。
3. Task 3/4 任何改动只要影响 Superkey、媒体适配、计费、暗色主题或禁更新行为，立即回退该优化并保留当前实现。
4. 每移植一组官方优化就运行对应回归测试，不把“官方测试通过”视为定制功能安全的证明。
5. Task 6 全部通过后才允许构建交付镜像；本计划不包含直接覆盖生产数据卷。
