# 部署清单（AI 部署前必读）

核对日期：2026-10-07。所有 AI / 自动化执行者从根目录 `AGENTS.md` 进入本清单。

**统一分类：11 个卫星应用；AgentAPI 是代理站；归因探测是 Sub2API 内部模块；Cost Console 仅为参考项目，不部署。** 用户本次明确要求优先于默认范围。每次部署先读本清单并说明选定范围，不根据目录、菜单、SSO 注册数量或正在运行的容器推断要部署什么。

AgentAPI 所有租户共用当前代理站部署；开通新租户不意味着创建新的代理站容器。部署不得擅自更改其收费模式。

### Cost Console 的参考边界

- 保留该目录供 AI / 开发者查看源码结构、界面设计、数据处理和相关功能实现；“参考这个项目”不表示要运行它，也不表示要维护第二套主站。
- 参考代码需要落地时，在用户指定的 `sub2api/` 或其他实际业务项目中实现，并遵循该项目已有的身份、数据和部署规范。参考项目的配置、凭据、数据库、菜单和账号体系不能直接当成本仓库运行配置。
- 归因探测属于 Sub2API 内部模块，其修改与验收都针对 `sub2api/`。参考材料不是独立服务依赖，不能用参考项目的首页或测试结果代替实际模块验收。
- 该目录即使带有 README、Dockerfile、Compose、启动脚本或完整部署说明，也只说明参考项目自身具备这些内容，不能据此加入本仓库的构建、启动、更新、健康检查或发布列表。
- AI 直接进入该目录时，先读 [sub2api-cost-console/AGENTS.md](../sub2api-cost-console/AGENTS.md)。默认只读查阅；没有针对参考源码的修改要求时，不为日常业务开发顺带修改或更新它。
- 如果用户今后明确改变该项目的用途，应先按新要求同步分类和清单，再执行相应任务；不能从“全部项目”“全部目录”或“参考实现”推断用途已改变。

## 5. 每次部署的执行规则

1. 读取本清单、`卫星应用.txt` 和用户本次要求，先列出包含与排除的项目。范围明确就执行；只有影响部署目标且无法从上下文判断时才询问。
2. 读取 [卫星应用接入公共层.md](卫星应用接入公共层.md)、[卫星公开模型.md](卫星公开模型.md)、[本地链接.txt](../本地链接.txt)，以及目标目录的 `AGENTS.md`。沿用已有 SSO、服务端凭据和 3 天 Session 约定。
3. 核对所选项目的源码目录、Dockerfile、实际 Compose 配置、容器、端口、挂载、网络和环境变量。`deploy` 项目同时包含 Sub2API 与 Canvas；局部部署必须指定服务，不能仅凭 Compose 项目名扩大范围。
4. 区分“启动现有容器”和“从当前源码覆盖部署”。覆盖部署要构建目标镜像、重建对应应用容器，并保留现有环境、凭据、数据和回滚依据；不能用一次 `docker start` 代替。
5. 使用历史脚本前先核对其实际目标列表，必要时按本次范围调整。`.local/redeploy-all.py` 等历史脚本不是部署范围的权威；引用独立 Cost Console 的历史构建 / 部署脚本不得直接重跑。`scripts/Start-LocalDocker.ps1` 已移除参考项目及其依赖，启动当前 13 个业务项目的既有容器；局部范围仍需只启动所选目标。
6. 私密 Compose、环境文件、数据库备份留在被 Git 忽略的本地目录；公开文档只记录路径和验证结果，不写入密钥。
7. 验收所选项目的目标镜像、运行状态、健康检查和入口；卫星与代理站按各自身份流程检查 SSO 和余额。修改归因探测时检查主站模块路由和相关功能，不能只用独立 Cost Console 首页证明通过。
8. 汇报分别列出主站数、卫星数、代理站数、应用容器数、依赖容器数，以及未执行的验证；参考项目列为排除项。将实际部署结果追加到 [Docker本地部署.md](Docker本地部署.md)，不以历史总数覆盖本次选择。

新增或退役项目时，按用户明确要求同步本清单与根目录 `AGENTS.md` 的摘要；卫星名单变更还需同步 `卫星应用.txt`。目录存在、容器存在或曾部署过，都不等于默认纳入。

## 6. 历史记录说明

本次文档整理不停止、删除或重新部署任何现有实例，也不修改历史验收原始数据。
