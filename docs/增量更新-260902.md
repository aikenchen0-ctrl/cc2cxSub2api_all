## 2026-09-02-01：Anthropic Responses 流式转换修复

### 问题

当 Anthropic 流中先出现 `text` 再出现 `thinking` 时，旧实现直接覆盖当前 item 状态，已累积文本不会进入 `response.completed`。同一 message item 中出现多个文本块时，旧实现重复使用 `content_index=0`，累积式 SDK 会覆盖前一个文本块。

### 实施

- 在开始 `thinking` 或新建非当前 message item 前，先调用 `closeCurrentResponsesItem`，保证已宣布的 output item 有对应的 done 事件。
- 文本块结束时保存当前 `content_index`，然后递增状态；`output_text.done` 与 `content_part.done` 使用递增前的 index。
- 仅修改 `sub2api/backend/internal/pkg/apicompat/anthropic_to_responses_response.go`，并在 `anthropic_to_responses_stream_test.go` 增加两条回归测试。

### 验证

```text
go test ./internal/pkg/apicompat -run 'TestAnthropicEventToResponses_(ThinkingAfterTextKeepsMessageOutput|MultipleTextBlocksAdvanceContentIndex)$' -count=1  PASS
go test ./internal/pkg/apicompat -count=1  PASS
```

### 影响边界

不涉及 Superkey 分组解析、媒体适配器、Canvas/QRCode/PPT 入口、计费金额、数据库迁移或 Docker 配置。

## 2026-09-02-02：OpenAI WebSocket 直写容量降载修复

### 问题与实施

官方修复了 WS v2 ingress 直写分支遗漏的客户端错误码清洗：上游 `error`/`response.failed` 中的 `server_is_overloaded` 或 `slow_down` 会被 Codex 客户端当作致命错误。现仅对写给客户端的副本调用既有 `sanitizeOpenAICapacityShedErrorCodeForClient`，内部 `handleOpenAIWSTerminalTransientFailure` 仍接收原始 payload，因此不改变账号状态、故障转移和计费行为。

修改文件：`sub2api/backend/internal/service/openai_ws_forwarder_ingress.go`。

### 验证

```text

```

### 保护确认

未修改 Superkey 分组解析、WS 连接容量租约、HTTP Bridge、媒体/协议适配、Canvas/QRCode/PPT 接口或 Docker 配置。

## 2026-09-02-03：官方剩余差异审计

对官方版本剩余差异进行了逐文件核对：

- `native_compaction_v2` 查询/写入链：当前版本已按上一轮定制迁移保留该观测字段；官方删除它会破坏现有统计兼容性。

- 后台 TTFT、设置字段及 Codex 目录：当前版本存在定制路由、计费和 Superkey 逻辑，官方差异包含删除或弱化行为，不能整文件覆盖。

本轮未产生代码变更，仅更新项目清单为“已核对暂缓”，避免下一次 AI 重复审计或误迁移受保护逻辑。后续若要继续，应从官方新版本中寻找不改变上述契约的独立修复。

验证：`go test ./internal/pkg/antigravity -run TestGeminiUsageMapping_NoCacheCreationTokens -count=1` 通过。
## 2026-09-02-06：群组限额 null 语义修复

官方版本将管理端群组限额字段定义为三态：字段省略表示不修改，`null` 表示不限额，数字表示具体限额（`0` 仍表示禁止用量）。当前版本曾将 `null` 转换为 `0`，会误关闭群组用量。本轮恢复官方语义：`null` 转换为 `-1`，由服务层 `normalizeLimit` 归一化为不限额；新增回归测试覆盖该行为。

修改文件：`sub2api/backend/internal/handler/admin/group_handler.go`、`group_handler_limit_test.go`。

验证：`go test ./internal/handler/admin -run 'Test(UpdateGroupRequestLimitFieldsTriState|.*Group.*)' -count=1` 通过。
