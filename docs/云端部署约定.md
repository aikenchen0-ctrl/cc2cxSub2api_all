# 云端部署约定

## 域名分工

- `https://api.cc2.cx`：Sub2API 中转站，对外提供 `/v1/*` 接口。
- `https://canvas.cc2.cx`：Canvas 静态前端，由 Linux Nginx 托管。
- Sub2API 控制台左侧的 Canvas 快捷入口固定跳转到 `https://canvas.cc2.cx`，并附带当前用户的 Superkey 配置参数。生产环境禁止通过 HTTP 传递密钥。

## 部署形态

- Sub2API：部署在 Linux Docker 中，使用 `sub2api/deploy/docker-compose.yml`，持久化 PostgreSQL、Redis 和 `/app/data`。
- Canvas：只构建前端静态文件，将 `canvas/web/dist` 发布到 Linux Nginx，不运行 Canvas 后端容器。
- Canvas 在线默认 API 地址为 `https://api.cc2.cx`；本地开发仍使用 `http://localhost:18080`。

## 反向代理与跨域

- `api.cc2.cx` 的 TLS 终止和反向代理指向 Sub2API 容器端口 `8080`。
- `canvas.cc2.cx` 的 TLS 终止和静态文件根目录指向 Canvas `dist`。
- Sub2API 的 `CORS_ALLOWED_ORIGINS` 至少包含 `https://canvas.cc2.cx`；如同时部署 PPT、二维码站点，也加入对应 HTTPS 域名。
- 不要把线上域名配置为 HTTP，否则 HTTPS Canvas 会触发混合内容阻止请求。

## 发布顺序

1. 在 Linux 构建并启动 Sub2API Docker 服务。
2. 配置 `api.cc2.cx` 的 DNS、TLS 和反向代理，确认 `GET /health` 返回成功。
3. 构建 Canvas 前端并将 `dist` 发布到 Nginx。
4. 打开 `https://canvas.cc2.cx`，确认请求目标为 `https://api.cc2.cx/v1/...`，并验证视频创建、状态轮询和 `/content` 下载。

后续用户提出“部署到云端 Linux”时，默认按本约定处理：Sub2API 走 Docker，Canvas 走 Nginx，API 域名为 `api.cc2.cx`，Canvas 域名为 `canvas.cc2.cx`。
