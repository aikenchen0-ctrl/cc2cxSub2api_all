# 卫星应用接入公共层

给后续 AI / 开发者对接新项目用。**先读完再改代码，不要另发明协议。**

对照表：根目录 `本地链接.txt`。  
代码：`sub2api/backend/pkg/satellite/`（环境变量与请求头）。

---

## 1. 目标

用户已登录 Sub2API 后，点左侧菜单进入任意 AI 项目，即可直接使用文本 / 图片 / 视频能力。

- Sub2API 负责登录、计费、跨分组选上游账号。
- 卫星项目独立部署，只负责自己的业务数据和本地会话。
- SuperKey 永远不进浏览器、不进 URL、不能当普通 API Key。
- 本地 / 云端只改 `LINK` 和 `{slug}_link`。

---

## 2. 点击菜单后的链路

```text
用户登录 Sub2API
  → 点左侧项目
  → GET /api/v1/auth/integrations/{slug}/start?next=/
  → 一次性 HMAC 票据（身份，不含明文 Key）
  → 卫星 /api/auth/sso/callback?ticket=...
  → 卫星建立本地用户 + Session
  → 浏览器只带卫星 Session
  → 卫星服务端调 Sub2API /v1：
        Authorization: Bearer <SUB2API_APP_CREDENTIAL>
        X-Sub2API-On-Behalf-Of: <Sub2API 用户 ID>
        X-Sub2API-Satellite: <slug>
  → 网关内部用该用户 SuperKey，在全部分组里选上游
  → 用量记到该用户
```

`sk-super-` 出现在 Authorization / x-api-key 里必须 403 `SUPER_KEY_NOT_AN_API_KEY`。

SuperKey 只存在于 Sub2API 服务端：卫星 SSO 不带 Key，控制台 Key 列表不返回 SuperKey 明文，不能当普通 API Key 调用 `/v1`。卫星代调时网关内部取出该用户 SuperKey，并在**全部分组**里选上游（`SuperKeyCrossGroup`）。

---

## 3. 硬性规则

1. 卫星必须有服务端。纯静态站不能进菜单。
2. 单体必须先改成多用户：本地用户表用 `(identity_provider=sub2api, subject=<Sub2API user id>)`，资源带 `owner_user_id`。
3. 浏览器不出现 SuperKey、Sub2API JWT、模型 API Key。
4. 没有当前用户身份时卫星调模型返回 401，禁止回退到共享 `.env` Key。
5. Sub2API 管理员进卫星仍是普通用户。
6. 不要把卫星合并进 `sub2api/` 进程。
7. 不要为新项目再复制一套 SSO Handler 协议；沿用现有 HMAC 票据 + 公共头。

---

## 4. 环境变量（必须保留）

来源：`本地链接.txt`。

### 模型地址 `LINK`

所有卫星调大模型都走 Sub2API：

```env
# 本地
LINK=localhost:18080

# 云端
LINK=https://api.cc2.cx
```

无协议的本地值补 `http://`。Docker 容器互访可用 `SUB2API_RELAY_BASE_URL=http://sub2api:8080/v1`，未设则回退 `LINK`。

### 菜单 / SSO 地址 `{slug}_link`

```env
# 本地
aicut_link=http://localhost:5199
aiexcel_link=http://localhost:4173
canvas_link=http://localhost:3522
ju_link=http://localhost:3000
livart_link=http://localhost:8080
ppt_link=http://localhost:8341
qrcode_link=http://localhost:5221
screen2code_link=http://localhost:5173

# 云端
aicut_link=https://aicut.cc2.cx
# 其余同理：https://{slug}.cc2.cx
```

SSO 回调默认 = `{slug}_link` + `/api/auth/sso/callback`（PPT 为 `/api/v1/auth/sso/callback`）。  
只有路径特殊时才设 `{SLUG}_SSO_CALLBACK_URL`。

两端还要相同：

```env
SUB2API_SSO_SECRET=<至少 32 字节>
SUB2API_APP_CREDENTIAL=<卫星调用 /v1 的项目凭证，不是用户 Key>
```

卫星自己的 Session 密钥与 SSO 密钥分开。

## 5. 新项目清单（按顺序做完再挂菜单）

1. **多用户**：本地用户、Session、数据按 `owner_user_id` 隔离。
2. **SSO 接收**：`GET /api/auth/sso/callback`，校验 HMAC 票据 `iss=sub2api`、`aud`（见 `apps.go` 的 Audience，不一定等于 slug）、一次性 `jti`，映射 `sub` 到本地用户，发 HttpOnly Session。
3. **模型调用**：服务端用第 2 节三个头打 `{LINK}/v1/...`，模型只发公开名。
4. **Sub2API**：在 `pkg/satellite/apps.go` 加一行（slug、audience、默认 origin、回调路径）；左侧菜单加一项指向 `/auth/integrations/{slug}/start`。不要新写 `*_sso.go`。
5. **环境**：`{slug}_link`、`LINK`、`SUB2API_SSO_SECRET`、`SUB2API_APP_CREDENTIAL`。Docker 加入 `deploy_sub2api-network`。
6. **验收**：两个 Sub2API 用户数据隔离；用量分别记账；URL 无 Key；用 SuperKey 当普通 Bearer 调 `/v1` 失败。

## 6. SSO 票据

```text
base64url(JSON) . base64url(HMAC-SHA256(payload, SUB2API_SSO_SECRET))
```

必填：`iss=sub2api`，`aud`（注册表 Audience：如 aicut=`openchatcut`、ppt=`presenton`，其余一般等于 slug），`sub`（Sub2API 用户 ID），`jti`，`iat`，`exp`（默认约 2 分钟），安全的站内 `next`。

票据只带身份，不带 SuperKey。新项目不要读 `rk`，用 `sub` 作为 `X-Sub2API-On-Behalf-Of`。

参考：`sub2api/backend/pkg/satellite/apps.go`、`internal/handler/satellite_sso.go`；卫星回调可看 `aiexcel/app/auth-sso.ts`。

## 7. 调模型

公开接口（只发公开模型名）。完整目录、各项目对照、本地名映射见 **`docs/卫星公开模型.md`**。

| 能力 | 接口 | 默认模型 |
| --- | --- | --- |
| 文本 | `POST /v1/chat/completions` 或 `/v1/responses` | `gpt-5.5` |
| 图片 | `POST /v1/images/generations`、`/v1/images/edits` | `gpt-image-2` |
| 视频 | `POST /v1/videos`，轮询 `GET /v1/videos/{id}` | `grok-imagine-video-1.5` |

代码目录：`sub2api/backend/internal/domain/satellite_models.go`。上游适配原料：`docs/模型适配.md`。

Go 设置请求头：

```go
satellite.SetRequestHeaders(req.Header, os.Getenv("SUB2API_APP_CREDENTIAL"), "myslug", sub2apiUserID)
```

其他语言等价三个头，见第 2 节。

## 10. 不要做的事

- 不要把 SuperKey 显示给用户或放进 URL / Hash / localStorage。
- 不要用全站一把 `SUB2API_RELAY_API_KEY` 给门户用户跑模型。
- 不要把 OIDC 当作当前接入的前置条件。
- 不要改 `本地链接.txt` 的变量含义；本地 / 云端只替换值。
