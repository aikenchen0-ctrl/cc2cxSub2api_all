# 云端部署包说明

本目录对应 `2026-09-06` 构建产物，目标域名为：

- Sub2API API：`https://api.cc2.cx`
- Canvas 前端：`https://canvas.cc2.cx`
- Sub2API 控制台左侧 Canvas 快捷入口：`https://canvas.cc2.cx`

## Sub2API Docker

1. 将 `sub2api-docker-20260906.tar` 上传到 Linux 服务器。
2. 导入镜像：

   ```bash
   docker load -i sub2api-docker-20260906.tar
   docker tag sub2api:cloud-20260906 weishaw/sub2api:latest
   ```

3. 将 `sub2api/deploy/docker-compose.yml` 和 `.env.example` 放在同一目录，复制并编辑环境文件：

   ```bash
   cp .env.example .env
   chmod 600 .env
   ```

   至少设置 `POSTGRES_PASSWORD`、`JWT_SECRET`、`TOTP_ENCRYPTION_KEY` 和管理员密码。
4. 启动服务：

   ```bash
   docker compose up -d
   docker compose ps
   curl -fsS http://127.0.0.1:8080/health
   ```

   反向代理 `api.cc2.cx` 到宿主机 `8080`。生产环境的 `CORS_ALLOWED_ORIGINS` 必须包含 `https://canvas.cc2.cx`。

## Canvas Nginx

`canvas-static-20260906.zip` 内的 `dist/` 是可直接托管的静态文件。解压到 Nginx 网站根目录，并将 `nginx.conf` 中的 `root` 改为实际目录；TLS 由云端 Nginx 或负载均衡终止。

```nginx
server {
    listen 80;
    server_name canvas.cc2.cx;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name canvas.cc2.cx;
    root /srv/canvas/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location = /config.js {
        add_header Cache-Control "no-store";
    }
}
```

当前 Canvas 线上默认 API 已指向 `https://api.cc2.cx`；本地开发地址仍由本地配置保留为 `http://localhost:18080`。
