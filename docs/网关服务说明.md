# 网关服务说明

路径：**系统设置 → 网关服务**

这一页管的不是「网站长什么样」，而是：**用户打过来的 API 请求，系统怎么选账号、怎么转给上游、出错了怎么处理。**

可以把它想成前台窗口：

1. 用户拿 Key 来问路（发请求）
2. 网关决定用哪张上游账号去办
3. 把请求改成上游能认的样子再发出去
4. 上游忙、限流、超时、报错时，决定这张号先歇一会，还是立刻换下一张

下面按页面上的卡片，用白话说明每个开关。  
**没把握就保持默认。** 改之前先想清楚：这是「保护账号」，还是「伪装成官方客户端」，还是「拦截某种请求」。

部分卡片右侧/底部有独立「保存」，改完要点那个按钮才会生效。其余项要点页面底部的「保存设置」。

## 一、出错时，这张号还用不用

这三块决定：**上游报错后，要不要让这张账号暂时离开调度池。**  
它们只管「这张号后面还会不会被选中」，不管单次请求里已经发生的换号。

池模式账号默认不写本地限流/错误状态，这三块对池模式的作用会变弱或被跳过。

### 1. 529 过载冷却

上游说「我现在过载了」（HTTP 529）时：

- **开**：这张账号暂停调度一段时间，冷却结束自动回来
- **关**：不因为 529 把号摘掉（本次请求仍可能换号）

**冷却时长**：1–120 分钟。账号多、过载常见，可以短一点（几分钟）；号少、过载很伤，可以长一点。

适合 Anthropic 一类会返回 529 的上游。

### 2. 429 默认回避

上游说「你请求太频繁了」（HTTP 429），但**没告诉你什么时候能再试**时：

- **开**：按这里填的秒数，让这张号先回避
- **关**：没有明确重置时间时，不额外回避

上游如果带头或响应体里给了重置时间，**仍优先听上游的**，不会被这里覆盖。

**回避时长**：1–7200 秒。没有 reset 信息的 429 很常见时，建议开，几十秒到几分钟即可，避免刚限流的号下一秒又被选中。

### 3. 流超时处理

对话是一边生成一边往回推的。如果上游**中间长时间没再吐字**，可能是号卡住了。

- **开**：按下面规则处理问题账号
- **关**：超时只影响这一次请求，不给账号记过

可调项：

| 项 | 意思 |
|---|---|
| 超时阈值 | 两次数据间隔超过多少秒算超时（30–300 秒） |
| 处理方式 | 临时不可调度 / 标成错误 / 不处理 |
| 暂停时长 | 选「临时不可调度」时歇多久（1–60 分钟） |
| 触发阈值 | 窗口内超时几次才处理（1–10 次） |
| 阈值窗口 | 这几次超时在多长时间内累计（1–60 分钟） |

建议：先用「临时不可调度」+ 较高阈值，避免偶发网络抖动就把号打成错误。  
「标记为错误」要人手工恢复，适合确认号已经坏了的场景。

## 二、请求整流器：自动改一改再试

上游有时不是号坏了，而是请求参数差一点点。整流器会**改参数后用同一张号再打一次**，提高成功率。

总开关关掉后，下面几项全部无效。

| 项 | 干什么 |
|---|---|
| Thinking 签名整流 | thinking 块签名校验失败时，去掉签名再试 |
| Thinking Budget 整流 | `budget_tokens` 不符合约束时，自动改成 32000 再试 |
| API Key 签名整流 | API Key 账号遇到签名类错误时去签名再试（内置规则一直在） |
| 自定义匹配关键词 | 在内置规则之外，再按响应原文匹配（不区分大小写） |

适合 Claude 带 thinking 的请求。不是万能重试器，只修这几类已知格式问题。

## 三、拦截或改写「特殊能力」

### 1. Beta 策略（仅 `/v1/messages`）

Anthropic 的 Beta 头（例如 1M 上下文）有的账号能用、有的不能。这里决定转发时怎么处理。

**处理方式：**

- **透传**：原样带给上游
- **过滤**：悄悄去掉 Beta，请求照发
- **拦截**：直接拒绝，可自定义错误文案

还可以限制：全部账号 / 仅 OAuth / 仅 API Key / 仅 Bedrock，以及模型白名单（支持 `claude-opus-*` 这种前缀）。  
白名单外的模型走「未匹配模型处理方式」。

快捷预设「仅 Opus 允许 1M」：Opus 透传，其它模型过滤。常用。

### 2. OpenAI Fast / Flex 策略

管请求体里的 `service_tier`：

- `priority`：更快更贵（页面里叫 fast）
- `flex`：更便宜、可能更慢

**处理方式：** 透传 / 去掉该字段 / 强制改成 priority / 拦截。

可按账号类型、指定用户、模型名单分层。规则按列表顺序，指定了用户的规则优先。

这页改完要点页面底部「保存设置」，没有单独保存按钮。

典型用法：不想让用户乱开 fast 把上游打爆，就过滤或拦截 `priority`。

## 四、只让官方客户端进来

上游（尤其是 OAuth 订阅）经常查客户端是不是官方的。这里用来卡版本、卡指纹。

### 1. Claude Code 设置

填最低 / 最高版本号（如 `2.1.63`）。低于最低或高于最高的 Claude Code 请求会被拒。留空 = 不检查。

只在你明确要求「必须用 Claude Code」时才填。填错版本会把正常用户挡在门外。

### 2. Codex 设置（客户端限制）

**只对已开启「仅允许 Codex 官方客户端」的 OpenAI OAuth 账号生效**，这里是全局加严。

| 项 | 意思 |
|---|---|
| 最低 / 最高 Codex 版本 | 官方客户端版本区间，留空表示该侧不限 |
| 引擎指纹信号 | 查请求头/正文里像不像 Codex 引擎。勾「必须」的要全部命中；一条都不勾 = 指纹门关闭 |
| 放行 Codex app-server | 允许经 app-server 接入的第三方（例如 Claude Code 的 Codex 插件）。默认关 |
| 黑名单 | originator 精确匹配或 User-Agent 包含即拒，**优先于一切放行** |
| 白名单 | 放行官方集之外的客户端；「跳过引擎指纹」风险高，可伪造，只给真正可信的客户端勾 |

一条「必须」信号都不勾时，指纹门等于没开，版本过了就放行。

## 五、上游倍率探测 和 Ollama 用量

### 1. 上游倍率自动探测

本地账号如果接的是**另一套 Sub2API**，可以定期去问对方「你们现在声明的计费倍率是多少」。

- 这里是**全局总开关和周期**（5–1440 分钟）
- 真正会更新倍率的，还要在**该账号**上另行打开「同步上游声明倍率」
- 关掉全局后，定时探测全停，**手动探测仍可用**

成功结果的有效期大约是两个探测周期。只对「账号连的是上游 Sub2API」有意义。

### 2. Ollama Cloud 用量刷新

按真实模型请求，去刷新 Ollama 官方设置页上的用量。默认关。

- 没新请求就不会去抓
- 账号自己也要开自动刷新，并且已保存浏览器会话
- **请求安静等待**：最后一次请求安静满这段时间再抓（1–60 分钟）
- **持续请求最长等待**：请求一直不断、安静窗口一直被推迟时，最晚等到这时强制刷一次（15–1440 分钟）

手动刷新不受这两项影响。

## 六、网关调度：怎么选号

决定「下一个请求用哪张账号」。

### 1. 允许未分组 Key 调度

- **关（建议）**：没有分到任何分组的 API Key 直接 403，强迫每把 Key 都有归属
- **开**：未分组 Key 也能打，管理会乱

### 2. 平台账号自动停调阈值

看账号自己的官方用量窗口（OpenAI Codex / Anthropic 会话，或 Grok 的请求、Token 利用率）。  
达到你填的百分比，就先把这张号移出调度，窗口重置后再回来。

- 填 **100** = 关闭该平台自动停调
- 填 **1–99** = 用到这么多就暂停
- 只对 OpenAI / Anthropic / Grok
- 系统级默认；单个账号编辑页可以覆盖

想「别把号用到封顶才歇」，可以填 80–90。

### 3. OpenAI 实验调度策略

默认关。只影响**本网关在 OpenAI 账号之间怎么挑**，不是 OpenAI 官方功能。没问题不要开。

**没开实验调度时：**

- **低倍率优先**：同样能用的号，先用计费倍率低的，省成本
- **OAuth 调度参考倍率**：分组里 API Key 和 OAuth 混在一起时，OAuth 按这个假倍率参与排序

**打开实验调度后**，「低倍率优先」失效，改用加权打分：

| 项 | 意思 |
|---|---|
| 粘性加权 | 同一会话尽量还用刚才那张号（缓存更划算）；关则仍硬粘 |
| 订阅优先 | 先在 ChatGPT 订阅池里挑，没有席位再找非订阅号 |
| OAuth 参考倍率 | 混池时 OAuth 按这个倍率算「计费倍率」分 |
| 权值覆盖 | 优先级、负载、排队、错误率、首包延迟、重置窗口、额度余量、计费倍率、粘性等。留空用内置默认 |

权值是给熟手微调的。调乱了会出现「老选差号」或「粘不住会话」。

## 七、请求转发行为：发出去长什么样

请求已经选好号了，发出去之前还可以改头、改正文，让上游看起来更像官方客户端。

### Grok

| 项 | 意思 |
|---|---|
| 默认 Grok 文本模型 | 请求没带模型名时用这个；右侧开关打开时，其它客户端的模型名也会映射过来 |
| 映射其他客户端模型到 Grok | 默认关。开了以后，GPT / Codex / o 系列 / Claude 的模型 ID 会转到左边那个默认 Grok 模型 |
| 默认 Grok 上游 | 账号没填 base URL 时，文本请求走哪：CLI 聊天代理 / 公共 API / 各区域 API。图片和语音仍走官方媒体接口 |

没在做「用 ChatGPT 客户端打 Grok」这种桥，就不要开跨客户端映射。

### 伪装与透传

| 项 | 白话 |
|---|---|
| 指纹统一化 | 多人共用同一 OAuth 号时，把 `X-Stainless-*` 请求头统一掉，减少「一个人一个指纹」被风控。关则原样透传客户端 |
| Metadata 透传 | 原样转发客户端的 `metadata.user_id`，不改写。有时能提高上游缓存命中 |
| CCH 签名 | 给转发请求的 billing 头做哈希签名。关则保留占位符 |

OAuth 共享号建议开「指纹统一化」。要排查客户端原始头时再关。

### Claude OAuth 的 System 注入

非 Claude Code 的客户端，走 Claude OAuth 时，上游常要求请求长得像 Claude Code。  
默认会注入若干 system 块（计费头、身份提示词、扩展提示词等）。

可以增删改排序、开关某一块、设缓存。`{billing_header}` 会按请求动态生成。  
搞乱了点「恢复默认」。

只影响 **Claude OAuth**，不影响 API Key 账号。

### Anthropic 缓存相关

| 项 | 意思 |
|---|---|
| 缓存 TTL 注入 | 把已有的 ephemeral 缓存块强制写成 1 小时。计费默认仍按 5 分钟回写，账号自己的 TTL 计费设置优先 |
| 改写消息缓存断点 | 默认关，尊重客户端自己的 `cache_control`。开了会清掉客户端断点、改用代理断点。客户端不会自己管缓存时再开 |
| 客户端 dateline 归一化 | 默认开。把 system 里 `Today's date is …` 的奇怪撇号、日期分隔符改回普通形态，减少「发现你不是官方地址」时留下的指纹。只动 OAuth/Setup Token，不动 API Key |

### 客户端版本伪装

| 项 | 意思 |
|---|---|
| Antigravity UA 版本 | 发给 Antigravity 的 User-Agent 版本。留空用环境变量或内置 `1.23.2` |
| OpenAI Codex UA | 完整 User-Agent。留空则按下面的版本号拼标准 `codex-tui`（推荐）。填了整串时，里面的版本号仍会被下面的版本覆盖，避免停在过期身份上——上游忙的时候，旧身份更容易被丢成过载 |
| Codex 客户端版本号 | 网关对上游宣称的版本，和 UA、version 头一起用。留空 = 跟自动同步的官方稳定版；填了就钉死，不再跟同步 |
| 自动同步 Codex 版本号 | 每 6 小时拉官方最新稳定版。关则只用手填或内置版本 |

一般：开自动同步，UA 和版本号留空。只有要伪装成特定环境时才手填 UA。

## 八、Web Search 模拟

有的 Anthropic **API Key** 账号本身不能搜索。这里用 Brave / Tavily 等搜索商，把搜索能力「补」进请求。

- 这是**全局总开关**。关掉后，所有渠道、账号上的模拟都不生效
- 要添加服务商、填 API Key、可选配额和代理
- 配额可设上限、订阅日起每月重置，也可以手动清零
- 「测试」用默认问句试一下搜索是否通

OAuth 官方若已自带搜索，不必开。只给没有原生搜索的 API Key 渠道用。

## 九、使用记录

**允许用户查看自己的错误请求**：开了以后，用户在用量页能看到自己失败请求的**精简信息**，看不到内部或上游细节。

数据来自运维监控，监控没开就没有内容。给用户排查「我刚才为什么 502」时再开。

## 十、和账号页上两个容易混的开关

| 位置 | 管什么 |
|---|---|
| **账号编辑 → 池模式** | 这张号如果接的是号池或另一套 Sub2API，出错时**不要把这张入口 Key 标成限流/错误** |
| **本页 429 / 529 / 流超时** | 普通账号（非池模式）出错后，要不要暂时不选这张号 |
| **账号编辑 → 自定义错误码 / 临时不可调度** | 比本页更细，按账号覆盖 |

单次请求里「这张失败了换下一张」是网关内置逻辑，不在本页配置。本页主要管：**失败之后，这张号还在不在明天的候选池里**，以及**请求发出去长什么样**。

## 建议怎么改

1. **刚上手**：429 默认回避打开，529 过载冷却打开，流超时用「临时不可调度」。其它保持默认。
2. **号是 OAuth 订阅、怕风控**：指纹统一化开着；Claude OAuth 注入保持默认；Codex / Claude Code 版本限制按你实际客户端填。
3. **本地号接的是别人的 Sub2API**：本页的 429/529 对「入口 Key」意义不大，去账号上开池模式；需要同步对方价格时再开「上游倍率自动探测」。
4. **成本敏感**：可开「低倍率优先」（不要同时乱开实验调度）。
5. **有人乱开 Fast 档**：用 OpenAI Fast/Flex 策略过滤或拦截 `priority`。

改完对应卡片要保存。拿一把测试 Key 打一发请求，看运维日志里选了哪张号、上游回了什么，比只看开关更准。
