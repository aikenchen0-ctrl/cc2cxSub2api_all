# 导入云数据

本文记录本次把 Linux Docker Sub2API 数据导入本地 Docker 的过程。

## 1. 云端备份

云端容器和目录：

```text
应用容器：sub2api
数据库容器：sub2api-postgres
应用数据：/opt/sub2api-deploy/data
数据库：sub2api
数据库用户：sub2api
```

停止应用，避免导出时继续写入：

```bash
cd /opt/sub2api-deploy
docker stop sub2api
```

导出 PostgreSQL 逻辑备份：

```bash
docker exec sub2api-postgres pg_dump -U sub2api -d sub2api -Fc -f /tmp/sub2api-server.dump
docker cp sub2api-postgres:/tmp/sub2api-server.dump /opt/sub2api-deploy/sub2api-server.dump
```

打包应用数据：

```bash
tar -czf /opt/sub2api-deploy/sub2api-data.tar.gz -C /opt/sub2api-deploy data
```

## 2. 下载到本地

```powershell
scp root@服务器IP:/opt/sub2api-deploy/sub2api-server.dump .
scp root@服务器IP:/opt/sub2api-deploy/sub2api-data.tar.gz .
```

本次下载文件位于：

```text
C:\Users\Administrator\Desktop\data\sub2api-server.dump
C:\Users\Administrator\Desktop\data\sub2api-data.tar.gz
```

## 3. 本地备份

本地数据库容器为 `sub2api-postgres-dev`。数据库使用 `pg_dump -Fc` 备份，应用文件使用 tar 备份：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$dir = '.\sub2api\deploy\migration-backups'
New-Item -ItemType Directory -Path $dir -Force
docker exec sub2api-postgres-dev pg_dump -U sub2api -d sub2api -Fc -f "/tmp/sub2api-local-$stamp.dump"
docker cp "sub2api-postgres-dev:/tmp/sub2api-local-$stamp.dump" "$dir\sub2api-local-$stamp.dump"
tar -czf "$dir\sub2api-data-$stamp.tar.gz" -C '.\sub2api\deploy' data
```

本次本地备份：

```text
sub2api/deploy/migration-backups/sub2api-local-20260901-112648.dump
sub2api/deploy/migration-backups/sub2api-data-20260901-112648.tar.gz
```

## 4. 恢复云端数据库

停止本地应用，并重建本地数据库：

```powershell
docker stop sub2api-dev
docker exec sub2api-postgres-dev psql -U sub2api -d postgres -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='sub2api' AND pid <> pg_backend_pid();"
docker exec sub2api-postgres-dev psql -U sub2api -d postgres -c "DROP DATABASE IF EXISTS sub2api;"
docker exec sub2api-postgres-dev psql -U sub2api -d postgres -c "CREATE DATABASE sub2api OWNER sub2api;"
```

复制并恢复云端 dump：

```powershell
docker cp 'C:\Users\Administrator\Desktop\data\sub2api-server.dump' sub2api-postgres-dev:/tmp/sub2api-server.dump
docker exec sub2api-postgres-dev pg_restore -U sub2api -d sub2api --no-owner --exit-on-error /tmp/sub2api-server.dump
```

## 5. 恢复应用数据

先保留旧本地目录，再解压云端数据：

```powershell
Move-Item '.\sub2api\deploy\data' '.\sub2api\deploy\data-before-cloud-20260901-112648'
tar -xzf 'C:\Users\Administrator\Desktop\data\sub2api-data.tar.gz' -C '.\sub2api\deploy'
```

云端压缩包应展开为 `sub2api/deploy/data/...`，包含 `config.yaml`、`model_pricing.json`、`logs` 等内容。

## 6. 密钥同步

数据库中的账号凭证使用云端密钥加密，本地 `sub2api/deploy/.env` 必须与云端保持一致：

```text
POSTGRES_PASSWORD
JWT_SECRET
TOTP_ENCRYPTION_KEY
```

如果 PostgreSQL 用户密码也发生变化，需要执行：

```powershell
docker exec sub2api-postgres-dev psql -U sub2api -d postgres -c "ALTER ROLE sub2api PASSWORD '云端数据库密码';"
```

## 7. 启动验证

```powershell
docker compose -p sub2api-pro -f '.\sub2api\deploy\docker-compose.dev.yml' up -d
Invoke-WebRequest -UseBasicParsing http://localhost:18080/health
```

预期健康检查返回：

```json
{"status":"ok"}
```

检查数据库：

```powershell
docker exec sub2api-postgres-dev psql -U sub2api -d sub2api -c "select count(*) from users; select count(*) from accounts; select count(*) from groups;"
```

本次恢复结果为：用户 `2` 个、账号 `40` 个、分组 `12` 个。云端原有 `268` 条迁移，本地启动后自动补齐到 `272` 条。

## 8. 回滚

数据库回滚备份：

```text
sub2api/deploy/migration-backups/sub2api-local-20260901-112648.dump
```

应用数据回滚备份：

```text
sub2api/deploy/migration-backups/sub2api-data-20260901-112648.tar.gz
```

导入前的本地应用目录也保留在：

```text
sub2api/deploy/data-before-cloud-20260901-112648
```

不要直接复制 Linux 的 `postgres_data` 到 Windows；使用 `pg_dump`/`pg_restore` 可以避免 PostgreSQL 版本和文件系统差异导致的数据目录损坏。Redis 本次没有迁移，因为它主要保存缓存和临时状态。
