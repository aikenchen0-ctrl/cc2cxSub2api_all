# 16 参考实现状态与边界

本文把设计文档与当前 `agentapi/backend`、`agentapi/frontend` 的实际能力对齐，避免把规划中的主站控制面误认为已经完成。

## 1. 已实现链路

| 链路 | 当前实现 | 入口 |
| --- | --- | --- |
| 品牌 | Agent 名称、站点名、Logo 公开配置与管理员在线修改 | `GET /api/v1/settings/public`、`/api/v1/agent/admin/branding` |
| 注册/登录 | AgentAPI 接收请求，服务端调用主站认证；会话为 3 天 | `/api/v1/auth/*` |
| 公共层 SSO | HMAC ticket、持久化 `jti` 防重放、3 天本地 Session | `/api/auth/sso/callback` |
| 映射 | `agent_users(agent_id, main_user_id)`，复合唯一约束 | AgentAPI SQLite |
| 会话 | SQLite 保存哈希会话 ID，主站 access/refresh token AES-GCM 加密 | HttpOnly `agentapi_session` |
| 代理额度 | Agent 钱包、用户子余额、分配/消费/退款流水 | `/api/v1/agent/*` |
| 控制台 | 所有者查看钱包、映射用户并分配子余额 | `/agent-admin` |
| 客户端调用 | 本地 `sk-agent-*` 一次显示、哈希保存、可吊销 | `/keys`、`/api/v1/api-keys` |
| 模型 | 服务端事务性预授权、模型端点白名单、JSON/multipart 公开模型名校验、固定 Owner 计费身份转发、幂等回放保护 | `/v1` 公开端点 |
| 结算 | `settlements` pending/confirmed/released 状态、主站 usage 查询、后台 reconciler 和管理员手动对账 | `/api/v1/agent/admin/settlements*` |
| 视频异步任务 | 创建响应持久化任务归属；轮询校验 Agent 用户并结算原始 request，不新增第二笔预授权 | `POST /v1/videos`、`GET /v1/videos/{id}` |
| 审计 | 品牌修改、余额同步/分配、结算对账和客户端 Key 变更写入 Agent 范围审计事件 | `/api/v1/agent/admin/audit-events` |
| 健康 | 存活和基础就绪检查 | `/healthz`、`/readyz` |
| Host 隔离 | 配置 `AGENT_DOMAIN` 后拒绝未知 Host；健康探针不受影响 | `HOST_NOT_ALLOWED` |
| 部署 | 前端/Go 单容器、多阶段 Docker 构建、SQLite 持久卷 | `Dockerfile`、`docker-compose.yml` |
| 开站部署包 | 幂等锁、slug/domain 唯一占用、独立 Session Secret、Compose/Nginx/非秘密环境配置生成 | `go run ./cmd/agentapi-provision` |

前端生产源码已完成独立裁剪，只保留 AgentAPI 页面、路由、会话和接口适配层；默认 Vitest 配置扫描所有保留测试，不再携带 Sub2API 管理后台、支付 SDK、旧 OAuth 或 localStorage JWT 实现。

## 2. 当前未实现或仅有契约

- 主站 `agent-provisioning` HTTP 控制面、按钮和 DNS/TLS/启动/健康检查编排；AgentAPI 已提供可由控制面调用的幂等部署包生成 CLI；
- 多 Agent 共享集群的 Host → Agent 路由；当前镜像按一个 `AGENT_ID` 运行；
- provider-neutral 充值订单、HMAC webhook、支付事件幂等记录和等待 Owner 额度的本地分配已经实现；但真实支付供应商 SDK、渠道专属签名/支付页、退款、拒付和主站自动入账仍未实现；
- 主站为每个 Agent 签发独立 scope 服务凭据；当前过渡使用服务端 `SUB2API_ADMIN_KEY` 与 `SUB2API_APP_CREDENTIAL`；
- 视频任务已支持归属隔离、受控轮询及完成/失败结算；后台按 `AGENT_VIDEO_TASK_RECONCILE_AGE` 探测长期无人轮询任务，失败任务释放冻结额度，成功任务交给 usage 对账；文本/响应类请求已支持显式 `stream=true` 或 `Accept: text/event-stream` 的实时转发，图片仍按缓冲接口处理；
- 自动证书申请、自定义域名 DNS 验证和平台级 Nginx 编排；
- 主站侧对 `X-Sub2API-Satellite`、`X-Sub2API-On-Behalf-Of` 的生产策略变更。本目录不修改主站代码。

### 2.1 账务桥接的实现边界

当前参考实现已经有本地代理钱包和用户子余额，但主站 `/v1` 的公共卫星协议会按 `X-Sub2API-On-Behalf-Of` 对对应主站用户做真实余额扣减。也就是说，不能把“本地扣款”和“主站扣款”同时当成两笔独立的最终账务。

当前已冻结并按方案 A 实现：`agent_owner_main_user_id` 是主站唯一计费身份，代理用户余额只用于本地预授权和归属；主站余额差额/usage 是结算依据。主站不能确认 usage 时记录保持 `pending`，由管理员对账接口处理，不自动退款。

### 2.2 充值桥接边界

`recharge_orders` 和 `payment_events` 已提供最小可运行的订单/回调状态机：合法支付事件先进入 `paid_pending_allocation`，只有同步到足够的 Owner 主站余额后才会原子地增加用户子余额。webhook 不会直接增加主站余额，不接受浏览器提交的代理或用户归属，也不会生成佣金。支付关闭、签名错误、金额/币种不匹配和重复事件均不会改变钱包。

这仍不等于主站已经提供原子“用户间额度转移”；如果未来产品要求主站原生按代理用户统计扣费，必须切换到方案 B 并先改造主站控制面，不能在 AgentAPI 内伪造转账。

## 3. 上线前强制条件

1. 主站提供或确认受控的用户创建、模型代调和额度结算契约；
2. `SUB2API_ADMIN_KEY`、`SUB2API_APP_CREDENTIAL`、`SESSION_SECRET` 通过 Secret Manager/Docker Secret 注入；
3. AgentAPI 数据库位于持久卷，完成备份恢复和余额对账演练；
4. 仅配置一个内部 Agent 通过全部自动化测试后，再开放外部“一键开站”；
5. 明确支付主体、退款责任、代理预充值和用户子余额之间的合同与合规边界；
6. 完成主站 usage 查询权限、`settlement_pending` 对账演练和人工异常处理；
7. 若接入主站菜单，严格使用公共 HMAC SSO、3 天 Session 和公共模型目录，不另造主站 SSO 协议。

## 4. 版本策略

当前实现按 `agentapi` 初始版本管理。涉及主站头部、余额语义、Key 格式、Session TTL 或公开模型目录的变化，必须同步更新：

- `05-主站接口契约.md`；
- `06-认证与安全.md`；
- `07-预充值与账务.md`；
- `08-用户注册与模型请求.md`；
- `12-测试验收清单.md`；
- 本文和 Docker 示例配置。
