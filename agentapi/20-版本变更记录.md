# 20 版本变更记录

## v0.1-agentapi（设计与参考实现基线）

日期：2026-09-21

### 已冻结决策

- 部署模型：通用 AgentAPI 镜像 + 每个代理独立实例和 SQLite 持久卷；
- 身份模型：主站保存真实用户，AgentAPI 保存 `agent_id + main_user_id` 映射；
- 账务模型：采用方案 A，无佣金、无差价、无分成；
- 主站扣费身份：固定为 `AGENT_OWNER_MAIN_USER_ID`；
- 本地钱包角色：预授权、额度分配和代理用户归属镜像，不创造主站余额；
- 浏览器凭据：只使用 AgentAPI HttpOnly Session，不保存主站 JWT、管理员 Key、SuperKey 或用户主站 Key；
- 模型协议：服务端使用 `SUB2API_APP_CREDENTIAL`、`X-Sub2API-On-Behalf-Of`、`X-Sub2API-Satellite`；
- 会话 TTL：3 天；
- 主站通用 `/api/v1`：不做代理转发，只开放 AgentAPI 明确列出的接口。

### 已实现能力

- 主站注册、登录、2FA、刷新和退出的服务端代理；
- AES-GCM 加密的主站 token 会话存储；
- Agent 用户映射、用户子余额、分配/消费/退款流水；
- 一次显示、哈希保存、可吊销的 `sk-agent-*`；
- 公开品牌设置、代理控制台、用户用量和 Owner 余额同步；
- 事务性 pending settlement：本地预授权和结算记录原子创建；
- 相同 `request_id` 不重复转发；
- 主站管理员 usage 查询驱动的 pending 对账接口；
- JSON 与 multipart 请求统一执行公开模型目录校验；
- `/v1` 模型路径收敛为公开端点白名单；
- 公共层 HMAC SSO 回调与持久化 ticket 防重放；
- 可配置的后台 pending settlement reconciler；
- Docker 多阶段构建、非 root 运行、SQLite 持久卷、健康检查。

- 主站一键开站控制面、域名分配和 Nginx 自动编排；
- 多 Agent 共享进程的 Host 路由；
- 视频供应商特有的取消/退款策略；文本长连接 SSE、视频归属/轮询/原 settlement 结算和后台超龄探测已在 2026-09-22 增加；
- 细粒度 Agent scope 凭据（当前仍需服务端过渡管理员 Key）。

### 变更规则

涉及以下任何字段或协议时，必须同时更新代码、接口手册、验收清单和本文件：

- `AGENT_OWNER_MAIN_USER_ID` 或扣费身份；
- settlement 状态和幂等键；
- `sk-agent-*` 格式；
- Session TTL、Cookie 属性；
- 主站三个服务请求头；

### 2026-09-25 异步图片任务结算闭环

### 2026-09-25 超龄失败视频任务账务核验

- 超龄失败视频任务改为先查主站权威 usage：按实际 usage 结算，确认无 usage 才释放；usage API 不可用、查询失败或实际费用超过预留时保留 pending；
- 异步视频/图片轮询不再以轮询前后的余额差猜测原任务费用；usage API 不可用时保持 pending；pending settlement 对应的终态任务会继续进入后台探测，等待主站恢复后重试；
- 增加视频任务部分费用、usage 查询错误、确认无 usage、旧版 usage API 下失败轮询保留 pending 和待结算终态任务重试覆盖。

### 2026-09-24 主站开站控制面基础 API

- Sub2API 新增管理员鉴权的 Agent 开站记录 API：幂等创建、状态查询、暂停/恢复/撤销；
- Agent、域名、操作者作用域幂等键及状态事件持久化在主站 PostgreSQL；创建和状态变更使用事务，Owner 必须是启用且未删除的主站管理员；
- 每次状态变更要求幂等键，撤销还需重复确认 Agent ID；审计沿用主站管理面审计中间件；
- 首次记录保持 `pending/queued`。API 不调用 `agentapi-provision`、不分配主站账务账户、不发凭据、不执行 DNS/TLS/Nginx/容器工作；暂停/撤销也尚未连接到运行实例流量控制；
- 增加服务、处理器与 SQL 幂等/状态事件测试。完整部署编排和 Agent scope 凭据仍是后续阶段。

### 2026-09-24 托管实例状态同步与显式激活

- AgentAPI 托管实例改用主站开站 API 返回的 `agt_<uuid>` 作为 `AGENT_ID`；部署 CLI 将 `--agent-id` 设为必填，不再生成与主站记录不一致的本地 ID；
- AgentAPI 通过服务端管理员鉴权 GET 读取主站权威状态，并订阅主站数据库变更 SSE；SSE 事件只触发重读，另以周期 GET 兜底；状态非 `active`、读取失败或缓存过期时业务请求 fail closed，`/healthz` 和 `/readyz` 仍可用；
- 增加主站显式激活 API 和管理页就绪确认操作，要求操作者确认 Agent ID 与 readiness；API 本身不访问 Agent 实例执行探活，不能视为自动健康检查；
- 状态同步让已运行实例的暂停、恢复和撤销能够影响业务请求，但自动部署 worker、DNS/TLS/Nginx/Compose 编排、凭据自动发放及端到端开站验收仍未实现。

### 2026-09-24 开站进度报告契约

- Sub2API 增加管理员鉴权的 `PATCH /api/v1/agent-provisioning/agents/{agent_id}/progress`，供后续 worker 幂等报告顺序部署阶段；
- 进度状态与事件事务提交，复用既有数据库变更监听/SSE 通知；SSE 仍只是提示，记录 GET 才是权威；
- 进度步骤严格排序，失败采用有限 `failure_code` 映射固定错误文案，不持久化 worker 任意日志或可能泄漏凭据的错误文本；
- 该契约尚不构成部署 worker；DNS/TLS、Compose/Nginx、每站凭据签发和真实 `/readyz` 检查仍未实现。

### 2026-09-24 worker 凭据收敛与 SSE 最小化

- Sub2API 增加 `X-AgentAPI-Provisioning-Credential` 专用凭据，仅允许 worker 读取 pending/provisioning 列表、订阅 SSE、GET Agent、PATCH progress 和 POST activate；创建、暂停、恢复、撤销、重试与其他 Admin API 均拒绝；审计身份标记为 `agent_provisioning_worker`；
- AgentAPI 开站 worker 从 `AGENT_PROVISIONING_WORKER_CREDENTIAL_FILE` 读取控制凭据，不再使用 `SUB2API_ADMIN_KEY_FILE` 认证主站；后者仅作为 Secret 路径传递给新建的 AgentAPI 运行实例 Compose；
- provisioning 凭据为主站范围的共享凭据，不等同逐 Agent scope，也不解决 AgentAPI 运行实例仍使用全局管理员 API 的问题；
- SSE `agent` 事件改为仅携带 `agent_id`，消费者必须 GET 权威记录；增加 worker 凭据 allowlist、鉴权身份与 SSE 契约测试；生产 edge 安装验收仍未完成。

### 2026-09-24 Agent 用户控制、模型策略与用量明细

- Agent Owner 可从管理控制台启用/停用当前 Agent 已映射用户，复用 Sub2API 现有 `PUT /api/v1/admin/users/{id}` 且只提交 `status` 字段；禁用先关闭本地门控，启用等主站确认后才恢复，Owner 自身受保护；
- 停用状态会阻断已有 Agent Session 与客户端 Key；增加 Owner、同源、目标映射、状态值、主站失败 fail-closed 及模型访问门控测试；该操作改变的是 Sub2API 全局账号状态；
- 新增 Agent 本地公开模型策略管理：管理员只能配置卫星公开目录，模型列表隐藏未启用模型，JSON/multipart 请求在扣费预授权及主站调用前校验；
- 增强主站 usage 结算/对账快照和 Agent 用量分页，使用同一 `request_id` 查主站 usage，保留用户安全的 token、费用分项、路由和时延等信息；普通用户只能看自己的记录，管理员只看本 Agent，过滤掉主站管理 DTO 中的敏感账户和网络字段；
- 运行 `go test ./...`、`go vet ./...`、前端 `test:run`、`typecheck`、`lint:check` 和生产 `build` 验证；真实支付渠道、逐 Agent runtime scope 凭据与 edge 生产安装/验收仍未完成。

### 2026-09-24 开站 worker 跨进程租约

- Sub2API 新增原子 claim 与 lease renew API；主站仅存储随机租约 token 的 SHA-256 哈希，默认租期 90 秒；
- worker 默认每 20 秒续租，worker progress/activate 必须携带租约头，成功进度更新续租，激活或失败释放租约；
- claim 响应设置 `Cache-Control: no-store` 和 `Pragma: no-cache`；worker 失租后取消部署 context；
- 增加租约竞争、续租、过期接管、失租状态变更拒绝和 worker 取消部署测试；真实 edge 安装与 DNS/TLS/Compose 运行验收仍未完成。

### 2026-09-25 Agent Runtime 最小权限、映射证明与状态通知

- AgentAPI 用户/Owner/usage/托管状态管理改用 Sub2API 逐站 runtime control API；模型/余额请求使用逐站 model credential 与 Sub2API 管理 API，不以全局管理员 Key 作为业务凭据；
- 用户映射现在必须同时验证 Agent runtime control credential 和匹配的用户身份：认证/注册代理使用 Sub2API JWT，菜单 SSO 复用既有短时 `agentapi` HMAC ticket；原浏览器 SSO URL、ticket 和 Session 契约保持不变；
- Agent Runtime 状态 SSE 复用 Sub2API PostgreSQL 数据变更通知，只向对应实例发 Agent ID 提示，AgentAPI 仍 GET 权威状态并保留周期轮询兜底；
- 同步修正运行时接口、部署 Secret、启停用户、usage 对账和状态控制文档；增加身份映射证明、同 Agent 幂等绑定、跨 Agent 冲突拒绝与 SSE 回归测试。全量 Sub2API 测试仍需在支持 `sh` 的环境复验，真实 edge 部署与生产 DNS/TLS/Compose 验收未完成。
