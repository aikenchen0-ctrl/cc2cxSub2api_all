# 20 版本变更记录

## v0.1-agentapi（设计与参考实现基线）

日期：2026-09-21

### 已冻结决策

- 部署模型：通用 AgentAPI 镜像 + 每个代理独立实例和 SQLite 持久卷；
- 身份模型：主站保存真实用户，AgentAPI 保存 `agent_id + main_user_id` 映射；
- 账务模型：采用方案 A，无佣金、无差价、无分成；
- 主站扣费身份：固定为 `AGENT_OWNER_MAIN_USER_ID`；
- 本地钱包角色：预授权、额度分配和代理用户归属镜像，不创造主站余额；
- 浏览器凭据：只使用 AgentAPI HttpOnly Session，不保存主站 JWT、管理员 Key、SuperKey 或用户主站 Key；
- 模型协议：服务端使用 `SUB2API_APP_CREDENTIAL`、`X-Sub2API-On-Behalf-Of`、`X-Sub2API-Satellite`；
- 会话 TTL：3 天；
- 主站通用 `/api/v1`：不做代理转发，只开放 AgentAPI 明确列出的接口。

### 已实现能力

- 主站注册、登录、2FA、刷新和退出的服务端代理；
- AES-GCM 加密的主站 token 会话存储；
- Agent 用户映射、用户子余额、分配/消费/退款流水；
- 一次显示、哈希保存、可吊销的 `sk-agent-*`；
- 公开品牌设置、代理控制台、用户用量和 Owner 余额同步；
- 事务性 pending settlement：本地预授权和结算记录原子创建；
- 相同 `request_id` 不重复转发；
- 主站管理员 usage 查询驱动的 pending 对账接口；
- JSON 与 multipart 请求统一执行公开模型目录校验；
- `/v1` 模型路径收敛为公开端点白名单；
- 公共层 HMAC SSO 回调与持久化 ticket 防重放；
- 可配置的后台 pending settlement reconciler；
- Docker 多阶段构建、非 root 运行、SQLite 持久卷、健康检查。

### 尚未纳入本版本

- 真实支付供应商 SDK、验签回调、退款和自动入账；
- 主站一键开站控制面、域名分配和 Nginx 自动编排；
- 多 Agent 共享进程的 Host 路由；
- 视频供应商特有的取消/退款策略；文本长连接 SSE、视频归属/轮询/原 settlement 结算和后台超龄探测已在 2026-09-22 增加；
- 细粒度 Agent scope 凭据（当前仍需服务端过渡管理员 Key）。

### 2026-09-22 验证修复

- 模型转发保留客户端 `Content-Type`（包括 multipart boundary），图片编辑等上传端点可按原协议交给主站解析；
- 后台 settlement reconciler 实际读取 `AGENT_SETTLEMENT_RECONCILE_BATCH`，默认值为 50；
- 后端、前端和只读非 root Docker 冒烟检查重新通过。
- 增加显式文本流式模型转发：正常 EOF 后结算，客户端/上游中断保留 `pending`；
- 增加浏览器模型控制台和管理员 pending settlement 对账操作；
- 支持 `SUB2API_*_FILE` Docker Secret 文件变量和 `AGENT_ENABLED` 运行时暂停开关。
- 增加管理员品牌配置接口和前端 Logo/站点名编辑；品牌写入 SQLite，默认重启不被环境变量覆盖，`AGENT_BRAND_SYNC=true` 才会显式同步环境值。
- 收紧代理管理员额度分配接口的同源校验，并增加充值待分配订单的管理员操作入口。
- 增加 `AGENT_DOMAIN` 应用层 Host 校验，未知域名返回 `HOST_NOT_ALLOWED`，内部健康探针仍可用。

### 2026-09-22 一键开站部署基元

- 新增 `backend/cmd/agentapi-provision` 服务端 CLI；
- 使用全局锁、请求指纹和持久化状态保证重放幂等，并拒绝 slug/domain 冲突；
- 生成每站独立 Compose、持久卷、Nginx Host、非秘密 `.env` 和随机 Session Secret；
- 管理员 Key、应用凭据和 SSO Secret 仅引用运行时外部文件，不进入部署包；
- 覆盖重放、幂等冲突、slug/domain 冲突、路径/换行/镜像注入和 HTTPS 主站 URL 校验测试。

### 变更规则

涉及以下任何字段或协议时，必须同时更新代码、接口手册、验收清单和本文件：

- `AGENT_OWNER_MAIN_USER_ID` 或扣费身份；
- settlement 状态和幂等键；
- `sk-agent-*` 格式；
- Session TTL、Cookie 属性；
- 主站三个服务请求头；
- [卫星公开模型](../docs/卫星公开模型.md) 的模型名。

### 2026-09-22 前端独立裁剪

- 物理删除未被 AgentAPI 生产入口引用的旧 Sub2API 页面、测试和依赖，不重新引入 localStorage JWT、完整管理后台或旧 OAuth；
- 默认 `pnpm run test:run` 扫描当前源码中全部测试，不保留 `test:legacy` 旁路；
- 增加 Cookie-only 会话、模型控制台、Agent 管理员 pending settlement 对账、`sk-agent-*` 客户端 Key 和路由权限测试。
- 模型控制台向请求适配器传递消息快照，避免响应追加后反向修改已经提交的请求体；路由初始化状态绑定 Pinia Session，而不是绑定模块级全局标志。
- 本轮验收结果：前端 typecheck/build/lint/test（6 个测试文件、10 个测试用例）、后端 `go test`/`go vet` 和最终 Docker 镜像冒烟均通过。

### 2026-09-22 充值订单与 provider-neutral webhook

- 增加 `recharge_orders`、`payment_events` 表和订单状态：`pending`、`paid_pending_allocation`、`allocated`、`failed`、`closed`、`expired`；
- 增加用户订单创建/查询、管理员订单查询/分配和无 Cookie 的支付 webhook 路由；
- webhook 使用 `X-Agent-Payment-Event-ID` + `sha256=<HMAC-SHA256>` 原始 body 签名，事件和供应商交易号具备幂等/冲突保护；
- 订单支付成功不直接伪造主站余额，只能在 Owner 主站额度同步成功后原子分配用户子余额；主站不可用或余额不足时保持 `paid_pending_allocation`；
- 增加充值页面、导航入口和默认关闭的支付配置；
- 明确真实支付供应商 SDK、退款/拒付、支付渠道对账和主站自动入账仍未实现；
- 后端新增支付成功、错误签名和重复回调测试，前端默认验收通过 6 个测试文件、10 个测试用例。

### 2026-09-22 审计闭环

- 增加 `audit_events` 持久化表和 Agent 范围查询接口；
- 品牌修改、Owner 余额同步、用户额度分配、settlement 对账和 AgentAPI Key 创建/吊销写入结构化审计事件；
- 审计查询只允许当前 Agent Owner 使用，事件不保存任何密钥、Cookie 或完整授权头；
- 增加 Agent 隔离、排序和时间格式自动化测试。

### 2026-09-22 视频异步结算

- 增加 `video_tasks` 归属表，绑定 `agent_id + main_user_id + task_id + request_id`；
- 视频创建成功后持久化任务 ID，跨代理用户轮询在访问主站前被拒绝；
- 视频轮询不创建第二笔预授权，完成或失败结果作用于原始 pending settlement；
- 增加任务幂等冲突、用户隔离和原请求结算回归测试；后台超龄探测和失败任务释放已纳入 reconciler。
