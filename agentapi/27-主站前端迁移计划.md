# AgentAPI 前端与产品范围实施说明

> 更新日期：2026-09-30
> 本文是当前 AgentAPI 的实施说明和 AI 执行约束，不再保存逐批迁移流水账。架构、权限和安全规则以 [00-AI开发规范与目标架构.md](00-AI开发规范与目标架构.md) 为最高优先级，并同时遵守仓库根目录 `AGENTS.md`、`docs/卫星应用接入公共层.md` 和 `docs/卫星公开模型.md`。

## 1. 产品结论

AgentAPI 是一套由所有代理站共用的共享多租户站点，不是每个站长各部署一套程序。

- 主站用户点击“一键开分站”时，Sub2API 只幂等创建或返回一个逻辑租户。
- 所有代理站进入同一套 AgentAPI 前后端和同一公共入口。
- 租户、站长、成员、Session、Key、订单、公告、任务和用量均按可信 `agent_id` 隔离。
- AgentAPI 服务端代表当前登录用户调用 Sub2API；浏览器不能接触 `SUB2API_APP_CREDENTIAL`、管理员 Key、Sub2API JWT 或 SuperKey。
- 主站仍是身份、余额、模型目录、上游选择和真实计费的权威来源。
- AgentAPI 只保留代理站用户真正需要的核心功能，不复制 Sub2API 的全局运营后台。

AI 不得把“共享站点”误解为“共享租户数据”，也不得重新引入逐站容器、逐站端口、逐站数据库或逐站 Secret。

## 2. 当前保留的界面

### 2.1 公开页面

- 首页
- 登录、注册、邮箱验证、找回密码、重置密码
- 主站 SSO、第三方登录和账号绑定回调页
- 客户端下载
- Key 用量查询
- 只读法律协议

### 2.2 用户菜单

- 仪表盘
- API 密钥
- 使用记录
- 充值
- 订单记录
- 推广返利
- 个人资料

用户只能管理自己的 AgentAPI Key、资料和认证因素。站长也不能代其他用户创建、查看或撤销 Key。

### 2.3 站点管理菜单

- 仪表盘
- 推广管理：邀请记录、返利记录、划转记录
- 支付管理：支付统计、订单管理
- 用量同步
- 公告管理
- 系统设置

这些管理能力必须限定当前 `agent_id`。它们不授予站长 Sub2API 全局管理员权限，也不能修改主站渠道、账号、分组、代理池、模型价格或安全配置。

## 3. 永久删除的模块

以下模块不属于 AgentAPI 产品范围，菜单、路由、页面、浏览器 API、专属 Handler 和新库专属表均不得恢复：

- 模型广场
- 模型工作台
- 模型策略和租户模型白名单
- 批量图片
- 代理站开通管理
- 逐站 provisioning、runtime control、容器、端口和 Secret 管理
- 运营监控
- 优惠码管理
- 订阅管理
- 渠道管理
- 代理站计费
- 内容页面管理和自定义页面管理
- 备份管理界面
- 分组管理
- 账号管理
- 代理管理
- 兑换码管理
- 插件管理
- 安全审计
- 上游核验
- 站长代管其他用户 API Key

说明：运维侧 `agentapi --backup <destination.db>` 是数据库灾备工具，不是面向站长的“备份管理”产品模块，不得为它新增菜单或浏览器接口。

遗留管理路径必须继续返回 `404`。站长跨用户 Key 管理必须继续返回 `403`。隐藏菜单不等于删除模块；任何恢复都必须同时检查路由、动态导入、客户端方法、后端分发、Store 查询、数据库初始化和测试。

## 4. 共享多租户链路

```text
主站用户点击“一键开分站”
  -> Sub2API 幂等创建/返回共享租户记录
  -> GET /api/v1/auth/integrations/agentapi/start
  -> 一次性 HMAC SSO ticket（只含身份和可信租户关系）
  -> AgentAPI /api/auth/sso/callback
  -> 建立 3 天 HttpOnly Session
  -> 浏览器仅携带 AgentAPI Session
  -> AgentAPI 服务端调用 Sub2API /v1
       Authorization: Bearer <SUB2API_APP_CREDENTIAL>
       X-Sub2API-On-Behalf-Of: <当前用户的 Sub2API user id>
       X-Sub2API-Satellite: agentapi
  -> Sub2API 内部使用该用户 SuperKey 跨分组选上游
  -> 用量和真实费用归属当前主站用户
```

禁止新增第二套 SSO、API Key 传递、菜单跳转或租户选择协议。禁止从 query、body、任意浏览器 header 或 localStorage 接受 `agent_id` 作为授权依据。

## 5. 身份与权限

### 5.1 租户身份

- `agent_id` 必须来自已验证的 SSO 关系、AgentAPI Session 或服务端解析结果。
- 共享域名只允许配置在 `AGENTAPI_SHARED_HOSTS` 中的精确 Host；未知 Host 返回 `421`。
- 自定义域名映射到唯一租户，不能覆盖共享域名或其他租户域名。
- 所有写操作必须再次校验对象的 `agent_id`，不能只依赖前端隐藏或 URL 层判断。

### 5.2 用户身份

- 模型请求默认使用当前认证用户的主站用户 ID，不用站长身份代付。
- 主站管理员进入代理站时仍是普通代理站用户，除非可信租户成员关系明确授予 `agent_admin`。
- 普通用户不能进入 `/admin/*` 页面或站长接口。
- Session、Key、对象 ID、任务 ID、请求 ID和幂等键都必须同时受租户边界约束。

### 5.3 密钥

- SuperKey 只能存在于 Sub2API 服务端，不能作为普通 Bearer Key 使用。
- `SUB2API_APP_CREDENTIAL`、`SUB2API_SSO_SECRET`、`SESSION_SECRET` 只能存在于部署端。
- 共享运行模式下应用凭据不能为空，两个 Secret 均至少 32 字节；不满足时必须拒绝启动或就绪。
- 错误响应、日志、公开设置、HTML、JS bundle 和浏览器存储不得出现上述密钥。

## 6. 模型与计费边界

- 模型目录固定使用 `docs/卫星公开模型.md`，不提供租户级 allowlist、模型策略或模型管理 UI。
- 文本、流式、图片、视频和异步任务统一由 AgentAPI 服务端代调 Sub2API。
- AgentAPI 不建立第二套余额或扣费事实；真实费用以 Sub2API 返回和同步结果为准。
- 主站事实缺失时显示“未知”“待确认”或“尚未同步”，不能用本地零值、标准价格或估算费用冒充真实扣费。
- 同一请求、回调或异步任务必须保证只计费一次；不同租户可安全复用相同外部任务号或请求号。

## 7. 前端实现要求

- 当前侧栏清单以 `frontend/src/components/layout/AgentAppSidebar.vue` 为准。
- 当前路由清单以 `frontend/src/router/index.ts` 为准。
- 所有管理页面必须同时具有前端路由门禁和服务端权限校验。
- 深浅主题、桌面折叠侧栏和移动端抽屉可以保留，但不得为了“看起来完整”增加无后端能力的假入口。
- 页面只显示当前接口能证明的事实。缺少数据时使用明确空态或错误态，不填造假数字。
- 公开首页和下载页可以匿名访问；AgentAPI 不注册租户内容页或法律协议路由；账户、支付、订单、Key、用量和资料必须按各自 Session 要求保护。
- 任何新增页面先判断它是否属于核心范围；若命中永久删除清单，AI 必须停止实现并指出范围冲突。

## 8. 后端实现要求

- 浏览器业务接口统一位于 `/api/v1/agent/*`，模型兼容接口位于 `/v1/*`。
- 所有 Repository、Store 查询和更新都必须带 `agent_id`；包含 JOIN、回调、缓存键、幂等键和后台任务。
- 旧单租户数据只允许通过明确迁移兼容处理，不得成为共享运行时默认身份来源。
- `/healthz` 必须验证进程和本地持久化可用；`/readyz` 必须验证共享运行所需的上游配置和强密钥。
- SQLite 在线备份使用 CLI `agentapi --backup <destination.db>`，通过一致性快照生成并执行完整性检查；目标已存在、与源相同或备份无效时必须失败。
- 余额敏感的模型结算、充值同步、异步任务结算和后台核验必须按主站用户取得数据库租约；租约要支持续期、过期接管和 owner token 校验释放，不能退回进程内 mutex。
- 业务层不得重新增加站长可调用的备份、恢复、导入或文件下载接口。

## 9. 部署事实

当前仓库提供的是一套共享 AgentAPI Docker 服务：

- 默认本地端口：`18081`
- 主站本地端口：`18080`
- 共享运行时不设置固定 `AGENT_ID`
- 必须配置 `AGENTAPI_SHARED_HOSTS`
- 必须连接 Sub2API 网络并使用服务端应用凭据
- 健康检查：`GET /healthz`
- 就绪检查：`GET /readyz`

不得再按租户复制 Compose 或容器。扩容时只能增加相同共享服务副本，并确保数据库、Session、队列、限流和后台任务具备一致的多副本语义。当前数据库租约只证明同一用户的余额敏感操作可跨 Store 互斥，不代表单 SQLite Compose 已满足完整多副本条件。

## 11. 正式上线验收

正式发布前必须在目标环境完成并记录：

1. 配置正式 AgentAPI 共享域名、HTTPS、反向代理和精确 Host 白名单。
2. 配置正式应用凭据、SSO Secret 和 Session Secret，确认浏览器产物及日志无密钥。
3. 在生产备份后执行 Sub2API 246/247 迁移，核对有效 owner、共享租户和成员数量，再确认旧 provisioning/runtime 表已删除。
4. 两个真实站长分别点击“一键开分站”，容器数不变，得到不同 `agent_id`；同一站长重复点击仍返回原租户。
5. 两个站长和各自成员同时登录，验证品牌、用户、Key、订单、公告、用量、任务和设置不串租户。
6. 篡改 Host、query、body、header、cookie、对象 ID、任务 ID 和请求 ID 均不能切换或影响其他租户。
7. 使用当前用户个人 Key 实测非流式文本、流式文本、图片、视频和异步轮询，核对 Sub2API 只计费一次且归属真实用户。
8. 实测充值、订单、支付二维码、Stripe、Airwallex、微信回调及余额到账；不支持的支付方式必须明确关闭。
9. 验证正式域名 Cookie、OAuth 回调、账号绑定、TOTP、Passkey 和密码恢复策略。
10. 在目标部署拓扑执行备份、恢复和回滚演练；扩为多副本时额外验证 Session、队列、限流、后台任务隔离，以及同一用户并发结算/充值只能由一个副本执行。
11. 灰度期间核对租户数、成员数、请求数、用量、费用和失败重试，不以健康检查替代业务验收。

部署后先执行只读自动核验：

```powershell
.\scripts\VerifyDeployment.ps1 `
  -AgentBaseUrl 'https://agent.example.com' `
  -ExpectedHost 'agent.example.com'
```

脚本必须在正式 HTTPS 域名上通过首页、健康、就绪、未知 Host、退役路径和浏览器产物密钥扫描。若部署者已有测试会话或个人 Agent Key，可通过 `-SessionCookieFile`、`-AgentKeyFile` 从本地文件增加认证读取检查；脚本不打印文件内容、不创建业务数据、不发模型请求。自动核验通过后仍必须人工完成本节的真实浏览器、付费模型、支付回调和多副本验收，不能把脚本结果写成生产业务验收完成。

没有正式生产环境、域名、凭据和支付/模型流量时，AI 应明确写成“核心代码与本地共享部署已验证，生产验收待执行”，不能写成“已经正式上线”。

## 12. AI 执行协议

AI 修改 AgentAPI 时必须按以下顺序工作：

1. 先读根目录 `AGENTS.md`、公共接入文档、公开模型文档和本文。
2. 判断需求是否属于保留核心能力；命中永久删除模块时不得恢复代码。
3. 明确当前用户、租户、主站权威数据和浏览器可见数据的边界。
4. 先补服务端授权和租户条件，再接前端入口；禁止只做界面隐藏。
5. 对读取、写入、JOIN、任务、回调、缓存和幂等逐项检查 `agent_id`。
6. 补充正常、越权、跨租户、配置缺失和故障回退测试。
7. 运行与修改范围匹配的后端、前端和 Sub2API 回归。
8. 更新 `26-部署验收记录.md`，区分“已实现、已测试、已部署、已验收”。

AI 的文档语气必须使用可验证事实，避免“应该没问题”“理论上支持”“基本完成”等模糊表述。每个结论应说明证据范围；未执行的生产验证必须明确标为未执行，不能借用本地测试结果替代。

## 13. 禁止回退

后续提交出现以下任一情况即视为架构回退：

- 为每个站长创建独立容器、端口、数据库或 Secret。
- 从浏览器接收或暴露 SuperKey、Sub2API JWT、应用凭据或可信 `agent_id`。
- 使用站长身份替普通用户调用模型或代付。
- 恢复本文永久删除的菜单、路由、Handler 或数据表。
- 为 AgentAPI 发明新的 SSO、API Key 或菜单跳转协议。
- 让主站管理员自动成为代理站站长。
- 用本地估算覆盖或伪装 Sub2API 权威余额、用量或费用。
- 仅依赖前端隐藏实现权限控制。

发现回退时应先删除回退代码并补回归测试，再继续新增功能。
