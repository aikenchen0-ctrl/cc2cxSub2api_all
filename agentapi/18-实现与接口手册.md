# 18 实现与接口手册

本文是当前 `agentapi/backend` 已实现接口的操作手册。它与前面的设计文档分开：设计文档说明目标边界，本文件只记录当前代码可以验收的行为。

## 1. 接口分层

| 层 | 路径 | 调用者 | 说明 |
| --- | --- | --- | --- |
| 存活检查 | `GET /healthz` | 负载均衡器 | 进程存活，不访问主站，不产生扣费 |
| 就绪检查 | `GET /readyz` | 负载均衡器/运维 | 检查 Agent 状态、Owner、管理员 Key 和应用凭据 |
| Host 隔离 | 所有业务路径 | 入口层/应用 | `AGENT_DOMAIN` 配置后只接受匹配 Host；`/healthz`、`/readyz` 保留给内部探针 |
| 认证 | `/api/v1/auth/*` | 浏览器 | 主站认证由服务端代调，浏览器只得到 AgentAPI HttpOnly Cookie |
| 公共层 SSO | `GET /api/auth/sso/callback` | Sub2API 菜单跳转 | 校验 HMAC 身份票据并消费一次性 `jti`，不接收主站 JWT/Key |
| 品牌 | `GET /api/v1/settings/public`、`/api/v1/agent/admin/branding` | 浏览器/Agent 管理员 | 公开读取品牌；管理员可修改名称和 Logo，不可修改域名、Owner 或账务模式 |
| 代理控制台 | `/api/v1/agent/*` | Agent Session | 钱包、用户映射、用量和受限管理员操作 |
| Agent 客户端 Key | `/api/v1/api-keys` | Agent Session | 生成、列出和吊销 `sk-agent-*` |
| 模型网关 | `/v1/models`、`/v1/chat/completions`、`/v1/responses`、`/v1/images/*`、`/v1/videos*` | Agent Session 或 `sk-agent-*` | 只允许公开模型名，服务端固定使用代理 Owner 计费身份 |

除上表列出的接口外，AgentAPI **不代理主站通用 `/api/v1/*`**。例如 `/api/v1/users`、`/api/v1/balance`、`/api/v1/keys`、`/api/v1/admin/*`、支付、订阅和设置接口均返回 `403 AGENT_ROUTE_FORBIDDEN`。

## 2. 认证接口

### 2.1 注册

```http
POST /api/v1/auth/register
Content-Type: application/json
Origin: https://agent01.example.com
```

```json
{"email":"user@example.com","password":"a-strong-password"}
```

服务端使用 `SUB2API_ADMIN_KEY` 创建主站普通用户，随后建立 `agent_users(agent_id, main_user_id)` 映射。主站凭据不会写入响应。Agent 尚未 `active` 时返回 `503 AGENT_SUSPENDED`。

### 2.2 登录、当前用户和退出

```http
POST /api/v1/auth/login
POST /api/v1/auth/login/2fa
GET  /api/v1/auth/me
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
Cookie: agentapi_session=<HttpOnly>
```

Session 服务端保存并加密主站 access/refresh token；Cookie 的有效期固定为 3 天。响应中的 `access_token` 和 `refresh_token` 为空字符串，不能把它们当作 Bearer 凭据使用。

## 3. 代理管理员接口

代理管理员由当前 Session 的 `main_user_id == AGENT_OWNER_MAIN_USER_ID` 判定，不读取浏览器提交的角色字段。

### 3.1 品牌配置

```http
GET   /api/v1/agent/admin/branding
PUT   /api/v1/agent/admin/branding
Content-Type: application/json
Origin: https://agent01.example.com
```

请求体支持部分更新：

```json
{
  "name": "Agent 01",
  "site_name": "Agent 01 API",
  "site_logo": "/logo.svg"
}
```

Logo 只能使用应用相对路径或 `http(s)` URL；控制字符、`javascript:` 和协议相对 URL 会被拒绝。品牌值保存在 AgentAPI SQLite 中，普通重启不会被环境变量覆盖；只有显式设置 `AGENT_BRAND_SYNC=true` 才会用环境值覆盖已保存品牌。响应只返回品牌字段，不返回 Owner、余额或管理员凭据。

### 3.2 查看和同步 Owner 钱包

```http
GET  /api/v1/agent/admin/wallet
POST /api/v1/agent/admin/wallet/sync
```

`wallet/sync` 通过服务端管理员 Key 读取主站 Owner 余额，更新本地镜像的 `main_balance_cents`、`available_cents`、`billing_status`。同步不会凭空增加已分配额度；如果主站余额小于已分配额度，钱包进入 `overallocated`，新分配会被拒绝。

### 3.3 用户和额度分配

```http
GET  /api/v1/agent/admin/users
POST /api/v1/agent/admin/users/{main_user_id}/allocate
Content-Type: application/json
Idempotency-Key: allocate-20260921-001
```

```json
{"amount_cents":1000,"order_id":"main-order-001","note":"manual allocation"}
```

分配只改变 AgentAPI 的 `available/allocated/user balance` 三个本地镜像，不改变主站余额。重复幂等键不会重复分配；跨用户或不同金额复用会返回冲突。

### 3.4 待结算和对账

```http
GET  /api/v1/agent/admin/settlements
POST /api/v1/agent/admin/settlements/reconcile
Content-Type: application/json
```

不带请求体时，对账最多处理 `AGENT_SETTLEMENT_RECONCILE_BATCH` 条 pending 记录（默认 50，受配置上限约束）；也可以指定单条：

```json
{"request_id":"req_abc123"}
```

AgentAPI 使用同一个 `request_id` 调用主站 `GET /api/v1/admin/usage?request_id=...`。找到主站 usage 后，按 `actual_cost`（没有时回退 `total_cost`）确认本地结算并幂等退回未使用的预授权；找不到时保持 `pending`，绝不自动退款。

本接口只允许代理管理员 Session 使用，不能用 Agent 客户端 Key 或任意主站 Key 调用。

### 3.4 本地充值

```http
POST /api/v1/agent/admin/wallet/credit
```

固定返回 `410 LOCAL_CREDIT_DISABLED`。方案 A 的充值必须发生在主站 Owner 账户，再通过 `wallet/sync` 同步；不能用浏览器接口伪造本地余额。

## 4. Agent 客户端 Key

```http
POST /api/v1/api-keys
GET  /api/v1/api-keys
DELETE /api/v1/api-keys/{id}
Cookie: agentapi_session=<HttpOnly>
```

创建响应中的 `key` 只显示一次，格式为 `sk-agent-*`。数据库只保存哈希和前缀。该 Key 仅能调用当前 Agent 的公开 `/v1` 端点，不能调用控制台、主站管理员接口或其它 Agent。

## 5. 模型网关

```http
POST /v1/chat/completions
Authorization: Bearer sk-agent-...
Idempotency-Key: model-request-001
Content-Type: application/json
```

JSON 请求体或 multipart 表单中的 `model` 必须在 [卫星公开模型](../docs/卫星公开模型.md) 允许目录内；图片编辑即使使用文件上传也不能绕过目录校验。路径也必须属于上表明确公开的模型端点，未知 `/v1/*` 路径返回 `403 MODEL_ROUTE_FORBIDDEN`。服务端向主站发送：

```http
Authorization: Bearer <SUB2API_APP_CREDENTIAL>
X-Sub2API-On-Behalf-Of: <AGENT_OWNER_MAIN_USER_ID>
X-Sub2API-Satellite: agentapi
X-Request-ID: model-request-001
```

客户端提交的 `Authorization`、`X-Sub2API-On-Behalf-Of` 和 `X-Sub2API-Satellite` 不会被透传。一次请求的本地预授权与 pending settlement 在同一事务中创建；同一幂等键第二次到达时返回 `409 IDEMPOTENCY_REPLAY` 或 `409 SETTLEMENT_PENDING`，不会再次访问主站。

当 JSON 请求设置 `"stream": true` 或请求头包含 `Accept: text/event-stream` 时，AgentAPI 会在上游响应到达后边转发边读取，正常 EOF 后再用 Owner 余额差额确认结算；客户端断开、上游连接异常或结果不确定时保留 `pending`，由对账接口处理。流式时长由 `MODEL_STREAM_TIMEOUT` 和 `AGENTAPI_WRITE_TIMEOUT` 控制。普通 JSON、图片上传和视频任务仍采用缓冲响应路径。

## 6. 错误码约定

| 错误码 | 含义 | 客户端动作 |
| --- | --- | --- |
| `AGENT_SUSPENDED` | 实例尚未就绪、被暂停或已撤销 | 联系平台管理员，不要重试模型请求 |
| `AGENT_INSUFFICIENT_BALANCE` | 用户子余额或代理已分配额度不足 | 由管理员同步/分配额度 |
| `MAIN_OWNER_BALANCE_INSUFFICIENT` | Owner 主站余额不足 | 在主站充值后同步 |
| `SETTLEMENT_PENDING` | 请求状态不确定，正在等主站 usage | 使用管理员对账，不要换请求 ID 重放 |
| `IDEMPOTENCY_REPLAY` | 请求已结算 | 使用原响应记录，不要重复扣款 |
| `AGENT_ROUTE_FORBIDDEN` | 未公开的主站接口 | 使用 AgentAPI 公共接口 |
| `MODEL_ROUTE_FORBIDDEN` | 未公开的模型端点 | 使用 AgentAPI 公共模型端点 |
| `MODEL_NOT_ALLOWED` | 模型名不在公开目录 | 改用公开模型名 |
| `LOCAL_CREDIT_DISABLED` | 禁止 AgentAPI 伪造充值 | 走主站 Owner 充值 |
| `PAYMENT_DISABLED` | 当前实例未启用充值桥接 | 联系平台配置支付供应商 |
| `PAYMENT_SIGNATURE_INVALID` | webhook 原始 body 签名不正确 | 由支付服务修正签名后重试 |
| `PAYMENT_EVENT_CONFLICT` | 事件、金额、订单状态或交易号冲突 | 停止重放，人工核对订单 |
| `RECHARGE_ALLOCATION_FAILED` | 支付已记录但本地分配失败 | 查看管理员订单并重试 |
| `VIDEO_TASK_NOT_FOUND` | 任务不存在或不属于当前代理用户 | 不得轮询其他用户任务 |
| `VIDEO_TASK_ID_MISSING` | 主站创建成功响应缺少可追踪任务 ID | 保持原 settlement pending，人工检查主站响应 |
| `VIDEO_TASK_TRACKING_FAILED` | 主站已创建任务但本地归属持久化失败 | 使用响应中的 `task_id` 人工恢复，不要重复创建 |

## 7. 反向代理要求

Nginx 必须把原始 Host 传给 AgentAPI，并禁止把管理端环境变量写入前端资源、访问日志或错误响应。建议至少设置：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Request-ID $request_id;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_read_timeout 120s;
```

AgentAPI 当前按单实例配置运行；多代理部署应使用多个容器和多个 SQLite 数据卷，不能让不同 Agent 共享同一个数据库文件。

## 8. 充值订单与支付回调

### 8.1 用户订单

```http
GET  /api/v1/agent/recharge/orders
POST /api/v1/agent/recharge/orders
Cookie: agentapi_session=<HttpOnly>
Idempotency-Key: recharge-request-001
```

`GET` 只返回当前 Session 映射的 `main_user_id` 的订单。`POST` 请求体只提交 `amount`（例如 `"10.00"`）或 `amount_cents`，`agent_id`、`main_user_id`、`provider`、`currency` 均由服务端确定。支付关闭时返回 `410 PAYMENT_DISABLED`。创建成功返回 `201`，相同幂等键重试返回原订单而不会重复创建。

### 8.2 管理员订单与分配

```http
GET  /api/v1/agent/admin/recharge/orders
POST /api/v1/agent/admin/recharge/allocate
Cookie: agentapi_session=<HttpOnly>
Content-Type: application/json
```

管理员请求体：

```json
{"order_no":"ord_xxx"}
```

只有 `paid_pending_allocation` 订单可以分配。接口先同步 Owner 主站余额，再在 SQLite 事务中同时写入 `user_allocate`、`agent_allocate` 两条流水并把订单置为 `allocated`；余额不足返回 `402 MAIN_OWNER_BALANCE_INSUFFICIENT`。

### 8.3 支付供应商 webhook

```http
POST /api/v1/payments/webhook
X-Agent-Payment-Event-ID: evt_xxx
X-Agent-Payment-Signature: sha256=<hex HMAC-SHA256>
X-Agent-Payment-Timestamp: 1720000000
Content-Type: application/json
```

webhook 不读取 Cookie，先限制请求体大小、校验可选时间戳和原始 body HMAC，再校验订单金额、币种、供应商和状态。支付事件写入 `payment_events` 后才尝试 Owner 余额同步与分配。主站暂时不可用或额度不足时返回 `202`，订单保持 `paid_pending_allocation`，后续可由管理员接口重试。重复事件返回原订单并标记 `duplicate`，不会再次写余额流水。

当前 webhook 是 provider-neutral 适配层；真实供应商 SDK、渠道专属签名、退款、拒付和主站充值自动入账尚未实现。`AGENT_PAYMENT_ENABLED` 默认 `false`，上线前必须完成供应商适配和专项验收。

### 8.4 视频异步任务

`POST /v1/videos` 成功后，AgentAPI 从主站响应的 `id`、`task_id` 或 `video_id` 保存任务归属及原始 `request_id`。`GET /v1/videos/{id}` 必须继续使用创建任务的同一 Agent 用户 Session 或 `sk-agent-*`；其他用户统一得到 `404 VIDEO_TASK_NOT_FOUND`，请求不会到达主站。

轮询不会创建新的本地预授权。若主站余额差额在轮询时出现，系统确认原始 settlement；任务明确失败且没有产生费用时释放原预授权；完成但主站 usage/余额尚不可见时继续保持 pending，交由既有 reconciler 对账。后台 reconciler 会在任务年龄超过 `AGENT_VIDEO_TASK_RECONCILE_AGE` 后主动探测一次；失败任务释放原冻结，成功任务查询主站 usage，默认年龄为 30 分钟。

## 9. 审计事件

```http
GET /api/v1/agent/admin/audit-events?limit=100
Cookie: agentapi_session=<HttpOnly>
```

仅 Agent Owner 可以查询，`limit` 范围为 `1..500`。当前记录品牌修改、Owner 余额同步、用户额度分配、充值订单分配、pending settlement 对账以及 AgentAPI Key 创建/吊销。每条事件包含 `actor_type`、`actor_id`、`agent_id`、`operation`、目标、`request_id`、结果和时间；不会写入管理员 Key、支付密钥、Cookie、密码、完整 Authorization 或客户端 Key 明文。
