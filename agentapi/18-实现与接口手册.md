# 18 实现与接口手册

本文是当前 `agentapi/backend` 已实现接口的操作手册。它与前面的设计文档分开：设计文档说明目标边界，本文件只记录当前代码可以验收的行为。

## 1. 接口分层

| 层 | 路径 | 调用者 | 说明 |
| --- | --- | --- | --- |
| 存活检查 | `GET /healthz` | 负载均衡器 | 进程存活，不访问主站，不产生扣费 |
| 就绪检查 | `GET /readyz` | 负载均衡器/运维 | 检查本地 Agent 配置、Owner、逐站 runtime control/model 凭据和应用凭据；不等待主站期望状态，避免部署激活循环依赖 |
| Host 隔离 | 所有业务路径 | 入口层/应用 | `AGENT_DOMAIN` 配置后只接受匹配 Host；`/healthz`、`/readyz` 保留给内部探针 |
| 主站开站控制面 | `/api/v1/agent-provisioning/agents*` | 仅 Sub2API 主站管理员 | 记录 pending 开站任务和受控状态变更；不执行 DNS/TLS 或容器部署 |
| 主站 Agent Runtime | `/api/v1/agent-runtime/*` | AgentAPI 服务端 | 必须同时提供逐站 `X-AgentAPI-Runtime-Control`；绑定用户另需该用户 JWT 或已有的 `agentapi` HMAC SSO 票据；状态事件 SSE 只发本 Agent ID 提示 |
| 认证 | `/api/v1/auth/*` | 浏览器 | 主站认证由服务端代调，浏览器只得到 AgentAPI HttpOnly Cookie |
| 用户 Profile / 密码 | `/api/v1/agent/profile`、`/api/v1/agent/password` | Agent Session | 只调用当前用户的 Sub2API 自助账户 API；仅允许更新 username，主站敏感字段不会返回浏览器 |
| 公共层 SSO | `GET /api/auth/sso/callback` | Sub2API 菜单跳转 | 校验 HMAC 身份票据并消费一次性 `jti`，不接收主站 JWT/Key |
| 品牌 | `GET /api/v1/settings/public`、`/api/v1/agent/admin/branding` | 浏览器/Agent 管理员 | 公开读取品牌；管理员可修改名称和 Logo，不可修改域名、Owner 或账务模式 |
| 代理控制台 | `/api/v1/agent/*` | Agent Session | 钱包、用户映射、用量和受限管理员操作 |
| 媒体任务历史 | `GET /api/v1/agent/tasks` | Agent Session | 仅返回当前用户图片/视频任务索引，可在模型控制台恢复轮询 |
| Agent 客户端 Key | `/api/v1/api-keys` | Agent Session | 生成、列出和吊销 `sk-agent-*` |
| 模型网关 | `/v1/models`、`/v1/chat/completions`、`/v1/responses`、`/v1/images/*`、`/v1/videos*` | Agent Session 或 `sk-agent-*` | 只允许公开模型名，服务端固定使用代理 Owner 计费身份 |

除上表列出的接口外，AgentAPI **不代理主站通用 `/api/v1/*`**。例如 `/api/v1/users`、`/api/v1/balance`、`/api/v1/keys`、`/api/v1/admin/*`、支付、订阅和设置接口均返回 `403 AGENT_ROUTE_FORBIDDEN`。

### 1.1 Sub2API 主站开站控制 API

该组 API 运行在 Sub2API，不经过 AgentAPI。仅主站管理员可调用，并经过主站合规门控、面板限流与操作审计。当前使用全局管理员鉴权，没有按 Agent 隔离的管理 scope。

```http
POST /api/v1/agent-provisioning/agents
Idempotency-Key: create-agent-01
Content-Type: application/json
```

```json
{
  "requested_slug": "agent01",
  "display_name": "Agent 01",
  "owner_main_user_id": "u_10001",
  "plan_id": "standard",
  "brand": {"name": "Agent 01", "logo_url": null},
  "domain_mode": "platform_subdomain"
}
```

Owner 必须是启用且未软删除的主站管理员。第一版只接受平台子域名，按 `<slug>.cc2.cx` 生成；套餐 ID 目前仅做格式检查。首次请求返回 `202`，状态为 `pending`、步骤为 `queued`，同时提供相对状态 URL。重复的管理员身份、幂等键和规范化请求返回原 Agent；相同键用于不同参数返回 `409 AGENT_DUPLICATE_REQUEST`。状态响应包含 `current_step`、`recent_error`、`can_retry` 和 `domain_status`，不含秘密。

```http
GET  /api/v1/agent-provisioning/agents?page=1&page_size=20&status=pending&q=agent
GET  /api/v1/agent-provisioning/agents/stream
GET  /api/v1/agent-provisioning/agents/{agent_id}
POST /api/v1/agent-provisioning/agents/{agent_id}/claim
POST /api/v1/agent-provisioning/agents/{agent_id}/lease
PATCH /api/v1/agent-provisioning/agents/{agent_id}/progress
POST /api/v1/agent-provisioning/agents/{agent_id}/retry
POST /api/v1/agent-provisioning/agents/{agent_id}/activate
POST /api/v1/agent-provisioning/agents/{agent_id}/suspend
POST /api/v1/agent-provisioning/agents/{agent_id}/resume
POST /api/v1/agent-provisioning/agents/{agent_id}/revoke
Idempotency-Key: action-01
```

列表与 SSE 均为 Sub2API 管理接口，不经 AgentAPI。列表支持状态/关键词和分页；SSE 使用主站数据库提交后的 `LISTEN/NOTIFY` 刷新提示，只推送 `agent_id`，不携带完整 Agent 记录。worker 与托管 AgentAPI 进程都只将匹配 `agent_id` 的事件或 `resync` 用作 GET 唤醒提示；另有周期 GET 兜底。

worker claim/lease 只允许 `X-AgentAPI-Provisioning-Credential` allowlist 身份调用。claim 仅可取得 `pending/provisioning` 记录的有效执行租约，响应一次性返回 `lease_token` / `lease_expires_at`，并设置 `Cache-Control: no-store`、`Pragma: no-cache`；主站只存 token 的 SHA-256 哈希。租约默认 90 秒、worker 默认每 20 秒续租。renew 请求和 worker progress/activate 另须带 `X-AgentAPI-Provisioning-Lease: <lease_token>`；进度更新会一并续租，激活或失败释放租约。租约已被其他 worker 持有、过期或 token 不匹配时会拒绝，失租 worker 取消任务 context。租约不能为 Docker/Nginx 副作用提供 fencing，部署动作仍需幂等。

部署 worker 先 claim 并持有有效租约，再通过 `PATCH .../{agent_id}/progress` 以幂等键报告部署阶段。当前允许的有序步骤为 `validating`、`bundle_generated`、`deploying`、`domain_check`、`tls_check`、`readiness_check`；失败提交固定 `failure_code`（如 `readiness_failed`）和 `retryable`，主站生成安全的 `recent_error`，不存任意 worker 日志。每个进度变化、租约刷新与事件事务性写入并触发 SSE。

AgentAPI 仓库包含可运行的 `cmd/agentapi-provision-worker`：它以 `X-AgentAPI-Provisioning-Credential` 携带 `AGENT_PROVISIONING_WORKER_CREDENTIAL_FILE` 中的凭据，读取 pending/provisioning 列表，SSE 只作为 Agent ID 刷新提示，定期列表轮询兜底；单个 Agent 任务执行前以 GET 刷新权威状态并 claim 租约。Sub2API 仅允许该共享凭据访问开站列表/SSE/GET/claim/lease/progress/activate，不允许 create/suspend/resume/revoke/retry 或其他管理接口；它不是逐 Agent scope。租约 90 秒、默认每 20 秒续租，原始 token 只在 no-store claim 响应出现一次，worker 不写日志；失租后取消任务 context。租约不能为 Docker/Nginx 副作用提供 fencing，部署操作仍需幂等。worker 调用 CLI 生成幂等部署包、部署 Compose、安装/校验/失败回滚 Nginx host 配置、验证 DNS 仅指向 allowlist edge IP、验证 TLS/healthz 并等待 readyz。完成后 worker 显式调用 activation API。worker 不会自动重试 failed 记录；管理员显式调用 `POST .../{agent_id}/retry` 将可重试记录重置为 pending 后，SSE/轮询才会触发下一次部署。worker 自身不使用 `SUB2API_ADMIN_KEY_FILE` 进行控制面认证；该文件仍只传给 AgentAPI 运行实例的 Compose Secret。Worker 配置、所需绝对 secret-file 路径和构建方式见 [04-一键开分站流程](04-一键开分站流程.md)。

上述 allowlist 的当前实现还包括：worker 持有效租约调用 `POST /api/v1/agent-provisioning/agents/{agent_id}/runtime-credentials`，登记 CLI 已生成的当前 Agent `control_token_hash` 和 `model_token_hash`。主站只接收并存储 SHA-256 哈希；原始凭据只存在 worker 受保护的逐站 Secret 文件中。相同哈希重放幂等，已吊销哈希不能重新激活。

部署 worker 仍是独立受控运维组件，不随 Sub2API 自动启动或运行在主站进程中。它拥有 Docker daemon/Nginx 文件写入能力；主站管理 API 访问已改为独立的 provisioning-only allowlist credential，但凭据仍在 worker 间共享，未部署或配置/域名环境不匹配时，不能声称开站自动化已在生产运行。托管 AgentAPI 业务进程已使用逐 Agent runtime control/model 凭据，不依赖全局管理员 API Key；worker 会把相应哈希登记到主站，但外部 Secret 的注入、轮换和撤销以及 edge 生产验收仍未完成。

状态变更均要求幂等键。`retry` 仅允许 `failed && can_retry`，并恢复到 `pending/queued`；撤销还要求 JSON `{"confirm_agent_id":"<agent_id>"}`。对于已运行且使用该主站返回 `agt_<uuid>` 的受控 AgentAPI 实例，`active` 之外的最新状态会阻断业务请求；状态读取失败或超过 `AGENT_PROVISIONING_CONTROL_STALE_AFTER` 也 fail closed。`/healthz` 和 `/readyz` 可继续探测。worker 源码已实现逐站 runtime credential 生成、哈希登记、DNS/TLS/Compose/Nginx 编排和 `/readyz` 检查，但运维节点的实际安装配置、外部 Secret 轮换与生产端到端验收仍未完成。

激活接口 `POST /agents/{agent_id}/activate` 要求幂等键及 `{"confirm_agent_id":"<same-agent-id>","readiness_confirmed":true}`，仅将 `pending/provisioning/failed` 标记为 `active/ready`。worker 在自身完成 DNS、TLS、`/healthz` 与 `/readyz` 检查后调用该接口；人工运维也可由管理员 UI 确认目标域名的 `/readyz` 检查。接口本身不访问实例、不自动验证其配置。暂停、恢复和撤销会由已运行的托管 AgentAPI 门控执行。worker 代码已实现，但仍需在受控 edge 节点安装配置并完成真实生产环境验收。

## 2. 认证接口

### 2.1 注册

```http
POST /api/v1/auth/register
Content-Type: application/json
Origin: https://agent01.example.com
```

```json
{"email":"user@example.com","password":"a-strong-password"}
```

服务端将注册/登录请求代理到 Sub2API 公开认证 API；完成认证后，使用 `POST /api/v1/agent-runtime/users/{main_user_id}/map` 建立主站映射。该映射调用同时要求当前 Agent 的 runtime control 凭据和与目标 ID 一致的主站用户 JWT；从 Sub2API 菜单进入时则复用同一短时 `agentapi` HMAC SSO 票据作服务器间身份凭据。逐站 control 凭据不能单独绑定任意主站用户。主站凭据不会写入浏览器响应。Agent 尚未 `active` 时返回 `503 AGENT_SUSPENDED`。

### 2.2 登录、当前用户和退出

```http
POST /api/v1/auth/login
POST /api/v1/auth/login/2fa
GET  /api/v1/auth/me
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
Cookie: agentapi_session=<HttpOnly>
```

Session 服务端保存并加密主站 access/refresh token；Cookie 的有效期固定为 3 天。响应中的 `access_token` 和 `refresh_token` 为空字符串，不能把它们当作 Bearer 凭据使用。

显式刷新 Session 时必须返回新的主站 access token；刷新响应（或用新 access token 查询到的当前用户）还必须包含与本地 Session 完全相同的主站用户 ID。token 缺失、身份缺失或身份变化都会拒绝刷新、删除本地 Session 并清除 Cookie。Profile、自助改密及其他需要读取当前主站身份的请求也会在正常访问和 access token 续签后执行相同的身份匹配校验。

### 2.3 用户 Profile 和密码

```http
GET /api/v1/agent/profile
PUT /api/v1/agent/profile
PUT /api/v1/agent/password
Cookie: agentapi_session=<HttpOnly>
Origin: https://agent01.example.com
```

Profile 仅返回当前映射用户的 `id`、`email`、`username`、可选 `avatar_url` 和 `can_edit`。更新接口只读取 `username`，服务器固定调用该用户自己的 `PUT /api/v1/user`，不会透传浏览器提交的余额、角色、邮箱或 `agent_id`。读取及修改使用服务器 Session 中加密保存的当前用户 JWT，绝不返回或写入浏览器存储。

修改密码请求为 `{"old_password":"...","new_password":"..."}`，通过当前用户 JWT 调用 Sub2API `PUT /api/v1/user/password`。成功后主站使旧 JWT 失效，AgentAPI 删除当前本地 Session 并清除 Cookie，要求用户重新登录；密码不会写入 AgentAPI SQLite、响应或审计事件。来自菜单 SSO 的 identity-only Session 可以查看票据中的 Profile 摘要，但 `can_edit=false`，更新用户名/密码返回 `403 MAIN_SESSION_REQUIRED`；必须使用主站账号密码建立可认证 Session。

此处是固定的用户自助接口，不是通用 `/api/v1/*` 代理。任意其它主站账户、支付、Key、订阅或管理路径仍由 AgentAPI 的 deny-by-default 路由拒绝。

## 3. 代理管理员接口

代理管理员由当前 Session 的 `main_user_id == AGENT_OWNER_MAIN_USER_ID` 判定，不读取浏览器提交的角色字段。

### 3.1 品牌配置

```http
GET   /api/v1/agent/admin/branding
PUT   /api/v1/agent/admin/branding
Content-Type: application/json
Origin: https://agent01.example.com
```

请求体支持部分更新：

```json
{
  "name": "Agent 01",
  "site_name": "Agent 01 API",
  "site_logo": "/logo.svg"
}
```

Logo 只能使用应用相对路径或 `http(s)` URL；控制字符、`javascript:` 和协议相对 URL 会被拒绝。品牌值保存在 AgentAPI SQLite 中，普通重启不会被环境变量覆盖；只有显式设置 `AGENT_BRAND_SYNC=true` 才会用环境值覆盖已保存品牌。响应只返回品牌字段，不返回 Owner、余额或管理员凭据。

### 3.2 查看和同步 Owner 钱包

```http
GET  /api/v1/agent/admin/wallet
POST /api/v1/agent/admin/wallet/sync
```

`wallet/sync` 通过逐站 runtime control 凭据读取该 Agent 的 Owner 余额，更新本地镜像的 `main_balance_cents`、`available_cents`、`billing_status`。同步不会凭空增加已分配额度；如果主站余额小于已分配额度，钱包进入 `overallocated`，新分配会被拒绝。

### 3.3 用户和额度分配

```http
GET  /api/v1/agent/users?page=1&page_size=25&q=alice
GET  /api/v1/agent/admin/users?page=1&page_size=25&q=alice
POST /api/v1/agent/admin/users/{main_user_id}/allocate
Content-Type: application/json
Idempotency-Key: allocate-20260921-001
```

```json
{"amount_cents":1000,"order_id":"main-order-001","note":"manual allocation"}
```

分配只改变 AgentAPI 的 `available/allocated/user balance` 三个本地镜像，不改变主站余额。重复幂等键不会重复分配；跨用户或不同金额复用会返回冲突。

`agent/users` 的管理员视图与 `agent/admin/users` 都支持 `page`、`page_size` 和可选 `q`（默认页码/每页条数为 `1` / `25`，每页 `1..200` 条，搜索最多 512 字节）。搜索按当前 Agent 的本地映射 ID、邮箱和显示名做不区分大小写的包含匹配，过滤后的 `items` 与 `total` 在同一只读事务中读取。普通用户即使传入分页或搜索参数也只得到自己的映射行，管理员列表不会因固定条数上限而静默漏掉用户。

映射用户启停使用 AgentAPI 的代理管理员接口：PATCH /api/v1/agent/admin/users/{main_user_id}/status，请求体只接受 {"status":"active"} 或 {"status":"disabled"}。目标必须已映射到当前 Agent，操作者必须是当前 Agent Owner，并通过同源校验。AgentAPI 只向 Sub2API `PATCH /api/v1/agent-runtime/users/{id}/status` 发送状态字段；逐站 runtime control 凭据仍受当前 Agent ID 限制，主站还会再次检查用户映射关系，不会转发用户提供的其他字段。

禁用时先关闭本地用户门控，再请求主站，因此主站更新失败时用户仍被 AgentAPI fail-closed；启用时先由主站确认成功，再打开本地门控。主站拒绝的账号状态变更不会打开本地访问。主站不允许禁用管理员账户，Agent Owner 也不能从自己的代理控制台禁用自己。此操作会修改 Sub2API 账户的全局状态，不只是代理站内状态。

### 3.4 待结算和对账

```http
GET  /api/v1/agent/admin/settlements
POST /api/v1/agent/admin/settlements/reconcile
Content-Type: application/json
```

不带请求体时，对账最多处理 `AGENT_SETTLEMENT_RECONCILE_BATCH` 条 pending 记录（默认 50，受配置上限约束）；也可以指定单条：

```json
{"request_id":"req_abc123"}
```

AgentAPI 使用同一个 `request_id` 调用主站 `GET /api/v1/agent-runtime/usage?request_id=...`。Sub2API 在服务端将查询固定限制到该 Agent 的 Owner，响应只含白名单 usage 字段。找到主站 usage 后，若 DTO 带有效 `actual_cost` 字段就按它结算（包括 `0`）；仅旧版 DTO 缺少该字段时回退有效的 `total_cost`，字段存在但无效则保留 pending。SQLite 保存主站 usage ID、模型和白名单快照：输入/输出/cache/image Token、费用分项（USD 纳美元整数）、路由/服务层级/reasoning effort、耗时/TTFT、计费模式、上游映射/响应模型及来源标记；不保存或返回管理 DTO 中的 IP、账号或用户对象。即时结算、视频轮询和后台 reconciler 都使用相同快照写入逻辑；找不到 usage 时保持 `pending`，绝不自动退款。不能使用 Owner 余额前后差代替这条 request 级 usage 事实，因为 Owner 可能同时被其他入口消费。

用户用量接口 `GET /api/v1/agent/usage?page=1&page_size=25` 返回 AgentAPI `request_id`、主站 `usage_id`、本地预授权/结算额和结算状态；`page_size` 范围为 `1..200`，响应同时返回同一只读事务中的筛选后 `total`、`page` 和 `page_size`。普通用户只能分页查看自己的记录，代理管理员只查看当前 Agent 的记录。当前主站逐站 runtime usage 快照标记为 `usage_source=sub2api_owner_runtime_usage`，历史 `sub2api_admin_usage` 快照仍兼容显示；两者都提供 Token 与 USD 纳美元费用字段及模型来源信息。只有显式开启旧主站余额差兼容路径时才标注 `owner_balance_delta_fallback`；该值不是 request 级主站 usage 事实。历史记录没有快照时不伪造 Token 或费用详情。前端分页交互移植并精简自 `sub2api/frontend/src/components/common/Pagination.vue`，不依赖主站后台 i18n/Select 组件。

媒体任务历史接口 `GET /api/v1/agent/tasks?page=1&page_size=25` 返回当前 Session 主站用户在当前 Agent 创建的图片/视频任务 ID、类型、公开模型名、最近状态、原 request ID、结算摘要及时间。它以本地 task 表与 settlement 关联查询，`page_size` 范围为 `1..200`，响应设置 `Cache-Control: no-store`；即使当前 Agent Owner 登录，也不会扩大到其他用户的任务。接口不包含 Sub2API 原始媒体响应或 URL。用户点击“Resume / check”后，前端使用既有同源 `/v1/images/tasks/{id}` 或 `/v1/videos/{id}` AgentAPI 路由读取当前结果，不会再次创建任务；跨用户检查仍在模型 relay 查询前被拒绝。

本接口只允许代理管理员 Session 使用，不能用 Agent 客户端 Key 或任意主站 Key 调用。

### 3.4 本地充值

```http
POST /api/v1/agent/admin/wallet/credit
```

固定返回 `410 LOCAL_CREDIT_DISABLED`。方案 A 的充值必须发生在主站 Owner 账户，再通过 `wallet/sync` 同步；不能用浏览器接口伪造本地余额。

## 4. Agent 客户端 Key

```http
POST /api/v1/api-keys
GET  /api/v1/api-keys
DELETE /api/v1/api-keys/{id}
Cookie: agentapi_session=<HttpOnly>
```

创建响应中的 `key` 只显示一次，格式为 `sk-agent-*`。数据库只保存哈希和前缀。该 Key 仅能调用当前 Agent 的公开 `/v1` 端点，不能调用控制台、主站管理员接口或其它 Agent。

## 5. 模型网关

```http
POST /v1/chat/completions
Authorization: Bearer sk-agent-...
Idempotency-Key: model-request-001
Content-Type: application/json
```

JSON 请求体或 multipart 表单中的 `model` 必须在 [卫星公开模型](../docs/卫星公开模型.md) 允许目录内；图片编辑即使使用文件上传也不能绕过目录校验。路径也必须属于上表明确公开的模型端点，未知 `/v1/*` 路径返回 `403 MODEL_ROUTE_FORBIDDEN`。服务端向主站发送：

代理管理员可以通过 `GET/PUT /api/v1/agent/admin/model-policy` 从同一公开目录配置本 Agent 的模型 allowlist；默认未配置时开放整个公开目录，显式空列表则关闭全部模型。`GET /v1/models` 只返回启用模型，普通用户 Model Console 也从该接口装载选项并在空列表时禁用请求；JSON 与 multipart 请求都会在创建预授权/settlement 和访问 Sub2API 前校验 allowlist。托管 Agent 的策略写入、逐站 control credential 对 `PUT /api/v1/agent-runtime/model-policy` 的同步确认和失败回滚会在 AgentAPI 内串行执行，避免并发失败回滚覆盖较新的策略；只有 Sub2API 确认保存同一 Agent 的范围后才确认配置成功。Sub2API 将 scope 持久化到对应 model credential，并在 `/v1` 网关入口再次校验请求模型、要求显式模型、过滤 `/v1/models` 发现结果，因此直接持有该 model credential 也不能越过 Agent 范围。Sub2API 默认未配置的 NULL scope 表示完整卫星公开目录；显式空数组表示拒绝全部模型。

```http
Authorization: Bearer <SUB2API_APP_CREDENTIAL>
X-Sub2API-On-Behalf-Of: <CURRENT_SESSION_MAIN_USER_ID>
X-Sub2API-Satellite: agentapi
X-Request-ID: model-request-001
```

客户端提交的 `Authorization`、`X-Sub2API-On-Behalf-Of` 和 `X-Sub2API-Satellite` 不会被透传。AgentAPI 从当前 Session/本地 API Key 映射生成 `X-Sub2API-On-Behalf-Of`；Sub2API 逐请求确认用户仍 active 且映射到该 Agent，然后以逐站 model credential 绑定的 Agent Owner SuperKey 扣费。一次请求的本地预授权与 pending settlement 在同一事务中创建；同一幂等键第二次到达时返回 `409 IDEMPOTENCY_REPLAY` 或 `409 SETTLEMENT_PENDING`，不会再次访问主站。

当 JSON 请求设置 `"stream": true` 或请求头包含 `Accept: text/event-stream` 时，AgentAPI 会在上游响应到达后边转发边读取，正常 EOF 后优先按主站 usage 的原 `request_id` 确认结算；客户端断开、上游连接异常或结果不确定时保留 `pending`，由对账接口处理。旧主站未提供 usage 管理接口且显式设置 `AGENT_MAIN_USAGE_API=false` 时才使用余额差兼容路径。流式时长由 `MODEL_STREAM_TIMEOUT` 和 `AGENTAPI_WRITE_TIMEOUT` 控制。普通 JSON、图片上传和视频任务仍采用缓冲响应路径。

## 6. 错误码约定

| 错误码 | 含义 | 客户端动作 |
| --- | --- | --- |
| `AGENT_CONTROL_UNAVAILABLE` | 主站控制状态未知、不可读或已过期 | 保持暂停，检查主站 API 与管理员凭据 |
| `AGENT_NOT_ACTIVE` | 主站状态仍为 pending/provisioning/failed | 等待开站完成，不要重放模型请求 |
| `AGENT_SUSPENDED` | 主站管理员已暂停该实例 | 联系平台管理员，不要重试模型请求 |
| `AGENT_REVOKED` | 主站管理员已不可逆撤销该实例 | 停止使用该站点 |
| `AGENT_USER_DISABLED` | 当前 Agent 中的映射账号已停用 | 联系 Agent Owner；不可继续用旧 Session 或客户端 Key 请求 |
| `AGENT_USER_NOT_FOUND` | 用户未映射到当前 Agent，或映射不可用 | 核对 Agent 用户映射 |
| `AGENT_ADMIN_REQUIRED` | 当前 Session 不是该 Agent Owner | 由 Agent Owner 操作 |
| `OWNER_STATUS_PROTECTED` | 不允许从分站控制台停用 Agent Owner | 通过平台账号管理流程处理 |
| `INVALID_USER_STATUS` | 用户状态不是 `active` 或 `disabled` | 使用支持的状态值重试 |
| `MAIN_USER_STATUS_UPDATE_FAILED` | Sub2API 未确认全局账号状态变更；停用时本地门控仍关闭 | 检查主站权限/状态，再由 Owner 重试或联系平台管理员 |
| `AGENT_USER_STATUS_UPDATE_FAILED` | AgentAPI 本地映射状态无法同步 | 用户保持阻断，检查本地 SQLite 并重试 |
| `AGENT_INSUFFICIENT_BALANCE` | 用户子余额或代理已分配额度不足 | 由管理员同步/分配额度 |
| `MAIN_OWNER_BALANCE_INSUFFICIENT` | Owner 主站余额不足 | 在主站充值后同步 |
| `SETTLEMENT_PENDING` | 请求状态不确定，正在等主站 usage | 使用管理员对账，不要换请求 ID 重放 |
| `IDEMPOTENCY_REPLAY` | 请求已结算 | 使用原响应记录，不要重复扣款 |
| `AGENT_ROUTE_FORBIDDEN` | 未公开的主站接口 | 使用 AgentAPI 公共接口 |
| `MODEL_ROUTE_FORBIDDEN` | 未公开的模型端点 | 使用 AgentAPI 公共模型端点 |
| `MODEL_NOT_ALLOWED` | 模型名不在公开目录 | 改用公开模型名 |
| `MODEL_REQUIRED` | Agent 已配置模型 allowlist，但请求没有明确模型名 | 在请求体或 multipart 表单中提交已启用的 `model` |
| `MODEL_POLICY_UNAVAILABLE` | Agent 本地模型策略无法读取 | 保持拒绝，检查 SQLite 状态 |
| `INVALID_PAGINATION` | 用量分页参数超出支持范围 | `page >= 1` 且 `page_size` 为 `1..200` |
| `LOCAL_CREDIT_DISABLED` | 禁止 AgentAPI 伪造充值 | 走主站 Owner 充值 |
| `PAYMENT_DISABLED` | 当前实例未启用充值桥接 | 联系平台配置支付供应商 |
| `PAYMENT_SIGNATURE_INVALID` | webhook 原始 body 签名不正确 | 由支付服务修正签名后重试 |
| `PAYMENT_EVENT_CONFLICT` | 事件、金额、订单状态或交易号冲突 | 停止重放，人工核对订单 |
| `RECHARGE_ALLOCATION_FAILED` | 支付已记录但本地分配失败 | 查看管理员订单并重试 |
| `VIDEO_TASK_NOT_FOUND` | 任务不存在或不属于当前代理用户 | 不得轮询其他用户任务 |
| `VIDEO_TASK_ID_MISSING` | 主站创建成功响应缺少可追踪任务 ID | 保持原 settlement pending，人工检查主站响应 |
| `VIDEO_TASK_TRACKING_FAILED` | 主站已创建任务但本地归属持久化失败 | 使用响应中的 `task_id` 人工恢复，不要重复创建 |
| `IMAGE_TASK_NOT_FOUND` | 图片任务不存在或不属于当前代理用户 | 不得轮询其他用户任务 |
| `IMAGE_TASK_ID_MISSING` | 主站已接受图片任务但响应缺少任务 ID | 原 settlement 保持 pending，检查主站；不要重复创建 |
| `IMAGE_TASK_TRACKING_FAILED` | 主站已接受图片任务但本地归属持久化失败 | 原 settlement 保持 pending，使用接受响应人工恢复 |

## 7. 反向代理要求

Nginx 必须把原始 Host 传给 AgentAPI，并禁止把管理端环境变量写入前端资源、访问日志或错误响应。建议至少设置：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Request-ID $request_id;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_read_timeout 120s;
```

AgentAPI 当前按单实例配置运行；多代理部署应使用多个容器和多个 SQLite 数据卷，不能让不同 Agent 共享同一个数据库文件。

## 8. 充值订单与支付回调

### 8.1 用户订单

```http
GET  /api/v1/agent/recharge/orders
POST /api/v1/agent/recharge/orders
Cookie: agentapi_session=<HttpOnly>
Idempotency-Key: recharge-request-001
```

`GET` 只返回当前 Session 映射的 `main_user_id` 的订单。`POST` 请求体只提交 `amount`（例如 `"10.00"`）或 `amount_cents`，`agent_id`、`main_user_id`、`provider`、`currency` 均由服务端确定。支付关闭时返回 `410 PAYMENT_DISABLED`。创建成功返回 `201`，相同幂等键重试返回原订单而不会重复创建。

### 8.2 管理员订单与分配

```http
GET  /api/v1/agent/admin/recharge/orders
POST /api/v1/agent/admin/recharge/allocate
Cookie: agentapi_session=<HttpOnly>
Content-Type: application/json
```

管理员请求体：

```json
{"order_no":"ord_xxx"}
```

只有 `paid_pending_allocation` 订单可以分配。接口先同步 Owner 主站余额，再在 SQLite 事务中同时写入 `user_allocate`、`agent_allocate` 两条流水并把订单置为 `allocated`；余额不足返回 `402 MAIN_OWNER_BALANCE_INSUFFICIENT`。

### 8.3 支付供应商 webhook

```http
POST /api/v1/payments/webhook
X-Agent-Payment-Event-ID: evt_xxx
X-Agent-Payment-Signature: sha256=<hex HMAC-SHA256>
X-Agent-Payment-Timestamp: 1720000000
Content-Type: application/json
```

webhook 不读取 Cookie，先限制请求体大小、校验可选时间戳和原始 body HMAC，再校验订单金额、币种、供应商和状态。支付事件写入 `payment_events` 后才尝试 Owner 余额同步与分配。主站暂时不可用或额度不足时返回 `202`，订单保持 `paid_pending_allocation`，后续可由管理员接口重试。重复事件返回原订单并标记 `duplicate`，不会再次写余额流水。

当前 webhook 是 provider-neutral 适配层；真实供应商 SDK、渠道专属签名、退款、拒付和主站充值自动入账尚未实现。`AGENT_PAYMENT_ENABLED` 默认 `false`，上线前必须完成供应商适配和专项验收。

### 8.4 视频异步任务

`POST /v1/videos` 成功后，AgentAPI 从主站响应的 `id`、`request_id`、`task_id` 或 `video_id` 保存任务归属及原始账务 `request_id`（两者可能不同）。状态轮询中的 `done`、`completed`、`succeeded`、`success` 等均视为终态。`GET /v1/videos/{id}` 必须继续使用创建任务的同一 Agent 用户 Session 或 `sk-agent-*`；其他用户统一得到 `404 VIDEO_TASK_NOT_FOUND`，请求不会到达主站。

轮询不会创建新的本地预授权，只按主站权威 usage 对原始 settlement 结算。失败任务在 usage 查询确认无记录时释放原预授权；发现费用时按实际 usage 结算，usage 超过预留、尚不可见、查询失败或旧版主站没有 usage API 时保持 pending。异步任务不会用轮询时的 Owner 余额差额推测费用。后台 reconciler 会在任务年龄超过 `AGENT_VIDEO_TASK_RECONCILE_AGE` 后探测；只要原 settlement 仍 pending，即使主站已报告终态也会继续探测/对账，默认年龄为 30 分钟。

如果创建响应本身已经带有终态或视频结果，浏览器控制台仍会通过 AgentAPI 的同源视频任务轮询路由至少读取一次当前任务，使主站终态和原始 settlement 再经过服务端校验；不会重复创建视频。

### 8.5 异步图片任务

支持 Sub2API 的显式异步图片端点：

```http
POST /v1/images/generations/async
POST /v1/images/edits/async
GET  /v1/images/tasks/{task_id}
```

提交体沿用公开图片模型和对应同步 generation/edit 契约。AgentAPI 先进行和其他模型请求相同的公开模型 allowlist 校验、Owner 余额同步及用户额度预授权；收到 Sub2API 任务 ID 后，将 `agent_id + main_user_id + task_id + 原 request_id` 持久化。成功创建返回主站接受状态和任务响应；如果主站已接受但未返回任务 ID，或本地任务映射持久化失败，原 settlement 保持 pending，不得重复创建。

轮询由 AgentAPI 同源路由代理到 Sub2API，并强制使用创建任务的同一 Agent Session/API Key 身份；其他用户统一得到 `404 IMAGE_TASK_NOT_FOUND`，主站不会收到该跨用户轮询。轮询更新原任务状态，不创建第二笔预授权；按主站 runtime usage 对原 request ID 结算。明确失败且 usage API 确认没有 usage 时释放，发现部分费用则按实际 usage 结算，usage 超过预留或查询不确定时保持 pending。

后台 `AGENT_IMAGE_TASK_RECONCILE_AGE`（默认 30 分钟）控制长期无人轮询任务的探测；后台从 Sub2API 图片任务端点刷新状态，再以管理/runtime usage 接口核验费用。旧版没有权威 usage API、主站暂不可用、任务状态无法读取或 usage 尚不可见时不会猜测退款，settlement 留在 pending 供后续重试/人工对账。AgentAPI 只存任务归属与状态，不下载或复制主站图片结果。

如果图片创建响应本身已经带有终态，浏览器控制台仍会通过 AgentAPI 的同源图片任务轮询路由至少读取一次当前任务，使主站终态和原始 settlement 再经过服务端校验；不会重复提交 generation/edit 请求。

## 9. 审计事件

```http
GET /api/v1/agent/admin/audit-events?limit=100
Cookie: agentapi_session=<HttpOnly>
```

仅 Agent Owner 可以查询，`limit` 范围为 `1..500`。当前记录品牌修改、Owner 余额同步、用户额度分配、充值订单分配、pending settlement 对账以及 AgentAPI Key 创建/吊销。每条事件包含 `actor_type`、`actor_id`、`agent_id`、`operation`、目标、`request_id`、结果和时间；不会写入管理员 Key、支付密钥、Cookie、密码、完整 Authorization 或客户端 Key 明文。
