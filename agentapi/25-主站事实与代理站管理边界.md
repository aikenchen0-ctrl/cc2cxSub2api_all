# 主站事实与代理站管理边界

更新：2026-09-30。本文明确当前 user_upstream 模式；旧 Owner 桥接文档不再是该模式的实现依据。

## 明确排除的主站模块

AgentAPI 是代理站，不是 Sub2API 管理后台。当前版本不提供分组管理、账号管理、代理管理、兑换码管理、插件管理、安全审计（风险控制与提示词审计）和上游核验。上述模块不得通过隐藏菜单、只读镜像或代理主站管理员接口的方式重新引入；相关路由和服务端端点应返回未找到。普通用户自己的兑换入口保留，它只代表当前用户按主站协议使用兑换码，不包含兑换码发行、枚举或管理能力。

## 唯一上游

客户端 → AgentAPI URL + AgentAPI Key → AgentAPI 验证 Key 所属用户与本站状态 → 服务端按该用户身份调用 Sub2API → Sub2API 调模型、计费和保存用量 → AgentAPI 按请求 ID 读取主站记录，保存只读副本。

AgentAPI 不连接模型供应商，不建立独立收费账本，不以站长余额代付用户请求。本站调用日志可以先记录请求的 pending 状态，但这只是跟踪状态，不是提前生成账单。confirmed 表示已同步主站用量，不是代理站执行了扣费。

## 注册与归属

服务端使用部署者提供的 `SUB2API_ADMIN_API_KEY`（或 `_FILE`）调用现有 `POST /api/v1/admin/users`。只允许创建 role=user、初始余额为零的普通用户，不转发注册请求中的角色、余额、分组或其他管理字段。

主站创建成功后，本站存储 agent_id + main_user_id 的归属，再通过主站登录建立三天本地 Session。主站创建失败不建立本地用户；本地归属写入失败时返回明确错误并记录修复审计，不删除主站账号。归属已落库但登录失败时，用户可直接登录重试。

管理员密钥只由可信部署者保管，不进入站长 UI、不作为模型凭证、不提供任意主站管理路由代理。能控制服务器或密钥文件的人仍可取得该密钥：若要让不可信站长自行托管进程，必须改为主站提供最小权限注册凭据，不能交付全站管理员 Key。

## 本站管理

站长可管理本站用户访问状态、品牌、模型白名单以及本站用户的代理 Key。Key 管理支持列表、创建和撤销；服务端先校验站长身份与本站归属。普通用户仍只管理自己的 Key。代理 Key 仅首次显示，数据库存哈希，不将原 Key 转发到主站。本站“操作日志”用于记录代理站管理行为，不等同于主站安全审计模块。

外部 API 客户端用代理 Key 确认用户身份；浏览器管理操作仍要求 HttpOnly Session。随后复用现有卫星服务端请求头，不创造新的 SSO 或主站 Key 传递协议。

## 费用同步

- 主站真实费用不受代理旧版预留值限制，包括普通、流式、图片、视频及后台核对路径。
- user_upstream 不再用余额差值作为单次请求已确认账单；未查到主站明细保持待同步。
- 主站成功响应不因本地费用同步失败被改写为失败；保留日志并由后台继续核对。
- 新 user_upstream 请求的 Idempotency-Key 按 agent_id + user_id 做命名空间隔离；未提供该头时，客户端 X-Request-ID 也使用同样的隔离规则。同一用户重试不会重复转发，不同用户使用相同标识不会互相阻塞。原始旧记录仍执行归属校验后的兼容查询。
- 模型请求的 Idempotency-Key 与 X-Request-ID 去除首尾空白后均不得超过 128 字节；超长返回 400，不静默替换为随机标识或继续访问主站。

## 升级和未完成事项

旧请求使用原始 Idempotency-Key，新请求使用隔离后的请求 ID。新版本在转发前会兼容查询旧请求：仅当旧记录属于当前认证用户时返回重试状态，不再次调用主站；其他用户的旧键不阻塞当前用户的新命名空间。旧记录不改名，保留主站用量和异步任务引用。已覆盖旧 pending、confirmed 状态的升级重试测试。此保护要求保留原数据库；部署切换仍需停止旧版本接收请求，避免新旧进程同时使用不同规则。旧客户端未提供稳定重试键、已删除历史记录或更换数据库的情况无法据此防止重复提交。

已增加持久化注册限流：每小时每邮箱 5 次、每直接连接 IP 20 次、每站 200 次；不信任外部传入的 X-Forwarded-For。反向代理部署还需在可信入口按真实客户端 IP 限流，避免所有用户共用代理 IP 配额。

注册前持久化随机归属标记，并写入主站管理员专用 notes。主站建号后响应丢失或本地映射失败时，用户成功登录主站后，服务端核验 notes 与预存标记一致、主站 ID 一致且为普通用户，才能恢复本站归属；绝不只凭邮箱或密码冒领其他站用户。数据库完全丢失或主站备注被覆盖时不能自动恢复，需要人工核对。此前版本没有标记的注册失败也不自动认领。

仍需真实主站联调、浏览器验收及更完整的入口防滥用策略。没有管理员密钥时注册关闭，其他已关联用户的调用不依赖该密钥。自动化测试通过不等于已经部署或完成生产验收。
