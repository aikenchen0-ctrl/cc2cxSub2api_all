# 12 测试与验收清单



## 1. 开站验收

- [x] 部署包生成器使用同一个幂等键重放时只返回原 Agent；
- [x] 部署包生成器拒绝 slug 和域名冲突；
- [ ] 域名未就绪时 Agent 不进入 `active`；
- [ ] 健康检查不会产生真实模型扣费；
- [ ] 开站失败可以从失败步骤重试；
- [x] 部署包只引用外部服务凭据文件，管理员 Key、应用凭据和 SSO Secret 不写入生成文件；
- [ ] 暂停和撤销后入口行为符合状态机。



## 2. 用户隔离验收

准备至少两个代理、每个代理两个用户：

- [ ] 用户 A 只能看到自己 Agent 的数据；
- [ ] 用户 A 不能通过修改 `agent_id` 查看用户 B；
- [ ] 代理 1 管理员不能读取代理 2 用户；
- [ ] 同一个主站用户不能在第一版绑定两个代理；
- [ ] 主站用户创建失败时不产生半成品映射；
- [ ] 映射保存失败时重试不会重复创建主站用户。



## 3. 认证和凭据验收

- [ ] 浏览器网络、URL、localStorage 和页面源码没有管理员 Key；
- [ ] 浏览器没有 SuperKey、主站 JWT 或用户 API Key；
- [ ] 没有有效 Session 时返回 401；
- [ ] 缺少 `X-Sub2API-On-Behalf-Of` 时主站拒绝请求；
- [ ] AgentAPI 不会回退到共享 `.env` Key 或默认用户；
- [ ] 服务凭据可以单独轮换和撤销；
- [ ] 日志不会写完整 Authorization、Cookie 或支付密钥。
- [x] Agent 管理员可修改名称和 Logo，普通重启不会覆盖已保存品牌；
- [x] 品牌更新和额度分配的 Cookie 请求拒绝外部 Origin。



## 4. 充值和额度验收

- [ ] 重复支付回调只入账一次；
- [ ] 金额、币种、商户号和订单状态全部校验；
- [ ] 未验证支付不会增加余额；
- [ ] 代理预存额度不足时不能分配用户子余额；
- [ ] 用户子余额不能为负；
- [ ] 用户子余额汇总不超过代理可用额度；
- [ ] 退款产生反向流水而不是修改原流水；
- [ ] 订单和钱包流水可以通过 order_id 对账。



## 5. 模型请求验收

- [ ] 文本请求使用公开模型名 `gpt-5.5`；
- [ ] 图片请求使用公开模型名 `gpt-image-2`；
- [x] 视频请求使用公开模型名 `grok-imagine-video-1.5`；
- [ ] 服务端发送 `SUB2API_APP_CREDENTIAL`、`X-Sub2API-On-Behalf-Of`、`X-Sub2API-Satellite`；
- [ ] 浏览器不发送上述服务端凭据；
- [ ] 余额不足时不调用上游；
- [ ] 主站错误不会被伪装成成功扣费；
- [ ] 主站计费身份由服务端固定，客户端不能提交或覆盖；
- [ ] 一次模型请求不会同时扣代理用户主站余额和代理管理员主站余额；
- [ ] 本地预授权与主站 `usage_id`/余额差额可以一一对账；
- [ ] 主站成功但结算查询超时时进入 `settlement_pending`，不会静默退款；
- [x] 显式文本流式请求在 EOF 后结算，断流进入 pending；
- [x] 视频创建任务会保存用户归属，跨用户不能轮询，完成/失败轮询结算或释放原始冻结余额；
- [ ] 图片及其它未知异步任务均能释放或结算冻结余额；
- [ ] 同一个 request_id 重试不会重复扣费。

参考实现额外自动化覆盖：

- [x] Cookie Session 和 `sk-agent-*` 两种身份都能调用模型；
- [x] AgentAPI Key 创建只返回一次明文，列表不返回明文；
- [x] 吊销 AgentAPI Key 后模型请求返回 401；
- [x] AgentAPI Key 不会被转发为上游 `Authorization`；
- [x] 上游 `Set-Cookie` 不会复制到客户端；
- [x] 本地钱包消费和重复冲正具备幂等；
- [x] 幂等键不能跨用户或跨金额复用；
- [x] 外部 Origin 的带凭据预检被拒绝；
- [x] 外部 Origin 的管理员额度分配和品牌更新被拒绝；
- [x] `/api/v1/keys` 主站用户 Key 代理入口被拒绝；
- [x] `/healthz` 和 `/readyz` 的基础行为有测试覆盖。
- [x] 审计事件按 `agent_id` 隔离并按新到旧查询，不保存密钥或完整请求头。

充值桥接专项（provider-neutral）：

- [x] 支付默认关闭时，用户创建订单和 webhook 都不会改变钱包；
- [x] 创建订单只能使用 Session 的 `main_user_id`，不能由请求体覆盖 `agent_id`、用户、供应商或币种；
- [x] webhook 必须校验 `X-Agent-Payment-Event-ID` 和原始 body HMAC；
- [x] 金额、币种、订单状态和供应商不匹配时拒绝事件；
- [x] 同一事件重复回调只返回原订单，不重复写入 `user_allocate`/`agent_allocate`；
- [x] 已支付但主站不可用或 Owner 额度不足时保持 `paid_pending_allocation`，返回可重试的 `202`；
- [x] Owner 余额同步成功后，订单分配与两条钱包流水在同一事务中完成；
- [ ] 真实支付供应商 SDK、退款、拒付和主站自动入账（下一阶段，未纳入当前绿灯）。

当前实现对普通 JSON/上传请求进行完整缓冲，以便完成失败处理和余额差额结算；显式文本流式请求会边转发边等待 EOF，断开时保留 pending。视频任务已实现创建归属、受控轮询、原 settlement 结算和后台超龄探测；生产仍需根据实际视频供应商 SLA 调整超龄阈值。

### 5.1 AgentAPI 默认自动化验收

以下命令针对当前 AgentAPI 活跃入口执行，已在 2026-09-22 通过：

```bash
cd agentapi/backend
go test -count=1 ./...
go vet ./...

cd ../frontend
pnpm run typecheck
pnpm run build
pnpm run lint:check
pnpm run test:run
```

`test:run` 扫描当前 `frontend/src` 中保留的全部测试，覆盖 Cookie-only 身份、未登录/非管理员路由保护、公开模型请求、管理员 pending settlement 对账和 AgentAPI Key 一次性展示。未被生产入口引用的旧 Sub2API 管理页面、测试与依赖已从 AgentAPI 物理删除，不存在额外的“legacy 测试”旁路。

账务桥接专项验收和方案 A/B 的选择见 [17-账务权威与主站扣费桥接](17-账务权威与主站扣费桥接.md)。未完成该文档中的拍板记录，不得将 Agent 状态切换为可真实消费的 `active`。



## 6. 直连和绕过验收

- [ ] 用户无法凭 AgentAPI Session 访问另一个代理；
- [ ] 用户无法通过主站域名绕过代理额度；
- [ ] 如果开放主站 API Key，Key 带有 agent 归属并受主站额度校验；
- [ ] 任意伪造 Host、Forwarded Host 或 agent_id 都不能扩大权限；
- [ ] 代理暂停时所有新模型请求被阻断。



## 7. 部署验收

- [ ] Docker 镜像不包含环境秘密；
- [ ] Agent 域名 DNS、TLS、入口和应用 Host 映射一致；
- [ ] `healthz` 和 `readyz` 行为符合文档；
- [ ] 主站短暂不可用后 AgentAPI 可以恢复；
- [ ] 数据库备份可以恢复映射、订单和状态；
- [ ] 监控能按 agent_id、request_id、order_id 查询链路。



## 8. 公共层验收

如果 AgentAPI 作为卫星项目接入主站菜单，还必须验证：

- [ ] 使用现有 HMAC SSO 启动和回调；
- [ ] Session/JWT/Cookie 生命周期为 3 天；
- [ ] SSO ticket 只包含身份，不包含明文 Key；
- [ ] `X-Sub2API-Satellite` 使用已注册 slug；
- [ ] 不新增另一套 SSO 或 API Key 传递协议；
- [ ] `LINK` 和 `{slug}_link` 语义符合公共文档。
