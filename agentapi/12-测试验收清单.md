# 12 测试与验收清单



## 1. 开站验收

- [x] 部署包生成器使用同一个幂等键重放时只返回原 Agent；
- [x] 部署包生成器拒绝 slug 和域名冲突；
- [x] 主站开站 API 以管理员身份 + 幂等键创建 `pending` 记录，相同键重放返回原记录；
- [x] 主站开站 API 拒绝不同请求复用幂等键；
- [x] 主站撤销接口要求路径 Agent ID 与显式确认值相同；
- [x] 主站激活接口要求匹配的 Agent ID 与 `readiness_confirmed=true`；
- [x] AgentAPI 对 pending/suspended/revoked、控制状态未知和过期快照拒绝业务请求；
- [x] `agt_*` 托管 Agent 即使显式配置 `AGENT_PROVISIONING_CONTROL_ENABLED=false` 也会拒绝启动，不能绕过主站暂停/撤销门控；
- [x] AgentAPI 的 `/healthz`、`/readyz` 在控制状态非 active 时仍可探测；
- [x] AgentAPI 运行时只把 Agent Runtime 状态 SSE 当刷新提示，并通过状态 GET 更新本地快照；
- [x] worker provisioning credential 只能读取 pending/provisioning 列表、SSE、Agent 状态、上报 progress 和 activate；
- [x] worker credential 不能创建、暂停、恢复、撤销、重试或访问其他 Admin API；审计上下文标记为 `agent_provisioning_worker`；
- [x] provisioning SSE 事件只包含 `agent_id`，消费者通过 GET 刷新权威记录；
- [x] claim/lease worker 凭据权限受 allowlist 限制；claim 响应禁止缓存，主站只持久化 token hash；
- [x] 已占用租约阻止第二 worker 认领，过期租约可接管，续租只接受仍有效的原 token；
- [x] 无租约、过期租约或失租 token 不能上报部署进度或激活；失败/激活会释放租约，进度更新会续租；
- [x] worker 测试覆盖失租后取消部署 context，并停止后续控制面写入；
- [x] worker 的 DNS、TLS 或 `/readyz` 检查失败时 Agent 保持可重试 `failed`，不会调用激活接口；
- [x] `/healthz` 与 `/readyz` 只检查本地进程/配置，不会访问 Sub2API 模型网关或产生模型扣费；
- [x] 模型 relay 地址支持 Docker 内部 `SUB2API_RELAY_BASE_URL`，不覆盖管理 API 的 `MAIN_API_URL`，未配置时保留 `MAIN_MODEL_URL` / `LINK` 回退顺序；
- [x] worker 部署 bundle 校验真实路径并拒绝 state 目录外符号链接；元数据与 Nginx 配置原子写入不复用固定临时路径；
- [x] AgentAPI `/v1` 使用当前 Session 主站用户身份；Sub2API 校验其 active Agent 映射后仍只以 Agent Owner SuperKey 计费；
- [x] 托管 Nginx 入口允许 AgentAPI 32 MiB 模型请求，并透传流式响应与状态 SSE，不启用请求/响应缓冲；
- [x] 自动化验证开站失败保留失败步骤、管理员重试后从该步骤恢复；旧 `current_step=failed` 记录兼容地从 `queued` 重启；
- [ ] 生产 edge 上真实开站失败与重试端到端演练；
- [x] 部署包只引用外部服务凭据文件，管理员 Key、应用凭据和 SSO Secret 不写入生成文件；
- [ ] 暂停和撤销后入口行为符合状态机。
- [ ] 主站管理员 suspend/resume/revoke 到已部署实例的端到端验证与恢复演练。



## 2. 用户隔离验收

准备至少两个代理、每个代理两个用户：

- [ ] 用户 A 只能看到自己 Agent 的数据；
- [ ] 用户 A 不能通过修改 `agent_id` 查看用户 B；
- [ ] 代理 1 管理员不能读取代理 2 用户；
- [ ] 同一个主站用户不能在第一版绑定两个代理；
- [x] Sub2API 运行时映射表对 `main_user_id` 使用全局唯一约束：同 Agent 重复绑定幂等，跨 Agent 绑定冲突；
- [x] Sub2API 主站注册失败时不会创建本地 Agent 用户映射，也不会签发本地 Session；
- [x] 主站注册成功但 Agent 映射暂时失败时不签发 Session；用户重新登录可重试映射，不重复创建主站账号。



## 3. 认证和凭据验收

- [ ] 浏览器网络、URL、localStorage 和页面源码没有管理员 Key；
- [ ] 浏览器没有 SuperKey、主站 JWT 或用户 API Key；
- [ ] 没有有效 Session 时返回 401；
- [ ] 缺少 `X-Sub2API-On-Behalf-Of` 时主站拒绝请求；
- [ ] AgentAPI 不会回退到共享 `.env` Key 或默认用户；
- [ ] 服务凭据可以单独轮换和撤销；
- [ ] 日志不会写完整 Authorization、Cookie 或支付密钥。
- [x] 主站 runtime control、用户身份票据和模型 relay 请求不会跟随重定向把凭据或用户范围头转发到目标地址；
- [x] Agent 管理员可修改名称和 Logo，普通重启不会覆盖已保存品牌；
- [x] 品牌更新和额度分配的 Cookie 请求拒绝外部 Origin。



## 4. 充值和额度验收

- [ ] 重复支付回调只入账一次；
- [ ] 金额、币种、商户号和订单状态全部校验；
- [ ] 未验证支付不会增加余额；
- [ ] 代理预存额度不足时不能分配用户子余额；
- [ ] 用户子余额不能为负；
- [ ] 用户子余额汇总不超过代理可用额度；
- [ ] 退款产生反向流水而不是修改原流水；
- [ ] 订单和钱包流水可以通过 order_id 对账。



## 5. 模型请求验收

- [ ] 文本请求使用公开模型名 `gpt-5.5`；
- [ ] 图片请求使用公开模型名 `gpt-image-2`；
- [x] Agent 管理员只能从卫星公开目录配置模型 allowlist；禁用模型从 `/v1/models` 隐藏，JSON/multipart 请求在预授权和主站调用前拒绝；
- [x] 并发模型策略更新与 Sub2API 同步/失败回滚串行化，较早失败的请求不能覆盖较新已确认策略；
- [x] 视频请求使用公开模型名 `grok-imagine-video-1.5`；
- [ ] 服务端发送 `SUB2API_APP_CREDENTIAL`、`X-Sub2API-On-Behalf-Of`、`X-Sub2API-Satellite`；
- [ ] 浏览器不发送上述服务端凭据；
- [ ] 余额不足时不调用上游；
- [ ] 主站错误不会被伪装成成功扣费；
- [ ] 主站计费身份由服务端固定，客户端不能提交或覆盖；
- [ ] 一次模型请求不会同时扣代理用户主站余额和代理管理员主站余额；
- [ ] 本地预授权与主站 `usage_id`/余额差额可以一一对账；
- [ ] 主站成功但结算查询超时时进入 `settlement_pending`，不会静默退款；
- [x] 显式文本流式请求在 EOF 后结算，断流进入 pending；
- [x] 视频创建任务会保存用户归属，跨用户不能轮询；完成/失败轮询结算原始冻结，超龄失败任务须按主站 usage 结算、确认无记录才释放；
- [x] Agent 管理员可分页查看本 Agent 全部 usage，普通用户只能查看自己的记录；分页总数、页码与每页条数一致；
- [x] 用户首页从 Agent 上下文读取当前用户余额，与 user-scoped 最近五条 usage 并行加载；usage 故障不遮蔽余额和站点信息，连续刷新时旧响应不会覆盖新结果；
- [x] Agent 管理控制台各数据面板独立加载，单面板故障不隐藏其他数据，并避免较慢的旧刷新覆盖新数据；
- [x] Agent 管理员用户列表使用 Agent-scoped 服务端分页，不受旧 500 条上限静默截断；普通用户仍只能读取自己的映射记录；
- [x] Agent 管理员用户搜索按本 Agent 的 Sub2API 用户 ID、邮箱或显示名过滤，并在搜索时重置分页；非管理员传入搜索参数不能读取其他用户；
- [x] 显式异步图片 generation/edit 任务保存用户归属与原 request_id；跨用户轮询被拒绝，完成时按 Sub2API usage 结算，明确失败且无 usage 时释放；
- [x] 超龄未轮询视频和图片任务由后台探测；失败任务先查权威 usage，有部分费用则按实结算、确认无 usage 才释放、usage 查询不可用或失败则保持 pending；
- [x] 异步图片任务缺少 task ID 或本地归属写入冲突时保持原 settlement pending，同 request 重试不会再次创建任务；
- [x] 媒体任务历史分页仅返回当前 Session 用户的 Agent-scoped 图片/视频任务；刷新后可从列表恢复原任务轮询，不会重新提交生成请求；接口响应禁止缓存；
- [x] 图片/视频创建响应若已返回终态，浏览器控制台仍通过同源任务路由至少核验一次原任务状态与 settlement，不会因直接消费创建响应而跳过服务端轮询结算；
- [x] 同一个 request_id 重试不会再次调用 Sub2API；视频和异步图片的用户隔离与原结算均有专项测试；
- [x] 未纳入显式 AgentAPI 图片/视频任务契约的其他未知异步端点仍被白名单拒绝，不能创建无归属的本地冻结。

充值桥接专项（provider-neutral）：

- [ ] 真实支付供应商 SDK、退款、拒付和主站自动入账（下一阶段，未纳入当前绿灯）。

### 5.1 AgentAPI 默认自动化验收

以下命令针对当前 AgentAPI 活跃入口执行，已在 2026-09-24 通过：

```bash
cd agentapi/backend
go test -count=1 ./...
go vet ./...

cd ../frontend
pnpm run typecheck
pnpm run build
pnpm run lint:check
pnpm run test:run
```

`go test ./...`、`go vet ./...` 与前端检查覆盖 Agent 用户状态门控和主站失败 fail-closed、公开模型 allowlist、usage 服务端分页/用户隔离及白名单快照、Cookie-only 身份、管理员路由保护、pending settlement 对账、AgentAPI Key 一次性展示。未被生产入口引用的旧 Sub2API 管理页面、测试与依赖已从 AgentAPI 物理删除，不存在额外的“legacy 测试”旁路。

账务桥接专项验收和方案 A/B 的选择见 [17-账务权威与主站扣费桥接](17-账务权威与主站扣费桥接.md)。未完成该文档中的拍板记录，不得将 Agent 状态切换为可真实消费的 `active`。



## 6. 直连和绕过验收

- [ ] 用户无法凭 AgentAPI Session 访问另一个代理；
- [ ] 用户无法通过主站域名绕过代理额度；

## 8. 公共层验收

如果 AgentAPI 作为卫星项目接入主站菜单，还必须验证：

- [ ] 使用现有 HMAC SSO 启动和回调；
- [ ] Session/JWT/Cookie 生命周期为 3 天；
- [ ] SSO ticket 只包含身份，不包含明文 Key；
- [x] 配置拒绝未注册的 `SUB2API_SATELLITE` 或与注册表不匹配的 `AGENTAPI_SSO_AUDIENCE`，模型头与 HMAC SSO 均固定到已注册的 `agentapi` 身份；
- [ ] 不新增另一套 SSO 或 API Key 传递协议；
- [ ] `LINK` 和 `{slug}_link` 语义符合公共文档。
