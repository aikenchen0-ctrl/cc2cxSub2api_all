# 19 上线与运维手册

## 1. 生产上线顺序

```text
主站管理员创建 pending Agent 记录
  → 保留响应中的 `agt_<uuid>` / slug / domain / Owner ID
  → 为该 Owner 准备模型分组和余额
  → 使用返回的 Agent ID 生成独立实例配置
  → 部署 SQLite 持久卷和 Docker 容器
  → 配置 DNS/Nginx/TLS
  → GET /healthz
  → GET /readyz
  → 在主站将已就绪记录切换为 active
  → 创建一个内部测试用户
  → 同步 Owner 钱包并分配小额额度
  → 发送一条公开模型请求
  → 验证主站 usage 与 Agent settlement 一一对应
  → 才允许代理公开注册
```

首次上线建议把 `AGENT_DOMAIN`、`AGENT_OWNER_MAIN_USER_ID`、逐站 `AGENT_RUNTIME_CONTROL_CREDENTIAL`、逐站 `SUB2API_APP_CREDENTIAL`（`agt_model_`）和 `SUB2API_SSO_SECRET` 配好后重启一次。托管实例缺少 runtime control/model 或会话加密凭据时不会就绪；Agent 未处于 `active` 时也不会接受业务请求。

上面的顺序是人工逐站部署路径。自动开站必须先在受控 edge 运维节点单独安装并配置 `agentapi-provision-worker`：主站管理员只创建 pending 记录，worker 通过 GET/claim 获取权威任务和租约，再生成实例配置、部署 Compose/Nginx、检查 DNS/TLS/healthz/readyz，并持租约显式激活。当前代码和租约单测通过不等于生产自动化已启用；在 edge 节点安装、凭据/Secret 配置及真实环境验收前，仍须按人工流程完成并由主站管理员确认就绪。worker 参数和租约边界见 [04-一键开分站流程](04-一键开分站流程.md)。

完成镜像启动、正确域名路由和 `/readyz` 检查后，由主站管理员 UI 执行“确认就绪并激活”，或调用下面的幂等接口。该接口要求操作者显式确认 readiness；当前不是自动健康探测，也不替代部署 worker：

```http
POST /api/v1/agent-provisioning/agents/{agent_id}/activate
Idempotency-Key: activate-<unique-key>
Content-Type: application/json

{"confirm_agent_id":"agt_<same-id>","readiness_confirmed":true}
```

## 2. 配置原则

### 2.1 必填服务端秘密

| 变量 | 作用 | 轮换方式 |
| --- | --- | --- |
| `AGENT_RUNTIME_CONTROL_CREDENTIAL` | 当前 Agent 的 Owner/usage/状态管理、已验证用户映射与状态提示 SSE | 主站逐 Agent 撤销/重新注册，更新外部 Secret 后滚动重启 Agent |
| `SUB2API_APP_CREDENTIAL` | 当前 Agent 的 `agt_model_` 模型/余额请求凭据 | 主站逐 Agent 撤销/重发并更新外部 Secret |
| `SUB2API_SSO_SECRET` | 验证 Sub2API 现有 HMAC SSO ticket | 主站与 AgentAPI 同步轮换，重启两端 |
| `SESSION_SECRET` | 加密 Agent Session 中的主站 token | 轮换会使旧 Session 失效，先通知用户 |

这些值只能通过 Docker Secret、编排平台 Secret 或受保护环境变量注入，不能放到 `frontend/.env`、镜像层、浏览器响应、URL 或日志。可使用 `AGENT_RUNTIME_CONTROL_CREDENTIAL_FILE`、`SUB2API_APP_CREDENTIAL_FILE`、`SUB2API_SSO_SECRET_FILE`、`SESSION_SECRET_FILE` 指向挂载的 Secret 文件；生产环境必须显式设置 `COOKIE_SECURE=true`。

AgentAPI 运行实例不使用 `SUB2API_ADMIN_KEY`。这里的 `AGENT_PROVISIONING_WORKER_CREDENTIAL_FILE` 是开站 worker 的共享、provisioning-only 凭据，不可用于业务运行时，也不具备逐 Agent Docker/Nginx 主机权限隔离；必须与 Agent runtime control/model 凭据分开存储。

### 2.2 每个实例独立的非秘密配置

```env
AGENT_ID=agt_<Sub2API 开站记录返回的 ID>
AGENT_DOMAIN=agent01.cc2.cx
AGENT_NAME=代理 01
AGENT_SITE_NAME=代理 01 API
AGENT_SITE_LOGO=/logo.svg
AGENT_BILLING_MODE=owner_upstream
AGENT_OWNER_MAIN_USER_ID=123
AGENT_ENABLED=true
AGENT_PROVISIONING_CONTROL_ENABLED=true
AGENT_PROVISIONING_CONTROL_STALE_AFTER=90s
AGENTAPI_DATABASE_PATH=/app/data/agentapi.db
MODEL_STREAM_TIMEOUT=10m
AGENTAPI_WRITE_TIMEOUT=10m
```

`AGENT_ID` 一经生产初始化不得复用给另一个实例；`AGENT_OWNER_MAIN_USER_ID` 更换前必须清空或人工核对本地 `available/allocated/pending`，代码会拒绝带有未结余额的 Owner 迁移。

## 3. Docker 与 Nginx

### 3.1 启动

```bash
cp backend/.env.example backend/.env
# 先用 Sub2API 创建开站记录，再把返回的 agent_id / domain / owner 写入 backend/.env。
# 配好生产 Secret 后再启动；pending 状态下业务请求会被门控拒绝，但探针正常。
docker compose up -d --build
docker compose logs -f agentapi
curl -fsS https://agent01.cc2.cx/healthz
curl -fsS https://agent01.cc2.cx/readyz
```

实际生产环境不要直接使用示例文件；复制为受保护的 `.env` 并替换所有 secret。SQLite 数据目录必须挂载持久卷，并纳入备份。

Compose 默认以非 root 用户运行，根文件系统只读，仅把 `/app/data` 作为可写卷；`/tmp` 使用受限 tmpfs，容器丢弃全部 Linux capabilities，并启用 `no-new-privileges`。不要为了方便把根文件系统改回可写或把整个宿主机目录挂载到容器内。

托管 Agent 的期望状态通过逐站 runtime SSE 接收 Sub2API 数据库提交通知并触发即时重读，`GET /api/v1/agent-runtime/agent` 返回权威状态；`AGENT_PROVISIONING_CONTROL_STALE_AFTER` 限制缓存时效（默认 90 秒），SSE 断线时周期 GET 仍会刷新。状态变更不可读或缓存过期时业务路由 fail closed。`/readyz` 只证明本地部署配置可用，不代表主站开站状态已 active。后台 pending settlement 对账由 `AGENT_SETTLEMENT_RECONCILE_INTERVAL` 和 `AGENT_SETTLEMENT_RECONCILE_BATCH` 控制。将 interval 设为 `0` 可以关闭自动对账，但仍保留管理员手动对账接口；生产关闭前必须安排外部定时任务或人工值守。

异步视频与图片任务还分别受 `AGENT_VIDEO_TASK_RECONCILE_AGE`、`AGENT_IMAGE_TASK_RECONCILE_AGE` 控制（默认均为 30 分钟）。监控 pending settlement 数量、最老年龄及任务探测错误；视频或图片任务失败不得只凭供应商状态退款，必须确认主站 usage 查询可用且没有同 request ID 的费用记录。查到部分费用时按主站实际费用结算；主站不可用、旧版 usage API 不可用、查询失败或费用超过预留时保持 pending，安排恢复后重跑对账。

生产开站自动化还需要单独部署 `agentapi-provision-worker`，不能仅因 AgentAPI/Sub2API 容器健康就认为 worker 已运行。worker 与主站通过共享 provisioning-only 凭据认证，按 90 秒租约/20 秒续租保护控制面任务；claim token 只保存在 worker 内存中。监控 worker 进程存活、主站 claim/lease 错误和最近开站任务进度；worker 日志不得出现 worker credential 或 lease token。租约不隔离 worker 的 Docker/Nginx 主机权限，edge 节点必须作为高权限运维主机加固。

### 3.2 Nginx 最小要求

```nginx
server {
    server_name agent01.cc2.cx;
    location / {
        proxy_pass http://agentapi:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Request-ID $request_id;
        proxy_http_version 1.1;
        proxy_read_timeout 120s;
    }
}
```

证书由平台统一签发或使用 ACME；AgentAPI 本身不负责证书申请。不要用客户端提交的 `X-Forwarded-Host` 参与安全判断。

## 4. 日常监控

至少监控以下指标：

- `/healthz` 非 200：进程、容器或网络故障；
- `/readyz` 非 200：凭据、Owner、账务模式或 Agent 状态故障；
- `billing_status=overallocated`：主站余额小于本地已分配额度；
- pending settlement 数量和最老 `updated_at`；
- provisioning worker 最近成功续租时间、claim 冲突/失租次数和 pending 任务积压；
- `AGENT_INSUFFICIENT_BALANCE`、`MAIN_OWNER_BALANCE_INSUFFICIENT` 的比例；
- 主站 usage 与 Agent settlement 按 `request_id` 的匹配率；
- SQLite 文件大小、WAL 文件大小和备份最近成功时间。

日志只允许记录 `agent_id`、`request_id`、状态和错误码。不得记录 Cookie、`sk-agent-*` 完整值、runtime control/model credential、SSO ticket/secret、主站 JWT、provisioning worker credential、租约 token 或模型请求中的敏感内容。

## 5. 对账操作

1. 代理管理员打开控制台，先执行 `POST /api/v1/agent/admin/wallet/sync`；
2. 查看 `GET /api/v1/agent/admin/settlements`，确认 pending 是否持续增长；
3. 执行 `POST /api/v1/agent/admin/settlements/reconcile`；
4. 用主站管理员界面或逐站 `GET /api/v1/agent-runtime/usage?request_id=...` 核对 `actual_cost`；
5. 对 `actual_cost > reserved_cents` 的记录暂停 Agent，人工确认主站余额和请求重试，不得直接本地退款；
6. 对账完成后再次同步 Owner 钱包，确认 `available + allocated + pending` 不超过主站快照余额。

对账接口找不到主站 usage 时保持 `pending`，这是故障安全行为。不要通过换一个新的 `request_id` 重放原模型请求，因为可能形成重复主站扣费。

## 6. 备份和恢复

### 6.1 备份

在低流量窗口执行 SQLite 在线备份，并同时保存当前镜像版本和环境变量清单（secret 只记录版本/引用，不记录明文）：

```bash
sqlite3 /data/agentapi.db ".backup '/backup/agentapi-$(date +%Y%m%d-%H%M%S).db'"
```

备份必须加密、异地保存并定期执行恢复演练。至少保留最近 30 天的数据库和审计日志。

### 6.2 恢复

1. 停止旧容器，确认恢复目标是同一个 `AGENT_ID`；
2. 恢复 SQLite 数据卷；
3. 保持原 `SESSION_SECRET`，否则现有 Session 全部失效；
4. 启动容器并检查 `/readyz`；
5. 先同步 Owner 余额，再处理 pending settlements；
6. 恢复期间关闭外部流量，完成一条小额模型验收后再放行。

## 7. 吊销和撤站

撤站不是删除数据库：

```text
停止公开入口 → Agent 标记 suspended/revoked
→ 吊销逐站 runtime control/model credential 与必要的 App Credential
→ 停止模型转发
→ 保留 settlement、wallet_ledger 和映射用于审计
→ 完成 pending 对账/人工结算
→ 归档 SQLite 和日志
```

撤站后不得复用原 `AGENT_ID` 或域名给另一个 Owner，除非完成完整数据隔离和审计归档。
