# 06 认证与安全

## 1. 威胁模型

需要重点防护的资产：

- 主站管理员 Key 和 Agent 服务凭据；
- 主站用户身份和余额；
- 代理预存额度；
- 支付渠道密钥和回调；
- 用户 Session；
- 模型请求和用量数据。

主要威胁：

1. 浏览器或前端包泄露管理员 Key；
2. 一个代理访问另一个代理的用户或额度；
3. 客户端伪造 `agent_id` 或 `main_user_id`；
4. 重放充值回调或重复消费；
5. 用户绕过 AgentAPI 直接使用主站；
6. 日志、错误页面或监控中泄露凭据；
7. 自定义域名或 Host 导致 SSRF/Host 注入；
8. 代理服务被入侵后扩大到整个主站。

## 2. 浏览器认证

AgentAPI 浏览器端只保存自己的 HttpOnly、Secure、SameSite Cookie。服务端 Session 至少记录：

```text
session_id
proxy_user_id
main_user_id
agent_id
created_at
expires_at
last_seen_at
```

Session 失效时返回 401，不得回退到共享用户、默认用户、`.env` SuperKey 或匿名调用。

如果 AgentAPI 接入 Sub2API 左侧菜单：

- 使用现有 `GET /api/v1/auth/integrations/:slug/start`；
- 回调使用现有 HMAC 票据；
- 票据只带身份，不带 Key；
- 本地 Session/JWT/Cookie 统一 3 天；
- 不新增第二套 SSO Handler。

## 3. 管理员 Key

管理员 Key 的硬性规则：

- 只存在服务端密钥管理系统或容器 Secret；
- 不写入前端构建产物、URL、Cookie、localStorage、数据库普通字段或业务日志；
- 代理用户和代理管理员都不能看到；
- 不用于每一次模型请求；
- 不通过通用反向代理暴露 `/api/v1/admin/*`；
- 设置最短可接受的轮换周期和泄露吊销流程。

客户端调用模型所需的 `sk-agent-*` 是另一类低权限 AgentAPI 本地 Key：只能代表创建它的映射用户调用 `/v1`，完整值只在创建响应中显示一次，数据库只保留哈希。它不能创建/吊销 Key，也不能调用主站管理接口。

服务端调用必须记录：`agent_id`、操作名、目标对象、request_id、结果和操作者。

## 4. 代理范围校验

每个请求必须按以下顺序检查：

```text
可信 Host → agent_id
HttpOnly Session → main_user_id
映射表 → main_user_id 是否属于 agent_id
主站状态 → 用户和 Agent 是否可用
资源归属 → 目标资源是否属于当前 Agent
```

当配置 `AGENT_DOMAIN` 时，应用层会再次校验公开 `Host`；除 `/healthz` 和 `/readyz` 外，未知 Host 返回 `421 HOST_NOT_ALLOWED`。入口层仍应保留 Host 并在 Nginx/Ingress 侧做第一层 allowlist。

客户端传入的 `agent_id`、`main_user_id`、`owner_id` 只能用于冲突检测，不能直接作为授权依据。

主站模型请求使用哪个身份也属于服务端授权结果：方案 A 固定为 `agent_owner_main_user_id`，方案 B 才是当前映射用户的 `main_user_id`。不能让客户端通过请求头选择计费账户，也不能因为本地已经扣款就绕过主站唯一扣费。

## 5. 主站直连防绕过

第一版建议代理用户不能拿到可自由调用主站的普通 API Key。模型请求由 AgentAPI 服务端代理，主站根据：

```text
X-Sub2API-On-Behalf-Of
X-Sub2API-Satellite
source_agent_id / agent_id 归属
```

识别用户和代理。

如果业务必须向用户提供主站 API Key，则必须：

- 为 Key 绑定 `agent_id`；
- 主站网关校验该 Key 的代理额度；
- 禁止使用其他代理的 Key；
- 记录直接调用来源；
- 明确主站直连是否计入代理用户余额；方案 A 默认禁止直连，避免用户绕过 AgentAPI 直接消耗或改变代理管理员的主站余额。

## 6. 服务凭据隔离

每个 Agent 至少应有独立的服务凭据引用：

```text
agent_id = agt_a → credential_a
agent_id = agt_b → credential_b
```

凭据 scope 应区分：

```text
agent:users:read
agent:users:write
agent:wallet:read
agent:wallet:allocate
agent:usage:read
model:relay
```

控制面凭据和模型代理凭据可以分开，便于单独吊销。

## 7. 支付回调安全

- 回调必须验证签名、商户身份、订单号、金额、币种和状态；
- 使用支付渠道事件 ID 做幂等；
- 订单必须校验所属 `agent_id` 和 `main_user_id`；
- 回调重复到达只能返回原处理结果；
- 退款和拒付必须产生反向流水；
- 不信任前端传入的支付成功参数；
- 支付密钥使用加密存储或密钥引用。

## 8. Cookie、CORS 和 CSRF

- Cookie 使用 `HttpOnly`、`Secure`、合适的 `SameSite`；
- 代理域名之间默认不共享 Cookie；
- 管理操作和充值接口启用 CSRF 防护或同等的来源校验；
- CORS 只允许当前 Agent 的合法前端 Origin；
- 不允许 `Access-Control-Allow-Origin: *` 搭配凭据。
- 响应统一设置 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY` 和 `Referrer-Policy: no-referrer`。

## 9. 日志和监控脱敏

禁止记录：

- 管理员 Key；
- SuperKey；
- 用户密码；
- 完整支付密钥；
- 完整 Authorization 头；
- 完整 Cookie；
- 充值二维码中的敏感参数。

允许记录：

- 脱敏后的 agent_id、main_user_id；
- request_id、order_id、usage_id；
- 操作类型、金额、状态和错误码。
