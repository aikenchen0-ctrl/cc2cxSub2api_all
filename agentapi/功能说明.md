# AgentAPI 功能说明

最后核对：2026-11-16。本文按当前源码整理，描述的是“现在实际能做什么、和 Sub2API 主站怎么连接”，不是目标规划。收费细节以 [收费模块.md](收费模块.md) 为准，已知缺口以 [优化任务.md](优化任务.md) 为准。

## 1. 定位与边界

AgentAPI 是 Sub2API 的共享多租户代理站。一个进程、一套前端、一套 SQLite 数据库承载所有站长；开站只创建 `agent_shared_tenants` 记录，不创建独立容器、数据库或端口。所有业务表都带 `agent_id`，租户边界由服务端签发的 Session、Host 映射和 Agent Key 共同决定。

职责划分：

| 能力 | Sub2API 主站 | AgentAPI |
| --- | --- | --- |
| 真实用户、密码、邮箱、第三方登录 | 负责 | 只做代理入口 |
| 主站余额、充值、订单、退款、订阅 | 负责 | 通过服务端凭据读取或发起 |
| 模型目录、上游账号、路由、真实计费 | 负责 | 只接受公开模型并转发 |
| 代理站租户、成员关系 | 保存可信租户事实 | 保存本站用户映射和会话 |
| 本站支付渠道、本站钱包 | 不保存本站钱包 | 保存并按租户隔离 |
| 本站公告、品牌、首页、API Key | 不保存 | 负责 |

AgentAPI 明确不提供：模型广场、模型工作台、模型策略、渠道/上游管理、分组管理、账号管理、代理管理、运营监控、优惠码管理、订阅管理、内容页面、备份菜单、安全审计、上游核验、跨用户 Key 管理。退役路径固定返回 `404`；`/api/v1/agent/admin/wallet/credit` 固定返回 `410`。

## 2. 总体架构

```text
浏览器
  │  主站 SSO / 主站邮箱密码 / 本站注册
  ▼
AgentAPI 共享进程 ── HttpOnly 3 天 Session ──► TenantContext(agent_id, main_user_id, role)
  │
  ├─ 本站 SQLite：租户、成员、钱包、订单、公告、Key、结算
  ├─ 主站管理 API：余额、订单、退款、返利、兑换、用户、分组
  └─ 主站模型网关：/v1/chat/completions 等
```

主站调用 AgentAPI 使用固定协议：

- `Authorization: Bearer <SUB2API_APP_CREDENTIAL>`
- `X-Sub2API-Satellite: agentapi`
- `X-Sub2API-On-Behalf-Of: <主站用户 ID>`
- 本地钱包代付时额外发送 `X-Sub2API-Payer: <站长主站用户 ID>`，佣金率通常为 `0`

当前主站边界仍是“共享应用凭据 + On-Behalf-Of”。按卫星公共层的目标，后续应改为每卫星独立凭据和不可伪造的用户断言；在完成迁移前，不得把 AgentAPI 的调用当成强隔离的逐用户凭据。

## 3. 登录、注册与租户

### 3.1 主站一键进入

1. 主站左侧菜单打开 `GET /api/v1/auth/integrations/agentapi/start?next=%2Fdashboard`。
2. 主站 `AgentTenantService.ResolveSharedTenant` 优先返回已有成员关系；没有则创建逻辑租户，`agent_id = agt_ + UUID`。
3. 主站签发 2 分钟一次性 SSO ticket，携带签名后的 `sub`、`agent_id`、`agent_role`、`agent_name`。
4. AgentAPI `/api/auth/sso/callback` 校验 HMAC、audience、有效期和 JTI，只允许 owner 创建缺失租户，不允许改写已有 owner。
5. AgentAPI 建立 3 天 HttpOnly Session；浏览器拿不到主站 JWT、SuperKey、应用凭据或管理员 Key。

主站租户事实在 `agent_shared_tenants` 与 `agent_shared_tenant_members`；`246` 迁移建立共享表，`247` 迁移收敛历史 owner 并删除旧 provisioning/control-plane 表。

主站接入点：

- `sub2api/backend/pkg/satellite/apps.go`：`agentapi` 的 audience、origin、回调路径和菜单入口。
- `sub2api/backend/internal/handler/satellite_sso.go`：`GET /api/v1/auth/integrations/agentapi/start`，解析共享租户并签发 ticket。
- `sub2api/backend/internal/service/agent_tenant.go`：`ResolveSharedTenant` 的成员优先和 owner 幂等逻辑。
- 主站菜单直接打开 `/auth/integrations/agentapi/start?next=%2Fdashboard`，不在前端拼接租户或凭据。

### 3.2 主站邮箱密码登录

AgentAPI 服务端调用主站 `/auth/login`，成功后用主站 access token 请求同一个 SSO 启动接口，校验 ticket 的 `sub` 与刚登录用户一致，再建立本站 Session。两步中的主站令牌都不下发到浏览器。

### 3.3 本站域名注册

站长配置独立域名或 `AGENTAPI_ENTRY_TENANTS=host=agt_...` 后，匿名访客可注册。流程是：

1. AgentAPI 用 `SUB2API_ADMIN_API_KEY` 在主站创建普通用户（`role=user`、初始余额 0）。
2. 调用 `POST /api/v1/auth/satellite/agentapi/agent-membership` 写入 `agent_shared_tenant_members`，角色固定为 `member`。
3. 本站写入 `agent_users` 映射；注册者永远不能获得 owner。
4. `registration_intents` 用于恢复“主站已创建但响应丢失”的注册，避免重复建号。

注册可用性依赖可读的管理员 Key。缺失时注册应禁用，不能出现“能提交但必然失败”的入口。**注意：当前代码在环境变量缺失或为占位符时会回退到 `admin_key_config.go` 中的内置管理员 Key，这是尚未修复的 P0 风险。**

## 6. 模型网关

### 6.1 允许的接口

- `GET /v1/models`
- `POST /v1/chat/completions`
- `POST /v1/responses`
- `POST /v1/images/generations`
- `POST /v1/images/edits`
- `POST /v1/videos`
- `POST /v1/images/generations/async`
- `POST /v1/images/edits/async`
- `GET /v1/videos/{id}`
- `GET /v1/images/tasks/{id}`
- `GET /v1/usage`（本站本地按 Key 统计，不转发）

其他 `/v1/*` 路径固定返回 `403 MODEL_ROUTE_FORBIDDEN`。`/v1/models` 只返回仓库固定目录，绝不代理主站完整模型清单，避免泄露私有或未公开路由。

### 6.2 公开模型目录

当前代码中的目录：文本 `gpt-5.5`、`gpt-5.4-mini`、`gpt-5.6-luna`、`deepseek-chat`；图片 `gpt-image-2`、`gpt-image-1.5`、`gpt-image-1`、`gemini-3.1-flash-image` 及 `grok-imagine-image*` 系列；视频 `grok-imagine-video-1.5`、`seedance-2.0`、`seedance-2.0-fast`、`kling-v3`、`kling-v3-omni`、`kling-v2-6`、`kling-v2-5-turbo`、`kling-v1-6`、`kling-v1-5`、`kling-v1`。

**已知不一致：** `docs/卫星公开模型.md` 还列出 `grok-4.7`、`gpt-6`、`gpt-6-astra`、`gpt-5.6-sol` 和 AutoDL 视频 ID，但 `api/main.go` 的 `publicModelCatalog` 未包含，调用会被 `MODEL_NOT_ALLOWED` 拒绝。上线前必须二选一：补代码或收文档。

### 6.3 Key 与请求约束

- 新 Key 为 `sk-*`，只存哈希，完整值仅创建时返回一次；历史 `sk-agent-*` 兼容。
- `sk-super-*` 永远不能当本站 Key，也不会被转发为主站凭据。
- 请求按 Key 所属租户、所属主站用户解析，不接受 query 或 header 伪造租户。
- 上游请求强制使用本站 Key 的分组；响应剥离 `Set-Cookie`、`Authorization`、`x-sub2api-*`。
- 支持 SSE 流式文本、图片同步/异步、视频任务和轮询；任务表按租户隔离相同 `task_id`。
- `Idempotency-Key` / `X-Request-ID` 会形成结算幂等记录，重复请求不会二次转发。

## 7. 计费与结算

### 7.1 两种模式

| 模式 | 触发条件 | 谁扣费 | 本站钱包 |
| --- | --- | --- | --- |
| `user_upstream` | 默认 | 主站扣当前用户 | 不参与 |
| 本站钱包 | 站长开启本站收费 | 主站扣站长；本站再扣用户 | 参与，按实际费用 × 倍率 |

`user_upstream` 下 AgentAPI 只在请求前读取主站余额，不做本地预留；主站按自身规则计费。

本站钱包模式下：

1. 请求前检查主站付款人余额和本站钱包余额，任一不足直接拒绝。
2. 转发时携带 `X-Sub2API-Payer`，主站从站长账户结算实际费用。
3. AgentAPI 按主站 authoritative usage 记录结算，扣减本站用户钱包。
4. 结算状态为 `pending` → `confirmed` / `released` / `reversed`；后台每 5 分钟、每批最多 50 条核对，也支持站长手动核对。

### 7.2 本站支付

支持 `easypay`、`alipay`、`wxpay`、`stripe`、`airwallex`。渠道、套餐、订单、退款策略均按 `agent_id` 隔离，密钥加密保存，列表不返回明文。

支付回调有两条：

- 本站通用 HMAC：`POST /api/v1/payments/webhook`
- 渠道专用：`POST /api/v1/agent/billing/webhook/{agent_id}/{provider}`

回调不是唯一路径。后台会查询渠道订单，金额一致后幂等入账；支付成功后额度进入本站钱包，不直接改主站余额。

### 7.3 已知未闭环

- **P0：内置主站管理员 Key 回退。** 环境缺失时仍可能使用硬编码 Key，必须移除回退并让缺失配置 fail closed。
- **P0：根 Compose 没有显式注入 `SUB2API_APP_CREDENTIAL`。** 干净部署若缺少可选 env 文件，模型网关和结算不可用。
- **P1：套餐不是订阅。** `order_type=subscription` 只创建订单，履约仍按普通充值进入本站钱包；没有主站 `user_subscriptions` 或本地权益表。当前不得把套餐宣传为已生效订阅。
- **P1：取消只改本地状态。** 用户/站长取消订单不会调用渠道 `CancelPayment`，渠道侧仍可能付款。
- **P1：结算释放语义不完整。** `FinalizeSettlement` 对 `released` 仍计算 `stationChargeCents`；`debitUserUsageTx` 在余额不足时把余额截断为 0 但仍记 `confirmed`，没有欠款或短款记录。
- **P1：本站退款没有原始扣款锚点校验。** 退款额度可能被重复或超额使用，需补消费关联和唯一约束。
- **P1：共享应用凭据 + On-Behalf-Of 尚未迁移。** 当前隔离依赖服务端校验，目标是每卫星独立凭据和用户断言。

## 8. 主站联系矩阵

| AgentAPI 功能 | 主站接口/协议 | 方向 | 失败行为 |
| --- | --- | --- | --- |
| 一键进入 | `GET /api/v1/auth/integrations/agentapi/start` + 签名 ticket | 主站 → AgentAPI | 401/403，不建会话 |
| 密码登录 | `/auth/login`、`/auth/login/2fa`、SSO start | AgentAPI → 主站 | 保留本站会话边界，不泄露令牌 |
| 会话刷新 | `/auth/refresh`、`/auth/me` | AgentAPI → 主站 | 身份不一致即销毁本站会话 |
| 本站注册 | `POST /admin/users`；`POST /api/v1/auth/satellite/agentapi/agent-membership` | AgentAPI → 主站 | 缺管理员 Key 应禁用注册 |
| 找回密码 | `/auth/satellite/agentapi/forgot-password` 等 | AgentAPI → 主站 | 不暴露用户是否存在 |
| 余额 | `/v1/sub2api/balance`、`/admin/users/{id}/balance` | AgentAPI → 主站 | 显示暂不可用，不补 0 |
| 用量 | `/v1/sub2api/usage`、`/admin/usage` | AgentAPI → 主站 | 保持待确认，不估算 |
| 模型调用 | 主站模型网关 + 卫星头 | AgentAPI → 主站 | 透传错误，不二次扣费 |
| 主站充值单 | `/v1/sub2api/payment/*` | AgentAPI → 主站 | 仅历史单租户迁移路径 |
| 本站支付 | 渠道回调 + 本站钱包 | 渠道 → AgentAPI | 后台查询兜底 |
| 退款 | 本站渠道 + 主站订单接口 | AgentAPI → 渠道/主站 | 进入退款中，不假装成功 |
| 推广返利 | `/v1/sub2api/affiliate*` | AgentAPI → 主站 | 只读主站事实 |
| 兑换 | `/v1/sub2api/redeem*` | AgentAPI → 主站 | 只作用于当前用户 |
| 订单 | `/v1/sub2api/orders*` | AgentAPI → 主站 | 只读/受控操作 |
| API Key 分组 | `/admin/groups/all` | AgentAPI → 主站 | 无分组时禁止创建 Key |
| 资料/绑定/TOTP | `/user*`、`/user/account-bindings/*`、`/user/passkeys*`、`/user/totp/*` | AgentAPI → 主站 | 原样返回主站错误 |
| 公告/品牌 | 无 | 本站 | 不依赖主站 |

主站管理凭据只允许在服务端读取余额、创建用户和读取分组；不得用于模型调用，不得进入浏览器或前端构建产物。

## 9. 数据与隔离

- 本站表以 `agent_id` 为第一隔离键：`agent_users`、`agent_api_keys`、`agent_user_wallets`、`agent_wallets`、`wallet_ledger`、`settlements`、`station_payment_*`、`announcements`、`sessions`、`operation_leases`。
- Session 固定绑定 `agent_id + main_user_id`；跨租户 Cookie、伪造 Host 和重复域名均拒绝。
- `AGENTAPI_SHARED_HOSTS` 必须配置；未知 Host 在认证、公开设置和模型接口前返回 `421`。
- `AGENTAPI_ENTRY_TENANTS` 只做未登录访客的站点归属；已登录 Session 仍以自身租户为准。
- 自定义域名持久化在租户表；不代表独立实例。
- 单副本 SQLite；余额敏感操作使用数据库租约串行化，进程崩溃后租约自动过期。

## 10. 配置与部署

必填或强制的核心配置：

| 变量 | 作用 |
| --- | --- |
| `SUB2API_APP_CREDENTIAL` | 主站卫星应用凭据；共享模式启动必需 |
| `SUB2API_SSO_SECRET` | 与主站一致的 SSO 签名密钥，至少 32 字符 |
| `SESSION_SECRET` | 本站 Session 密钥，至少 32 字符 |
| `AGENTAPI_SHARED_HOSTS` | 共享入口允许的 Host，逗号分隔 |
| `SUB2API_ADMIN_API_KEY` / `_FILE` | 注册、余额和分组读取；当前存在内置回退风险 |
| `MAIN_API_URL` / `LINK` | 主站管理与公开地址 |
| `MAIN_MODEL_URL` / `SUB2API_RELAY_BASE_URL` | 模型网关地址 |
| `AGENTAPI_ENTRY_TENANTS` | 可选，`host=agt_...` 域名绑定 |
| `AGENT_EMAIL_VERIFY_ENABLED` | 必须与主站邮箱验证开关一致 |
| `COOKIE_SECURE` | 生产 HTTPS 必须为 `true` |

默认端口 `18081`，主站 `18080`。本目录 Compose 使用 `127.0.0.1` 或共享入口的反向代理；根 `docker-compose.online.yml` 的 AgentAPI 服务目前依赖可选 env 文件提供应用凭据。部署或重建前必须先读 `../docs/部署清单.md`，本次文档任务不执行部署。

## 11. 完成度结论

**功能覆盖：较完整。** 登录/注册、租户隔离、个人 Key、模型网关、文本/图片/视频、本站支付、退款、返利、兑换、公告、品牌、站长基础管理都已落地，并有 Go 与前端测试覆盖。当前验证基线：后端 `go test ./...` 通过；前端 67 个测试文件、343 项测试通过；`pnpm typecheck`、`pnpm build` 通过。

**商业可用性：尚未达标。** 阻塞项不是页面数量，而是资金与凭据边界：内置管理员 Key、干净部署缺少应用凭据、套餐未形成订阅权益、取消未撤销渠道支付、结算释放/短款语义和退款锚点。上述问题未修复前，不建议按“可对外收费的完整代理站”上线。
