# 13 实施顺序与风险

## 1. 实施阶段



### P0：方案确认

- 确认 A 方案、无佣金、代理预充值和用户子余额；
- 在 [17-账务权威与主站扣费桥接](17-账务权威与主站扣费桥接.md) 中拍板主站唯一扣费身份（推荐方案 A）；
- 确认用户是否允许直连主站；
- 确认支付渠道和部署方式；
- 评审本文档并冻结接口契约。



### P1：主站控制面

- [x] 建立最小 Agent 开站记录、slug/domain 唯一约束和状态事件表；
- [x] 增加管理员鉴权的幂等创建、状态查询、暂停/恢复/撤销接口；
- [x] 增加仅管理员可调用、要求显式 readiness 确认的幂等激活接口；
- [x] 增加请求幂等、数据库事务、主站操作审计和撤销二次确认；
- [x] AgentAPI 托管实例使用 `agt_<uuid>` 对齐开站记录，通过逐站 Agent Runtime GET + ID-only 数据库通知 SSE 监听期望状态，SSE 仅触发权威状态重读；状态非 active/过期时拒绝业务请求；
- [x] 增加幂等有序进度上报、受限失败码，以及仅重置 `failed && can_retry` 状态的重试接口；
- [x] AgentAPI 仓库实现独立受控 worker 源码：Sub2API 列表/SSE 提示、Compose/Nginx、DNS/TLS/healthz/readyz、显式激活和失败恢复；
- [x] 为跨进程 worker 增加 90 秒可续租 claim、租约 token hash、失租拒绝 progress/activate 与 worker context 取消；
- [x] Sub2API 为每个 Agent 签发/登记独立 runtime control/model credential，仅保存哈希并按 purpose 限制 API 面；
- [x] 增加逐站 Owner/usage/status 管理 API、映射用户身份证明和基于数据库通知的 ID-only 状态 SSE，保留 GET 权威读取/轮询兜底；
- [x] AgentAPI 模型 allowlist 经逐站 control API 同步到 Sub2API；Sub2API 在 model credential 记录公开目录 scope，并于 `/v1` 请求入口强制执行；
- [ ] 完善主站 Owner 账务/模型可用范围的自动配置和运营审批；
- [ ] 将 worker 构建、Secret/Docker/Nginx/edge IP 配置和部署纳入实际运维 edge 节点；worker 已改用共享的 provisioning-only 凭据和主站端点 allowlist，但不是逐 Agent scope，真实 edge 环境仍未验收；
- [ ] 自动化开站时核对 Owner/账务账户、逐站 runtime Secret 与模型范围的端到端关联；
- [ ] 完成主站到已部署实例的端到端 suspend/resume/revoke 运营验收；
- 不把通用管理员接口暴露给 AgentAPI。



### P2：AgentAPI 基础服务

- 创建独立服务和数据库；
- 实现域名解析、Agent 配置和 Session；
- 实现用户映射和健康检查；
- 实现服务凭据加载与轮换。



### P3：一键开站

- 实现 Agent 状态机；
- 接入域名/TLS/部署编排；
- 实现开站幂等、重试和失败恢复；
- 先完成测试环境平台子域名。



### P4：用户和模型链路

- 实现主站用户创建；
- 实现用户注册、登录和映射；
- 按公共层发送三个服务头；
- 按方案 A/B 固定主站计费身份，禁止客户端覆盖；
- 接入公开模型名；
- 完成用量归属。



### P5：账务和额度

- 实现代理预充值账户；
- 实现用户子余额和流水；
- 覆盖同步、流式、图片、视频和异步请求；
- 实现冻结、结算、释放、退款和对账。
- 主站成功但结算未知时进入 `settlement_pending`，不能静默释放；



### P6：支付

- 接入一个支付渠道；
- 实现订单状态、验签、幂等和对账；
- 首先上线代理预充值，再决定是否支持用户自动结算。



### P7：试点和上线

- 先创建一个内部代理；
- 使用测试支付和小额额度；
- 验证两个代理之间隔离；
- 通过全部验收清单后再开放更多代理。



## 2. 主要风险

| 风险                   | 缓解措施                                     |
| ---------------------- | -------------------------------------------- |
| Agent runtime credential 泄露 / worker 主机权限扩大 | runtime control/model credential 逐 Agent 隔离并可撤销；worker 使用共享 provisioning-only allowlist；Docker/Nginx edge 主机仍需独立加固与审计 |
| 代理与用户余额重复记账 | 明确方案 A/B 的唯一主站扣费身份、幂等流水、每日对账 |
| 主站用户可绕过代理     | agent 归属、Key 绑定、禁止直连或统一网关校验 |
| 多请求并发超扣         | 事务锁、冻结/结算、原子扣减                  |
| 支付回调伪造           | 验签、金额校验、事件幂等和人工对账           |
| 开站半成功             | 状态机、Saga 补偿、可重试步骤                |
| AgentAPI 版本漂移      | 版本化契约、兼容窗口、集成测试               |
| 代理服务被入侵         | 每 Agent 凭据隔离、scope、限速和吊销         |



## 3. 第一版不做

- 自定义域名自动证书全流程；
- 多代理共享一个主站用户；
- 用户直接拿主站 API Key；
- 佣金/分成/差价；
- 代理自定义任意计费价格；
- 多种支付渠道同时接入；
- 复杂订阅、套餐、赠送余额；
- 无审计的人工余额修改。



## 4. 上线门槛

以下条件全部满足后才允许生产开站：

1. 管理员 Key 不进入浏览器和镜像；
2. 开站、注册、充值和请求都有幂等键；
3. 两个代理之间的数据和额度隔离通过测试；
4. 余额不足和并发扣款测试通过；
5. 支付重复回调和退款测试通过；
6. 主站故障恢复和对账流程可执行；
7. 代理凭据可以独立吊销；
8. 账务负责人确认预充值和退款规则；
9. 本地预授权与主站 `usage_id`/余额差额可以完整对账，`settlement_pending` 补偿演练通过。
