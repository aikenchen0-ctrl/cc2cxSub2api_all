# 10 部署、域名与配置

## 1. 推荐部署形态

推荐先构建一个通用 AgentAPI Docker 镜像，再为每个代理使用独立配置和独立实例：

```text
agentapi-image:version
  ├── agent01.cc2.cx → Agent 01 配置
  ├── agent02.cc2.cx → Agent 02 配置
  └── agent03.cc2.cx → Agent 03 配置
```

独立实例便于隔离故障、暂停单个代理和轮换服务凭据。后续代理数量较大时，可以改为共享集群，由 Host 映射 `agent_id`。

## 2. 入口网络

```text
DNS
  → TLS/Nginx/Ingress
  → AgentAPI 实例或共享 AgentAPI 集群
  → AgentAPI 数据库
  → HTTPS 调用 Sub2API 主站
```

平台子域名优先使用：

- `*.cc2.cx` 通配符 DNS；
- `*.cc2.cx` 通配符证书；
- 入口层统一转发 Host；
- AgentAPI 根据 Host 查询 `domain_bindings`。

未知域名、暂停域名和撤销域名必须被入口或应用拒绝。

## 3. 域名分配

子域名生成规则：

```text
agent-{短码}.cc2.cx
```

或使用操作者申请的 slug。必须：

- 转小写；
- 只允许字母、数字和连字符；
- 禁止保留字、主站域名和内部服务名；
- 全局唯一；
- 记录生成来源和操作者。

自定义域名作为后续功能，需要额外完成 DNS 验证和证书签发，不应阻塞平台子域名 MVP。

## 4. 环境变量和密钥

当前单实例参考实现使用：

```env
MAIN_API_URL=https://api.cc2.cx
MAIN_MODEL_URL=https://api.cc2.cx
SUB2API_ADMIN_KEY=<server-only-secret>
SUB2API_APP_CREDENTIAL=<server-only-secret>
SUB2API_SATELLITE=agentapi
SUB2API_SSO_SECRET=<与主站相同的至少 32 字节 SSO 密钥>
AGENTAPI_SSO_AUDIENCE=agentapi
SESSION_SECRET=<long-random-secret>
COOKIE_SECURE=true
AGENTAPI_DATABASE_PATH=/app/data/agentapi.db
AGENTAPI_PORT=8080
AGENT_ID=agent01
AGENT_DOMAIN=agent01.cc2.cx
AGENT_NAME=Agent 01
AGENT_SITE_NAME=Agent 01 API
AGENT_SITE_LOGO=/logo.svg
AGENT_BRAND_SYNC=false
AGENT_OWNER_MAIN_USER_ID=<main-user-id>
AGENT_INITIAL_BALANCE=0
AGENT_MAX_REQUEST_COST=1.00
AGENT_SETTLEMENT_RECONCILE_INTERVAL=5m
AGENT_SETTLEMENT_RECONCILE_BATCH=50
AGENT_VIDEO_TASK_RECONCILE_AGE=30m
```

部署前将 `backend/.env.example` 复制为 `backend/.env` 并填入服务端密钥；如果同机运行多个实例，再将根目录 `.env.example` 复制为 `.env` 并为每个实例设置不同的 `AGENTAPI_PORT`。随后执行 `docker compose up -d --build`。Compose 将缺失的 `backend/.env` 标记为可选，便于检查配置；但没有必需密钥时 `/readyz` 不会就绪，生产环境不能省略配置。

约束：

- `MAIN_API_URL` 是主站 Origin 或 `/api/v1` 地址，`MAIN_MODEL_URL` 是主站 Origin 或 `/v1` 地址；
- `AGENTAPI_DATABASE_PATH` 必须位于持久化卷，SQLite 文件、WAL 和会话密文不能放在临时层；
- 管理员 Key 不写进 Dockerfile、镜像层、前端变量或 Compose 明文；
- `backend/.env`、根目录 `.env` 和 `secrets/` 被 `.dockerignore` 排除，不能把本地密钥带进 Docker 构建上下文；
- 密钥优先使用 Secret Manager、Docker Secret 或等价设施；
- 前端不读取这些服务端变量；初始品牌可用 `AGENT_SITE_NAME`、`AGENT_SITE_LOGO` 配置，运行中由 Agent 管理员通过品牌接口修改；仅在明确设置 `AGENT_BRAND_SYNC=true` 时用环境值覆盖已保存品牌。

反向代理必须保留公开域名 Host，避免 Cookie/CSRF/CORS 校验把内部容器地址误当成站点地址：

```nginx
location / {
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_pass http://agentapi:8080;
}
```

## 5. 容器和网络

AgentAPI 容器至少需要：

- 应用容器；
- AgentAPI 数据库；
- 可选的任务队列/缓存；
- 只读访问的密钥配置；
- 到主站 HTTPS 出站访问。

如果和主站在同一 Docker 环境运行，可以加入 `deploy_sub2api-network`，但仍使用服务间认证，不能因为同网段就绕过凭据校验。

## 6. 健康检查

```http
GET /healthz
GET /readyz
```

`healthz` 只表示进程存活；当前参考实现的 `readyz` 还检查：

- Agent 配置存在且为 `active`；
- SQLite 数据库可用；
- `SUB2API_APP_CREDENTIAL`、`SUB2API_ADMIN_KEY` 和 `AGENT_OWNER_MAIN_USER_ID` 已配置；
- `SESSION_SECRET` 达到至少 32 字节。

真正的主站探活和服务凭据撤销状态检查应由部署平台的外部探针或后续控制面实现，健康检查不得触发真实模型请求或扣费。

## 7. 观测和运维

必须关联并可检索：

```text
request_id
agent_id
main_user_id（脱敏）
order_id
usage_id
deployment_id
```

指标建议：

- Agent 状态分布；
- 注册成功率；
- 主站接口错误率；
- 充值回调成功/失败/延迟；
- 余额不足次数；
- 模型请求成功率和延迟；
- 未对账订单数；
- 服务凭据失败次数。

## 8. 备份和恢复

- AgentAPI 数据库每日备份；
- 主站账务以主站备份为准；
- 密钥不随数据库备份明文导出；
- 恢复后先进入只读/暂停模式，完成账务和订单对账后再开放消费；
- Agent 映射和订单必须能通过主站 ID 重建。
