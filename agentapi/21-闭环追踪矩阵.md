# 21 闭环追踪矩阵

本文把 AgentAPI 从“开站”到“撤站”的完整生命周期串起来，作为产品确认、开发实现、测试验收和上线运维之间的单一导航。每个业务动作都必须能回答四个问题：谁是事实来源、写入哪一份数据、失败后如何恢复、用什么验收。

## 1. 端到端业务闭环

```text
主站用户申请开站
  → 创建 Agent 与域名绑定
  → 创建/绑定主站代理管理员账户
  → 配置 Owner 扣费身份、模型范围和品牌
  → DNS/TLS/Nginx 就绪
  → Agent 健康检查通过并激活
  → 代理用户在 AgentAPI 注册
  → 主站创建真实用户，AgentAPI 保存映射
  → 代理管理员在主站充值
  → AgentAPI 同步 Owner 余额并分配用户子额度
  → 用户使用 AgentAPI Key 调用公开模型
  → 本地预授权 + 主站 Owner 唯一扣费
  → settlement 按 request_id/usage_id 对账
  → 钱包、用户用量和主站 usage 可追溯
  → 暂停、撤站、结算 pending 后归档
```

方案 A 的核心边界只有一句话：AgentAPI 的本地钱包负责预授权、分配和归属；Sub2API 主站的 `agent_owner_main_user_id` 负责模型请求的唯一真实扣费。

## 2. 生命周期追踪

| 阶段 | 事实来源 | AgentAPI 写入 | 主站动作 | 失败/恢复 | 验收依据 |

## 4. 不变量与阻断条件

以下任一条件不满足，都不能把 Agent 状态标为 `active`，也不能开放外部注册：

1. `agent_id`、域名、Owner 主站账户和服务凭据是一一对应的；
2. 浏览器无法获得主站 JWT、管理员 Key、SuperKey 或主站用户 Key；
3. 每次模型请求都有唯一 `request_id`，重试不会再次访问主站；
4. 主站扣费身份固定为 `agent_owner_main_user_id`，客户端请求头不能覆盖；
5. 本地 `available + allocated + frozen` 不超过最近一次可验证的 Owner 主站余额；
6. 主站成功但 usage 不可确认时进入 `settlement_pending`，不得猜测金额或静默退款；
7. 主站通用 `/api/v1/*` 不通过 AgentAPI 任意透传；
8. 撤站时保留用户映射、钱包流水、settlement 和审计记录，不物理删除账务历史。

## 5. 当前闭环范围与明确缺口

当前参考实现已闭环：认证代理、用户映射、本地额度预授权、Owner 唯一扣费转发、pending settlement、手动对账、品牌、客户端 Key、健康检查和单实例 Docker 部署。

以下能力仍是后续阶段，不能在上线说明中写成“已完成”：

- 主站“一键开分站”控制面、自动域名/证书/Nginx 编排；
- 真实支付供应商 SDK、渠道专属验签/支付页、退款、拒付和自动入账；provider-neutral HMAC 回调桥接已实现但默认关闭；
- 每个 Agent 独立 scope 的主站服务凭据；
- 多 Agent 共享进程的 Host 路由；
- 视频任务已完成创建归属、跨用户隔离、轮询、原 settlement 结算和后台超龄探测；明确失败任务释放冻结额度，成功任务转入主站 usage 对账。文本 SSE 已支持 EOF/断流 settlement 处理。

这些缺口的实现顺序见 [13-实施顺序与风险](13-实施顺序与风险.md)，上线前阻断条件见 [16-实现状态与边界](16-实现状态与边界.md)。

## 7. 充值桥接追踪补充

| --- | --- | --- | --- | --- |
