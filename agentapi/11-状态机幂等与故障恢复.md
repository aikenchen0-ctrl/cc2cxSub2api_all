# 11 状态机、幂等与故障恢复

## 1. Agent 状态机

```text
pending → provisioning → active
                         ├→ suspended → active
                         └→ revoked

provisioning → failed → provisioning
```

规则：

- `active` 才能注册、充值和消费；
- `suspended` 可以只读查询和处理必要退款；
- `failed` 可以重试未完成步骤；
- `revoked` 永久拒绝请求，历史数据保留。

## 2. 用户开通状态机

```text
requested → main_user_creating → mapped → active
                    │                         │
                    └────── failed             └→ disabled
```

同一个注册请求必须携带稳定的幂等键。主站已经创建成功时，AgentAPI 必须通过幂等查询完成映射，而不是再次创建用户。

## 3. 充值订单状态机

```text
created → pending → paid → allocated
             ├→ closed
             └→ failed
paid/allocated → refunded
```

所有支付渠道事件以 `provider_event_id` 幂等；所有余额入账以 `order_no` 幂等。

## 4. 模型请求状态机

```text
received → checking → reserved → running → settled
                       │             ├→ failed
                       │             └→ cancelled
                       └→ rejected
```

`reserved` 后发生任何异常，都必须有明确的 `settled`、`released` 或 `reversed` 结果，不能留下无限期冻结金额。

## 5. 幂等键规则

| 场景 | 幂等键来源 |
| --- | --- |
| 一键开站 | 客户端生成的开站请求 ID |
| 用户注册 | 注册请求 ID |
| 代理预充值 | 充值订单创建键 |
| 支付回调 | 支付渠道事件 ID |
| 模型同步请求 | AgentAPI request_id |
| 消费结算 | 主站 usage_id/request_id |
| 退款 | 原订单/用量 ID + reversal 类型 |

相同幂等键再次到达时，返回第一次处理的结果，不重新执行副作用。

## 6. 网络和超时策略

- 连接超时和读超时必须分开配置；
- 对主站控制接口使用有限次数指数退避；
- 对支付确认不能无限重试；
- 对模型请求重试前必须知道上一次是否已经被主站接受；
- 不对余额不足、权限拒绝、参数错误进行自动重试；
- 所有超时都记录 request_id 和当前状态。

## 7. Saga 补偿

开站和用户注册是跨系统操作，使用 Saga 思路：

```text
创建 Agent
  → 创建主站代理账户
  → 创建凭据
  → 配置域名
  → 启动实例
  → 健康检查
```

失败时按已完成步骤执行可逆补偿：撤销凭据、关闭域名、暂停账户、关闭支付入口。账务和用户对象优先保留并标记状态，不进行不可恢复的盲删。

## 8. 对账和修复任务

后台任务至少包括：

1. Agent 开站状态对账；
2. 主站用户映射对账；
3. 支付订单对账；
4. 代理额度与用户子余额对账；
5. 冻结余额超时释放；
6. 模型用量与 AgentAPI 展示缓存对账；
7. 服务凭据过期提醒。

修复任务必须：

- 记录修复原因和操作者；
- 使用幂等键；
- 先生成修复计划，再执行高风险操作；
- 对账结果可以导出。

## 9. 并发扣款

同一代理多个用户并发请求时：

- 代理钱包和用户子余额需要行锁、乐观锁或原子 SQL；
- 余额校验和扣减必须在同一个事务中；
- 不能先在 AgentAPI 本地判断余额，再异步通知主站扣款；
- 缓存只能做展示，不参与最终扣款决定。

当前参考实现还使用 `agent_owner_main_user_id` 级互斥锁，把 Owner 余额同步、用户额度分配、模型结算和 pending 对账串行化；SQLite 事务负责本地余额与流水的原子提交。
