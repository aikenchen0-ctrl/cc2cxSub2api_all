# 08 用户注册与模型请求

## 1. 注册流程

```text
用户访问代理域名
  → AgentAPI 根据 Host 找到 agent_id
  → 用户提交注册信息
  → AgentAPI 执行验证码、频控和基础校验
  → 主站创建 main_user_id
  → 主站写入 source_agent_id
  → AgentAPI 保存映射
  → AgentAPI 建立本地 HttpOnly Session
```

注册接口示例：

```http
POST /api/auth/register
Content-Type: application/json
```

```json
{
  "email": "user@example.com",
  "password": "<由主站认证规则处理>",
  "display_name": "User"
}
```

密码最终应由主站认证系统处理。AgentAPI 可以接收注册请求，但不应保存一份可独立登录主站的密码副本。

## 2. 本地映射

主站用户创建成功后，AgentAPI 写入：

```text
agent_id
proxy_user_id
main_user_id
status = active
```

写入映射必须与注册幂等键绑定。如果网络超时，使用相同幂等键查询主站，不重新注册。

## 3. 登录和 Session

AgentAPI 登录成功后只建立自己的 Session：

```text
Cookie: agentapi_session=<opaque-id>
```

浏览器不保存：

- 主站 JWT；
- 主站用户 API Key；
- SuperKey；
- `SUB2API_APP_CREDENTIAL`；
- 管理员 Key。

如果使用主站菜单进入 AgentAPI，沿用公共 HMAC SSO 建立本地 Session；SSO ticket 只用于一次身份交换，Session 生命周期为 3 天。

### 3.1 客户端模型 Key

浏览器控制台使用上面的 HttpOnly Session；需要从桌面客户端、脚本或 OpenAI 兼容工具调用 `/v1` 时，用户在 `/keys` 创建 AgentAPI 本地 Key：

```text
POST /api/v1/api-keys       → 返回一次明文 sk-agent-* → 客户端自行保存
GET  /api/v1/api-keys       → 只返回前缀、状态和时间
DELETE /api/v1/api-keys/{id} → 立即吊销
```

本地 Key 的哈希和 `main_user_id` 映射保存在 AgentAPI 数据库中，只能代表当前代理站的映射用户。它不是主站 API Key，也不能用于调用主站管理接口；模型请求到主站时仍由服务端替换为 `SUB2API_APP_CREDENTIAL` 和代用户请求头。

## 4. 模型请求身份

AgentAPI 服务端从当前 Session 或本地 AgentAPI Key 得到：

```text
agent_id
main_user_id
```

然后根据 [17-账务权威与主站扣费桥接](17-账务权威与主站扣费桥接.md) 选择主站计费身份调用主站 `/v1`：

```http
Authorization: Bearer <SUB2API_APP_CREDENTIAL>
X-Sub2API-On-Behalf-Of: <agent_owner_main_user_id 或 main_user_id>
X-Sub2API-Satellite: agentapi
```

方案 A 使用 `agent_owner_main_user_id`，代理用户 `main_user_id` 只保留登录和本地用量归属；方案 B 使用当前代理用户 `main_user_id`，但前提是主站已经原子完成额度转移。任何情况下都不能把本地子余额扣减和主站用户余额扣减当成两次独立收费。

这三个头只在服务端到主站的请求中出现。缺少 Session、映射或服务凭据时，返回 401/503，不允许回退到共享 Key 或默认用户。

## 5. 公开模型名

AgentAPI 会在 JSON 模型请求预扣前校验模型名，只允许公共层目录中的名称；未知名称直接返回 `400 MODEL_NOT_ALLOWED`，不会调用主站。出站请求只使用公共层允许的模型名：

| 能力 | 接口 | 默认模型 |
| --- | --- | --- |
| 文本 | `POST /v1/chat/completions` 或 `/v1/responses` | `gpt-5.5` |
| 图片 | `POST /v1/images/generations` 或 `/v1/images/edits` | `gpt-image-2` |
| 视频 | `POST /v1/videos`，轮询 `GET /v1/videos/{id}` | `grok-imagine-video-1.5` |

代理站前端可以使用自己的显示名称，但发给主站的模型字段必须遵循 `docs/卫星公开模型.md`。

## 6. 请求归属和账务

每一次模型请求在 AgentAPI 内生成：

```text
request_id
agent_id
main_user_id
session_id（脱敏引用）
model
created_at
```

主站返回或生成 `usage_id` 后，AgentAPI 只保存引用和展示缓存。实际用量、主站扣款和失败状态以主站记录为准；本地用户流水用于代理侧额度归属和对账，不得覆盖主站账务。

## 7. 失败处理

| 场景 | HTTP/业务结果 | 是否扣费 |
| --- | --- | --- |
| Session 过期 | 401 | 否 |
| 用户未映射 | 403/404 | 否 |
| 代理暂停 | 423 | 否 |
| 余额不足 | 402 | 否 |
| 主站不可用 | 503 | 不应产生成功扣费 |
| 上游失败 | 502/504 | 按主站结算策略释放或冲正 |
| 客户端断开 | 499/业务取消 | 按已计量用量结算 |

参考实现说明：普通 JSON/图片上传会缓冲上游响应后返回；JSON 设置 `stream=true` 或使用 `Accept: text/event-stream` 时走实时转发，正常 EOF 后结算，断流保留 pending。视频及显式异步图片端点会保存 Sub2API 返回的任务归属，并通过用户隔离的 AgentAPI 轮询接口观察原任务；超龄后台探测使用主站 usage 按原 `request_id` 对账，只有权威接口确认无 usage 时才释放失败任务预授权。浏览器不轮询 Sub2API，也不会因此创建第二笔预授权。图片异步任务结果留存在 Sub2API 对象存储/任务接口，不由 AgentAPI 下载或复制。

图片/视频任务 ID、最近状态与原 settlement 引用会同时保存在 AgentAPI 本地索引中。登录用户可以通过 `GET /api/v1/agent/tasks?page=1&page_size=25` 分页恢复自己的任务；页面刷新或重新打开后从列表继续轮询原任务，不会再次提交生成请求。该列表只返回 AgentAPI 保存的任务元数据，不包含供应商完整响应或媒体结果。

## 8. 直连主站规则

第一版不向代理用户发放可绕过 AgentAPI 的主站凭据。若未来开放直连，必须将 API Key 绑定 `agent_id`，并由主站网关继续执行代理额度检查，否则用户可能从主站入口绕过代理限制。
