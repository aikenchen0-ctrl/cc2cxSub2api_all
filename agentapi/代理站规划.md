# AgentAPI 共享代理站实施规划

更新日期：2026-09-30。

> 本规划服从 [00-AI开发规范与目标架构.md](00-AI开发规范与目标架构.md)。AI 必须把“目标、当前事实、实施任务、验收证据”分开书写，不得把计划描述成已完成能力。

## 1. 最终目标

AgentAPI 最终是一套共享的多租户代理站：所有站长共用同一站点和运行时；Sub2API 用户点击“一键开分站”只创建租户及站长关系，不新建容器、端口、数据库文件或逐站 Secret。

每个租户通过 `agent_id` 隔离站长与成员、品牌与域名、Agent Key、调用记录、用量副本、操作日志、限流、缓存、任务和幂等键。可调用模型固定来自仓库定义的卫星公开模型目录，不提供租户级模型策略管理。主站继续权威负责身份、余额、充值、订单、订阅、模型、上游调度、计费和真实用量。

## 2. 产品范围

### 保留和建设

- 一键开分站和站长入口；
- 代理站品牌与公告；正式法律协议由主站统一页面承载；
- 主站确认的租户成员归属与访问校验（无账号管理界面）；
- 用户自己的本站 `sk-*` Key；
- 固定卫星公开模型目录校验与 `/v1/*` 兼容网关；
- 本站请求、主站用量只读副本和完整性状态；
- 用户按主站事实充值、购买套餐、查看订单和推广返利；站长仅查看支付统计并处理当前租户订单；
- 站长基础仪表盘、公告、用量同步与品牌/系统设置；
- 共享域名和可选自定义域名。

### 永久排除

- 分组管理；
- 账号管理；
- 代理管理；
- 兑换码管理；
- 插件管理；
- 安全审计（风险控制与提示词审计）；
- 上游核验。
- 模型广场、模型工作台和批量图片；
- 模型权限/模型策略管理；
- 代理站开通管理页；
- 运营监控；
- 优惠码管理；
- 订阅管理；
- 渠道管理和模型定价页；
- 代理站计费页；
- 内容页面管理、自定义页面；
- 备份管理。

不得以“只读”“高级站长”“隐藏菜单”或“兼容旧版”为理由恢复以上模块。主站的一键开分站仍是租户开通入口，但 AgentAPI 本身不提供逐站部署或开通管理控制台。

## 3. 当前事实与缺口

当前已有：

- 主要数据表普遍包含 `agent_id`；
- Agent 用户映射、Agent Key、品牌、请求跟踪和部分跨租户测试；
- 用户按自身 `main_user_id` 调用主站的 `user_upstream` 路径；
- 三天 Session、公开模型和卫星服务端代调基础；
- 被排除模块的菜单、路由、浏览器客户端和专属后端清理；
- 被排除模块旧路径的统一 `404` 防回归，以及跨用户 Key 管理拒绝；
- 旧单租户 Docker 的本地运行与部分联调记录。
- Session、Agent Key 和模型转发的可信 TenantContext；
- 多站点 `agent_config`、旧单例表自动迁移与同库隔离测试；
- 数据库 Host 映射、域名唯一约束、公开品牌/模型与登录入口的租户解析。
- 共享入口 Host 使用显式 `AGENTAPI_SHARED_HOSTS` 白名单，数据库中已认领的自定义域名单独放行；未知 Host 在路由分派前返回 `421`，不信任转发头覆盖公共 Host。
- 主站 `agent_shared_tenants` / `agent_shared_tenant_members` 迁移及按 owner 幂等的 `EnsureSharedTenant`；
- 主站“一键开分站”通过既有 SSO start 签发带签名 `agent_id + role + agent_name` 的票据，不创建容器；
- AgentAPI 严格校验共享租户票据、创建缺失逻辑租户、拒绝 Host 冲突，并保持 owner 不可变；
- 后台结算、充值订单、图片和视频任务巡检显式枚举所有 active 租户。
- 视频任务、图片任务和结算均已用组合租户键保存；自动化测试证明两个租户可以复用相同 `task_id` / `request_id`，且状态与模型更新不会跨租户生效。

当前缺口：

- AgentAPI 内部的逐站 provision 命令、worker、runtime-control 路径和凭据已删除；共享生产启动不再自动创建固定租户，`cfg.AgentID` 仅作为运维显式启用的旧单租户迁移开关；
- 主站逐站 provisioning/runtime 路由、Handler、worker 凭据、管理前端和专用运行时模型凭据分支已删除；
- 主站新增前向迁移会保留每个历史 owner 的一个共享租户，再删除旧逐站 provisioning/runtime 表；该迁移尚未在生产执行和核数；
- 正式 AgentAPI 镜像、源码和配置，以及主站当前依赖注入，均不再包含逐站 provision/runtime-control；
- Compose 仍使用单 SQLite 数据卷；
- 仍需确认生产外部脚本、旧定时任务和运维平台未继续调用已经删除的 provision worker 协议；
- 已有同进程双租户单元与 Handler 级证据，但尚无真实主站、浏览器和生产流量下的完整证据；
- 共享/自定义域名、真实计费、多副本、备份恢复和浏览器跨租户验收未完成。

结论：当前代码已具备可信共享多租户主链路并退休旧逐站控制面；生产数据库、多副本、迁移核数、真实计费、浏览器与灾备验收尚未完成，因此仍不能宣称生产改造完成。

## 4. 工作流

### A. 规范与防回归

1. 所有入口文档链接 AI 规范；
2. 历史文档标注非规范性；
3. 阻止新增每站容器、SQLite 和端口；
4. 对全部删除模块建立路由、菜单、API 和旧路径回归检查；
5. 扫描浏览器产物，防止服务端凭据进入前端。

验收：文档链接、禁止模块符号、前后端路由和密钥扫描均有自动化结果。

### B. TenantContext 核心改造

1. 定义不可变 TenantContext；
2. 统一 Session、Agent Key、SSO 和 Host 的解析入口；
3. Handler 不再读取 `cfg.AgentID`；
4. Service 与 Store 显式接收 TenantContext 或 `agent_id`；
5. 后台任务按租户分片；
6. 缺少或冲突租户时拒绝请求。

验收：同一进程的 A/B 两租户并行调用核心接口，跨租户矩阵全部拒绝。

### C. 数据库共享化

1. 站长关系迁入成员表；
2. 审计所有表、索引、外键和唯一约束；
3. 租户化请求 ID、幂等键、任务键和缓存 Key；
4. 建立旧 SQLite 数据导入与校验工具；
5. 接入共享生产数据库；
6. 区分全局备份与单租户导出/恢复。

验收：迁移前后计数与哈希一致，并发、跨租户 SQL 和恢复演练通过。

### D. 一键开分站

1. **代码已实现**：主站按 `owner_main_user_id` 幂等创建租户；
2. **代码已实现**：原子写入租户和 owner 成员关系；
3. **代码已实现**：复用现有卫星 SSO start 进入稳定的共享 AgentAPI 入口；
4. **代码已实现**：签名票据携带租户、角色和名称，AgentAPI 建立可信租户 Session；
5. **代码已实现**：重复点击返回原租户，不执行 Docker provisioning；
6. **待完成**：生产迁移、并发数据库验收、停用/恢复、失败重试和真实浏览器联调。

验收：重复/并发点击、失败重试、不同用户开站、停用和恢复流程通过。

### E. 域名、品牌和缓存隔离

1. 默认共享域名使用可信 Session 定位租户；
2. 自定义域名通过唯一映射表绑定租户；
3. 规范化 Host 并防止伪造；
4. 页面、CDN 和服务端缓存按租户分区；
5. 域名解绑或租户停用后立即失效。

验收：共享域名和两个自定义域名并行测试无品牌、Session、缓存和数据串站。

### F. 模型、计费与异步任务

1. 文本、图片、视频和流式请求使用真实成员主站身份；
2. 可调用模型固定使用仓库定义的卫星公开模型目录，不存在租户 allowlist 或模型策略写入口；
3. 异步任务、轮询和回调保存原 TenantContext；
4. 主站成功而本地同步失败时不重复请求；
5. 用量副本标注来源、窗口和完整性；
6. 移除站长代付、本地钱包和余额差值计费旧路径。

验收：真实主站调用只计费一次，跨租户任务拒绝，故障恢复通过。

### G. 旧控制面下线

1. **已完成（AgentAPI）**：移除逐站 provision 命令、worker、runtime-control 和相关凭据；
2. **已完成（当前代码）**：停止并移除主站 Compose/端口/逐站 Secret 控制逻辑、worker 协议、旧管理入口和运行时凭据；
3. **待完成（生产）**：执行旧表收敛迁移，核对租户数量与 owner 归属，并确认外部运维调用已经清零；
4. **已完成（代码/配置模板）**：旧固定租户变量退出共享生产默认路径；
5. 更新部署、监控、备份和灾备文档；
6. 保留迁移审计，不保留可重新启用的旧入口。

验收：开通新租户前后容器、端口和数据库实例数量不变。

## 5. 建议顺序与里程碑

1. M1：完成 A，冻结错误方向；
2. M2：完成 B，同进程安全服务两个租户；
3. M3：完成 C，共享持久化和旧数据迁移；
4. M4：完成 D，一键开站不部署容器；
5. M5：完成 E/F，全链路隔离和真实计费；
6. M6：灰度迁移后完成 G，旧控制面下线；
7. M7：真实主站、浏览器、备份恢复、监控和回滚全部验收。

不得先删除旧运行路径再补迁移工具，也不得让多个旧实例直接共享同一个 SQLite 文件。

## 6. 测试矩阵

每个里程碑至少覆盖：

- owner A、member A、owner B、member B、无 Session、失效 Session；
- 浏览器 Session 与本站 `sk-*` 两类入口；
- 正常对象、外站对象、伪造 `agent_id`、重复与并发请求；
- 文本、流式、图片、视频、异步轮询；
- 品牌、公告、只读法律协议、Key、用量和操作日志；
- 共享域名、未知 Host、自定义域名；
- active、suspended、disabled 租户；
- 主站成功/失败/超时与本地数据库成功/失败组合。

## 7. 当前状态（2026-09-30）

- 文档规范：已建立共享多租户目标和 AI 执行规则。
- 产品精简：用户明确排除的非核心模块已删除，菜单、路由、客户端和专属后端均有不存在/拒绝回归。
- 共享运行时：核心代码已完成第一阶段，生产数据库、多副本和真实流量验收未完成。
- 请求级 TenantContext：核心请求与后台巡检已完成；Session、Agent Key、模型转发、公开品牌/模型、SSO、密码登录、结算与异步任务均使用可信租户或显式枚举 active 租户，仍需生产代理层与完整页面矩阵验收。
- 共享数据库：代码层组合租户键和同库隔离已有覆盖，包含相同任务号/请求号跨租户并存与更新隔离；生产持久化、多副本、迁移核数和恢复演练仍未完成，当前仍使用 SQLite。
- 一键开站只建租户：代码已完成；旧 provision worker 和管理入口已删除，生产迁移与浏览器验收未完成。
- 真实多租户端到端：未完成。
- 当前本地 Docker：仅是单副本 SQLite 开发/迁移运行证据，不代表共享生产拓扑验收。

AI 后续汇报必须沿用这些状态分类，只有获得对应代码和验收证据后才能更新为完成。
