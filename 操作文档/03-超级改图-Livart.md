# 超级改图（Livart）测试操作手册

## 1. 基线与验收边界

- 编写基线：2026-10-08 当前工作区源码，包含尚未提交的错误展示、服务调用和 UI 修改。
- 本文是可执行操作/验收用例，未全部实测，也未执行收费生图；不能把用例预期当成已通过结论。
- 当前本地 Docker 镜像可能缺少工作区最新改动，执行前记录版本，先判断界面差异是不是镜像未更新。
- 本应用是图片生成、图片编辑和画布，不提供视频制作工作台；对话主要围绕改图功能，非任意通用聊天。
- P0：登录、项目保存/恢复、账号隔离和费用归属；P1：图片处理与交付；P2：辅助交互。
- 测试只使用专用账号/测试素材，不清空已有项目、不运行周清理、不更改真实用户余额。

## 2. 入口、界面和模型

| 区域 | 当前入口/操作 |
| --- | --- |
| 主站入口 | `http://localhost:18080` 登录后点“超级改图” |
| 本地页面 | `http://localhost:8080`；已登录后进入当前项目画布 |
| 顶部 | 项目切换、新建项目、连接配置、保存同步状态、统计、清理倒计时、下载范围、退出 |
| 底部工具栏 | 撤回/重做、移动、选择、上传图片、社媒图片、商品详情图、添加文本、排列、缩放、重置视图 |
| 右侧对话 | 文字提示、`@` 图片引用、画幅/分辨率、优化提示词、错误反馈和 Agent 执行结果 |
| 图片工具 | 快捷编辑、裁剪、旋转、局部重绘、删除物体、去背景、多角度、全景、图层拆分、改色/增强/扩图、分享/下载 |

当前公开图片模型仅 `gpt-image-2`；对话默认 `gpt-5.5`，允许 `gpt-5.4-mini`。
主站 SSO 用户应使用服务端托管配置，无需粘贴 SuperKey 或主站 API Key。
页面保留个人服务连接配置，不应把该入口当作主站用户必填步骤；托管配置缺失记部署/环境阻塞。

画幅选项为自动、1:1、4:3、3:4、16:9、9:16、360°（2:1）。
清晰度选项为 1K、2K、4K，2K 是界面标示的默认高清档；实际请求尺寸受安全尺寸映射影响。
画布可能显示 512/1600 等预览版本，判断质量要下载原图并检查真实像素，不能只看画布缩放。

## 3. 保存、导出与数据生命周期

当前源码的自动保存通常有约 800 ms 防抖；有待完成图片任务时会更快保存。
顶部会显示“永久画布读取中/保存中/已同步/未连接”等状态，但“永久画布”文案不代表永久保留承诺。
`WeeklyDataCleanupService` 固定在每周一 00:00（Asia/Shanghai）清除用户画布、快照和素材对象。
UI 有首次告知和清理倒计时。重要结果应提前下载；本测试手册只验证告知，不触发定时清理。

| 下载方式 | 实际含义 |
| --- | --- |
| 图片工具“下载” | 下载当前选中的原始图片；不是画布缩略图 |
| 顶部“选中图” | ZIP 打包选中的已完成图片 |
| “最终图” | 没有后续子派生的叶子图片，不是 AI 评分选出的最佳图 |
| “全部派生图” | 有 `parentId` 的编辑/裁剪结果 |
| “项目交付包” | 当前项目所有已完成图片；不含可恢复画布结构的完整备份 |
| 文字图层下载 | 从文字工具单独下载，不应误认为已包含在图片 ZIP 中 |

本应用没有在该交付包路径实现可编辑画布 ZIP 导入；不要用“重新导入交付包恢复项目”验收。
分享链接属于公开交付路径，要先确定图片可公开；普通资源请求的账号隔离和公开分享访问分开测试。

## 4. 测试账号与素材

准备主站普通账号 A、B，使用两个浏览器配置文件；同浏览器切换另做隔离回归。
账号 A 有足够执行 1 张改图的测试额度；零余额和上游余额不足使用专用夹具分别测试。
从主站进入后记录匿名用户编号、项目 ID、余额和实际模型；不记录票据/Cookie/Key 原文。

测试材料：

- `cup-base.png`：1024×1024 白色杯子，灰背景，杯身标识“QA-CUP”。
- `blue-style.jpg`：1024×768 蓝背景风格图，不能含真实个人/品牌信息。
- `cup-side.png`：同一杯子侧面图；`cup-red.png`：不同 SKU 红杯子，供系列模式。
- `invalid.png`：后缀是 PNG 的文本文件；透明 PNG 一张，供 alpha 测试。
- 社媒导入使用测试人员有权使用的公开链接；记录来源，不发布或发送任何分享消息。

项目名统一 `QA-Livart-A-日期-序号` 和 `QA-Livart-B-日期-序号`。
生成提示统一要求“保留 QA-CUP 标识和杯子结构”，使肉眼验收有明确对照。

## 5. 主流程：上传、派生、刷新和交付

本流程先完成不调用模型的上传/裁剪/下载，再按需要执行改图，方便定位哪一层失败。

1. A 从主站菜单进入 Livart，点击“新建项目”，填 `QA-Livart-A-01` 后创建。
   - 预期：顶部项目名称变化；原项目继续存在；新项目为空或仅含初始化内容。
2. 如首次显示周期清理告知，阅读并关闭；记录顶部清理倒计时。
   - 预期：告知明确提醒下载，关闭后不遮挡画布；倒计时是下次周一 00:00 上海时间。
3. 底部“上传图片”上传 `cup-base.png`，等待上传完成。
   - 预期：出现完整图片，图名可辨认；上传中占位变成已完成状态；不可用图不得变成成品。
4. 用“添加文本”添加 `QA-裁剪验收`，修改字体、字号、颜色或描边，移动到图片旁边。
   - 预期：文本可见，字号变化不丢字符；保存后不是模糊图片假装文字。
5. 选中杯子图，点“裁剪”，拖动框包含主体和标识，点击“保存为新图”。
   - 预期：产生新的派生图片节点；原图保留；新图是所选区域，检查 `parentId` 对应关系。
6. 选中裁剪图，打开“旋转”，点向右 90°，先点“取消”，再向右并确认。
   - 预期：取消只恢复预览；确认旋转原始图片资源并重建预览，宽高正确交换。
7. 调整两图布局、文字样式和缩放，等待“已同步”或实际保存成功响应后刷新。
   - 预期：当前项目、图片、文字、位置、背景、视图恢复；保存失败不能计为通过。
8. 切换到原项目再切回测试项目。
   - 预期：不同项目内容不混入；原图和派生图仍可选中、预览。
9. 选中裁剪图，点图片工具“下载”，用独立图片查看器打开。
   - 预期：非空、可解码、旋转后的内容正确，实际像素对应原始资源而非预览缩略图。
10. 顶部下载范围选“全部派生图”，再选“项目交付包”，分别下载 ZIP。
    - 预期：派生包只含带父关系的图片；交付包含所有已完成图片；文字不会被默认为图片包内容。
11. 解压检查文件数量、文件名、格式和内容；记录原图、派生图和 ZIP 的校验值。
    - 预期：无空文件或错误图；处理中/失败占位不被打包；中文名称可辨认。
12. A 在另一浏览器会话从主站进入并选择同一项目。
    - 预期：可以读取服务端保存版本；只在原浏览器刷新成功不算云端保存通过。

## 6. 改图、蒙版和商品业务

### 6.1 单图与多图参考

1. 选中 `cup-base.png`，使用图片工具“快捷编辑”，输入：`仅把灰背景改成浅蓝摄影棚，保留杯子形状、QA-CUP 标识、颜色和位置。`
2. 提交一次，观察对话执行步骤、图片占位和任务状态，保存任务 ID。
3. 完成后检查背景、杯体、标识、光影；原图仍保留，新图有派生关系。下载原图判断质量。
4. 多图时上传 `blue-style.jpg`，在输入框键入 `@` 并点击选择对应图片。
5. 预期插入稳定图片 ID 引用；重命名/重新排列图片后引用仍指向原资源。
6. 提示明确“杯子图是底图，蓝图只参考背景”；不能只把两张图放在画布上假定均被模型收到。

### 6.2 局部工具

- “局部重绘”：先用涂抹工具圈杯子右侧背景，再输入 `把圈选背景补成浅蓝色，其余保持不变`。
- “删除物体”：涂抹干扰物后执行，检查物体移除与背景补全；未涂抹时应提示缺少区域。
- “去背景”：当前服务端指令要求保留主体、改为纯白背景，不应以透明 PNG 为必过条件。
- “图层拆分”：主体层指令要求透明 alpha，背景层独立生成；与白底“去背景”分别验收。
- “多角度”：调整旋转、倾斜、缩放后生成新视角，检查主体身份与结构。
- “全景”：转换为 2:1 球形全景并用全景查看器检查接缝，不把普通 2:1 图片等同无缝全景。
- “增强/扩图/改色”是明确的 AI 编辑提示，需要真实调用；它们不等于本地像素处理。

### 6.3 商品详情图

1. 上传产品图片后点底部“商品详情图”；无产品图时该按钮应禁用或提醒。
2. 选择单品模式（同商品多角度）或系列模式（不同产品/SKU）；先在对话中补齐商品信息。
3. 填入真实产品名、材质、规格、使用场景和卖点，不知道的硬参数留空。
4. 观察“信息已足够”的状态后再选生成数量；先用最小数量验证，不直接批量。
5. 预期 Agent 分析/规划后产生图片任务；系列不把不同 SKU 融成一个商品。
6. 逐张核对中文短标题、规格、外观、SKU、文案事实和裁切；失败项记录单项，不将全部任务一概算成功。

## 8. 负向、边界与故障回归

| ID | 优先级 | 前置/操作 | 可观察预期 |
| --- | --- | --- | --- |
| LIV-N01 | P1 | 上传 `invalid.png`、不支持格式 | 中文“文件格式/图片无法读取”提示，不产生成功占位 |
| LIV-N02 | P1 | 未选底图就局部重绘；无蒙版就删除物体 | 提示缺少图/区域，不能乱选其他画布图执行 |
| LIV-N03 | P1 | 引用已删除或仍上传中的图片 | 明确不可用，不能悄悄切到别人的资源 |
| LIV-N04 | P1 | 无图片时下载、无派生图时导出派生 | 明确空范围提示；已有文件不受影响 |
| LIV-N05 | P1 | 导出返回 404/500，存储不可用 | “导出图片未完成”及排查信息；不下载假 ZIP |
| LIV-N06 | P1 | 上游 401/403/404/405 | 区分通道认证、模型缺失、编辑接口不支持，不让用户乱改主站密码 |
| LIV-N07 | P1 | 上游余额不足和用户余额不足分别注入 | 上游问题提示管理员补通道；个人余额才提示主站充值 |
| LIV-N08 | P1 | 429/超时/网络断开 | 等待/重试建议可读；先检查旧任务结果，避免重复收费 |
| LIV-N09 | P1 | 生成中刷新或关闭再进 | 按原任务恢复；失效任务提示记录已过期，不永久“同步中” |
| LIV-N10 | P1 | 社媒链接失效/私网地址/无候选图 | 提示链接/来源失败，无内网数据泄露；不访问任意私网服务 |
| LIV-N11 | P2 | 超长错误和小窗口 | 错误区域换行可滚动，不遮住输入/重试/下载 |
| LIV-N12 | P1 | 切换项目时有待保存/生成任务 | 结果写回正确原项目；新项目不被旧响应覆盖 |

失败反馈当前新增 `FailureNotice`，可展开“查看排查详情”并复制排查信息。
只有出错状态码时不能推断具体上游原因；记录系统实际返回的分类和 requestId。
故障注入使用专用测试夹具/浏览器网络控制，不中断共享容器或线上账号。

## 9. 双账号、3 天会话与费用

- 公共期望：A/B 画布、聊天、素材、API 配置、任务和导出文件互相隔离；管理员 SSO 不自动获得他人项目权限。
- B 独立浏览器不得列出 A 项目；B 复用 A 的测试 asset/export/project ID 时应拒绝私有读写。
- 同浏览器 A→退出→B→A，检查最后项目、画布历史、图片缓存、聊天和个人配置不会继承另一账号。
- SSO 回调设置 `livart_session` HttpOnly Cookie，前端保存 `cookie:用户ID` 身份提示；该提示不是模型密钥。
- Cookie 代码的 SSO Max-Age 为 259200 秒；JWT 时长仍受 `JWT_TTL_DAYS` 配置控制，实际配置/到期须与公共 3 天约束一致。
- 无/过期 Session、重放票据应拒绝；重新从主站菜单进入恢复，禁止要求粘贴 SuperKey。
- 余额组件按当前用户每 60 秒刷新，零余额标红/提示充值；充值目标仅是公开主站 `/purchase`。
- 余额界面金额标识和弹窗显示币种须与主站一致，记录实际格式差异，不自行换算。
- AI 调用前后核对主站 usage 和 A/B 余额；上传、裁剪等本地/存储操作不应伪造模型消费记录。
- “失败免费”“ZIP 是永久备份”等说法都不是当前已验证承诺。

## 10. 执行记录与缺陷提交

| 字段 | 填写内容 |
| --- | --- |
| 环境 | 源码版本/未提交差异、Docker 镜像、浏览器、执行时间和入口 |
| 身份 | 匿名 A/B、是否 SSO、会话到期摘要；不存凭据原文 |
| 输入 | 项目/节点/asset ID、图像尺寸/校验值、提示词、引用 ID、蒙版截图 |
| 模型 | 公开名、画幅、清晰度、数量、Agent 模式、任务/run ID |
| 结果 | 通过/失败/阻塞/未执行；保存/刷新/另一会话读取结果 |
| 交付 | 下载格式、真实像素、alpha、ZIP 图片数量/范围/校验值 |
| 费用 | 前后余额、usage ID、重复提交与失败计费实际值 |
| 证据 | 中文提示、脱敏排查详情、状态码/业务码/requestId、时间线 |

缺陷格式：`LIV-缺陷编号 / 标题 / 前置 / 最短步骤 / 预期 / 实际 / 影响 / 版本 / 附件`。
图片编辑缺陷附底图、蒙版、结果三者对照；导出缺陷附文件数/尺寸，不只贴成功提示。
附件不包含票据、Cookie、真实账号、模型 Key、内网地址或未脱敏的日志。

## 11. 测试结束清理

先保存原图/蒙版/结果对照、导出包、任务 ID、费用和脱敏失败信息，再移除自己的 `QA-Livart` 测试项目/图片。
私有导出文件、公开分享和任务记录只按现有界面可用的管理入口处理；无法清理的残留记录 ID 和实际保留期限。
生成中的任务先检查最终状态；删除图片节点/项目不等于取消上游任务，也不代表费用回滚。
严禁在共享实例手动调用或通过修改系统时间触发每周清理，它会清除所有用户项目和素材。
不得删除非测试作品、共享存储或容器卷；退出测试账号，保留需要复现的失败现场并在执行记录注明。
