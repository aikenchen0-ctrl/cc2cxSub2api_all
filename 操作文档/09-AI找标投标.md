# 09. AI 找标投标测试操作手册

## 1. 基线与范围

- 应用目录：`yibiao/`；依据 **2026-10-08 当前工作区源码，包括尚未提交的服务端、页面与模型更新**编写。
- 本地入口：[AI 找标投标](http://localhost:8081)；主站：[Sub2API](http://localhost:18080)。正常从主站左侧“AI 找标投标”进入，SSO slug 为 `yibiao`。
- 本次是源码和页面结构核对，**未完成真实网站抓取、模型分析、调度和通知实测**。预期是测试判据，不表示已通过。
- Docker 镜像可能旧于工作区；执行前记录镜像、构建时间和代码版本，核对实际页面模型是否仍为旧值。
- 本地主站曾导入线上数据库，执行前重新登录并核对当前支付、主动监控、OAuth 自动刷新开关；后续更新可能改变配置，不能假设仍关闭。主站开关也不等于 Yibiao 的“开始”被禁用：用户启动会实际抓取，并可能触发模型和通知。
- 使用独立测试用户、测试站点、测试收件人；真实模型、短信、语音和邮件/微信测试需要事先约定预算与接收对象。
- P0 为账号隔离、错通知、计费及数据丢失；P1 为抓取、筛选、调度和配置主流程；P2 为兼容和体验。

## 2. 产品当前边界

当前是标讯监控和相关性筛选工具，不是自动投标平台。
实际页面只有 **控制台、结果、网站、联系人、配置**；没有地区选择器、配置方案命名列表、收藏、导出按钮、站内标书生成/提交、详情页或预算/资质专用字段。
结果仅展示标题、发布时间、来源和原公告链接；报名时间、资质、预算等应在原站人工核对，不能按旧文档中的不存在入口测试。

AI 分析默认公开模型更新为 `gpt-6-astra`，服务端可以用 `SUB2API_RELAY_MODEL` 覆盖。
管理接入模式中 UI 的“模型通道”和“公开模型”只读，没有模型 API Key 输入。UI 固定显示值不证明服务端覆盖值相同，应结合日志和主站用量核对。
当前默认 AI 画像是**光伏/风电无人机巡检服务**，页面没有自定义画像或自定义 Prompt 编辑入口；它不会仅因关注词改成其他行业就自动成为其他行业专家。

| 准备项 | 内容 | 用途 |
| --- | --- | --- |

| Z | 可选零余额账号 | 余额提示和 AI 失败 |

| 受控列表网站 | 部署侧已提供、Docker 可访问的测试列表页，包含下表标题及唯一链接 | 不受线上站点改版、反爬影响 |
| 测试联系人 | A/B 各一条独立姓名，初始不启用通知；用自有测试邮箱/手机号/PushPlus | 保存、脱敏、通知隔离 |
| 异常依赖 | 无效站点、返回空列表的页面、阻断抓取或模型的隔离测试环境 | 失败、恢复和停止行为 |

受控列表应至少提供以下记录，全部使用不同 URL，先关闭 AI，仅测试关键词层：

| 标题 | 预期 | 原因 |
| --- | --- | --- |
| 光伏无人机巡检服务采购公告 | 保留 | 含关注、必含，无排除 |
| 风电无人机巡检服务采购公告 | 保留 | 同上 |
| 光伏无人机设备大疆采购公告 | 排除 | 命中排除词 |
| 光伏组件建设采购公告 | 排除 | 未含无人机 |
| 农业无人机植保服务公告 | 当前实现可能保留 | 必含词命中也加入匹配结果，关注词并非额外必需条件 |

关键词层会比较标题和抓到的正文；部分通用站点只提供标题，不代表抓取到公告全文。
自定义通用爬虫从列表所有链接提取记录，日期默认抓取当天；测试“今日新增”不能等同于原公告的真实发布日期或今天入库条数。

## 4. 页面与控件

| 页面 | 真实操作 | 核对内容 |
| --- | --- | --- |
| 控制台 | 刷新、开始、停止、立即检索一次、清除日志 | 运行状态、今日新增/轮数/总计、下次倒计时、进度与当前网站 |
| 结果 | 点击标讯标题原链接 | 默认最多 50 条，发布日期倒序；无 UI 翻页/导出 |
| 网站 | 内置网站勾选、全选/取消全选、保存网站配置；添加/删除自定义网站 | 网站名称、URL、启用项保存 |
| 联系人 | 添加、编辑、删除、启用开关、测试 | 姓名、手机、邮箱类型/授权码、PushPlus Token |
| 配置 | 关注、排除、必须包含、间隔、Selenium、保存 | 当前账号配置持久化 |
| 配置弹窗 | 短信 API、语音 API、AI 智能分析 | 开关、参数、保存、测试；测试会发真实外部请求 |
| 危险操作 | 清空历史数据 | 删除当前账号标讯，不是清日志 |

页面约每 5 秒刷新状态和日志；顶部“刷新”主要刷新这两项，结果需切到结果页重新加载。
Selenium 默认关闭，当前卫星镜像不自带 Chrome/Chromedriver；开启开关不能证明浏览器依赖存在。

## 5. 主流程 A：保存配置和单次检索

1. A 主站重新登录，点“AI 找标投标”。
   - 预期：进入本地 8081，有 `yibiao_session`，业务接口识别 A；不要求填写模型 Key。
2. 打开“配置”，填测试关键词和 5 分钟，保持 Selenium 关闭。
   - 预期：输入完整显示；关键词使用英文逗号分隔。点击“保存配置”后必须检查 HTTP 成功并重新进入配置，不能只凭提示框判保存成功。
3. 打开“AI 智能分析”，关闭 AI 并保存。
   - 预期：关闭状态刷新后保留；先建立无模型费用的关键词基准。
4. 在“网站”取消全选，点“保存网站配置”；添加受控列表的名称和完整 URL。
   - 预期：内置列表为空选，自定义网站显示；刷新后仍存在。没有现成受控站时记录“数据源阻塞”，不要用当天线上无结果判功能失败。
5. 在“联系人”添加 `QA-A`，不启用通知，不填写真实第三方凭据。
   - 预期：联系人出现，刷新可见；后续无通知到生产对象。
6. 返回控制台，点“立即检索一次”。
   - 预期：立即响应“已开始检索”，日志增加手动触发、HTTP 模式、网站进度；等待完成，不能把请求已接受当抓取已完成。
7. 观察日志、统计和结果页。
   - 预期：显示抓取数、新匹配数和完成轮数；结果包含对应匹配项；总计与 `/api/results` 一致。农业无人机项单独记录当前匹配语义。
8. 再次“立即检索一次”，列表内容保持不变。
   - 预期：以 URL 的哈希去重，旧标讯不重复入库；第二次新增应为 0。标题相同但 URL 不同仍可能算新记录。
9. 点击结果标题。
   - 预期：新窗口打开该记录原 URL，标题/来源与受控页面一致；系统不提供站内全文和投标资格判断页面。
10. 刷新整个网页，检查配置、联系人、自定义站和结果。
    - 预期：这些保存数据还在；单次检索结束后恢复“已停止”，没有自动开始持续调度。

## 6. 主流程 B：持续监控、停止和并发

1. 仍用受控站、AI 和通知关闭，确认间隔为 5 分钟。
   - 预期：只当前账号启动；不影响 B 的状态。
2. 点“开始”。
   - 预期：开始按钮禁用、停止可用，立即执行第一轮；第一轮完成后显示下次时间和倒计时。
3. 比较完成时间和下次时间。
   - 预期：下一轮按**本轮完成后加间隔**安排，不是固定从开始时刻每 5 分钟并发启动。
4. 等一个周期，确认下一轮。
   - 预期：轮数增加，未新增标讯不反复插入，不出现多份同用户调度器。
5. 在抓取过程中点击“停止”。
   - 预期：立即标已停止、清下次时间；日志可能提示等待当前检索中断。正在网络等待的站点不保证立刻退出，之后不得继续下一轮。
6. 再开始并重复点击开始，抓取时点“立即检索一次”。
   - 预期：已运行/已有任务应被识别，不重复启动。同一用户的重复单次调用返回失败状态/消息，不等同成功抓取。
7. A 正在检索时，B 从自己的会话启动/停止独立测试任务。
   - 预期：日志、进度、停止事件和调度独立，B 停止不截断 A；后台任务费用仍归原用户。
8. 关闭浏览器后从新页面重新登录查看。
   - 预期：关闭页面不是“停止监控”；后台任务是否仍运行必须查状态。测试结束显式点击停止并确认无下次时间。

服务重启恢复结果/配置与恢复调度是两件事；当前没有自动恢复全部用户运行任务的承诺。重启专项只在另行授权的测试环境执行，本次文档改写未操作容器。

## 7. 主流程 C：AI 相关性分析

1. A 在“配置 → AI 智能分析”启用并保存。
   - 预期：模型通道显示服务端 Sub2API，公开模型显示 `gpt-6-astra`；无可输入 API Key 控件。
2. 在预算允许时点“测试”。
   - 预期：先保存当前 AI 配置，再发真实 `/api/test/ai` 请求；成功返回原因文字，日志记录模型。相关性为 false 也可以表示连通测试成功。
3. 用两条关键词都能命中的测试标讯运行一次：无人机巡检服务、单纯无人机设备采购。
   - 预期：默认画像通常保留巡检服务、排除单纯设备；以真实响应记录，不以非确定性的模型回答做固定字符串断言。
4. 在日志检查关键词匹配、AI 通过和 AI 拒绝汇总。
   - 预期：拒绝条目不入结果，原因可在日志观察；结果列表本身没有 AI 原因列。
5. 记录主站用量和余额。
   - 预期：当前 A 的真实分析记到 A，模型与实际服务端配置一致；每条候选可能独立请求模型，重复抓取已存在标讯也可能再次先分析后去重。
6. 在隔离环境模拟模型超时、502 或非标准 JSON。
   - 预期：连通测试明确失败；正式筛选遇到部分模型请求异常可能保留候选并记“AI异常”，不能报告所有保留项都经可靠 AI 审核。

AI 内容截取到正文前 800 字，默认服务画像固定。没有自定义画像 UI、完整标书理解、截止日期校验或自动投标承诺。
缺少卫星身份/项目凭据/中转地址属于配置错误，应阻断并记录，不得回退共享 Key；正常模型网络故障的保留逻辑需与身份错误区分。

## 8. 主流程 D：联系人和通知

1. 添加测试联系人，姓名必填；按需填写自有手机、邮箱类型/授权码或 PushPlus Token。
   - 预期：保存后列表可见；重新读取凭据应脱敏为 `***`，不是返回实际授权码/Token。
2. 编辑只改姓名，保持密码/Token 空白或脱敏值，保存再读取。
   - 预期：服务端保留原有凭据，其他字段正常更新；不把 `***` 当真实密钥存入。
3. 短信/语音弹窗填约定测试配置，先保存后测试。
   - 预期：缺参数/号码返回明确错误；真实配置的测试会联系测试号码并可能收费。
4. 邮箱先保存到联系人，再点击测试；PushPlus 仅填测试 Token。
   - 预期：邮箱测试查找已保存联系人授权码，发给该测试邮箱；微信发送到指定测试通道。
5. 联系人弹窗有手机号时点击“测试”。
   - 预期：当前前端会依次测试短信和语音，**不只测试已开启的渠道**；执行前核预算和号码，不能用禁用开关推断无外发。
6. 将测试联系人设禁用，正式监控出现新标讯。
   - 预期：正式通知跳过禁用联系人；启用后只给本人测试对象发送。无新增不应重复发通知。

新账号默认邮件和短信开关可能开启，AI 在管理接入模式也默认启用；不要假设首次登录一定零调用。开始检索前检查实际配置。

## 10. 边界和故障专项

1. **关键词语义**：分隔器为英文逗号；中文逗号、空项、大小写、空全部关注词需回归。必含列表实际“至少一个”，不是每项都需含；必含命中也能构成匹配，不宣称“关注 OR 与必含 OR 必须同时命中”。
2. **跨标题/正文**：匹配逐段处理，任何段命中排除则整体排除；关注词在标题而必含仅在正文的组合不保证按拼接全文规则处理，用测试样本固定实际语义。
3. **间隔**：UI 标 min=5、max=120，但保存函数/后端未见对应强约束；0、负数、空值、121 应只在隔离环境测试并登记，不按 UI 属性判服务端必拒绝。
4. **抓取依赖**：403、验证码、动态页面、登录需求、改版、TLS/网络错误分站点记录；一个源失败不应等于全部源成功，也不以“空列表”推断反爬。
5. **自定义站**：通用解析会抓导航类链接、日期用当天；有效 URL/协议的验证目前有限。不要把保存成功当站点可抓取或公告日期准确。
6. **统计**：今日新增按 `publish_date` 与服务端当天比较；UI 日期/倒计时还受容器时区影响，执行记录注明 Asia/Shanghai 与容器时区差异。
7. **接口与 UI**：多个保存/测试函数未统一检查 `res.ok`，HTTP 401/400/500 可能仍出现保存提示或 `undefined`；查网络响应、回读后才能判成功。
8. **模型异常**：筛选支持网络重试，最长可明显超过单请求时间；非标准 JSON 文本兜底可能把“不相关”误判为相关，登记原始脱敏响应与最终结果。
9. **日志和结果**：UI 日志最近 50 条、结果默认 50 条，无完整导出/翻页按钮；后台结果 API 支持 limit/offset 仅供接口验证，不写成页面功能。
10. **删除**：清历史只对少量可丢测试数据，先停止任务并导出必要证据；取消确认应无删除请求，确认后 B 不受影响。日志是内存状态，不能当长期审计库。

## 11. 身份、余额和收费验收

- 新 `yibiao_session` 的服务端和 Cookie 期限均应为 259200 秒，HttpOnly；短时 SSO 票据不能重放。未登录业务 API 应 401，配置缺失模型测试应 503，上游故障测试应 502。
- A/B 分别设置独有关键词、站点、联系人，分别抓不同结果；刷新、后台线程、调度回调、清除操作均不得看到/修改对方数据。管理员从主站进入仍按自己的普通卫星身份测试。
- 余额同源 `/api/sub2api/balance` 不缓存；零余额红色提示，充值只到公开主站 `/purchase`。先核对支付开关，本手册默认只验跳转，付款需单独约定测试范围。
- 关闭 AI 的普通 HTTP 抓取不应产生模型费；AI 测试、逐候选分析可能收费，重复结果也可能先分析。核对请求数与 A 用量、B 不代扣；短信/语音服务费用单独核。
- 浏览器不得出现主站 JWT、SuperKey、用户模型 Key、服务端凭据和身份代调头；测试联系人凭据允许输入但回读必须脱敏，不在截图/缺陷中粘贴。
- 关闭页面/Session 过期是否停止已启动任务需作为待测行为记录；源码后台调度保留原 subject，不应以页面关闭推断停止。测试结束显式停止 A、B 的任务。

## 12. 执行记录与缺陷模板

| 日期/执行人 | 镜像/源码 | 账号 | 数据源/AI/通知 | 用例 | 结果 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| 待填写 | 待填写 | A/B/Z | 测试站/开关状态 | YB-xx | 未执行/通过/失败/阻塞 | 脱敏配置、日志、HTTP、主站用量 |

```text
标题：[AI找标投标][版本][YB-xx] 实际问题
前置：账号、关键词三组、网站、Selenium、AI/通知开关、余额

实际：结果/日志、HTTP 与界面差异、运行状态、异常费用

影响/次数：错标讯、错通知、串账号、删除数据及复现次数
```

## 13. 测试结束与清理

1. 保存测试网站内容、关键词/AI/通知开关、日志时段、结果 URL、脱敏通知与费用证据；失败场景保留最小输入用于复测。
2. 分别以 A、B 点击“停止”，核对无下次执行时间，并等待正在网络请求的检索结束。关闭浏览器不能替代停止后台监控。
3. 仅删除本人建立的测试网站和联系人；清日志与清历史是两种操作，先确认数据均为可丢测试数据，再按界面确认范围清除，不清空共享数据库。
4. 恢复本轮在隔离环境更改的 AI、Selenium、通知和间隔配置，确认没有面向真实号码、邮箱或公众号的待执行测试。保留缺陷所需结果与证据，不删除其他用户数据。
