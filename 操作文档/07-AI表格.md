# 07. AI 表格测试操作手册

## 1. 基线与验收范围

- 应用目录：`aiexcel/`；依据 **2026-10-08 当前工作区源码，包括尚未提交的更新**编写。
- 本地入口：[AI 表格](http://localhost:4173)；主站：[Sub2API](http://localhost:18080)。正常入口为主站左侧“AI 表格”，SSO slug 为 `aiexcel`。
- 本次核对源码、界面结构和已有测试，**没有完成浏览器全流程、真实模型和计费实测**。“预期”是待执行验收条件，不表示已经通过。
- 本地 Docker 镜像可能早于工作区源码；执行前记录镜像标签、构建时间及代码版本。按钮或模型不同先记录版本差异，再判断缺陷。
- 本地主站曾导入线上数据库，执行前重新登录并核对当前支付、主动监控、OAuth 自动刷新开关；后续项目更新可能改变配置，不能假设这些开关仍关闭。使用独立测试用户和脱敏文件。
- P0 为登录、数据正确性、隔离和收费阻断项；P1 为主要业务回归；P2 为兼容和体验项。

## 2. 准备账号与工作簿

| 准备项 | 内容 | 用途 |
| --- | --- | --- |
| 用户 A、B | 两个独立 Sub2API 测试账号，分别使用独立浏览器配置或无痕窗口 | 身份、余额、用量隔离 |
| 用户 Z | 可选的零余额测试账号 | 余额提示及模型拒绝 |
| `QA-销售.xlsx` | 第 1 行表头：商品、数量、单价；第 2 行苹果、10、5；第 3 行香蕉、20、3 | 公式、修改、撤销和导出 |
| `QA-租房.xlsx` | Sheet“租房”；第 1 行标题、第 2 行空白，第 3 行表头：省份、租房价格、飞机、高铁、普铁 | 非首行表头及新操作 |
| 租房数据 | 第 4 行黑龙江、1000、空白、有、空白；第 5 行黑龙江、2000、有、空白、空白；第 6 行吉林、3000、空白、有、有 | 填空、排序、高亮、统计基准 |
| `QA-分页.xlsx` | 1201 行、3 个 Sheet，记录第 499、500、501、1001 行唯一标记 | 分页和全表范围 |
| 兼容与异常文件 | 真实 `.xls`、损坏 `.xlsx`、改扩展名的文本、空表、含公式/日期/合并单元格的表 | 导入导出兼容 |
| 大文件 | 低于、等于及高于 5 MiB 的 `.xlsx`，第 1000 行以后保留哨兵 | 延迟加载不丢尾部 |

默认文本公开模型为 `gpt-6-astra`，默认低思考档；服务端可用 `SUB2API_RELAY_MODEL` 覆盖，浏览器没有可编辑的模型或 API Key 设置。
AI 请求需要有效卫星 Session、完整中转配置、可调度上游及用户额度。发送指令就会请求模型，即使随后取消计划也可能产生费用；真实验收应事先确认测试预算。

## 3. 当前页面和控件

| 位置 | 可操作内容 | 核对重点 |
| --- | --- | --- |
| 首页 | 选择文件、拖放 `.xlsx/.xls`、连接设置、余额 | 打开文件不调用 AI |
| 工作区顶部 | 返回首页、撤销、重做、历史、导出 Excel、设置 | 返回有未导出修改丢失确认 |
| 表格上方 | 单元格地址、只读公式栏、在工作表中搜索 | 点击只能选择，不能直接编辑 |
| 表格底部 | Sheet 标签、前后分页、60% 至 160% 缩放 | 每页预览 500 行；渲染数据最多 80 列 |
| AI 助手 | 美化报表、智能分析、检查公式、聊天、计划、取消、确认执行 | 快捷按钮只填指令，仍需发送 |
| 筛选表头 | 升序、降序、条件筛选、显示全部数据 | 菜单操作直接本地执行 |
| 研究报表 | 平均、最高、最低、样本数，升降序，条形详情 | 交互图最多 24 组，内嵌图片最多 16 组 |

连接设置目前是接入说明和关闭按钮，不是连通性探测器；“Sub2API 已接入”不能证明模型可用。
Sheet 菜单图标当前无业务处理，不应写成新增、重命名、删除 Sheet 的入口。

## 4. 主流程 A：公式、计划确认与导出

1. A 在主站重新登录，点“AI 表格”。
   - 预期：到达本地 4173，完成 SSO 后使用 `aiexcel_session`；无需填写 API Key。
2. 点击“选择文件”，选择 `QA-销售.xlsx`。
   - 预期：文件名、Sheet 数、内容正确；苹果第 2 行、香蕉第 3 行。网络中没有原工作簿上传请求。
3. 点击 C2，查看地址和公式栏；切换 Sheet 后返回。
   - 预期：地址 C2，内容 5；选择和切换不改变数据。
4. 输入“在当前表新增金额列，公式为 B2*C2，填充所有数据行”，发送。
   - 预期：显示“正在理解你的需求”，同源 `POST /api/ai`；返回计划等待确认，表格尚未改变。
5. 核对计划类型、新列名和公式，第一次点“取消”。
   - 预期：计划不再可执行，内容和 Sheet 数不变；取消不撤销已经发生的模型费用。
6. 再发送同一请求，审阅计划后点“确认执行”。
   - 预期：金额标题出现，D2 为 `=B2*C2`、D3 为 `=B3*C3`；执行成功，历史新增一项。
7. 点击“撤销”、再“重做”；打开“历史”，选择“打开工作簿”。
   - 预期：撤销恢复修改前，重做恢复公式列，导入历史中金额列消失。
8. 恢复含金额列的版本，点“导出 Excel”。
   - 预期：下载 `QA-销售-AI优化.xlsx`，原文件没有被覆盖；导出不是服务端保存。
9. 用 Excel 或兼容程序打开下载文件并重新计算。
   - 预期：苹果金额 50、香蕉 60，公式和行数正确。浏览器显示公式文本，不能仅据预览验计算值。
10. 导出后刷新，再导入下载文件。
    - 预期：刷新回到上传页，聊天和可恢复历史未持久化；重新导入才能恢复内容。

## 5. 主流程 B：非首行表头与完整数据处理

每个用例从原始 `QA-租房.xlsx` 独立开始，避免排序、删除改变后续行号。

1. 导入工作簿，确认第 3 行为表头。
   - 预期：`headerCandidates` 包含真实表头；原文件不整体上传，但表名、字段、样例及最近聊天会发送。
2. 发送“租房表第 3 行是表头，从第 4 行起，把飞机、高铁、普铁三列全部空白填为无，已有值不改”。
   - 预期：计划 `fill_blank` 包含三列，`headerRow=3`、`startDataRow=4`；不是仅列举样例的 `set_cells`。
3. 执行并导出抽查。
   - 预期：C4、E4、D5、E5、C6 为“无”，原有“有”保留；分页文件尾部指定列也处理，其他列不改。
4. 发送“为第 3 行表头添加筛选和排序按钮”，确认执行。
   - 预期：`enable_filter` 让第 3 行非空字段出现按钮；仅添加控件不改行序。
5. 打开“租房价格”表头菜单，点“降序排列”。
   - 预期：顺序为吉林 3000、黑龙江 2000、黑龙江 1000；整行一起移动，标题和表头不排序。
6. 选择“大于”，输入 1500，点“应用筛选”。
   - 预期：只显示 2000、3000；隐藏不是删除。菜单有文本包含、等于、不等于、大于、小于、空白、非空白。
7. 点“显示全部数据”。
   - 预期：隐藏行恢复，表头按钮保留，行数一致。
8. 在原始表发送“第 3 行是表头，省份为黑龙江的所有数据整行标绿色，背景 C6EFCE，文字 006100”。
   - 预期：`highlight_rows` 让黑龙江记录整行变色，吉林不变，不能仅标省份单元格。

顶部搜索只查当前页已加载预览，不同于 `filter_rows` 全表筛选，也不改 Excel 行隐藏状态。
“美化报表”按第 1 行美化和冻结，不自动识别第 3 行表头，应分开测试。

## 6. 主流程 C：研究报表与大文件

1. 导入原始租房表，发送“第 3 行表头，第 4 行起按省份汇总租房价格，在新 Sheet 省份租房价格研究生成样本数、平均、最低、最高、图表和研究选项”。
   - 预期：`create_dashboard` 使用“省份”和“租房价格”；`create_analysis` 仅简单行列统计，不满足该用例。
2. 确认执行，检查自动切换到新 Sheet。
   - 预期：黑龙江样本 2、平均 1500、最低 1000、最高 2000；吉林样本 1、平均/最低/最高 3000；总有效记录 3。
3. 切换平均、最高、最低、样本数，切升降序，点黑龙江条形。
   - 预期：排序和详情符合基准，无额外模型请求，原始 Sheet 不变。
4. 导出并用 Excel 打开。
   - 预期：包含新 Sheet、五列统计、柱状图片、研究选项；浏览器交互控件不是 Excel 可交互图表。
5. 导入 >=5 MiB 的 `.xlsx`，不修改直接导出。
   - 预期：快速预览提示、前 500 行、分页暂禁用；下载使用原文件名和完整原文件，尾部不丢失。
6. 发送明确的非删除修改，审阅后执行，等待完整簿加载。
   - 预期：完成后分页可用，导出为 `-AI优化.xlsx`，尾部哨兵和目标修改正确。
7. 普通 1201 行文件翻到第 2、3 页，再切换 Sheet。
   - 预期：绝对行号连续不重复，切 Sheet 回第 1 页。后页 AI 指令需明确真实表头行；schema 样例行号受分页影响，列为专项回归。

## 8. 边界、负向与故障

1. **格式和体积**：CSV、PDF、伪 xlsx、损坏文件提示失败；50 MB 是建议值，当前不是硬性限制，不按“50 MB 必拒绝”断言。
2. **结构**：空表、空表头、重复字段、表头在第 10 行以后、合并单元格、隐藏行列、跨表公式分别记录；有限样例不保证结构理解正确。
3. **公式**：`add_formula` 默认第 1 行表头、第 2 行起；非首行表头用明确范围 `set_formula`。公式需外部程序重算。
4. **统计解析**：`2000-3000` 取中点、`2万` 换算、无/未知/面议跳过；空分组继承前一分组。负数、百分比、货币混合独立对照人工值。
5. **同名报表**：新建同名研究/分析 Sheet 替换旧 Sheet；先留副本，验覆盖后源表未损坏。
6. **模型失败**：无 Session 401，缺中转/凭据 503；上游 404、非 JSON、无效计划显示错误，不能显示执行成功。
7. **并发**：同一用户两标签同时请求，第二次应 429；原请求结束后能重试。B 不受 A 的用户锁阻挡。
8. **多步失败**：执行器没有整计划事务回滚，前一步可能已修改。检查数据，用历史或原文件恢复；“未标记成功”不等于完全未改。
9. **持久化**：仅历史标题元数据写 `localStorage`；工作簿、聊天、快照不刷新恢复。研究交互状态未从导入或撤销快照重建。
10. **浏览器异常**：断网、刷新、内存不足前先导出；没有后台任务恢复或云端簿列表。

## 9. 身份、隔离、余额与收费

- A、B 用独立浏览器上下文；工作簿仅在页面内存，没有服务端列表。另测同浏览器切账号后旧页内容，当前没有按身份自动清空工作簿的保证。
- 新 `aiexcel_session` 和 Cookie TTL 应均为 259200 秒、HttpOnly；票据不能复用。过期 AI 请求拒绝，主站菜单重新进入恢复。
- 浏览器同源 `/api/ai`、`/api/sub2api/balance` 不应出现 SuperKey、用户 API Key、主站 JWT 或服务端凭据。样例发送是实际设计，不能宣称零数据出站。
- 余额不得缓存；零余额红色充值提示；充值只到公开主站 `/purchase`。执行前核对支付开关，本手册默认只验跳转，不进行付款。
- 真实规划核对 A 的主站用量与余额；上传、导出、撤销、筛选菜单不应有模型费用，B 不代扣。
- 零余额、过期身份、无可用上游分别记录 UI、HTTP 状态和用量；取消计划不能要求退回已发生规划费。

## 12. 测试结束与清理

1. 导出需要保留的测试工作簿，保存原文件、优化文件、关键单元格对照、脱敏网络记录和本人用量证据；记录文件路径及执行版本。
2. 等本人 AI 请求结束后关闭测试页面，注销测试会话；刷新会丢失内存工作簿和历史，必须先保存证据。
3. 只删除本人本轮产生且不再需要的测试下载副本；不覆盖原始素材，不清除他人的浏览器数据、主站用量或账号，也不因测试清理删除卫星容器/卷。
