# 08. 艺术二维码测试操作手册

## 1. 基线与验收范围

- 应用目录：`qrcode/`；本手册依据 **2026-10-08 当前工作区源码**，包括当前未提交的样式和余额组件更新。
- 本地入口：[艺术二维码](http://localhost:5221)；主站：[Sub2API](http://localhost:18080)。正常从主站左侧“艺术二维码”进入，SSO slug 为 `qrcode`。
- 本次仅核对源码、UI 与已有测试，**未完成浏览器全流程、真实生图、扫码及微信素材实测**。下文预期均待执行，不代表已通过。
- Docker 可能仍运行较旧镜像，执行前记录镜像标签、构建时间和源码版本；运行界面不同先登记版本差异。
- `qrcode/AGENTS.md` 规定项目冻结，本次只改本手册，未改二维码源码、密钥、模型或部署。
- 本地主站曾导入线上库，执行前重新登录并核对当前支付、主动监控、OAuth 自动刷新开关；用户后续更新可能改变配置，不把历史关闭状态当作现状。生成可收费，微信上传会写素材，须使用约定的测试预算与测试公众号。
- P0 为扫码有效性、结果对应、身份和计费；P1 为主要流程；P2 为兼容和体验。

## 2. 当前链路必须区分

| 阶段 | 真实实现 | 测试判断 |
| --- | --- | --- |
| URL 转普通二维码 | 本地二维码生成接口，不抓取目标网页正文 | 检查二维码解码值，不把 URL 生成当网页可访问验证 |
| “艺术化二维码” | 默认 `stylizeQrImage` 使用旧 `open-qr.mewx.art` 生成/详情接口，模型 `67` | 有卫星登录校验，但此默认服务不按 Sub2API 公开图片调用记账；需单独核对供应商费用 |
| 模板、裁剪、上下文预览 | 图片处理和合成，不调用 AI | 调位置只应刷新上下文，不产生新生图任务 |
| “生成二维码”最终盘面扩图 | 服务端调用 Sub2API `/v1/images/edits`，默认公开模型 `gpt-image-2` | 核对当前用户模型用量、中心二维码和模板外观 |
| 微信素材 | 微信 token、上传、列表、下载接口 | 公众号凭据与模型凭据是两类不同配置 |

前端“服务端思路 / 调试链路”是固定文字，仍宣称艺术化使用 Sub2API `gpt-image-2`，与当前默认服务不一致。
“实际提示词”也由初始固定文字展示，可能不同于修改后真正提交的 Prompt。验收应以脱敏请求及服务端响应为依据，发现不一致登记缺陷，不修改冻结链路。
页面提到自动同步微信，但当前生成完成后需手动点上传按钮，不能按“生成即自动上传”验收。

## 3. 账号与素材准备

| 项目 | 准备内容 | 判定基准 |
| --- | --- | --- |
| A、B | 两个 Sub2API 测试账号，独立浏览器上下文 | 生成任务及最终扩图用量隔离 |
| Z | 可选零余额账号 | 余额提示及最终扩图失败条件 |
| URL-A | `https://example.com/?qa=A` | 每个阶段解码均应保持该字符串 |
| URL-B | `https://example.com/?qa=B` | 排查沿用上一张二维码 |
| 普通二维码 | URL-A 的清晰 PNG，另准备 JPG、WebP、带白边图 | 输入、裁剪、艺术化回归 |
| 模板 | 内置青花瓷盘；另准备非方形、本地小图、白底模板 | 默认居中、换图和放大行为 |
| 异常素材 | 无二维码照片、损坏图、伪图片、8/15 MiB 边界文件 | 格式和体积失败提示 |
| 微信环境 | 独立测试公众号 AppID/Secret、服务器出口 IP 白名单、唯一素材名 | 素材上传和查询；截图中隐藏凭据 |
| 扫码设备 | 至少两款手机/扫码器，固定距离和亮度 | 原码、艺术码、最终图、压缩图对照 |

保留输入文件、输出下载文件及扫码结果。扫码成功的证据应包含识别设备、距离、耗时和解码字符串，而不是仅记“图片很好看”。

## 5. 主流程 A：URL 到艺术化二维码

1. A 主站重新登录，点“艺术二维码”。
   - 预期：进入本地 5221，SSO 发出 `qrcode_session`；生成不要求用户模型 API Key。
2. 先检查内置模板。
   - 预期：青花瓷盘正常加载，默认选中；当前内置预设位置应为 X=575、Y=670、大小=950，而非 HTML 初始旧值。
3. 选择“输入 URL 地址”，输入 URL-A，点“转换为二维码”。
   - 预期：普通二维码和裁剪区显示；没有生图请求；下载输入图可用。
4. 下载普通码并扫码，记录解码字符串。
   - 预期：精确为 URL-A，包括 `?qa=A`；浏览器能否打开目标页是独立网络检查。
5. 在裁剪区拖框，仅移除额外外边，保留完整定位图形和二维码内容。
   - 预期：X/Y/宽/高随选区变化；框选不越过原图区域；点击未形成有效框时恢复完整图片选区。
6. 在确认生图费用后点“艺术化二维码”，等待结束。
   - 预期：按钮锁定、进度可见；成功后艺术图显示，裁剪区自动切换到艺术图，下载艺术图可用。
7. 下载艺术码，至少用两台设备扫描。
   - 预期：仍解码为 URL-A；不能只以 HTTP 200 或出现图片判成功。失败记录定位点、对比度和裁剪范围。
8. 输入或上传 URL-B 的二维码，再艺术化。
   - 预期：新的输入、艺术码和解码对应 URL-B，不复用 A 的旧图或旧任务。

“艺术化二维码”的默认风格由服务端旧艺术服务配置提供；下方正负 Prompt 主要用于最终盘面扩图，不应认为修改它们就改变旧艺术化模型参数。

## 6. 主流程 B：模板合成、批量生成和下载

1. 从已成功艺术化且可扫码的 URL-A 结果继续，保持内置模板。
   - 预期：上下文图把当前二维码放在模板中心区域，不使用上一张输入。
2. 将 X 增加 10，点向左、放大、缩小，再切方形/圆形。
   - 预期：位置和形状随控件变化，上下文更新；这些操作不请求旧艺术生图或 Sub2API 图片生成。
3. 更换本地模板并查看位置值。
   - 预期：本地模板走旧预设 X=250、Y=270、大小=950，可继续调整；小模板可能被放大以容纳当前框，不保证原尺寸。
4. 保留完整可扫码区域，填正向 Prompt：“只延展盘面四周青花荷花纹理，中心二维码像素、位置与定位图形保持不变”。
   - 预期：输入值实际进入最终生成请求；负向 Prompt 强调不破坏二维码。固定“实际提示词”文字需额外比对。
5. 将生成张数设为 1，点击“生成二维码”。
   - 预期：先完成无 AI 上下文预览，再提交异步 `POST /api/generate`，返回 202 和任务 ID；随后轮询 `/api/generate/jobs/{id}`。
6. 等待任务成功，下载上下文与最终结果，逐项对照。
   - 预期：中心码位置正确，结果可下载，图片大小可见；最终扫码仍是 URL-A，模板内容没有错配。
7. 用约定预算把张数改为 3，再生成。
   - 预期：3 个状态卡从排队到生成中/完成；默认服务端并发为 1，完成一张即显示，无需等待全部成功。
8. 切换每张已完成结果，下载并查看微信上传目标。
   - 预期：主预览、下载图和选中卡一致；默认文件名为对应 `generated-qrcode-N.png`；未完成/失败卡不能当作图片。
9. 人为模拟一张任务失败，仅在隔离测试环境进行。
   - 预期：报告成功/失败数量，已成功图可继续下载和上传；失败不是整批成功，也不抹掉成功结果。
10. 在保存结果后刷新页面。
    - 预期：结果和输入没有持久化恢复；新页面不能宣称自动续跑或重载云端历史。

源码可能允许普通输入直接进入上下文生成，但标准验收先完成艺术化；不以按钮错误文案替代实际请求参数检查。

## 7. 主流程 C：微信素材

该流程会访问微信接口；上传会创建真实素材，仅在明确约定的测试公众号执行。

1. 选一张已成功最终图，填测试 AppID、Secret 和唯一名称 `qa-A-日期-01.png`。
   - 预期：凭据初始空白，Secret 是密码框，没有预填生产凭据；未生成或 >10 MiB 图的上传按钮禁用。
2. 点“上传选中生成图到素材库”。
   - 预期：先自动获取/复用 access_token，再上传当前选中图，过程按钮锁定、进度和成功/失败信息可见。
3. 在“按名称查询”填唯一名称，点“查询并展示图片”。
   - 预期：出现匹配素材表；点对应“查看图片”后加载内容，图片与上传图一致，不只显示远程 URL。
4. 查询不存在的名称。
   - 预期：明确无匹配结果，旧预览清空，不把旧图当新查询结果。
5. 对 >10 MiB 的已生成图点“压缩为微信素材大小”，重新下载并扫码。
   - 预期：服务端准备接口返回尺寸/体积，<=10 MiB 后可上传；压缩图依然解码正确，文件名和真实 MIME 一致。
6. 重复查询同一凭据，观察 token 复用；切换测试公众号，再刷新/关闭页面。
   - 预期：凭据切换清 token，离页清理被触发；新页面不可静默沿用他人的素材访问凭据。

token 与素材缓存目前使用同源 `localStorage`，不按 Sub2API 用户分区；需专门执行同浏览器换号测试。离页事件并不保证崩溃时清理，不能把文字说明当安全保证。

## 9. 边界、失败和已知差异

1. **URL**：空、无协议、ftp、畸形地址应拒绝；Unicode、长查询串应解码精确。转换成功不说明网页存在。
2. **图片**：前端 PNG/JPG/WebP 上限 15 MiB，通用服务端上传上限 8 MiB，旧艺术服务加工 JPG 上限 5 MiB。分别测边界，记录提示不一致；不要宣称 15 MiB 都可生成。
3. **选区**：零面积、反向拖动、超边缘、屏幕缩放、移动触控、方圆切换后扫码；裁剪掉定位点应作为业务失败记录。
4. **张数**：默认 3，1 至 12；代码对 >12 截为 12，非整数/小于 1 回退默认。负向测试用模拟接口，避免意外发起 3/12 次收费请求。
5. **队列和等待**：前端轮询间隔约 2 秒，单张前端等待最多 15 分钟，批次随张数增长。取消浏览器等待不保证服务器任务取消。
6. **任务生命周期**：异步任务存内存，30 分钟清理、服务重启丢失；没有可恢复任务列表。过期查询 404 应提示，而非无限等待。
7. **部分成功**：保留成功图；不要直接整批再点导致重复费用。缺图、非 JSON 响应、断网、超时分别登记阶段和任务 ID。
8. **微信依赖**：错误 AppID/Secret、出口 IP 白名单、token 失效、网络异常、无素材、压缩仍超限须显示具体诊断，不能把失败写成上传成功。
9. **自动化文字**：未实现生成后自动微信上传；当前 Prompt/调试文字固定；默认艺术化仍是旧服务。这些均需在实测中记录影响。
10. **权限范围**：源码对生成、艺术化、任务查询和余额显式校验身份；URL 转码、预览和部分微信路由未显示同样检查。公共规范要求相关业务隔离，需测试其实际行为，不能预先判通过。

## 10. 身份、余额与执行证据

- 新 `qrcode_session` 应为 HttpOnly、Max-Age=259200 秒，服务端过期时间同为 3 天；重放 SSO 票据应失败，失效 Session 生图应 401。
- A/B 独立浏览器检查任务结果、余额和最终扩图用量；再用同一浏览器换账号检测素材缓存、旧图是否残留。
- 任务 ID 的本人归属校验仅覆盖本应用异步最终生成任务；旧艺术化使用共用供应商配置，微信素材按公众号凭据访问且浏览器缓存未按主站用户分区。A/B 测试是待验隔离要求，不能据此宣称供应商账户、微信素材或全部路由已经隔离。
- 余额同源接口不得缓存；零余额标红，充值只跳公开主站 `/purchase`。执行前核对支付开关，本手册默认只验跳转，不进行付款。
- 浏览器、下载名称、URL 和日志中不得出现 SuperKey、主站 JWT、用户模型 Key 或项目凭据。微信 Secret 必须从证据中脱敏。
- 旧艺术阶段不走普通 Sub2API 图片计费路径，不能根据主站没扣费断言免费；最终 `gpt-image-2` 阶段核对 A 用量，B 不代扣。
