# aicut 对接 Sub2API 流程文档

> 强制约束：模型请求只能由当前 HttpOnly Session 映射出的用户身份发起。服务端必须发送应用凭据、`X-Sub2API-On-Behalf-Of` 和 `X-Sub2API-Satellite`；缺少 Session 不得回退到共享 Key 或 SuperKey。

| --- | --- | --- |
| aicut | aicut | http://localhost:5199 |
| Sub2API | sub2api-dev | http://localhost:18080 |

aicut 和 Sub2API 使用 Docker 网络 deploy_sub2api-network。aicut 容器内必须使用 SUB2API_BASE=http://sub2api:8080，浏览器使用 http://localhost:5199。

## 3. SSO 配置

aicut/.env 的关键变量：

~~~env
SUB2API_BASE=http://sub2api:8080
SUB2API_SSO_SECRET=<与 Sub2API 完全相同、至少 32 字节的随机密钥>
OPENCHATCUT_SSO_CALLBACK_URL=http://localhost:5199/api/auth/sso/callback
OCC_SESSION_SECRET=<aicut 自己的会话签名密钥>
OCC_SECURE_COOKIE=0
OCC_OPEN_REGISTER=0
~~~

生产 HTTPS 环境将回调地址改为 https 地址，并设置 OCC_SECURE_COOKIE=1。SUB2API_SSO_SECRET 只用于跨服务 SSO；OCC_SESSION_SECRET 只用于 aicut 的 occ_session，不能混用。

## 4. 点击 AI 剪辑后的流程

1. Sub2API 菜单调用 GET /api/v1/auth/integrations/aicut/start?next=%2F。
2. Sub2API JWT middleware 验证当前用户。
3. Sub2API 在服务端解析该用户的 SuperKey，但 ticket 只包含身份字段（不包含 rk 或任何 Key）。
4. Sub2API 创建短期 ticket，包含 iss、aud、sub、email、iat、exp、jti 和 next。
5. ticket 使用 HMAC-SHA256 签名。
6. 浏览器跳转到 aicut GET /api/auth/sso/callback?ticket=...。
7. aicut 校验签名、issuer、audience、时间窗口和一次性 jti，并把 sub 映射到本地用户。
8. aicut 只保存本地用户映射，签发 HttpOnly occ_session Cookie，然后跳转到站内路径 /。

实现位置：sub2api/backend/internal/handler/aicut_sso.go、sub2api/backend/internal/server/routes/auth.go、aicut/server/gateway/sso.ts、aicut/server/gateway/plugin.ts。

浏览器只携带 aicut 的 occ_session，不直接携带 Sub2API JWT、SuperKey 或用户 API Key。

## 5. LLM 中转和计费

请求链路：

~~~text
浏览器/编辑器 -> aicut /llm -> 当前 occ_session -> 当前 Sub2API subject
-> Authorization: Bearer <SUB2API_APP_CREDENTIAL>
   X-Sub2API-On-Behalf-Of: <subject>
   X-Sub2API-Satellite: aicut -> http://sub2api:8080/v1
-> Sub2API 选择上游并记录用量
~~~

Sub2API API Key 和 usage_logs 都带有 user_id/api_key_id，使用量还包含模型、Token 和 cost。因此用户 A 和用户 B 的 LLM 用量按用户分别计费，不会合并到共享服务账号。

关键实现：aicut/server/plugins/llm-proxy.ts。网关模式下目标永远是 SUB2API_BASE/v1；没有用户 Key 直接 401。

## 6. 当前中转边界

## 9. 黑屏问题排查和修复

HTML 曾返回 200，但 root 为空。Chrome 控制台错误为：

~~~text
Uncaught ReferenceError: $RefreshReg$ is not defined
~~~

原因是 Docker 运行 Vite 长驻服务时，React TSX 模块仍带 Fast Refresh 注册调用，而入口没有 HMR runtime，icons.tsx 抛错后 main.tsx 没有完成 render。

修复：

- config/vite.config.ts 使用 react({ fastRefresh: false })。
- index.html 在 main.tsx 之前提供无副作用的 $RefreshReg$ 和 $RefreshSig$ 兼容桩。
- 重新构建并覆盖 aicut:workspace。
- Chrome 无头截图已确认显示 cut000 登录界面，容器接口返回正常。

## 10. 后续建议

1. 生产环境使用 HTTPS，并设置 OCC_SECURE_COOKIE=1。
2. 将两个密钥放入 Docker secrets 或外部密钥管理，不提交到公开仓库。
3. 多实例部署时，将一次性 ticket 消费记录从进程内 Map 迁移到 Redis。
4. 长任务使用 Redis/BullMQ 或 Redis Streams；数据库保存最终状态和用量账本，队列消息只保存任务引用，不保存明文 API Key。
