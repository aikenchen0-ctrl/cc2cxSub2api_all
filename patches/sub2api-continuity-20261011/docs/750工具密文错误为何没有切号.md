# 750工具密文错误为何没有切号

核查日期：2026-10-11，香港时间；源码与已部署 `eb623f4` 一致。本文区分06:24—07:26的事故证据与09时复查的当前配置，不能将当前配置倒推为每个历史时刻的状态。

<重表述提示词为问题>既然目标是一个上游失败后同组快速恢复，为什么750返回工具密文解码失败后没有换号？是次数或时间门槛、配置问题、错误分类问题，还是尚未实现上下文迁移？</重表述提示词为问题>

## 直接原因：错误没有进入换号分支

上游事件的三个字段为：

```json
{
  "code": "invalid_encrypted_content",
  "type": "invalid_request_error",
  "message": "Encrypted function output content could not be decrypted or decoded."
}
```

`service/openai_gateway_passthrough.go` 中 `openAIStreamFailedEventShouldFailover` 对 `response.failed` 按错误语义分类。该样例不是认证拒绝、429、已识别的暂时处理错误或普通5xx；组合字段命中 `invalid_request` 后返回false。普通流和自动透传流都使用该判断。因此不会生成供处理器执行同组切换的 `UpstreamFailoverError`，而是记录并交付失败事件。

这条分支不读取账号的 `fast_failover` 开关。**即使给750打开快速切换，只要收到同样的事件，当前代码仍不会切号。** 此前完整Forward回归测试已用 `fast_failover=true` 的模拟账号复现：普通与自动透传路径都只发送一次，保留失败原文，不登记为成功。

不是错误累计到多少次才切，不是在等冷却时间，也不能因为客户端显示“断流”就将底层请求错误等同于网络断流。

## 当前配置还有两个独立限制

09时只读数据库复查分组32：

| 项目 | 当前事实 | 影响 |
| --- | --- | --- |
| 750快速切换 | `credentials.fast_failover`未设置 | 不适用需要显式开关的通用快速策略；不代表普通5xx永远不会走既有切换 |
| 750调度状态 | active，schedulable=true | 当前允许选择 |
| 分组32其他未删除账号 | 全部schedulable=false | 即使进入切换，也没有允许调度的备用 |
| 744 | fast_failover=true，但schedulable=false | 标记为快速切换不等于账号当前允许调度 |
| 751、752 | active，但schedulable=false | 账号存在不等于可作为备用 |
| 753 | error，schedulable=false | 不可作为备用 |

本次没有修改账号开关，没有替用户重新启用禁调度账号。事故日志已证明108次请求没有发生切号；当前候选池事实只是额外解释当前不能换到哪里，不能替代事故路径证据。

## 目标与实现之间的缺口

用户的目标是客户不因上游切换而中断。当前已实现普通账号故障的有限重试与换号，但没有实现任意工具密文状态的跨上游迁移。将“已实现快速切换”表述为“所有密文故障都能无感恢复”是不准确的。

工具密文错误本身不能证明750整体不可用，也不能证明另一个账号一定能够解释相同状态。同样的字节在其他上游可能成功，也可能重复失败；不能仅按账号ID相同或不同断言兼容性。直接上游内部还可能再次调度到不同凭据，这不在本网关控制范围。

如果已有**同组可调度、能力匹配且有证据接受该状态的目标**，并且当前尚未向客户端交付内容、没有不确定的服务端工具副作用，则受限地保持原文切换有合理性。该针对工具密文的受限恢复分支目前没有实现，不能声称现有分类已经覆盖。

若没有兼容目标，必须有可验证完整的明文上下文及工具配对才能讨论重建；不能靠删除工具结果、伪造密文、将未完成工具转成普通文本来保证200。对只有密文或远端状态的历史，网关无法保证等价重建。已经交付内容或工具执行不确定时，整轮重放还可能重复执行操作。

## 必须分别修复的对象

1. **调度资源**：明确哪些同组账号实际可用、允许调度，并将快速策略用于显式标记账号；不能把存在于列表中的禁调度账号算入冗余。
2. **上下文兼容恢复**：对具体密文来源、目标兼容证据、首输出/工具执行边界建立受限分支，记录请求级次数预算；不要直接把所有invalid_request都改成可换号。
3. **出站最小删减**：旧store=false兼容规则会删掉没有有效密文的整个reasoning，含可见summary。这是已复现的另一项缺陷，必须在完整Forward终点验证，不可只靠低层剥字段测试。
4. **状态说明**：工具密文不兼容不能误标为账号永久失效，也不能把HTTP200误标为会话成功。客户端依旧保存原历史，后续轮次必须执行一致规则。

这些是后续修正边界，并非已经部署的新行为。本次交付只补齐调查结论与已部署补丁归档。
