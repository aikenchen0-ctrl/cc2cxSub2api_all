## 已部署能力

1. 对显式开启快速切换的OpenAI/Anthropic API Key通用生效，无账号编号白名单。短暂、可安全重放的502/503仅给予一次原号恢复机会，并限制请求级总预算。
2. 首个有效输出等待与模型推理级别、已观察延迟结合；已交付正文后不以首输出超时截断长答案，客户端执行本地脚本的等待不是上游推理计时。
3. 成功后更新亲和，使用原子比较更新防止旧并发请求抢回粘性；兼容备用成功后减少反复切回造成的缓存损失。
4. 对可定位的普通reasoning密文做有界恢复，记录按客户、分组、目标身份隔离，固定48小时；**低层仅删密文字段，但旧前置兼容规则仍存在后续整项删除漏洞，详见已知问题。**
5. 对已经交付输出、服务端工具执行情况不确定的请求阻止盲目整轮重放；不能用第二次调用掩盖第一次工具可能已执行的事实。
6. 客户缓存优惠与真实上游Usage统计分离。计价估算不等于供应商账单。
7. 审计连接建立前失败可安全绕行到网关；POST已经发送或流中断后不自动重复发送。

## 必须保留的已知问题

- 108个集中错误来自同一下游Key、分组和直接上游的 `response.failed`，不是Nginx自行生成的解密错误；不能扩展为全部客户同时故障。
- 两个真实旧会话仍分别存在体积过大、工具密文解码失败。此次没有继续删除agent_message、压缩密文或工具结果。
- `store=false`旧兼容规则会删除无有效密文的整条reasoning，即使仍有摘要。后续命中恢复缓存后也可能触发该规则。需内部逐项保护、缓存契约升级以及完整Forward验证；该修正未包含在已部署功能补丁中。
- 部分custom_tool_call_output对象ID被既有前缀校验删除，call_id与结果正文不变；与第三方引用扩展是否冲突需独立验证。
- 无完整明文历史、仅有远端锚点/密文压缩/服务端工具状态时，网关不能制造等价上下文。通用完整会话账本、附件/容器迁移未实现。
- 客户端仍保存旧历史；修改出站副本不会修改客户端，后续处理必须保持一致。不能保证所有上游或客户端失效都无需用户恢复。
