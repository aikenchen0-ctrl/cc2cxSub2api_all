# sub2api 构建与运行计划

## 目标

在不影响同级其他项目的前提下，按仓库现有方式构建并启动 `sub2api`，确认服务可访问。

## 成功标准

- 依赖与配置满足项目要求。
- 构建命令成功完成。
- 服务进程持续运行。
- 健康检查或实际 HTTP 请求成功。
- 记录访问地址、运行方式和停止方式。

## 阶段

| 阶段 | 状态 |
|---|---|
| 1. 检查仓库结构、说明与环境 | 已完成 |
| 2. 确定本地部署路径与配置 | 已完成 |
| 3. 构建镜像或应用 | 已完成 |
| 4. 启动并验证服务 | 进行中 |

## 约束与决策

- 仅操作 `sub2api` 目录及其运行资源。
- 优先采用仓库已有、文档推荐的构建与部署方式。
- 使用 `deploy/docker-compose.dev.yml` 从当前源码构建，而非拉取发布镜像。
- 本机开发服务默认只绑定 `127.0.0.1:8080`。
- 由于另一套现有 Sub2API 已占用 8080，本项目改用 `127.0.0.1:18080`。
- Compose 项目名固定为 `sub2api-pro`，避免与现有名为 `deploy` 的 Compose 项目混淆。
- 不新增静默 fallback，不掩盖构建或运行错误。
- 不把凭证写入源码。

## 错误记录

| 错误 | 尝试 | 处理 |
|---|---|---|
| 工作区根目录不是 Git 仓库 | 1 | 后续在 `sub2api` 项目目录执行 Git 检查 |
| `sub2api` 目录也没有 `.git` 元数据 | 1 | 记录为源码快照，不影响 Docker 构建 |
| 8080 已被旧 Sub2API 部署占用 | 1 | 当前源码部署改用 18080，保留旧服务不动 |
| 最终核验的 Docker Go 模板解析失败 | 1 | PowerShell 丢失模板内层引号；改用 `docker inspect` JSON 结构解析 |
| 管理员登录核验的顶层字段断言失败 | 1 | HTTP 请求成功但字段位置未确认；检查统一响应封装结构后再断言 |
| 最终长脚本使用 `$home` 触发只读 `$HOME` 冲突 | 1 | PowerShell 变量名大小写不敏感；拆分核验命令并使用任务专用变量名 |
