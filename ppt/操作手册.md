# Presenton 操作手册

## 1. 项目定位

Presenton 是一个自托管的 AI PPT 生成、编辑和导出平台，包含 Next.js 界面、FastAPI API、Nginx 统一入口和 MCP Server。`/app_data` 保存用户配置、演示文稿、上传文件、图片及导出结果。

## 2. 当前启动方式

当前实例使用缓存镜像运行：

```powershell
cd D:\\Workspace\\sub2api-pro\\presenton
docker run -d --name presenton-8341 `
  -p 8341:80 `
  -p 1455:1455 `
  -v "${PWD}\\app_data:/app_data" `
  ghcr.io/presenton/presenton:latest
```

访问 `http://localhost:8341`，查看日志：

```powershell
docker ps --filter name=presenton-8341
docker logs -f presenton-8341
```

停止/重启：

```powershell
docker stop presenton-8341
docker start presenton-8341
```

Compose 支持通过 `PRESENTON_HTTP_HOST_PORT` 覆盖宿主机端口：

```powershell
$env:PRESENTON_HTTP_HOST_PORT = "8341"
docker compose up -d production
```

容器内端口仍为 Nginx `80`，不要将 `8341` 改成 FastAPI 端口。内部端口为：Next.js `3000`、FastAPI `8000`、MCP `8001`；`1455` 是 Codex OAuth 回调端口。

## 3. 首次配置

1. 打开 `http://localhost:8341` 完成管理员初始化。
2. 在设置页选择文本模型 provider 并填写模型 ID、API Key 或 Base URL。
3. 选择图片 provider；图片配置与文本 LLM 配置相互独立。
4. 在 `Admin -> API keys` 创建 `sk-presenton-...` 访问密钥，供 REST API 或 MCP 调用。
5. API Key 只放在密码管理器或 Sub2API 安全配置中，不要写入 URL、前端源码、Git 或日志。

## 4. 模型能力清单

### 4.1 文本模型

文本模型用于大纲、页面内容和编辑对话。通过 `LLM` 选择 provider：

| `LLM` | 主要配置 | 说明 |
|---|---|---|
| `openai` | `OPENAI_API_KEY`、`OPENAI_MODEL` | OpenAI |
| `deepseek` | `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、可选 Base URL | DeepSeek |
| `google` | `GOOGLE_API_KEY`、`GOOGLE_MODEL` | Gemini |
| `vertex` | `VERTEX_MODEL`，API Key 或 GCP 凭证 | Vertex AI |
| `azure` | `AZURE_OPENAI_*` | Azure OpenAI |
| `bedrock` | `BEDROCK_REGION`、`BEDROCK_MODEL`、AWS 凭证或 API Key | Amazon Bedrock |
| `openrouter` | `OPENROUTER_API_KEY`、`OPENROUTER_MODEL` | OpenRouter |
| `fireworks` | `FIREWORKS_API_KEY`、`FIREWORKS_MODEL` | Fireworks |
| `together` | `TOGETHER_API_KEY`、`TOGETHER_MODEL` | Together AI |
| `cerebras` | `CEREBRAS_API_KEY`、`CEREBRAS_MODEL` | Cerebras |
| `anthropic` | `ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL` | Anthropic |
| `litellm` | `LITELLM_BASE_URL`、`LITELLM_MODEL`、可选 Key | LiteLLM |
| `lmstudio` | `LMSTUDIO_BASE_URL`、`LMSTUDIO_MODEL`、可选 Key | 本地 LM Studio |
| `ollama` | `OLLAMA_URL`、`OLLAMA_MODEL` | 本地/远程 Ollama |
| `custom` | `CUSTOM_LLM_URL`、`CUSTOM_LLM_API_KEY`、`CUSTOM_MODEL` | OpenAI 兼容接口 |
| `codex` | `CODEX_MODEL`、Codex OAuth | ChatGPT/Codex 登录流程 |

通用高级参数：`LLM_GENERATION_PROFILE`、`LLM_MAX_OUTPUT_TOKENS`、`LLM_REASONING_MODE`、`LLM_REASONING_EFFORT`、`LLM_REASONING_BUDGET_TOKENS`。

### 4.2 图片模型与图片来源

通过 `IMAGE_PROVIDER` 选择，图片 Key 与文本 Key 可不同：

| `IMAGE_PROVIDER` | 配置 | 类型 |
|---|---|---|
| `pexels` | `PEXELS_API_KEY` | 素材检索 |
| `pixabay` | `PIXABAY_API_KEY` | 素材检索 |
| `gemini_flash` | `GOOGLE_API_KEY` | Gemini 图片生成 |
| `nanobanana_pro` | `GOOGLE_API_KEY` | Nano Banana 图片生成 |
| `dall-e-3` | `OPENAI_API_KEY`，可选 `DALL_E_3_QUALITY` | OpenAI 图片生成 |
| `gpt-image-1.5` | `OPENAI_API_KEY`，可选 `GPT_IMAGE_1_5_QUALITY` | OpenAI 图片生成 |
| `comfyui` | `COMFYUI_URL`、`COMFYUI_WORKFLOW` | 自托管 ComfyUI |
| `openwebui` | `OPEN_WEBUI_IMAGE_URL`、`OPEN_WEBUI_IMAGE_API_KEY` | Open WebUI 兼容接口 |
| `openai_compatible` | `OPENAI_COMPAT_IMAGE_BASE_URL`、`OPENAI_COMPAT_IMAGE_API_KEY`、`OPENAI_COMPAT_IMAGE_MODEL` | OpenAI 兼容图片接口 |

辅助开关：`DISABLE_IMAGE_GENERATION`、`ENABLE_PARALLEL_IMAGE_GENERATION`。

### 4.3 视频能力结论

截至当前仓库，没有发现文生视频（T2V）或图生视频（I2V）的 provider、环境变量、路由或导出流程。当前输出重点是 PPTX、PDF、HTML 和图片。视频能力需要另加视频生成服务、异步任务、进度回调、素材存储和前端播放，不能仅设置 `LLM` 或 `IMAGE_PROVIDER` 开启。

## 5. 与 Sub2API 对接

### 推荐方案：Sub2API 作为 OpenAI 兼容网关

```env
LLM=custom
CUSTOM_LLM_URL=http://sub2api:端口/v1
CUSTOM_LLM_API_KEY=<Sub2API 分配的 Key>
CUSTOM_MODEL=<Sub2API 中可用的文本模型 ID>

# 只有 Sub2API 暴露兼容图片接口时才配置
IMAGE_PROVIDER=openai_compatible
OPENAI_COMPAT_IMAGE_BASE_URL=http://sub2api:端口/v1
OPENAI_COMPAT_IMAGE_API_KEY=<图片路由对应的 Key>
OPENAI_COMPAT_IMAGE_MODEL=<图片模型 ID>
```

不同 Docker Compose 项目不能用 `localhost` 互访，应使用同一 Docker network 的服务名、宿主机网关或内网地址。先用 `/v1/models`（若 Sub2API 支持）和 Presenton 的小请求验证模型路由。

### 一键跳转与自动填充 API Key

- 当前前端没有证据表明支持通过 URL 查询参数自动填充 API Key。
- 不要使用 `http://localhost:8341/?api_key=...`，Key 会进入浏览器历史、代理日志和 Referer。
- 推荐 Sub2API 登录后由服务端生成一次性短期授权码，跳转到 Presenton 受控入口；Presenton 服务端兑换授权码，写入当前用户作用域。授权码需一次性、短时有效、绑定用户和来源，并使用 HTTPS。
- 单机临时方案可预先通过环境变量注入 `CUSTOM_LLM_API_KEY`，再跳转到固定地址，但这不是按用户隔离的自动填充。

### Presenton API

生成 PPT：`POST /api/v1/ppt/presentation/generate`。调用需发送：

```http
Authorization: Bearer sk-presenton-...
Content-Type: application/json
```

接口分组包括 `/api/v1/ppt/files`、`/api/v1/ppt/images`、`/api/v1/ppt/presentation`、`/api/v1/ppt/outlines`、`/api/v1/auth/token` 和 `/mcp`。请求字段以运行实例的 `/docs` 或 `/openapi.json` 为准。

## 6. 故障排查

| 现象 | 检查 |
|---|---|
| 8341 无法访问 | `docker ps`、`docker logs`、端口占用 |
| 页面能开但生成失败 | `LLM`、模型 ID、Base URL、Key、容器到 Sub2API 的网络 |
| 图片失败 | `IMAGE_PROVIDER` 对应的 Key/Base URL |
| 上传失败 | `/app_data` 挂载和 Nginx 110MB 限制 |
| API 返回 401 | 使用 Presenton `sk-presenton-...`，不要混用 Sub2API Key |
| OAuth 回调失败 | 宿主机 `1455` 未占用且浏览器可访问 `localhost:1455` |
