# PPT 使用手册

适用对象：第一次使用本项目制作 PPT 的用户，以及负责日常维护的管理员。

编写日期：2026 年 9 月 18 日。本文根据当前项目代码和本地部署记录整理，部分按钮保留英文名称，方便对照界面查找。

## 1. 先了解这个工具

你可以把它理解为一个“帮你起草和排版 PPT 的助手”：输入主题，或者上传资料，它会生成演示文稿，你再检查、修改，最后下载。

基本流程：**登录 → 写要求 → 生成 → 检查修改 → 下载 PPTX 或 PDF。**

AI 生成的数字、日期、引用和结论不一定准确，正式使用前需要自己核对。

### 当前部署的特别提醒

根据项目中 2026 年 9 月 18 日的部署记录：

- 从 Sub2API 进入 PPT、免重复登录和刷新后保留登录状态已经通过验证。
- 实际生成大纲时，上游模型服务曾出现限流、不可用等问题，尚未验证完整生成成功。
- 部署记录中的默认文本模型为 `gpt-5.4-mini`，但当时启用的上游服务未提供该模型，需要管理员调整。
- 当前部署默认关闭 AI 图片生成，需要配图时应由管理员单独配置。

以上是部署记录中的状态，不是编写手册时重新运行测试的结果。**能打开页面，不代表 AI 生成服务一定可用。** 遇到生成错误，先看第 9 节，不要反复提交。

## 2. 如何进入

### 从 Sub2API 进入

1. 在部署服务的这台电脑上，用浏览器打开 `http://localhost:18080`。
2. 登录 Sub2API 账号。
3. 点击 `Eternal PPT` 入口。
4. 正常情况下，新标签页会进入创建页面，无需再次输入 PPT 密码或模型密钥。

如果提示跳转链接过期，请回到 Sub2API 重新点击入口，不要重复使用旧链接。

### 直接打开 PPT

在部署服务的这台电脑上，打开 `http://localhost:8341`，按页面提示登录。

注意：

- Sub2API 登录和 PPT 本地密码登录是两种入口，不要默认它们使用同一套密码。
- 通过 Sub2API 进入的账号，不会与原有 PPT 本地账号自动合并。查找旧文稿时，请使用创建它时的账号和登录方式。
- `localhost` 表示“当前这台电脑”。手机或其他电脑不能直接使用这个地址，请向管理员索取可访问的地址。
- 如果首次打开看到创建管理员页面，应由负责部署的人完成初始化。

## 3. 第一次制作 PPT

### 第一步：写清楚要求

在创建页面的大输入框中，说明主题、听众、页数、重点和风格。不要只写“帮我做一个 PPT”。

可以直接参考下面的例子：

> 请制作一份面向公司新员工的“信息安全入门”PPT。
> 共 8 页，使用简体中文，风格简洁、正式。
> 内容包括密码安全、钓鱼邮件识别、文件分享注意事项、办公设备使用规范和重点回顾。
> 每页只讲一个重点，多用短句，不要堆积大段文字。
> 不要编造公司制度；涉及具体制度的地方请标注“待公司确认”。

### 第二步：设置语言和页数

| 设置 | 通俗解释 |
| --- | --- |
| `Language` | 内容语言，中文 PPT 选择相应的中文选项 |
| 页数 | 希望生成多少页，当前代码中的上限为 50 页 |
| `Tone` | 表达语气，例如正式或日常 |
| `Verbosity` | 文字的详细程度 |
| `Title Slide` | 是否包含封面 |
| `Include Table of Content` | 是否包含目录 |

部分选项在高级设置里。不确定如何选择时，先保留默认值，只调整语言和页数。第一次建议做 5 到 8 页，确认服务正常后再生成长文稿。

### 第三步：选择模式

| 模式 | 操作过程 | 适合的情况 |
| --- | --- | --- |
| `Standard`，标准模式 | 先生成大纲，检查后选模板，再生成页面 | 想先确认讲述顺序，或需要统一版式 |
| `Smart`，智能模式 | 根据要求直接生成页面，布局更灵活 | 想先得到完整初稿，再修改 |

第一次使用建议先选标准模式。

智能模式可以选择社区设计作为外观参考。它不是你的业务资料，重要事实仍需在输入框或附件中说明。

### 第四步：开始生成

点击输入框下方的向上箭头按钮，提示名称为 `Generate presentation`。

生成过程中保持页面打开，等待进度变化。耗时取决于页数、资料量和模型服务，不要连续重复提交。

标准模式的后续步骤：

1. 等待大纲生成结束。大纲就是“每一页准备讲什么”。
2. 点击某一页的大纲文字，可以修改内容。
3. 拖动大纲旁的拖拽手柄，可以调整顺序。
4. 选择一个模板。
5. 点击 `Continue`，生成正式页面。

如果按钮显示 `Select a Template`，说明还没选模板；显示 `Loading...`，说明仍在处理。

智能模式会直接进入演示文稿页面生成内容，不经过标准模式的大纲确认步骤。

## 4. 使用自己的资料生成

有现成报告、会议记录或旧 PPT 时，可以把它们作为参考资料上传。

1. 点击回形针旁的 `Attach files`。
2. 选择文件，也可以把文件拖到附件区域。
3. 检查附件列表，误选的文件可点击旁边的叉号移除。
4. 在输入框中说明如何使用这些资料。
5. 设置语言、页数和模式，再开始生成。

常见支持格式：

| 资料 | 常见格式 |
| --- | --- |
| 文档 | .doc、.docx、.odt、.rtf |
| 演示文稿 | .ppt、.pptx、.odp |
| 表格 | .xls、.xlsx、.csv、.tsv |
| PDF 和纯文本 | .pdf、.txt |
| 图片 | .jpg、.png、.webp、.gif |

一次最多选择 **8 个附件**。文件能被选中，不代表内容一定能完整识别。扫描件、模糊图片、加密文件和复杂排版需要特别检查。

配合附件，可以这样写：

> 请根据附件中的项目总结，制作一份 8 页的中文汇报 PPT。
> 听众是部门负责人，重点介绍目标、完成情况、主要问题和下一步计划。
> 数字以附件为准，不要自行补造数据。
> 附件中没有的信息，请写“待补充”。

上传旧 PPT 是提供参考，不应理解为逐页原样还原。涉及公司机密或个人信息的文件，上传前请确认允许交给所配置的 AI 服务处理。

## 5. 修改生成的 PPT

生成完成后，先检查内容，再调整外观。

### 管理页面

- 点击侧边缩略图，切换到对应页面。
- `Add Slides`：添加页面。
- 页面操作菜单中的 `Duplicate Slide`：复制当前页面。
- 页面操作菜单中的 `Delete Slide`：删除当前页面，操作前确认选对了页。
- 点击文稿标题旁的编辑按钮，可以修改名称。

### 调整文字和排版

标准模式提供页面元素编辑功能。选中文字、图片等元素后，使用出现的工具调整。需要添加内容时，可以使用文本、图片、表格、图表等插入工具。

两种模式的编辑工具不完全相同，以当前页面可用按钮为准。

### 让 AI 帮忙修改

打开编辑页中的 AI 对话区域，明确说明改哪一页、如何修改，例如：

> 请把第 3 页压缩成 3 个要点，保留原有数字，不修改其他页面。

> 请把当前页的标题改得更简洁，正文改成适合向新员工讲解的语气。

智能模式提供选择页面内容后交给 AI 修改的功能。修改后仍需检查，明确写出范围也不能保证 AI 完全按预期执行。

### 保存与撤销

- 编辑器带有自动保存功能，但“已经输入文字”不等于“已经保存成功”。
- 留意保存中的动画和错误提示，等待保存结束再离开。重要文稿可重新打开确认。
- 改错时，可尝试使用顶部的撤销和重做按钮。
- **谨慎使用 `Regenerate`（重新生成）**：它会替换当前页面并清空撤销历史，已有修改可能丢失。重要版本先导出留存。

## 6. 放映和下载

### 在线放映

点击编辑页顶部的播放图标，进入放映页面。正式讲解前，先浏览一遍，检查内容与排版。

### 下载文件

1. 等待生成和保存结束。
2. 点击右上角的 `Export`。
3. 选择 PDF 或 PPTX。
4. 等待完成，在浏览器下载记录中找到文件。

| 格式 | 用途 |
| --- | --- |
| `PPTX` | 在 PowerPoint、WPS 等软件中继续处理或演示 |
| `PDF` | 阅读、发送或打印，不需要继续调整页面元素 |

导出后请打开检查，尤其注意中文字体、换行、图片和图表。不要假定所有复杂效果都能完全一致地转换成可编辑的 PPT 元素。

当前编辑页的导出菜单提供 PDF 和 PPTX，不要把其他内部格式当成此菜单已支持的下载选项。

## 7. 下次如何找到文稿

进入 `Dashboard`（工作台），查找自己账号下的演示文稿，打开后继续编辑。

找不到时，先检查是不是同一个账号和同一种登录方式。通过 Sub2API 进入的用户拥有各自的文稿访问范围，不会因为使用同一个入口就自动共享文稿。

自动保存依赖服务器正常运行。重要文稿建议另外保留导出文件。

## 9. 遇到问题怎么办

| 情况 | 处理方法 |
| --- | --- |
| 网页打不开 | 确认地址正确、服务已启动；其他电脑不能直接使用部署机器的 localhost 地址 |
| 登录跳转链接失效 | 回到 Sub2API 重新点击 Eternal PPT |
| 页面正常，但生成失败 | 记录报错，联系管理员检查模型服务，不要连续提交 |
| 提示 rate limit 或 429 | 可能触发限流，稍后再试 |
| 提示模型不存在 | 请管理员检查模型名称和上游是否支持 |
| 提示余额不足 | 请管理员检查模型服务账户 |
| 提示 502、503 或服务不可用 | 可能是网关或上游异常，稍后重试或联系管理员 |
| 能生成文字，不能生成图片 | 两者分别配置；当前部署记录中 AI 图片生成默认关闭 |
| 附件失败 | 检查格式和数量，尝试较小、未加密、文字清晰的文件 |
| 标准模式不能继续 | 等大纲生成结束，并确认已选模板 |
| 导出按钮不可用 | 等待当前生成或导出任务结束 |
| 找不到下载文件 | 检查浏览器下载记录和下载拦截提示 |
| 旧文稿不见了 | 检查账号及登录方式，再到工作台查找 |
| 页面文字拥挤 | 精简内容或拆成多页，再检查排版 |

向管理员反馈时，提供发生时间、进行到哪一步、报错原文和必要截图。不要发送密码、API Key 或完整登录跳转链接。

## 10. 管理员补充说明

普通用户可以跳过本节。

### 模型配置的几个概念

- 文本模型：负责大纲、正文和 AI 修改。
- 图片服务：负责生成或查找配图，需要单独配置。
- API Key：调用服务的密钥，应像密码一样保管。
- Base URL：模型接口地址，不一定是浏览器打开的首页地址。
- 模型名称：必须是上游实际支持、能正常调用的名称。

当前 Sub2API 集成使用实例级共享服务密钥。不同用户的文稿访问范围分开，但模型费用记在共享密钥上，**不是按每位用户的个人密钥分别扣费**。

普通用户不能修改管理员模型配置。数据库中已保存的模型设置优先，仅修改启动环境变量不会自动覆盖旧配置。

应先在管理员设置中选择可用模型，再用少量页面进行生成测试。仅能获取模型列表，不代表生成一定成功。

### 查看与重启本地服务

以下命令适用于本项目的 Sub2API Compose 部署。在当前项目目录打开 PowerShell 执行：

~~~powershell
# 查看 PPT 服务状态
docker compose -f docker-compose.yml -f docker-compose.sub2api.yml ps

# 查看最近日志
docker compose -f docker-compose.yml -f docker-compose.sub2api.yml logs --tail 100 production

# 重启会短暂中断访问，请避开有人正在生成或编辑的时间
docker compose -f docker-compose.yml -f docker-compose.sub2api.yml restart production
~~~

重启不能解决上游余额不足或模型不受支持的问题，也不会自动应用新修改的环境变量。

### 数据与密钥保护

- `app_data` 保存本地部署的重要数据，不要随意删除或覆盖。
- 升级迁移前，应安排停机或使用一致性备份方式，备份 PPT 数据和相关配置；Sub2API 数据库另行备份。
- 不要为了修复生成或登录错误而删除数据库、清空数据卷或重新初始化账号。
- 不要把 `.env.sub2api` 中的密钥写进文档、截图或公开仓库，也不要拼到网页地址里。
- 公开部署应使用 HTTPS，并由管理员确认访问范围和服务配置。
