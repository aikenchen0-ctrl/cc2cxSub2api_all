# PPT 与 Sub2API 单点登录对接流程

## 1. 今日完成的工作

本次对接以仓库根目录的 `SSO登录设计方案.md` 为准，完成了 Sub2API（身份中心）与 PPT/Presenton（业务应用）之间的单点登录链路。

完成内容如下：

- 配置并验证 Python 3.11、Go 1.27、uv 0.12.16 和 Node.js/npm 环境。
- 在 Sub2API 左侧快捷应用中接入“永恒PPT”。点击后先打开新的浏览器窗口，再在新窗口中继续 SSO，避免当前 Sub2API 页面被替换。
- Sub2API 增加 PPT SSO 启动接口：`GET /api/v1/auth/integrations/ppt/start`。
- 使用短期 HMAC-SHA256 票据传递身份，不把 Sub2API JWT、API Key 或密码放进浏览器跳转地址。
- 票据增加并校验 `iss=sub2api`、`aud=presenton`、`sub`、`jti`、`iat`、`exp` 和安全的 `next`。
- PPT 按 `sub2api subject` 创建或查找本地普通用户，Sub2API 管理员权限不会继承到 PPT。
- PPT 增加 handoff Cookie 和同源 exchange 两步登录，避免在回调阶段直接签发正式会话。
- 增加重放、过期、篡改、错误 audience、跨站 exchange、禁用用户和安全重定向测试。
- 更新 SSO 文档和运行配置，保留现有 PPT 数据库、用户、作品和上传文件。

## 2. 参与服务与职责

### Sub2API

Sub2API 是身份中心和 SSO 启动方：

1. 浏览器当前必须已经登录 Sub2API。
2. 校验当前用户 JWT 和账户状态。
3. 从用户上下文取得稳定的 `subject`/用户 ID。
4. 生成只对 Presenton 有效的短期签名票据。
5. 返回一个只包含票据的 `redirect_url`，供新窗口导航。

Sub2API 不下发 PPT 的正式会话 Cookie，也不把服务端 Relay API Key 返回给浏览器。

### PPT/Presenton

PPT 是独立的业务应用和会话边界：

1. 校验票据签名、发行方、受众、字段、时间和 `jti` 一次性消费。
2. 将外部 subject 映射到 PPT 自己的本地普通用户。
3. 创建短期 handoff Cookie。
4. 通过同源 exchange 建立 PPT 自己的 `presenton_session` Cookie。
5. 由 PPT 自己负责用户权限、作品数据隔离、会话生命周期和登出。

## 3. 用户点击“永恒PPT”后的完整流程

```text
Sub2API 已登录用户
        |
        | 点击左侧“永恒PPT”
        v
浏览器打开新窗口 about:blank
        |
        | 前端携带当前 Sub2API Bearer JWT 请求
        v
GET /api/v1/auth/integrations/ppt/start?next=%2Fupload
        |
        | Sub2API 校验登录状态并签发 HMAC 票据
        v
JSON { data: { redirect_url: "http://localhost:8341/api/v1/auth/sso/callback?ticket=..." } }
        |
        | 新窗口导航到 redirect_url
        v
PPT GET /api/v1/auth/sso/callback?ticket=...
        |
        | PPT 校验票据并创建/查找本地普通用户
        | 写入 60 秒、Path 受限的 HttpOnly handoff Cookie
        v
303 Location: /?sso=1
        |
        | 根页面 AuthGate 检测 sso=1
        v
POST /api/v1/auth/sso/exchange
X-Presenton-SSO: 1
        |
        | PPT 校验同源请求
        | 原子删除 handoff 记录并立即清除 Cookie
        | 签发 PPT 正式 presenton_session Cookie
        v
JSON { authenticated: true, redirect: "/upload", ... }
        |
        v
浏览器进入 /upload，用户无需再次登录
```

## 4. Sub2API 侧流程

### 4.1 菜单和新窗口

实现位置：

- `sub2api/frontend/src/components/layout/AppSidebar.vue`
- `sub2api/frontend/src/utils/juSso.ts`

PPT 快捷项使用：

```text
/api/v1/auth/integrations/ppt/start?next=%2Fupload
```

点击处理步骤：

1. 阻止普通链接立即替换当前页面。
2. 使用 `window.open("about:blank", "_blank")` 预先打开新窗口，满足浏览器弹窗策略。
3. 使用当前 Sub2API 登录令牌调用启动接口。
4. 校验返回的 `redirect_url` 是 HTTP/HTTPS 且没有用户名密码部分。
5. 通过 `popup.location.replace()` 导航新窗口。
6. 请求失败或弹窗被浏览器阻止时关闭空白窗口并提示用户。

### 4.2 启动接口

路由：

```text
GET /api/v1/auth/integrations/ppt/start
```

主要检查：

- 必须是已认证且启用的 Sub2API 用户。
- `SUB2API_SSO_SECRET` 至少 32 个字符。
- `PPT_SSO_CALLBACK_URL` 必须是精确路径 `/api/v1/auth/sso/callback`。
- 生产环境回调地址必须使用 HTTPS；HTTP 只允许 localhost、127.0.0.1 或 ::1 开发地址。
- `next` 只能是 PPT 站内相对路径，拒绝外部 URL、`//`、反斜杠和控制字符。

票据格式：

```text
base64url(JSON payload) . base64url(HMAC-SHA256(payload, SUB2API_SSO_SECRET))
```

票据关键字段：

| 字段 | 作用 |
| --- | --- |
| `iss` | 固定为 `sub2api` |
| `aud` | 固定为 `presenton` |
| `sub` | Sub2API 稳定用户标识 |
| `jti` | 随机一次性票据 ID |
| `iat` | 签发时间 |
| `exp` | 约两分钟后过期 |
| `next` | PPT 内部安全目标路径 |

## 5. PPT 回调和本地用户映射

实现位置：

```text
ppt/servers/fastapi/api/v1/auth/sub2api_sso.py
```

回调路由：

```text
GET /api/v1/auth/sso/callback
```

处理步骤：

1. 读取 `ticket`，使用服务端 `SUB2API_SSO_SECRET` 验证 HMAC。
2. 验证 `iss`、`aud`、`sub`、`jti`、`iat`、`exp` 和票据长度。
3. 使用数据库唯一键消费 `jti`，同一票据再次使用会失败。
4. 检查 PPT 已完成管理员初始化，避免 SSO 用户占用首个管理员账户位置。
5. 使用 `sub2api subject` 的哈希建立稳定的身份映射。
6. 首次登录创建 PPT 普通用户；再次登录复用同一个 PPT 用户。
7. 禁用用户或被提升为管理员的映射会被拒绝。
8. 创建一条 handoff 数据，保存本地用户 ID、`next` 和 60 秒过期时间。
9. 设置 `presenton_sso_handoff` Cookie：HttpOnly、SameSite=Strict、Max-Age=60、Path 仅为 exchange 路由。
10. 返回 `303 /?sso=1`，不会在地址栏保留票据。

回调和错误响应都包含：

```text
Cache-Control: no-store
Referrer-Policy: no-referrer
```

## 6. PPT exchange 正式登录

路由：

```text
POST /api/v1/auth/sso/exchange
```

请求必须包含：

```http
X-Presenton-SSO: 1
```

服务端还会：

- 拒绝 `Sec-Fetch-Site: cross-site`；
- 校验 Origin 与当前 PPT 站点一致（支持反向代理的 forwarded host/proto）；
- 读取 handoff Cookie 后立即发送删除 Cookie；
- 按 handoff ID 原子删除数据库记录，保证成功、过期和重放都只能消费一次；
- 验证本地用户仍存在且仍启用；
- 生成 PPT 自己的 JWT，并设置 `presenton_session` HttpOnly Cookie；
- 返回已经校验过的本地 `redirect` 路径；
- 不返回 Sub2API JWT、API Key 或 handoff 原文。

无 Cookie、过期、重复、跨站或缺少请求头时返回 401/403，并清理 handoff Cookie。

前端实现位置：

```text
ppt/servers/nextjs/components/Auth/AuthGate.tsx
```

AuthGate 发现 URL 中有 `sso=1` 时自动发起 exchange；成功后使用安全的 `redirect` 路径进入 `/upload`，并刷新页面状态。失败时回到普通登录状态。

## 7. 配置步骤

### 7.1 共享密钥

Sub2API 和 PPT 必须使用同一个随机密钥。示例变量名：

```dotenv
SUB2API_SSO_SECRET=<同一个随机字符串，至少 32 个字符>
```

不要把真实密钥提交到 Git、写入 URL、打印到日志或放到前端环境变量中。

### 7.2 Sub2API 回调地址

本地 Docker：

```dotenv
PPT_SSO_CALLBACK_URL=http://localhost:8341/api/v1/auth/sso/callback
```

生产环境使用实际公网 HTTPS 地址，例如：

```dotenv
PPT_SSO_CALLBACK_URL=https://ppt.example.com/api/v1/auth/sso/callback
```

### 7.3 PPT Relay 配置

PPT 的服务端 Relay 配置可以使用：

```dotenv
SUB2API_BASE_URL=http://host.docker.internal:18080
SUB2API_API_KEY=<服务端专用 Relay API Key>
SUB2API_MODEL=gpt-5.4-mini
```

Relay API Key 只在服务端使用，不能通过 URL、浏览器存储或前端配置下发给用户。

## 10. 故障排查

### 跳转到 `/login?error=SSO_failed`

这通常表示运行中的 PPT 容器仍是旧镜像或旧前端。检查容器镜像 ID、容器日志和回调响应头。新实现的失败地址应为：

```text
/?error=SSO_failed
```

重新从 Sub2API 菜单发起一次流程，不要重复使用已经过期的旧回调 URL。

### 502 Bad Gateway

检查容器是否仍在运行，以及 FastAPI 是否启动：

```powershell
docker ps --filter name=ppt-production-1
docker logs --tail 100 ppt-production-1
curl.exe -i http://localhost:8341/api/v1/auth/status
```

如果日志显示数据库迁移重复创建表，先备份 `ppt/app_data/fastapi.db`，再按第 8 节临时关闭启动迁移。

### SSO exchange 返回 401

可能是 handoff 已超过 60 秒、Cookie Path 不匹配、浏览器没有携带 Cookie，或者该 handoff 已经被消费。回到 Sub2API 重新点击“永恒PPT”即可。

### SSO exchange 返回 403

检查请求是否来自 PPT 同源页面，并确认请求头：

```http
X-Presenton-SSO: 1
```

跨站 fetch 会被主动拒绝。

## 11. 重要安全边界

- Sub2API JWT 只用于请求启动接口，不传给 PPT。
- PPT 会话使用自己的 `presenton_session` Cookie。
- Sub2API 管理员角色不会自动变成 PPT 管理员。
- Relay API Key 是服务端配置，不属于用户会话。
- `next` 只允许站内相对路径。
- 票据、handoff 和会话都不应写入日志或 URL 长期保存。
- 生产部署应使用 HTTPS，并定期轮换共享密钥。
