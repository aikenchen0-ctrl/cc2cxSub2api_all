# Presenton 项目架构

## 1. 总体结构

```
浏览器 / Sub2API / MCP 客户端
              |
       宿主机 8341（Docker）
              |
       Nginx :80（统一入口）
        /        |        \\
   Next.js    FastAPI     MCP
    :3000      :8000      :8001
        \\        |        /
          /app_data + 数据库
```

Docker 对外只需要发布 Nginx 的宿主机端口。当前实例是 `8341:80`；Next.js、FastAPI、MCP 端口在容器内部通信。

## 2. 目录职责

```
presenton/
├─ start.js                         容器入口，启动 Nginx、FastAPI、Next.js、MCP
├─ nginx.conf                       反向代理、上传限制、静态文件和认证子请求
├─ docker-compose.yml               production/development/GPU 服务编排
├─ Dockerfile                       生产镜像
├─ servers/
│  ├─ fastapi/
│  │  ├─ server.py                  Uvicorn 启动入口
│  │  ├─ api/                       REST 路由、中间件、认证
│  │  ├─ services/                  LLM、图片、导出、数据库等业务服务
│  │  ├─ models/                    SQLModel/SQLAlchemy 数据模型
│  │  ├─ utils/get_env.py           环境变量读取集中位置
│  │  ├─ mcp_server.py               MCP 服务
│  │  └─ tests/                     后端测试
│  └─ nextjs/
│     ├─ app/                       页面和 Next.js Route Handler
│     ├─ components/                 编辑器、生成表单等 UI
│     ├─ lib/                       服务端库和导出运行时
│     ├─ store/、models/、types/    前端状态、类型和数据访问
│     └─ tests/、cypress/            测试
└─ app_data/                        持久化挂载点（运行时生成）
```

## 3. 启动与请求流

1. 容器执行 `node /app/start.js`。
2. `start.js` 启动 FastAPI `127.0.0.1:8000`、Next.js `127.0.0.1:3000` 和 MCP `:8001`。
3. Nginx 监听容器 `:80`，将 `/` 转发到 Next.js。
4. `/api/v1/`、`/api/v2/`、`/docs`、`/openapi.json` 转发到 FastAPI。
5. `/mcp` 转发到 MCP Server，由 MCP 自身校验 Presenton Bearer Key。
6. `/app_data/images`、`exports`、`uploads` 通过 Nginx `auth_request` 做访问控制。

## 4. PPT 生成数据流

```
用户输入/上传文件
        |
        v
Next.js 生成页面或 REST API
        |
        v
FastAPI /api/v1/ppt
  ├─ 文件解析与文档转换
  ├─ 大纲生成（文本 LLM）
  ├─ 页面内容/布局生成（文本 LLM）
  ├─ 图片检索或生成（图片 provider）
  ├─ 演示文稿持久化
  └─ PPTX/PDF/HTML/图片导出
        |
        v
    /app_data
```

文本 LLM 负责语言和结构推理；图片 provider 负责图片素材。两条链路配置独立，视频链路目前不存在。

## 5. Provider 抽象与 Sub2API 接入点

环境变量首先由 `servers/fastapi/utils/get_env.py` 读取，再由 provider/service 层创建客户端。最适合对接 Sub2API 的边界是 OpenAI 兼容 HTTP 接口：

```
Presenton FastAPI
  ├─ 文本：LLM=custom
  │       CUSTOM_LLM_URL + CUSTOM_LLM_API_KEY + CUSTOM_MODEL
  └─ 图片：IMAGE_PROVIDER=openai_compatible（可选）
          OPENAI_COMPAT_IMAGE_BASE_URL + API_KEY + MODEL
                |
                v
          Sub2API OpenAI-compatible Gateway
                |
                v
       实际文本/图片模型账号或上游 provider
```

Sub2API Key 和 Presenton Key 是两套不同凭证：

- Sub2API Key：Presenton 调用 Sub2API 上游时使用。
- Presenton `sk-presenton-...`：调用 Presenton 自身 REST/MCP API 时使用。

不要在前端把两者混用，也不要让浏览器直接暴露长期 Sub2API Key。

## 6. 认证与数据边界

- 浏览器登录使用 Presenton 会话 Cookie。
- REST/MCP 自动化调用使用 Presenton 管理员生成的访问 Key。
- API Key 按所属用户生效；撤销后立即失效。
- `/app_data` 保存用户配置、演示文稿、上传文件、图片和导出结果，必须持久化备份。
- `DISABLE_AUTH=true` 只适用于明确受控的本地场景，不应作为多用户 Sub2API 集成方案。

## 7. 能力矩阵

| 能力 | 当前状态 | 主要入口/配置 |
|---|---|---|
| 文本生成 | 已支持，多 provider | `LLM` 与各 provider 的 `*_MODEL`/`*_API_KEY` |
| PPT 大纲 | 已支持 | `/api/v1/ppt/outlines` |
| PPT 生成与编辑 | 已支持 | `/api/v1/ppt/presentation`、Next.js 编辑器 |
| 文档上传解析 | 已支持 | `/api/v1/ppt/files` |
| 图片检索 | 已支持 | Pexels/Pixabay、`IMAGE_PROVIDER` |
| 图片生成 | 已支持，多 provider | DALL-E、GPT Image、Gemini、ComfyUI、OpenAI compatible 等 |
| PPTX/PDF/HTML/图片导出 | 已支持 | 导出服务和 `/app_data/exports` |
| 文生视频 | 当前未发现实现 | 需要新增视频 provider/任务系统 |
| 图生视频 | 当前未发现实现 | 需要新增视频 provider/任务系统 |
| MCP | 已支持（容器模式） | `/mcp`，使用 Presenton API Key |

## 8. 对接改造建议

### 最小可行对接

只需在 Sub2API 提供 OpenAI 兼容文本接口后配置：

```env
LLM=custom
CUSTOM_LLM_URL=https://sub2api.example.com/v1
CUSTOM_LLM_API_KEY=${SUB2API_APP_CREDENTIAL}
CUSTOM_MODEL=<实际可用模型>
```

这条路径不需要修改 Presenton 核心代码。

### 一键跳转并按用户自动填充

需要新增明确的身份交换层，而不是把 Key 放进 URL：

1. Sub2API 登录后生成一次性短期 code。
2. 跳转到 Presenton 的受控入口并携带 code，而不是 API Key。
3. Presenton 服务端向 Sub2API 后端兑换临时凭证或 provider 配置。
4. 配置写入当前 Presenton 用户作用域，前端只显示脱敏状态。
5. 过期、退出登录、撤销授权时清理本地凭证。

该方案需要同时修改 Sub2API 和 Presenton 的认证/配置接口，并补充 CSRF、重放、过期、审计日志和多用户隔离测试。当前仓库没有现成的自动填充接口，不能仅靠现有环境变量实现真正的按用户一键配置。

## 9. 关键验证点

- `GET http://localhost:8341/api/v1/auth/status` 返回认证状态。
- `GET http://localhost:8341/docs` 或 `/openapi.json` 查看当前镜像实际 API。
- 文本链路：用一个小主题生成 2 页 PPT，检查 Sub2API 日志和模型 ID。
- 图片链路：单独调用图片生成或生成带图片的单页，确认图片 provider 的 Key 与路由。
- 重启验证：容器重启后 `/app_data` 中用户和演示文稿仍存在。
