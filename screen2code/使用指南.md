# Screen2Code 使用指南

这是一个“看图写网页”的工具：上传截图或输入描述，AI 帮你生成网页代码。你可以预览效果、继续提出修改要求，最后下载结果。

本文对应当前项目的本地版本，以 Windows PowerShell 为例。

## 一、它能做什么

| 入口 | 中文意思 | 用途 |
| --- | --- | --- |
| Upload | 上传 | 上传截图、设计图或录屏，生成网页 |
| URL | 网址 | 给公开网页截图，再生成网页 |
| Text | 文字 | 描述想要的页面，让 AI 生成 |
| Import | 导入 | 导入已有网页代码，再预览和修改 |

注意：生成的是网页界面或原型，不代表登录、支付、数据库等功能已经接好。页面看起来像截图，也不代表所有按钮都有实际功能。

## 二、准备运行环境和密钥

项目需要同时运行两部分：前端是浏览器里的操作界面，后端负责调用 AI 和处理代码。

需要准备 Python、Poetry、Node.js 和 pnpm。项目声明的 Python 要求是 `^3.10`，包管理器是 `pnpm@10.32.1`。Python 相关命令统一通过 `poetry run` 执行，避免用错环境。

如果当前环境已经配置好，可以直接启动。若提示找不到 `poetry` 或 `pnpm`，先确认工具已安装并加入 PATH，再重新打开终端。

API Key 可以理解为“让程序调用 AI 的钥匙”。下面前三项至少配置一项，不必全部填写。

| 配置项 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | 使用 OpenAI 模型生成代码 |
| `ANTHROPIC_API_KEY` | 使用 Claude 模型生成代码 |
| `GEMINI_API_KEY` | 使用 Gemini 模型，也用于素材提取和视频模式 |
| `REPLICATE_API_KEY` | 可选，支持相应的图片生成、编辑和去背景工具 |
| ScreenshotOne API Key | 使用 URL 截图入口时需要，在界面设置中填写 |

视频模式必须配置 Gemini。第一次使用截图模式，只配一种模型密钥即可。

不要分享真实密钥或提交到代码仓库。图片、文字和视频可能会发送给配置的模型或相关服务，请先去掉敏感信息，并确认服务额度和网络连接。

## 三、启动项目

### 1. 配置密钥

在 `backend` 文件夹中新建或编辑 `.env` 文件，使用 UTF-8 编码。注意文件名不是 `.env.txt`。

只填写实际拥有的密钥。例如，只使用 Gemini：

```dotenv
GEMINI_API_KEY=替换成你的真实密钥
```

需要其他服务时，再添加对应的配置行：

```dotenv
OPENAI_API_KEY=替换成你的真实密钥
ANTHROPIC_API_KEY=替换成你的真实密钥
REPLICATE_API_KEY=替换成你的真实密钥
```

不要原样保留示例占位文字，也不要覆盖已有的其他配置。修改 `.env` 后需要重启后端。

另一种办法是先启动程序，再到 **Settings（设置）** 填写 OpenAI、Anthropic 或 Gemini 密钥。Replicate 密钥需要写在 `backend/.env` 中。

### 2. 启动后端

打开一个 PowerShell 窗口，执行：

```powershell
cd C:\Users\kodesh\Desktop\sub2api\screen2code\backend
poetry run uvicorn main:app --reload --port 7001
```

如果尚未安装后端依赖，先在 `backend` 文件夹执行一次 `poetry install`，再运行启动命令。

看到服务运行在 `http://127.0.0.1:7001`，没有启动失败的报错，就保持这个窗口开着。

可选：如果希望 AI 使用浏览器截图检查生成的页面，在 `backend` 文件夹执行一次：

```powershell
poetry run playwright install chromium
```

这是自动检查页面需要的浏览器组件，缺少它不影响基本使用。

### 3. 启动前端

再打开一个 PowerShell 窗口，执行：

```powershell
cd C:\Users\kodesh\Desktop\sub2api\screen2code\frontend
pnpm dev
```

如果尚未安装前端依赖，先在 `frontend` 文件夹执行一次 `pnpm install`，再运行启动命令。

在浏览器打开：

```text
http://localhost:5173
```

如果终端显示其他端口，以终端显示的地址为准。两个终端窗口都要保持运行。项目存放位置改变后，请相应修改命令中的路径。

## 四、第一次生成网页

1. 确认已在配置文件或 Settings 中填好模型密钥。
2. 选择 **Upload（上传）**，上传或拖入一张清晰的截图。支持 PNG、JPG、JPEG。
3. 在 **Stack（技术方案）** 中选择输出类型，不熟悉时可以先用 **HTML + CSS**。
4. 点击 **Add instructions（添加要求）**，补充想保留或修改的内容，也可以跳过。
5. 点击 **Generate（生成）**，等待结果。
6. 查看预览。如果有多个候选结果，分别查看，再选中想继续修改的那一个。
7. 在修改输入框中写出具体要求，继续生成。
8. 满意后点击下载图标，导出代码。

补充要求可以这样写：

> 请尽量还原截图的布局、颜色和字号，把文字改成中文，保留顶部导航和产品列表，并兼容手机屏幕。

生成时尽量不要刷新页面。重要结果及时下载，不要把页面里的历史记录当成唯一备份。

## 五、其他输入方式

### 用文字生成

选择 **Text**，写清楚“做什么页面、有哪些内容、需要什么交互”，选择技术方案后点击 Generate。例如：

> 做一个中文待办事项页面。顶部显示日期，中间是任务列表，可以添加、完成和删除任务。提供全部、未完成、已完成三个筛选项。白色背景，绿色按钮，手机上也能正常使用。

### 用网址生成

在 Settings 中填写 ScreenshotOne API Key，再选择 **URL**，输入公开网页地址，选择技术方案并生成。

这是先截图再照图写代码，不是下载对方网站的源代码。需要登录、只能在本机访问或截图服务无法访问的页面，建议自己截图后上传。

**不能直接导入 Figma 链接。** 请先导出设计稿图片，或者截屏，再通过 Upload 上传。本地 `file://` 地址也不能用于 URL 截图。

### 导入已有代码

选择 **Import**，粘贴网页代码，或拖入一个 `.html` / `.htm` 文件；选择匹配的技术方案后导入。随后可以预览，再让 AI 修改。这不是导入整个项目文件夹的功能。

### 用录屏生成

在 Upload 中上传 MP4、MOV 或 WebM 视频，也可以使用界面中的录屏功能。视频模式需要 Gemini 密钥。

建议录制简短、清楚的操作，比如打开菜单、切换标签页。录屏能提供交互参考，生成结果仍需检查。

### 上传多张截图

上传区最多支持 5 张截图。可以提供不同区域或状态，同时说明图片之间的关系，例如：“第一张是桌面版，第二张是手机版，请生成同一个响应式页面。”

## 六、技术方案怎么选

Stack 指生成网页使用的技术，和 AI 模型不是一回事。

| 选项 | 适用情况 |
| --- | --- |
| HTML + CSS | 普通网页，方便直接查看和修改样式 |
| HTML + Tailwind | 使用 Tailwind 样式的页面 |
| React + Tailwind | 准备把结果用于 React 项目 |
| Vue + Tailwind | 准备把结果用于 Vue 项目，界面标记为测试阶段 |
| Bootstrap | 希望使用 Bootstrap 风格和组件 |
| Ionic + Tailwind | 偏移动应用风格，界面标记为测试阶段 |

没有明确要求时，先用 HTML + CSS 跑通流程。选择 React 或 Vue 不代表下载后就得到完整的工程目录。

## 七、检查和修改结果

| 常用按钮 | 用途 |
| --- | --- |
| Desktop / Mobile | 查看桌面或手机效果 |
| Code | 查看代码 |
| Open in New Tab | 在新标签页查看 |
| Refresh Preview | 刷新预览 |
| Previous version / Next version | 切换前后版本 |
| View all versions | 查看版本记录 |
| Download Code | 下载当前代码 |

部分按钮只显示图标，把鼠标放上去可以查看名称。

修改时尽量具体，一次处理一个或几个相关问题。例如：

> 只调整顶部导航：高度改为 64 像素，Logo 靠左，登录按钮靠右，下面内容不变。

> 手机端产品卡片改为一列，图片不要裁掉，按钮铺满卡片宽度。

除了看外观，还要点击按钮、输入文字、切换手机预览，确认交互是否符合预期。

## 八、下载后得到什么

点击 Download Code 后，程序会尝试下载 `screenshot-to-code-export.zip`，包含 `index.html` 和成功获取并打包的图片等资源。

解压后，先尝试用浏览器打开 `index.html`。保持解压后的文件结构，不要只移动 HTML 而遗漏资源。

如果打包接口失败，前端会退回到只下载 `index.html`，图片可能仍引用原地址。即使下载了 ZIP，也不保证所有外部依赖都已打包，字体、脚本、样式等可能仍需联网。

正式上线前，应进一步检查交互、依赖和数据接口。

## 九、常见问题

### 网页打不开

检查 `pnpm dev` 窗口是否还在运行、有没有报错，并使用终端显示的地址访问。默认地址为 `http://localhost:5173`。

### 网页能打开，但生成失败

前端启动不代表后端已启动。检查后端是否正常运行，再检查密钥、网络和服务额度。后端终端报错通常比页面提示更具体。

### 提示没有模型密钥

OpenAI、Anthropic、Gemini 三种密钥至少需要一种。确认填在 Settings 或 `backend/.env` 中，不要误填到前端配置文件。修改 `.env` 后重启后端。

### 提示视频模式需要 Gemini

配置 `GEMINI_API_KEY` 后重试。只有其他模型密钥时，可以先用截图模式。

### URL 截图失败

确认填写了 ScreenshotOne 密钥，且网址能被外部服务访问。Figma 链接、本地文件或需要登录的页面，改为手动截图上传。

### Screenshot preview 不可用

这是 AI 自动截图检查功能，不是普通页面预览。到 `backend` 文件夹执行 `poetry run playwright install chromium`，再重启后端并重新打开设置。

### 后端端口 7001 被占用

在 `backend` 文件夹改用一个空闲端口，例如：

```powershell
poetry run uvicorn main:app --reload --port 7002
```

当前前端默认通过 Vite 转发请求。在 `frontend/.env.local` 中设置新的转发目标：

```dotenv
PROXY_CODEGEN_BACKEND=http://127.0.0.1:7002
```

如果已经配置了下面两项，也要一起修改，避免请求仍指向旧端口：

```dotenv
VITE_HTTP_BACKEND_URL=http://127.0.0.1:7002
VITE_WS_BACKEND_URL=ws://127.0.0.1:7002
```

修改后重启前端。这些地址用于本机浏览器访问，不要直接照搬到远程访问场景。

### 图片缺失，或与截图差距较大

尝试更清晰的截图，并补充具体要求。素材提取依赖 Gemini，部分图片工具依赖 Replicate，没有对应配置时相关能力可能无法使用。下载后图片缺失，也可能是资源未打包成功或原地址不可访问。

### 如何停止和重新启动

分别在前端和后端终端按 `Ctrl+C` 停止。下次重新运行两条启动命令即可，通常不用重新安装依赖。

## 十、记住这条流程

**启动后端 → 启动前端 → 配置密钥 → 上传截图 → 选择技术方案 → 生成 → 检查并修改 → 下载。**

先用简单截图跑通流程，再尝试多图、录屏和复杂页面。
