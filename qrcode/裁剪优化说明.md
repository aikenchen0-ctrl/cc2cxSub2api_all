# 裁剪精准度优化说明

## 🎯 优化内容

### 1. **高精度坐标计算**

#### 问题原因
之前使用 `cropCanvas.width` 和 `cropCanvas.height` 来计算坐标，但这些是Canvas的实际像素尺寸（可能包含DPR缩放），而不是显示尺寸。

#### 解决方案
```javascript
// ❌ 旧方式（不精确）
const scaleX = cropImage.width / cropCanvas.width;

// ✅ 新方式（精确）
const displayWidth = parseFloat(cropCanvas.style.width);
const displayHeight = parseFloat(cropCanvas.style.height);
const scaleX = cropImage.width / displayWidth;
```

### 2. **Retina屏幕支持**

#### 实现原理
```javascript
// 检测设备像素比（DPR）
const dpr = window.devicePixelRatio || 1;

// Canvas实际像素 = 显示尺寸 × DPR
cropCanvas.width = displayWidth * dpr;
cropCanvas.height = displayHeight * dpr;

// CSS显示尺寸保持不变
cropCanvas.style.width = displayWidth + 'px';
cropCanvas.style.height = displayHeight + 'px';

// 缩放绘图上下文
cropContext.scale(dpr, dpr);
```

这样在高分辨率屏幕上，Canvas会更清晰，不会有模糊问题。

### 3. **精确的鼠标事件处理**

#### 坐标转换公式
```javascript
// 获取Canvas边界矩形
const rect = cropCanvas.getBoundingClientRect();

// 计算相对于Canvas的坐标
const clientX = e.clientX - rect.left;
const clientY = e.clientY - rect.top;

// 转换为Canvas内部坐标（考虑DPR）
const canvasX = clientX * (cropCanvas.width / rect.width);
const canvasY = clientY * (cropCanvas.height / rect.height);
```

这个公式确保了：
- 无论Canvas如何缩放，坐标都准确
- 支持任意CSS变换
- 在不同设备上保持一致

### 4. **边界限制**

```javascript
// 确保不超出Canvas边界
currentRect.x = Math.max(0, newX);
currentRect.y = Math.max(0, newY);
currentRect.width = Math.min(newWidth, cropCanvas.width - currentRect.x);
currentRect.height = Math.min(newHeight, cropCanvas.height - currentRect.y);
```

防止用户框选到Canvas外部区域。

### 5. **最小选择区域保护**

```javascript
if (currentRect.width < 10 || currentRect.height < 10) {
  // 如果选择区域太小，重置为全选
  currentRect = { x: 0, y: 0, width: displayWidth, height: displayHeight };
  setStatus("选择区域太小，已重置为全选", "working");
}
```

避免误操作导致的选择区域过小。

## 📊 精度对比

### 优化前
```
Canvas显示: 600x400
Canvas实际: 600x400 (DPR=1) 或 1200x800 (DPR=2)
用户框选: (100, 100, 200, 200)
计算比例: 1200/600 = 2 (错误！应该用显示尺寸)
发送给后端: (200, 200, 400, 400) ❌ 不准确
```

### 优化后
```
Canvas显示: 600x400 (style.width/height)
Canvas实际: 1200x800 (width/height, DPR=2)
用户框选: (100, 100, 200, 200)
计算比例: 1200/600 = 2 (正确！)
发送给后端: (200, 200, 400, 400) ✅ 精确
```

## 🔧 技术细节

### 坐标转换流程

```
用户鼠标位置 (clientX, clientY)
    ↓
减去Canvas偏移 (clientX - rect.left, clientY - rect.top)
    ↓
转换为Canvas坐标 (× canvas.width / rect.width)
    ↓
存储为 currentRect
    ↓
转换为原始图片坐标 (× image.width / displayWidth)
    ↓
发送给后端
```

### DPR处理

```
低DPR屏幕 (DPR=1):
  Canvas实际: 600x400
  Canvas显示: 600x400
  比例: 1:1

高DPR屏幕 (DPR=2):
  Canvas实际: 1200x800
  Canvas显示: 600x400
  比例: 2:1
  
context.scale(2, 2) 确保绘制时使用正确的坐标系
```

## 🐛 常见问题

**Q: 为什么坐标还是有点偏差？**
A: 检查浏览器的缩放比例是否为100%，非100%缩放可能导致微小偏差。

**Q: 在手机上框选不流畅？**
A: 确保使用了最新的代码，已添加触摸事件支持。

**Q: 高清屏上图片模糊？**
A: 已实现DPR支持，如果仍模糊，请清除浏览器缓存后刷新。

**Q: 如何验证坐标是否正确？**
A: 打开浏览器控制台，查看"框选完成"和"发送裁剪坐标"的日志输出。
