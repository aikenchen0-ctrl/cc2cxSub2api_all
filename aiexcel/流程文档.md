## 二、最终架构

```text
浏览器
  -> Sub2API 左侧“AI表格”
  -> Sub2API SSO 启动接口
  -> AIExcel SSO 回调与本地会话
  -> AIExcel /api/ai
  -> Sub2API /v1/chat/completions
  -> 上游模型服务
```

Sub2API 负责统一身份、登录、API Key 鉴权、余额、分组和上游路由；AIExcel 负责 Excel 本地解析、操作计划、用户确认、修改和导出。

## 三、SSO 登录流程

### 1. 从菜单启动

已登录 Sub2API 的用户点击“AI表格”，前端访问：

```text
/api/v1/auth/integrations/aiexcel/start?next=%2F
```

该接口经过 Sub2API JWT 中间件保护，未登录返回 `401`。

### 2. Sub2API 签发票据

Sub2API 查询用户资料，生成有效期约两分钟的 HMAC-SHA256 票据：

```json
{
  "iss": "sub2api",
  "aud": "aiexcel",
  "sub": "Sub2API 用户 ID",
  "email": "用户邮箱",
  "username": "用户名",
  "iat": 0,
  "exp": 0,
  "jti": "一次性随机编号",
  "next": "/"
}
```

签名密钥是 `SUB2API_SSO_SECRET`。浏览器不会获得 Sub2API JWT 或模型 API Key。

### 3. AIExcel 回调

Sub2API 将浏览器跳转到：

```text
http://localhost:4173/api/auth/sso/callback?ticket=<短期票据>
```

生产环境必须使用 HTTPS 和精确的回调地址。

AIExcel 会校验签名、`iss`、`aud`、时间范围、`jti` 重放状态和安全的 `next` 路径。成功后设置短期 HttpOnly handoff Cookie，并清理最终地址中的票据。

### 4. 兑换本地会话

首页检测到 SSO 参数后，同源请求：

```text
POST /api/auth/sso/exchange
X-AIExcel-SSO: 1
```

AIExcel 读取并删除 handoff Cookie，签发自己的 `aiexcel_session` HttpOnly Cookie。后续业务接口只信任本地会话。

当前用户接口：

```text
GET /api/auth/me
```

未登录返回 `401`，已登录返回当前用户信息。

## 四、AI 调用流程

1. Excel 文件由浏览器使用 ExcelJS/SheetJS 本地解析。
2. 浏览器只发送 Sheet 名称、表头候选行、行列数量、少量样例和自然语言指令。
3. 浏览器请求 AIExcel：

   ```text
   POST /api/ai
   ```

4. AIExcel 校验 `aiexcel_session`，未登录返回 `401`。
5. 同一用户已有请求时返回 `429`，避免重复消耗额度。
6. 服务端读取 `SUB2API_RELAY_API_KEY`，调用：

   ```text
   POST http://sub2api:8080/v1/chat/completions
   Authorization: Bearer <服务端 API Key>
   ```

7. Sub2API 负责余额、分组、模型调度和上游转发。
8. AIExcel 解析 JSON 操作计划，并先展示给用户确认。
9. 用户确认后，浏览器在本地修改工作簿，支持撤销、重做和导出。

前端不再使用 `localStorage` 保存 API Key，也不再直连 `https://api.deepseek.com`。

AIExcel：

## 六、Docker 部署步骤

### 1. 先检查 Sub2API

```powershell
docker ps --filter name=^sub2api$
docker inspect sub2api --format '{{.State.Health.Status}}'
docker network inspect deploy_sub2api-network
```

必须确认 Sub2API 容器存在且为 `healthy`，并确认网络存在。

### 2. 读取现有 SSO 密钥

```powershell
$secret = (docker inspect sub2api --format '{{range .Config.Env}}{{println .}}{{end}}' |
  Select-String '^SUB2API_SSO_SECRET=').ToString().Split('=', 2)[1].Trim()
$env:SUB2API_SSO_SECRET = $secret
```

实际密钥不能写入文档、Git 或日志。

### 3. 覆盖部署 AIExcel

```powershell
$env:SUB2API_DOCKER_NETWORK = 'deploy_sub2api-network'
docker compose up -d --build --force-recreate
```

Compose 会重建 `aiexcel:local`、覆盖同名旧容器、映射 `4173:80`，并将 AIExcel 加入 `deploy_sub2api-network`。不会停止或重建 Sub2API。

### 4. 部署后检查

```powershell
docker ps --filter name=^sub2api$ --filter name=^aiexcel$
docker inspect aiexcel --format '{{.State.Health.Status}}'
Invoke-WebRequest http://127.0.0.1:4173/
```

预期：Sub2API 和 AIExcel 均为 `healthy`，主页返回 `200`，未登录 `/api/auth/me` 返回 `401`。

## 七、环境变量

```env
SUB2API_SSO_SECRET=与 Sub2API 完全一致的至少 32 位密钥
AIEXCEL_SSO_CALLBACK_URL=http://localhost:4173/api/auth/sso/callback
SUB2API_RELAY_BASE_URL=http://sub2api:8080/v1
SUB2API_RELAY_API_KEY=Sub2API 中创建的服务端 API Key
SUB2API_RELAY_MODEL=deepseek-chat
```

当前部署已经配置 SSO 密钥和中转地址，但 `SUB2API_RELAY_API_KEY` 为空。因此 SSO 和页面可以使用，实际 AI 请求需要先注入服务端 API Key。

## 九、当前限制与后续建议

1. 并发锁目前是单 Node 进程内存状态，多副本部署时应迁移到 Redis 分布式锁。
2. `jti` 防重放记录目前是进程内存状态，多副本部署时应迁移到 Redis 或数据库。
3. 当前 AI 调用是同步请求；批量或长任务场景再接入 BullMQ、Redis 或 RabbitMQ。
4. 生产环境必须使用 HTTPS，并固定精确的 SSO 回调地址。
5. 建议后续增加 AI 任务表、用量记录和审计日志。
