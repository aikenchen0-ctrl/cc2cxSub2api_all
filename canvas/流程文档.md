# Canvas 与 Sub2API 对接流程

## 1. 今日完成内容

本次工作只修改 `canvas`，不涉及 `canvas-old`。

已完成的目标：

- 普通用户通过 Sub2API SSO 登录后，自动获得 Canvas 本地会话。
- Canvas 为每个 Sub2API 用户建立独立的本地用户 ID。
- 用户的画布、项目、素材、图片任务、视频任务、工作流和算力点按 Canvas 用户 ID 隔离。
- 普通用户无需填写 Base URL、API Key 或本地模型渠道。
- 普通用户的文本、生图、图像编辑、视频、音频和 Workflow Agent 请求统一通过服务端 `sub2api-relay` 渠道。
- 浏览器提交的本地渠道 ID 或用户渠道 ID 不再能够绕过 Relay。
- Relay API Key 只保存在 Canvas 服务端，不返回浏览器。
- Canvas 按模型价格扣除用户算力点；上游调用失败时自动退款。
- Sub2API 按服务端 Relay Key 所属账户记录实际上游消耗。
- 管理员仍可以在 Canvas 后台维护和测试其他模型渠道。

## 2. 系统角色

```text
Sub2API 用户
    |
    |  SSO 一次性票据
    v
Canvas SSO 接收端
    |
    |  创建/查找 Canvas 本地用户 + Canvas JWT
    v
Canvas Web
    |
    |  仅携带 Canvas JWT，不携带 Sub2API Relay Key
    v
Canvas 服务端
    |
    |  选择 sub2api-relay，执行额度扣减、请求代理、失败退款
    v
Sub2API /v1 网关
    |
    v
上游文本、图片、视频模型
```

对象归属如下：

| 对象 | 归属方 | 用途 |
| --- | --- | --- |
| Sub2API 账号 | Sub2API | 统一身份认证和上游账户计费 |
| Canvas 本地用户 | Canvas | 画布、项目、素材、任务和本地算力点隔离 |
| `sub2api-relay` API Key | Canvas 服务端 | 访问 Sub2API，绝不下发浏览器 |
| Canvas 算力点 | Canvas | 按 Canvas 用户记录业务额度和消费流水 |

## 3. 登录流程

### 3.1 Sub2API 发起登录

1. 用户已在 Sub2API 登录。
2. 用户打开“无限画布”入口。
3. Sub2API 校验自己的 JWT。
4. Sub2API 生成短期 HMAC SSO 票据，包含：
   - `sub`：Sub2API 稳定用户标识。
   - `iat`、`exp`：签发时间和过期时间。
   - `jti`：一次性随机票据 ID。
   - `username`、`displayName`、`email`、`avatarUrl`：可选展示信息。
   - `next`：Canvas 内部相对跳转路径。
5. 浏览器跳转到 Canvas：

```text
/api/auth/sso/callback?ticket=<one-time-ticket>
```

### 3.2 Canvas 接收票据

1. Canvas 使用相同的 `SUB2API_SSO_SECRET` 校验 HMAC 签名。
2. 校验票据长度、时间窗口、字段长度和控制字符。
3. 对 `jti` 做 SHA-256 摘要并写入 `sso_tickets`。
4. 已消费过的票据直接拒绝，防止重放。
5. 使用 `sha256(sub)` 派生 Canvas 用户 ID：

```text
sub2api-<sha256(subject)>
```

6. 用户不存在时创建普通 Canvas 用户；存在时复用该用户。
7. 用户被禁用或身份字段不匹配时拒绝登录。
8. Canvas 创建自己的 JWT，并放入短期 HttpOnly handoff Cookie。
9. 浏览器回到 `/login?sso=1`。

### 3.3 前端交换会话

1. Canvas 登录页检测 `sso=1`。
2. 前端同源 POST：

```text
POST /api/auth/sso/exchange
X-Canvas-SSO: 1
```

3. Canvas 检查请求来源和 handoff Cookie。
4. 读取并立即删除 Cookie。
5. 返回 Canvas `AuthSession`。
6. 前端保存 Canvas JWT，后续请求只使用 Canvas JWT。
7. URL 中不保留 SSO 票据、Sub2API JWT 或 API Key。

## 4. 无感知模型调用流程

### 4.1 前端模式切换

用户登录后，Canvas 加载公开模型设置。如果发现启用的 `sub2api-relay`，且当前仍处于本地模式，前端自动切换到远程模式。

用户不会看到或填写：

- Relay Base URL。
- Relay API Key。
- 服务端渠道权重。
- 上游供应商凭据。

前端只选择公开的模型名称和业务参数，然后把请求发送到 Canvas：

```text
POST /api/v1/chat/completions
POST /api/v1/responses
POST /api/v1/images/generations
POST /api/v1/images/edits
POST /api/v1/videos
POST /api/v1/audio/speech
```

### 4.2 服务端渠道强制策略

Canvas 服务端的 `selectAIRequestChannel` 对普通用户执行以下策略：

1. 检查 `sub2api-relay` 是否已启用且包含服务端 Key。
2. 普通用户始终按模型名称选择 `sub2api-relay`。
3. 忽略普通用户提交的 `X-Model-Channel-ID`。
4. 忽略普通用户提交的 `X-User-Model-Channel-ID`。
5. 未配置 Relay 时，才回退到原有渠道选择逻辑。
6. 管理员不受此强制策略影响，可以使用后台管理的渠道。

这样即使用户修改浏览器请求，也不能把普通用户请求改成其他本地或服务商渠道。

## 5. 文本调用流程

```text
Canvas Web
  -> POST /api/v1/chat/completions 或 /responses
  -> Canvas 鉴权并读取 model
  -> 选择 sub2api-relay
  -> 计算模型价格和请求数量
  -> 扣除 Canvas 用户算力点
  -> POST <SUB2API_RELAY_BASE_URL>/chat/completions 或 /responses
  -> 使用服务端 Relay API Key
  -> 原样/协议适配返回结果
  -> 写入 AI 调用日志
```

流式文本响应仍由 Canvas 代理返回；请求失败会执行退款。

## 6. 生图和图像编辑流程

### 6.1 普通生图

```text
Canvas Web
  -> POST /api/v1/images/generations
  -> Canvas 解析 JSON 或 multipart 中的 model
  -> 强制选择 sub2api-relay
  -> 按 n 计算扣费数量
  -> 扣除用户算力点
  -> POST Sub2API /v1/images/generations
  -> 解析 b64_json、url 或兼容响应
  -> 返回图片结果
```

### 6.2 图生图和参考图编辑

```text
Canvas Web
  -> POST /api/v1/images/edits
  -> Canvas 保留 multipart 图片和遮罩数据
  -> 强制选择 sub2api-relay
  -> 转发到 Sub2API /v1/images/edits
  -> 解析图片结果并记录任务/日志
```

图片任务使用 Canvas 用户 ID 保存，因此不同用户无法读取、删除或批量操作其他用户的图片任务。

## 7. 视频调用流程

### 7.1 创建任务

```text
Canvas Web
  -> POST /api/v1/videos
  -> Canvas 解析 model、prompt、seconds、size 和参考素材
  -> 强制选择 sub2api-relay
  -> 按时长/请求参数计算 Canvas 扣费
  -> 扣除用户算力点
  -> POST Sub2API /v1/videos
  -> 保存 Canvas video_tasks 记录
  -> 返回 Canvas 任务 ID
```

### 7.2 异步轮询

1. Canvas 后台轮询器读取 `video_tasks`。
2. 按任务所属用户和 `sub2api-relay` 渠道恢复任务。
3. 请求 Sub2API：

```text
GET /v1/videos/{upstream-id}
```

4. 将上游状态转换为 Canvas 的 `queued`、`processing`、`completed` 或 `failed`。
5. 任务失败时退款，并保存错误详情。
6. 任务完成后保存结果地址或上游视频 ID。

### 7.3 视频内容下载

当任务没有公开可直接访问的 URL 时，Canvas 服务端执行：

```text
GET /v1/videos/{upstream-id}/content
```

Canvas 校验任务必须属于当前用户、状态必须为 `completed`，然后以私有无缓存响应流式返回视频内容。

## 8. Workflow Agent 流程

Workflow Agent 虽然是工作流草稿能力，但本质上也是大模型调用，因此单独处理：

1. 普通用户提交工作流描述和参考图。
2. Canvas 忽略请求中的本地 Base URL、API Key 和渠道 ID。
3. 选择 `sub2api-relay` 的文本模型。
4. 扣除 Canvas 用户算力点。
5. 调用 Sub2API `/v1/chat/completions`。
6. 解析 JSON 工作流草稿。
7. 失败时退款并写入 AI 日志。

## 9. 计费流程

### 9.1 Canvas 侧

每个远程任务在发起上游请求前执行：

1. 根据 `model` 查找 Canvas 模型价格。
2. 根据 `n`、视频时长或请求数量计算总额度。
3. 原子扣减当前 Canvas 用户算力点。
4. 记录 `ai_consume` 流水。
5. 上游网络失败、HTTP 错误或返回无效任务 ID时退款。
6. 记录 `ai_refund` 流水。

扣费用户是当前 Canvas 登录用户，不是其他用户，也不是匿名共享账户。

### 9.2 Sub2API 侧

Canvas 使用服务端配置的共享 Relay Key 调用 Sub2API。Sub2API 会把真实上游消耗归属于该 Key 所属账户。两套账本职责不同：

- Canvas 算力点：面向 Canvas 用户的业务计费和限额。
- Sub2API 余额/消耗：面向 Relay Key 所属账户的上游成本。

## 10. 必需配置

Canvas 服务端：

```env
SUB2API_RELAY_BASE_URL=http://sub2api:8080/v1
SUB2API_RELAY_API_KEY=<server-side-key>
SUB2API_RELAY_MODELS=<text-model-ids>
SUB2API_RELAY_IMAGE_MODELS=<image-model-ids>
SUB2API_RELAY_VIDEO_MODELS=<video-model-ids>
SUB2API_SSO_SECRET=<same-secret-as-sub2api>
```

Sub2API 侧需要配置：

```env
CANVAS_SSO_CALLBACK_URL=https://canvas.example.com/api/auth/sso/callback
SUB2API_SSO_SECRET=<same-secret-as-canvas>
```

注意：图片和视频模型列表必须填写 Sub2API 实际开放的公开模型 ID。模型没有写入对应列表时，Canvas 不会把它展示为该能力模型，也不会允许普通用户调用。

## 11. 验收步骤

1. 启动 Sub2API，并确认 Relay Key 可以访问 `/v1`。
2. 启动 Canvas，确认日志中没有 Relay 配置错误。
3. 从 Sub2API 入口打开 Canvas，确认自动登录成功。
4. 检查浏览器请求：不应出现 Relay API Key。
5. 普通用户调用一次文本模型，确认：
   - Canvas 服务端收到请求。
   - Sub2API 收到 `/v1/chat/completions` 或 `/v1/responses`。
   - Canvas 用户算力点扣减。
6. 调用一次生图和一次图像编辑，确认请求到 `/v1/images/generations` 或 `/v1/images/edits`。
7. 创建视频任务，确认创建、轮询、完成和 `/content` 下载完整可用。
8. 制造一次上游失败，确认 Canvas 用户额度自动退款。
9. 创建两个 Sub2API 用户，确认两人的项目、素材和任务互不可见。
10. 尝试修改请求中的渠道 Header，确认普通用户仍然使用 `sub2api-relay`。
11. 管理员登录后台，确认仍可维护渠道和模型配置。
