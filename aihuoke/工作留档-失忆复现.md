## 3. 主链路（代码里真实在跑的图）

`ai-hunter-root/backend/graph/builder.py`：

```
parse_description → insight → keyword_gen → search → lead_extract → evaluate
                                              ↑                         |
                                              └──── continue ───────────┘
                                                                   finish → email_craft → END
```

界面不是浏览器里同步等 hunt。真实行为：

1. 新建页提交 → 创建 **automation job**

## 5. 搜索层（最容易误判的一块）

### 5.1 路由边界

网页搜索走独立模块 `tools/web_search_router.py`。

- Insight / LeadExtract / CompanyWebsiteFinder / Customs **只认** `WebSearcher.search()`
- 付费 Serper 与免费 DuckDuckGo 各管各的
- **Maps 仍留在 `search_agent` + `GoogleMapsSearchTool`**，不要把 Maps 塞进 web_search_router

`SEARCH_BACKEND`：

- `auto`：有真 Serper Key → Google Maps；否则 DuckDuckGo
- `serper`：强制 Maps，没 Key 就失败
- `free`：强制免费网页搜索，无 Maps

无 Serper 时：

- 关键词走 `agents/keyword_strategy.py` 网页提示，不是 Maps 词
- 并发由 `tools/search_limits.py` 限到 **2**
- 每轮关键词限到 **4**（`effective_keywords_per_round`）
- 发现阶段 `FreeSearchTool.search(allow_encyclopedia=False)`
- 抽线索 / 找官网 `open_web_search(allow_encyclopedia=False)`
- Insight **默认仍可走百科**
- 词典 / 百科 / 中文门户由 `tools/lead_source_filter.py` 丢掉

### 5.2 出口与代理

`tools/outbound_http.py`：

- `SEARCH_HTTP_PROXY=http://127.0.0.1:7897`（Clash Verge）
- 显式代理时 `trust_env=False`，跳过 WorkBuddy 沙箱 `60376`
- **配了显式代理就不要再直连超时重试**（直连在本机也出不去）
- 无显式代理时，502 / ConnectError / Timeout 才允许 `trust_env=False` 直连重试

DuckDuckGo 细则：

- **不要传 `kl`**。`de-de` 会变成 202 验证页
- **不要单发 `Content-Type`**，会盖掉 UA，变成空页
- HTML 空则试 lite
- HTML + lite 全失败抛 `SearchBackendError`
- httpx `ConnectTimeout('')` 字符串是空的，必须走 `format_http_error`，否则界面变成 `ddg_html: ; ddg_lite:`

被墙处理：

- `round_search_is_blocked()` 只看**本轮关键词是否全失败**。历史错误不要误杀续挖
- 本轮 0 新增 + 被墙 → 立刻停（包括已有旧线索的续挖）
- 第一个关键词抛 `SearchBackendError` 后，`tools/search_circuit.py` 熔断本轮其余关键词，避免每个词再超时一遍
- 详情黄条、运营报告、KeywordGen 提示都要带上错误

新建 / 控制台 / 设置 / 续挖的提前警告：

- `tools/search_readiness.py`（只看配置，不探网）
- 经 `GET /api/settings.search_readiness`
- 新建 / 控制台用 `warning` + `new_hunt_note`
- 续挖用 `resume_note`：跳过 Insight，但仍会搜；被墙且 0 新增即停

Jina 抓页失败走 `tools/page_fetch.py`，不要把兜底塞进 Jina 模块。

### 5.3 密钥卫生

`SERPER_API_KEY=        # comment` 曾经被当成真钥匙，Maps 打了 16 次全空。

- `sanitize_secret` / `has_usable_api_key` 在 `config/settings.py`
- `#` 开头、占位符 `xxx` / `your-key` 都不是 Key
- 真钥匙后面可以跟 ` # comment`，会裁掉注释

### 5.4 实测结论（以最后一次探测为准，不是永久保证）

Clash `127.0.0.1:7897`：

- 端口开着时，Google / Serper 入口 / 出口 IP 能通
- **代理通 ≠ DuckDuckGo 通**
- 2026-09-18 白天：7897 打过 DDG，德国逆变器经销商出过 8 条
- 2026-09-18 19:10：同一 7897，DDG HTML / lite **ConnectTimeout**
- Bing 能开，但跳中文门户（知乎 / 吾爱破解 / 百度百科），当不了外贸线索
- Startpage 验证页，未接入

所以：

- 「搜索走 7897」——代码层仍成立
- 「DuckDuckGo 能出网页结果」——**当时成立，现在不保证**
- 没有 Serper 时质量低于 Maps——前提是 DDG **先能出结果**。出不来就不是质量差，是搜索层完全没回来

## 6. LLM 网关（当前配置）

网关是 **sub2api**：`OPENAI_API_BASE=http://api.cc2.cx/v1`

当前 `.env`（密钥在文件里，不要抄进 git / 聊天）：

- `LLM_MODEL=grok-4.5`
- `REASONING_MODEL=grok-4.5`
- `OPENAI_API_MODE=chat`
- LiteLLM 实际走 `openai/grok-4.5`（裸名不是官方 OpenAI 模型，不加前缀会报 `LLM Provider NOT provided`）

切换历史，避免你再走回头路：

| 时期 | 模型 | 结果 |
| --- | --- | --- |
| 最早体验 | MiniMax | 旧任务 401，不要重试 |
| 其后 | `gpt-5.5` + `OPENAI_API_MODE=auto` | 自定义网关上 gpt-5/gpt-6 走 `openai/responses/<model>` |
| 中途 | gpt-5.5 上游 503 | 请求已入 sub2api 账，即使立刻失败。断点在 sub2api→上游，不在本机 |
| 再其后 | `grok-4.6` chat | 通过；裸名必须加 `openai/` |
| 现在 | `grok-4.5` | 因 `grok-4.20-0309-non-reasoning` 限流而换。chat 200，上游实际 `grok-4.5-build` |

`tools/llm_client.py` 的路由规则：

- 调用方始终发聊天消息
- `OPENAI_API_MODE=auto` + 自定义 base + gpt-5/gpt-6 → `openai/responses/<model>`（打 `/v1/responses`）
- `chat` → `/v1/chat/completions`
- 自定义网关上 **非** gpt-/o1/o3 的名字（grok-*）→ 加 `openai/` 前缀
- gpt-5/gpt-6 强制 `temperature=1`

探测网关模型列表：`GET http://api.cc2.cx/v1/models`。换模型先 chat 打一发 `Reply with exactly OK`，再改 `.env`，再 `POST /api/settings` 刷新缓存。

设置页选项已含 `grok-4.5`。改设置后检查 `.env` 注释在不在。

## 11. 界面与 SSE 的已知假象

- 「实时流断开，回退轮询」：任务正常结束或主动 close 也会触发 SSE `onerror`。已修：completed/failed 不算断开；运行中 15s 心跳。Vite 代理 `timeout: 0`
- 控制台「3 次调用无线索」：多半是 Insight ReAct，不是 search
- 搜索 0 线索且黄条有 `search_backend_error`：是被墙/超时，不是关键词没命中
- 搜索 0 线索且没有黄条、关键词有 result_count：才是词不行或过滤太狠
- 设置页保存成功但 `.env` 变「无注释墙」：正常，store 会重写文件
