> 日期：2026-09-17

## 0. 结论（先看这个）

**根项目：`refs/AI_Find_Customer`（AI Hunter）**

其余四个全部当「模块源」，不当根：

| 仓 | 角色 | 原因 |
| --- | --- | --- |
| **AI_Find_Customer** | **根** | 唯一完整的「搜公开网页 → 抽线索 → 评分 → 邮件」大脑；Python + FastAPI + LangGraph + React；MIT；中文外贸场景 |
| OpenOutreach | 思想源 / 旁路找人 | 成熟度最高，但 GPL 传染；本仓只是编排壳，真正找人在 `openoutfind` pip 包，且绑 BetterContact，不爬公开网页 |
| ai-outreach-engine | 触达与联系人瀑布 | MIT，联系人瀑布 / dry-run / 审批门做得很干净，但 Bun+TS，体量是创始人玩具，不当根 |
| spiderfoot | OSINT 工具箱 | 200+ 模块 pub/sub，MIT；产品是侦察不是获客，整仓当根会把项目拖进威胁情报 |
| maigret | 社媒存在性工具 | 用户名扫 3000+ 站，MIT；适合给「已抽出的人」补档案，不是获客流水线 |

本地路径：

```
refs/AI_Find_Customer     ← 根
refs/OpenOutreach
refs/ai-outreach-engine
refs/spiderfoot
refs/maigret
```

## 1. 五仓拆解（基于实际代码，不是 README 广告）

### 1.1 AI_Find_Customer —— 根

栈：Python 3.11 + FastAPI + LangGraph StateGraph + React/Vite + SQLite。

真实图（`backend/graph/builder.py`）：

```
parse_description → insight → keyword_gen → search → lead_extract → evaluate
                                              ↑                         |
                                              └──── continue ───────────┘
                                                                   finish → email_craft → END
```

已经有、应原样保留的模块：

| 目录 | 干什么 |
| --- | --- |
| `backend/agents/` | Insight / KeywordGen / Search / LeadExtract / EmailCraft / ParseDescription |
| `backend/graph/` | HuntState、循环停止条件（target_lead_count / max_rounds / min_new_leads_threshold） |
| `backend/tools/` | Google/Tavily/Brave/Maps、Jina Reader、contact_extractor、email_finder、email_verifier（MX）、customs_router、platform_registry |
| `backend/emailing/` | SMTP/IMAP、scheduler、reply_detector、template_pipeline、policy |
| `backend/automation/` | job_queue + consumer + notifier |
| `backend/api/` | hunt / campaign / SSE / settings |
| `frontend/src/routes/` | new-hunt / hunt-detail / dashboard / settings / automation-job |

缺口（根仓自己也承认）：

- 邮件自动化不完整，详情页不是完整营销系统
- 联系人瀑布弱：`email_finder.py` 只做页面正则；`email_verifier.py` 只查 MX，没有 `first.last@` 猜测
- 没有「为什么选这条线索」的白话 `reason`
- 没有 Instantly/Smartlead 对齐的 CSV 契约
- 没有 dry-run / 日限额 / 角色邮箱黑名单这套发送护栏

### 1.2 OpenOutreach —— 不当根

本仓 `openoutreach/` 只有：`__main__.py`（CLI 编排）、`wizard.py`、Django settings、把 `openoutfind` / `openoutsend` 装进同一个进程。

找人和发信的实现 **不在这个 git 树里**，是 pinned pip 依赖：

- `openoutfind==0.1.12`
- `openoutsend==0.1.36`

产品边界：browserless、零爬虫、持牌源 BetterContact。跟「全网搜公开网页」是两条路。

GPL-3.0：任何拷贝其 Python 都会把我们的产品变成 GPL。只吸下面这些**非代码**资产：

- `reason` 字段（每条线索一句合格理由，没有 score 列）
- CSV 列名对齐 Instantly/Smartlead：`email, first_name, last_name, company, title, website, linkedin_url, reason, lead_id, qualified_at`
- 花费门：搜索免费，只有高置信线索才买验证邮箱
- CLI 动词：`find N` / `find N emails` / `status` / 默认不 send
- `skills/find-leads/SKILL.md` 的 agent 契约（可重写成我们自己的 hunt skill）

### 1.3 ai-outreach-engine —— 不当根

栈：Bun + React + SQLite。流水线是 job stage，不是 LangGraph：

```
scan_site → generate_audiences → generate_audience_email
find_companies → find_contacts → verify_contact → draft_message → send_message
```

值得吸的模块（MIT，**用 Python 重写进根仓 `tools/` / `emailing/`，不要混 TS**）：

| 源文件 | 吸什么 |
| --- | --- |
| `server/src/providers/emailPatterns.ts` | `first.last` / `flast` / `firstlast` / `first.m` / `first@`，按域名记住打中的格式 |
| `server/src/pipeline/stages/findContacts.ts` | 已有联系人则 resume，不重复烧搜索积分；丢掉 role/generic inbox |
| `server/src/compliance/guards.ts` | 免费邮箱域名黑名单 + 角色邮箱（info@, sales@…） |
| `server/src/providers/sender/dryRun.ts` | 默认 dry-run，审批后才出站 |
| `server/src/pipeline/stages/scanSite.ts` + `providers/crawler.ts` | Firecrawl 爬自己的产品站，给 Insight 加一份站点简报 |
| `server/src/compliance/` | 发送窗口、日限额、间隔、退订 |

不吸：jobs / investors 两条 playbook；Brevo 绑定；整套 Bun 运行时。

### 1.4 spiderfoot —— 不当根

200+ `modules/sfp_*.py`，事件总线：模块 watch 某些 event，produce 另一些 event。产品是红队/暴露面侦察。

只把「获客有用」的模块当 **LeadExtract 之后的可选 enrichment 插件**，默认关闭威胁情报：

**P1 吸（公开网页 / 公司 / 联系人）**

| 模块 | 用途 |
| --- | --- |
| `sfp_email` | 任意页面抽邮箱（比根仓 `email_finder` 覆盖的 event 类型多） |
| `sfp_emailformat` | 公司邮箱格式猜测，和 outreach-engine 的 pattern 瀑布互补 |
| `sfp_emailcrawlr` | 第三方邮箱爬取 API（有 key 才开） |
| `sfp_company` | 公司名抽取 |
| `sfp_builtwith` | 技术栈，当 ICP 信号（Shopify vs 自建站决定话术） |
| `sfp_github` | 公开 org / 贡献者 |
| `sfp_googlemaps` | 对照根仓已有 `google_maps_search.py`，补地理线索 |
| `sfp_accounts` | 社媒账号枚举（轻量；深度交给 maigret） |
| `sfp_clearbit` / `sfp_fullcontact` | 有 key 才开的 enrichment |

**明确不吸**

- 全部威胁情报 / 黑名单 / TOR / 暗网 / 端口扫描 / 比特币 / 数据泄露
- `sfp_spider` 整站爬虫（用 Jina / Firecrawl 代替）
- 把 200 个模块一次性挂上（噪声会淹死获客评分）

吸收方式：不要 fork spiderfoot 运行时。把选中模块改写成根仓 `tools/` 里的同步函数，输入 URL/域名/公司名，输出结构化字段。保留 MIT 版权头。

### 1.5 maigret —— 不当根

核心：`maigret/checking.py`（异步扫站）+ `maigret/sites.py`（站点库）+ `socid_extractor`。输入是 **username**，不是公司。

当 **SocialPresenceTool** 挂在「已经抽出姓名/用户名的线索」后面：

| 吸 | 不吸 |
| --- | --- |
| `checking.py` 的异步探测与反爬分类 | 默认扫 3000 站 |
| `sites.py` + 自动更新的站点库 | Tor / I2P |
| `--tags` 按国家/品类过滤 | 把 username 搜索当成获客主入口 |
| 递归：从主页链出的其它 ID 再查 | 把 AI profiling demo 当产品卖点 |
| 只开 LinkedIn / X / GitHub / Facebook / Instagram / YouTube + 目标国 tags |  |

调用时机：LeadExtract 得到 `full_name` 或社媒 URL 之后，**每条线索限额**（例如最多 20 站），结果写回 lead 的 `social_profiles[]`。

## 2. 目标架构（根 + 吸收）

```
[用户输入：官网 / 文档 / 关键词 / 目标市场]
        │
        ▼
 parse_description → insight ──┐  ← 可加 Firecrawl scan_site（来自 outreach-engine）
        │                      │
        ▼                      │
 keyword_gen ←─────────────────┘
        │
        ▼
 search（Google / Maps / Tavily / Brave / B2B 站内）
        │
        ▼
 lead_extract（Jina + contact_extractor）
        │
        ├─ enrichment 可选、默关、按 lead 限额
        │     spiderfoot: email / emailformat / company / builtwith / github / maps
        │     maigret: username → 社媒存在（tags 过滤）
        │     outreach-engine: 邮箱格式瀑布 + MX/Reoon 验证 + 域名格式记忆
        │
        ▼
 evaluate（原停止条件 + 新增：reason 字段、关键词效能）
        │
        ├ continue → keyword_gen
        └ finish → email_craft → campaign
                        │
                        ├ 护栏：dry-run、角色邮箱黑名单、免费邮箱剔除、日限额
                        └ 导出：Instantly/Smartlead CSV（含 reason）
```

OpenOutreach **不进图内主路径**。需要「描述即找人、不爬站」时，做成可选旁路：`tools/licensed_finder.py` 调 BetterContact（自己写适配器，不拷 GPL 代码）。

## 3. 吸收优先级

### P0 —— 根仓原样跑起来

- 保留 LangGraph 五段 + EmailCraft
- 保留 FastAPI + SSE + React
- 保留 customs_router / platform_registry（外贸差异化，别的仓都没有）

### P1 —— 立刻补上的缺口（outreach-engine → Python）

1. `tools/email_patterns.py`：格式猜测 + `domain_email_patterns` 表  
2. `emailing/guards.py`：freemail + role inbox  
3. `emailing/policy.py` 已有则扩展：dry-run 默认、日限额、发送窗口  
4. `find_contacts` 语义：已有联系人 resume，不重复搜

### P2 —— 线索变「人」而不是「公司名」（spiderfoot 精选）

1. 把 `sfp_email` / `sfp_emailformat` / `sfp_company` / `sfp_builtwith` 改写成 `tools/osint_*.py`  
2. 挂在 LeadExtract 后，失败不影响主流程  
3. 每条 lead 写 `evidence_urls[]`（根仓已有证据链接传统，对齐并强化）

### P3 —— 社媒补全（maigret 作为工具）

1. `tools/social_presence.py` 包装 maigret 库调用  
2. 白名单站点 + 国家 tags + 每 lead 上限  
3. 结果进 lead.social_profiles，给 EmailCraft 当个性化材料

### P4 —— 产品契约（OpenOutreach 思想，自写代码）

1. lead schema 加 `reason: str`，Evaluate / LeadExtract 必须写出  
2. `GET /export.csv` 列名对齐 Instantly/Smartlead  
3. 邮箱付费查询花费门：只对 `reason` 合格且置信过线的 lead 花验证额度  
4. 自写 `skills/hunt-leads/SKILL.md`（参考 find-leads 的「不擅自 send」规则）

### P5 —— 不做

- 不以 OpenOutreach 为根，不把 GPL 文件拷进仓库  
- 不把 spiderfoot 200 模块、maigret 3000 站做成默认扫描  
- 不把 ai-outreach-engine 的 Bun 服务并进 Python 后端  
- 不把 jobs/investors playbook 做进外贸获客 MVP

发送侧：默认 dry-run；角色邮箱/免费邮箱不出站；遵守目标市场的垃圾邮件规则（CAN-SPAM / GDPR）。OSINT 模块只读公开页，不绕验证码、不撞登录墙。
